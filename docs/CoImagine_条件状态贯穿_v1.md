# 将逐参数条件状态贯穿规划与执行更新（第 22 轮）

改了什么：把推演表示从「一个混合状态 + `b(θ)`」换成 `{b(θ), s^θ}`，并让它在四条链路上存活。
只改传播，不改网络、不重训、不改数据、不改奖励与代价、不加公共反馈分支；深度与束宽保持原值。
代码：`src/coimagine/diagnostics/conditional_planner.py`；入口
`scripts/conditional_propagation_probe.py`；原始数据
`outputs/grid/diagnosis/conditional_propagation.json`。

| 链路 | 实现 | 行为 |
|---|---|---|
| 动作展开 | `expand` / `expand_actions` | 每行 `s^θ` 用自己的 one-hot 过 `model.step`，不再先混再复制 |
| 反馈预测与更新 | `per_theta_outcome` / `condition` | 取 `model.observe` 的对角（各θ自己状态的似然），再 `b'(θ) ∝ P(y\|a,s^θ,θ)b(θ)` |
| 搜索分支 | `plan_with_conditional_states` / `beam_value_conditional` | 每个符号分支、每层 beam 都携带整组 16 行，深层不再压回一个状态 |
| 执行后更新 | `correct_observables` | 观测只改可观测部分（物体格、机器人坐标），`released` 逐行保留 |

评分仍用聚合量（位置分布、期望距离、到达概率），但聚合结果不再作为下一步的状态。

## 两个案例

**改善（场景 11，深度 1，`r=1, free, A=grip, B=slip`）。** 旧：首步排序 `push:1:E` 15.456 <
`push:0:E` 16.114，选了**打滑的 B**单独推 → 失败。新：`push:0:E` **12.452** < `push:1:E` 15.546，
选了**抓得住的 A** → 成功。这正是关联修复在起作用：旧方案把状态混成一个，"谁抓得住"被抹平；
逐参数行保留后，A 抓得住那个假设能正确预测推动。

**退化（场景 44，深度 2，`r=1, free, grip/grip`）。** 旧：首步 `wait` 21.286（次选 `co_push` 21.403），
第二步 `co_push` 11.208 → 成功。新：首步 `co_push` 21.482（次选 `probe` 22.009），第二步却选
`probe`，分数 **1.624**，远低于 `wait` 2.097、`push:1` 2.251 → 失败。逐层查明：第一步 `co_push` 后
真实物体在 **(2,2)**，而逐参数行的预测落在第 4 行，随后**执行后融合**用编码器的格子覆盖了所有行，
而编码器在该状态给出 **(4,0)、真值概率 0.002**；于是聚合位置 97.8% 在目标区、`cut` 从 ~11 掉到 0.58，
规划器以为已经完成，改成便宜的 `probe`。**退化发生在第 4 条链路：用一个不可靠的编码器格子覆盖了
逐行预测。** 这与上一轮测到的单步生产性推动错误（真参数下 0.798/0.500/0.870）是同一根源。

否则保留各行的预测格子"，再跑同一张对比表，并确认深度 1 的改善没被丢掉。**本轮不改单步转移、
