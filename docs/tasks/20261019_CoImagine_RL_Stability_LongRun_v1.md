# CoImagine：RL稳定性单因素对照与有界长训练任务书

版本：v1.0｜日期：2026-10-19（Asia/Shanghai）

仓库：`/home/tzl/repo/coimagine`。
本文供执行agent实施。先读全文和诊断材料，再编码、测试、训练；不要直接复用旧长训练命令。
与旧任务书冲突时，本任务范围内以本文为准。本任务不要求启动世界模型或规划器。

## 0. 目标、已知事实和本轮唯一训练变量

目标：确认在真实90秒任务预算下，当前策略能否稳定学到并保留多个实例上的成功行为；
检验critic对共享表示的更新是否影响这种稳定性。允许单因素对照结果为负。

背景材料：

1. `docs/random_start_rl_diagnosis_v4.md`：最新实际诊断及限制。
2. `outputs/random_start_rl_diagnosis_v4/README.md`：源码、轨迹、梯度、分支证据入口。
3. `docs/handoff/20261018_RL_Progress_and_Next_Agent_Report.md`：此前训练与修复历史。

必须承接的事实：

- 原8例热启动、256例更新100/4600分别为3/8、0/8、1/8确定性成功。
- 旧validation64与train重复，不能用旧“最佳更新0”证明独立泛化最优。
  新独立validation上热启动3/64、4600为7/64，差值区间包含零。
- 固定8条真实轨迹中，成功5个决策项、失败2103项；短失败实际贡献了主要梯度。
  共享critic梯度范数约actor的7.75倍，但余弦为+0.85；不能预设梯度冲突是根因。
- 仅critic更新时actor头完全不变，动作分布仍改变，原8例成功3/8→2/8。
  完整更新仍3/8，但实际是丢掉0017、增加0020；平均成功率会掩盖遗忘。
- 短循环中多个技能标签具有相同首周期命令。补充物理分支表明，两处可用现有
  REPOSITION在0.05/0.20秒解除双方安全触发；不能宣布这些状态永久不可恢复。
- PUSH寻物时钟已修，默认环境为`random-start-time-budget-v3.1`。
  修复本身未提高上述三检查点的原8例成功数。

本轮两臂，唯一训练差异：

| 臂 | actor损失 | critic对共享encoder/GRU的反传 |
|---|---|---|
| A：shared_value_grad | 原PPO | 保留，现有基线 |
| B：stopped_value_grad | 完全相同 | 阻断；value head仍正常训练 |

B的实现语义：`value = value_head(hidden.detach())`用于训练价值损失；actor读正常hidden。
网络、参数量、前向价值函数、目标、优势、优化器及其他设置相同。
它不是“独立critic网络”，也不保证更好。全局梯度裁剪仍共享，因此不能称为彻底消除
actor/critic所有优化耦合。不要同时拆网络、改优势权重或调整学习率。

候选B已有一次同批核验，闭环为2/8，未优于A的3/8；因此本轮是检验长期稳定性的
实验，不是将一个已证实更好的修复扩大训练。保留A及所有负结果。

## 1. 执行范围与总预算

阶段顺序：S0冻结/核验 → S1两臂短程检查 → S2配对长训练 → S3最终评价与交付。

| 阶段 | 硬上限 |
|---|---|
| S0实现与核验 | 2小时 |
| S1短程检查 | 每臂64次更新×8条完整episode；两臂合计2小时 |
| S2长训练 | 每臂最多5000次更新×8条完整episode，或24小时，先到者；两臂合计≤48小时 |
| S3最终评价与材料 | 2小时 |

整体≤54小时。S2建议顺序执行A/B，每次8个采样进程、一个同步学习器；不要在同一台
机器上盲目同时开16个worker。墙钟预算包括该运行的采样、训练、周期评价和保存。
固定行为种子与实例顺序不等于动作改变后的物理轨迹仍完全配对。

满足当前阶段检查即可自主进入下一阶段。无需为常规实现选择逐项请求确认。
遇确定性正确性错误先修复并复验；若改变了共同控制器/观测/奖励条件，则当前配对实验
失效，停止并报告，不能只修一臂后继续。不要自动延长预算或追加第三臂。

本任务只授权上述有界实现、诊断、两臂训练和评价。不自动扩采S5，不训练世界模型，
不增加技能类别、任务特例导航策略、物理参数随机化或3D工作。

## 2. 冻结环境、奖励与信息边界

使用现有v3.1：

- 连续二维L0，双机器人随机初态；15动作/机器人，225有序联合动作。
- 控制周期0.05秒，一个共享世界，每周期推进一次；技能边界不重置位置或速度。
- 普通任务失败仅在90秒物理预算结束时发生；不恢复30/50技能上限。
- 成功条件保持：中心距目标≤0.20m、线速≤0.02m/s、角速≤0.05rad/s，连续0.50秒。
- 每周期奖励：`d_before-d_after - 0.02*d_after*0.05 - 0.002 + event`。
  成功+10、预算失败−2、gamma=1、保留真实终点距离；不添加动作/换面/信息奖励。
- 单技能受阻/安全退出不自动结束episode，模拟异常单列且停止该训练臂调查。

输入固定当前324维合法观测布局，包括双方机器人状态、目标、预算、接触、测距及拟合。
物体真值、奖励、终局标记、仿真快照、实例ID/种子不得进入actor、critic或GRU。
本轮不补动作/阶段历史；该已知缺口单列，留作后续独立实验。

不改技能控制器或安全阈值来提高成功率。现有REPOSITION已有部分恢复证据，不能因为
看到短循环就自动新增逃逸状态机。若S0发现确切新控制语义错误，用最小复现说明其是否
阻断比较；阻断则停止本轮长训练，交付修复建议或单独版本，不混进两臂结果。

## 3. 面板、共同初始化和检查点

使用`independent-v2`拆分：L0 train256、validation64、test64。
以`outputs/random_start_rl_diagnosis_v4/panels.json`的几何内容为基准。
诊断文件的env_version为旧v3，当前可更新版本元数据，但物理内容必须逐例一致。

- S0检测train/validation/test完整物理内容无重复；不能只比较名称。
- 原8例跟踪列表：0005、0010、0013、0017、0020、0038、0056、0063。
- 固定32训练面板沿用coverage256 manifest的`evaluation_train_instances`。
- validation/test的分支、行为变体跟随同一root划分；test不参与训练、调参或选择检查点。
- 每轮打乱train256，每批8个不重复，32更新覆盖一遍。两臂使用同一遍历规则与种子。

共同warm start固定为：

`outputs/random_start_time_budget_v3_coverage256/checkpoints/initial.pt`

它对应原8例最佳1550权重。用诊断manifest的哈希复核，不改用看起来更好的晚期模型。
从旧v3权重转到v3.1是明确标注的推理/训练热启动；不是恢复旧v3训练状态。
两臂均新建AdamW，因为这个检查点只有权重。使用同一随机种子0。
不要加载旧resume.pt的优化器或在版本校验中偷偷允许跨版本恢复。

开始前，两臂的初始前向概率和值、确定性原8例结果必须一致；记录检查点和输入字段哈希。
每臂的update0同样参与“最佳模型”候选，避免把退化后的模型误称最好。

## 4. S0：实现与定向验证

主要入口：

- `experiments/random_start_reposition_v1/rl.py`：增加显式、可序列化的critic共享梯度开关。
- `long_train.py`：支持两臂配置、阶段预算、指标、独立评估及安全恢复。
- `src/coimagine/random_start/`：默认冻结；仅核验v3.1时钟与split修复。

保持现有设置：GRU128、条件联合动作头、完整MC目标、跨轨迹批次优势归一化、
3个PPO epoch、AdamW lr3e-4、clip0.2、value权重0.5、entropy权重0、weight_decay=0、
全局梯度裁剪5。不引入GAE、价值裁剪、KL提前停更、自适应学习率或新的采样加权。

新增有意义的回归：

1. B与A更新前的actor概率、V、MC target逐项相同。
2. 将actor优势置零并用新优化器做一小步：B的encoder/GRU/actor头不变，value head变化；
   A允许共享表示变化。测试不能误把value head也冻结。
3. 在B中，仅actor损失仍能训练共享表示和前一技能的合法中间帧；原TBPTT边界保留。
4. 原概率回放、critic决策前时间、局部RNG、并行/串行等价、正常checkpoint中断恢复通过。
5. 运行现有六组定向测试（见诊断报告）；split按内容去重，时钟测试覆盖新技能在70秒启动。
6. 训练/分支恢复拒绝环境、输入schema、拆分或critic模式不一致，恢复不静默重置最佳模型。

重复计数应清楚：控制器安全退出不是数据截断；一个0.05秒技能也必须真实推进物理。
继续保存失败轨迹，不删循环、不偷偷限制决策数，也不把buffer耗尽当正常任务失败。

S0交付：`CONTRACT.md`、两臂配置、源码哈希、测试结果、明确的启动与恢复命令。

## 5. S1：有界短程检查

两臂各从共同warm start独立开始，固定seed0、同256实例遍历，最多64更新×8 episode。
它只用于检验实现、资源和指标，不按短程成绩挑臂或调参。

需检查：无NaN/Inf、概率/价值时刻一致、无真实未来反馈、完整失败episode为1800周期、
恢复路径可重复、日志可与实际模型变化核对。至少保存一次原始batch与更新前/后模型。

评价update0和64：原8例确定性+每例3个行为种子、固定32训练面板确定性。
S1不读取test，不根据validation短程成绩选择配置。

两臂无正确性错误即可进入S2；不能因为B短期低成功率而暗中取消B或换成其他算法。
S2两臂重新从共同warm start与新AdamW开始，避免选取有利pilot状态；S1结果单列。

## 6. S2：两臂长训练

输出独立目录，例如：

```
outputs/random_start_rl_stability_long_v1/
  CONTRACT.md
  manifest.json
  panels/
  pilot_A/  pilot_B/
  A_shared/ B_stopped/
  comparison/
```

不得覆盖原v1/v2/v3/v4诊断输出。每臂最多5000更新或24小时，完成哪项就停止。
整批采样使用同一个策略快照，按提交顺序合批，worker不得更新模型。
只用epsilon=0的策略采样；不加入示范损失、成功重放、熵奖励或额外探索混合。

主比较按相同完成更新数/训练episode数对齐；若墙钟到期导致更新数不同，正文同时报告
共同更新前缀和各自预算内结果，不把一个臂更多训练量带来的差异算作方法收益。
另报告真实物理周期、决策项数、评价成本和墙钟时间。

每100更新评价：

- 原8例：确定性和每例行为种子0/1/2的随机执行。
- 固定32训练面板：确定性。
- 独立validation64：确定性。

每500更新及最终完整检查点，再做validation64每例行为种子0/1/2的随机评价。
训练不读取评价轨迹；同实例多行为种子按实例聚类统计。

最佳模型选择规则预先固定：validation64确定性成功率优先，再以最终距离中位数较小
打破平局，再平局保留更早检查点。update0包含在候选中。
每次完整评价的权重都保存，不能只留下best与resume。

## 7. 必须记录的诊断指标

每更新保存：成功episode数、回报及各分量、最终距离、真实时间、决策数、模拟异常，
原始/归一化优势分组统计、梯度范数及裁剪比例、PPO ratio/clip fraction、价值误差。
记录精确联合熵，或明确旧条件采样熵的估计方式，不把两种统计混用。

短技能：≤2周期（0.10秒）。分别统计：

- 成功/失败轨迹各自的短技能比例、短技能占物理时间比例、重复动作连续长度；
- safety_abort、not_observed、blocked等退出次数；技能数分位数；
- 成功与失败在batch中的episode占比和决策项占比，两者不能混写。

每100更新，在实际训练batch上测一次不改变优化状态的分组梯度：
成功、短失败、其他失败的actor贡献；critic对共享表示/价值头贡献；共享梯度余弦。
B的critic共享梯度应为零。不要仅输出范数比而忽略方向、归一化分母和全局裁剪。

每100更新记录一次更新前后完整225联合分布的KL：按决策平均和按轨迹平均分别报告。
另在固定旧成功轨迹上重放合法历史，测动作概率及KL，作为遗忘诊断；这些历史不参与
训练或模型选择。即使它们在当前v3.1下不完全复现，也保留“固定历史诊断”的标记。

对4个已观察短循环状态，可读已有恢复诊断作为定点跟踪。若统计恢复动作概率，
应考虑相同实际命令对应的多个参数标签；不能仅汇总4个0.25m标签就声称所有恢复概率低。
这类诊断不能以隐藏真值构造部署动作mask，也不能直接作为额外训练奖励。

## 8. 遗忘、critic质量与成功证据

固定面板逐实例绘制“检查点×实例”的成功热图。报告：

- 每次评价新获得、保留、丢失的成功实例，特别是原8例；
- 原8例初始成功集合的保留率、历史成功集合的再次成功率；
- 连续三点评价是否稳定，确定性与随机执行是否一致；
- critic同批EV，以及在固定评价轨迹上的回报预测误差/EV，两者分开。

critic在不同评价轨迹分布上可能不准；固定旧历史上的回报标签对应旧行为，不能将其
当作当前策略Vπ的精确真值。评估当前critic时优先使用当前策略新产生的随机评价轨迹。
高EV或回报上升不能单独作为成功能力改善证据。

旧S4可学习性指标保留为明确的报告项：原8例确定性≥75%，比update0提高≥20pp，
连续三个评价点保持。未达到就明确写“未通过”；它不阻止执行本文已规定的256例对照。
不以人为修改成功定义、删除困难实例或额外脚本策略满足门槛。

## 9. 停止、异常和资源保护

- 达到每臂墙钟/更新预算立即停止；时间上限含恢复后的累计预算，不重新计24小时。
- NaN/Inf、模拟异常、奖励复算失败、协议/版本不匹配：保存最近完整状态与原始轨迹，
  停止调查；未完成更新不进入成功统计。
- 成功率下降、低熵、连续失败本身不自动触发新算法或奖励改动，仍按计划记录负结果。
- 不根据评价结果在运行中更改lr、critic权重、网络、输入历史或控制器。
- 每5更新原子保存resume；每次评价保存检查点；每30分钟落盘监测摘要和曲线。
- supervisor、worker退出后统一刷新manifest/monitor状态；SIGTERM、截止、异常、
  正常完成分别编码。验收同时检查真实PID/进程组，不能只相信manifest的running。
- 中断恢复保留优化器、RNG、实例遍历位置、实际更新号、最佳选择状态、截止预算及配置。

## 10. S3：最终评价与比较

两个臂均完成或到预算后，先固定各自按validation选出的best。
再对新test64做每臂一次确定性评价及每实例3行为种子的随机评价；不再据此调参或选模型。
若要推荐一臂供后续使用，也须在查看test前按validation规则封存选择；不得据test换臂。
若某臂因正确性问题无有效模型，明确缺失，不用其他checkpoint填补。

分别报告共同更新预算的学习曲线、validation选定模型的独立test结果及其相对update0的变化。
配对差值以实例为单位，随机执行先在实例内汇总；单训练种子只能作为平台工程证据，
不能把实例bootstrap区间当作跨训练种子的稳定性证据。

选片规则预先固定：共同初始模型成功的同一实例、训练中新获得的成功实例、短技能最多的
失败实例；每类最多1例，允许同一实例覆盖多类。A/B/初始在同一起点对照，含完整失败过程。
从真实日志生成视频/关键帧，标出真实时间、技能阶段、退出原因和诊断真值。

最终必须回答：

1. 阻断critic共享反传是否改变学习稳定性、价值拟合及闭环成功？是否只是不同失败偏好？
2. 原成功行为有没有被保留，新成功是否覆盖更多实例，是否满足连续评价门槛？
3. 短循环是否减少，减少的是决策项还是实际物理时间；能否与成功变化对应？
4. 新独立验证/test上是否有收益；证据范围与不确定性是什么？
5. 下一步最小改动是什么？若本轮无优势，不自动追加网络、GAE、熵或新长训练。
