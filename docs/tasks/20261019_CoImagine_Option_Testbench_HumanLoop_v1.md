# CoImagine：Option 小场景测台与人在环快速调优任务书

版本 v1.0｜2026-10-19｜仓库 `/home/tzl/repo/coimagine`

## 0. 用户目标与本轮停点

当前优先级转为：option 设计优化、兑现率与覆盖率量化、多个物理 snapshot 下的真实执行可视化。先在少数场景中提高技能质量，再讨论规模测试。本文替代先前 RL 长训练任务在本轮的执行优先级，不要求补跑旧训练。

**首次执行只完成测台、旧版基线和一轮视觉反馈交付，然后等待用户反馈。** 如果发现确定性测台错误，可在本轮修复；不凭自己的观察连续迭代控制器。后续每收到一轮反馈，完成一轮针对性修改、短测和对照交付，再交还用户。用户明确授权连续若干轮时才改变停点。

本次授权搭建测试设施与后续有界技能优化；不启动 PPO、世界模型训练、网络扩容、全量测试或大规模采样。世界系八方向平移/两方向旋转暂列设计候选，不要求首次实现。不得以缩小任务成功定义、改奖励、改物理参数或放宽安全条件获得正结果。

先读：

- `docs/random_start_rl_diagnosis_v4.md`
- `docs/tasks/20261019_CoImagine_RL_Stability_LongRun_v1.md`（仅了解冻结环境和历史，不执行训练）
- `src/coimagine/random_start/{env,lidar,skills,spec,render}.py`
- `src/coimagine/local_contact_option/control.py`
- `experiments/random_start_reposition_v1/{audit_recovery_v4,audit_skill_alias_v4,render_cases}.py`

研究问题是有限信息、模型容量、数据与计算预算下的预测与闭环决策。测台不能把完整联合接触规划藏进技能，也不能用部署不可见的真值选接触点。

## 1. 严格短预算：首次搭建与每轮运行

预算是硬限制，不是建议。区分物理模拟时间与脚本墙钟时间。

| 工作 | 墙钟硬上限 | 达到上限后的行为 |
|---|---:|---|
| 首次阅读、编码、测台搭建和首轮交付合计 | 90 分钟 | 保存可用部分、问题与最小复现，交还用户；不悄悄延长 |
| 后续单轮修改与交付合计 | 20 分钟 | 即使未解决也交付证据与建议，不启动第二轮 |
| 单 snapshot × 单动作分支的模拟子进程 | 10 秒 | 停止该分支，标记 `wall_timeout`，保存已有日志 |
| 单个批量模拟命令 | 60 秒 | 保存已完成项和缺失项；不自动加 timeout 重跑 |
| 单个视频/HTML/图表生成命令 | 30 秒 | 降级为已有日志驱动的轨迹图、关键帧或浏览器回放 |
| 单组定向测试命令 | 30 秒 | 报告未完成项，不改跑全套 |
| 单轮全部模拟、测试、渲染累计 | 180 秒 | 停止计算，产出当前结果与预算状态 |

运行入口必须同时实现内部 monotonic deadline 与外部进程组超时保护，例如 `timeout --signal=TERM --kill-after=2s 60s ...`；2 秒为清理宽限，单列实际超时。不得用 `pkill -f`，不得杀其他训练或用户进程。所有子任务计入累计预算，禁止拆命令规避限制。进度和每个分支结果及时落盘，失败/超时也必须有结果记录。

首次最多 8 个 snapshot、每个最多 3 个预登记分支，共 24 个分支，默认单进程。后续每轮至多 24 个候选分支；基线可复用同哈希缓存。改变测试条件导致缓存失效时，基线与候选运行合计仍不超过 24 个分支，减少本轮子集并明确标记。

单技能默认沿用 8 秒物理窗口；不跑 90 秒完整任务。恢复序列每个最多 2 次技能、累计最多 12 秒物理时间，必须在物理周期内检查上限，不允许整段技能越过上限。窗口截断记作 `evaluation_horizon`，不是技能主动失败。恢复序列占用同一 24 分支配额。

如果当前环境性能使这些预算不可达，优先减少分支数和视频数，交付实际耗时与下一轮建议；**不要自行加预算**。

## 2. 首批场景：8 个冻结的开发 snapshot

只使用训练实例、诊断轨迹或显式构造的开发 fixture。不读现有 validation/test 的结果来挑场景。不宣称 8 例代表整体分布。

建议面板如下，首次搭建时可根据合法几何微调并冻结，之后不按结果换场景：

| ID | 几何/运动条件 | 重点问题 |
|---|---|---|
| face | 平直面中部、自由空间 | 基本接近、接触与推动兑现 |
| corner_minus | 同一凸角一侧的微小偏移 | 分段、选面、接触位置 |
| corner_plus | 上一场景镜像侧的小偏移，其余不变 | 小扰动是否造成大幅行为切换 |
| edge_turn | 接近边端，预期绕角 | 切向切换、间隙、进度是否真实 |
| corridor_wide | 物体与墙间可容纳目标间隙的通道 | 正常边界跟随 |
| corridor_tight | 机器人几何可放入但目标间隙受限的窄缝 | 受阻、退出和恢复；不预设一定应通过 |
| teammate | 两机器人接近或互相阻挡 | 联合执行干扰和安全退出 |
| moving_recovery | 非零速度/接触的真实边界状态，或明确标注的动态 fixture | 惯性、接触恢复、连续性 |

先确认无非法穿透、初始未任务终止、距物理预算终点足够。特意制造的不可通行条件放在诊断标签里，不能作为技能的真值输入。每个状态保存初始图和几何摘要，人在环可要求下一轮增删场景；变更必须升级面板版本，旧结果保留，交集单独比较。

snapshot 应冻结物体/机器人位置与速度、物理和环境状态、接触重建所需信息、时钟、RNG、任务配置及版本。优先在技能决策边界取样；若从技能内部恢复，必须额外保存控制器阶段、滤波器、参考速度、计时等状态，否则不称精确恢复。

旧 `short_loop_states.pkl` 属历史版本证据，不得直接关闭版本检查载入当前环境。可使用当前版本重新生成同类状态，或显式的离线迁移并做一致性检查，失败则使用新 fixture 并注明来源。测台不修改部署恢复校验。

## 3. 动作与配对执行

首次以现有技能为 baseline：`PUSH(0°,0.16m/s)`、`REPOSITION_CCW(0.25m)`、`REPOSITION_CW(0.25m)`；按场景预登记最多 3 个分支，不扫全部 225 组合。至少包含两处真实联合执行：共同 PUSH 和一个预设的混合/绕行组合。没有选择的动作标记未测，不外推。

单机器人诊断时，队友仍在同一物理世界，由明确记录的制动保持控制器执行；不冻结、不移除、不清零速度。称为“另一机器人持续制动的诊断条件”，不冒充原始联合动作。主机器人结束后停止该分支。

联合分支沿用共享时钟、每周期只推进一次、先结束方进入原有 hold 的语义。baseline 与 candidate 必须从完全相同的 snapshot 开始；固定动作参数和队友协议；若动作契约本身改变，明确标为语义变更比较，不写成纯实现修复。

每分支保存初态哈希、动作/目标、合法输入摘要、源码/配置哈希、逐周期控制与反馈、退出及终态。重复恢复同一 snapshot 的短运行须一致（容差预先声明），并保证运行一个分支不污染另一个。

## 4. 契约、兑现率与覆盖率：先冻结口径，后运行

写入 `contracts/*.json`，至少包括：option 版本、目标、合法适用条件、完成条件、允许退出类型、窗口、连续指标及阈值、信息权限。

**分开记录三个层次：**

1. 控制器声称完成：原 `push_complete/reposition_complete` 等。
2. 独立评价的控制契约兑现：从原始日志重算，不直接相信退出字符串。
3. 任务效果：物体真实位移/转角、目标方向进展等，仅离线评价。

首次不要把旧 PUSH 升格为“世界方向物体平移”。旧 PUSH 的基线承诺是接触推动，目标方向是否稳定、接触点是否跳变作为独立连续指标。未来锁定接触区域或世界方向目标时，增加相应契约，不能回头用新契约美化旧结果。

### 4.1 分母与三态判定

统计单位首先是冻结的 `(snapshot, action, teammate_protocol)` 请求。一个 snapshot 的多个请求相关，不作为独立随机样本计算显著性。

- `eligible` 必须在执行前由合法输入计算，记录接受/拒绝/不确定及原因；旧控制器若没有适用条件接口，则如实标记“默认接受全部请求”，不能事后剔除失败。
- 请求覆盖率 = 接受请求数 / 全部预登记请求数。
- 状态覆盖率 = 至少一个请求被接受的 snapshot 数 / 面板 snapshot 数；注明只针对已测动作菜单。
- 条件兑现率：对接受请求统计 `fulfilled / violated / unresolved`。`unresolved` 包括脚本超时、缺日志和窗口不足等，单列数量。
- 同时给出保守区间：`fulfilled / accepted` 到 `(fulfilled+unresolved) / accepted`；accepted=0 写 N/A，不能写 100%。
- 有效兑现覆盖：已证实兑现的接受请求数 / 全部预登记请求数，防止靠拒绝困难情况抬高兑现率。
- 合理拒绝/安全退出单列，不算承诺效果兑现。`evaluation_horizon` 是否能判定违约依据预登记契约，不能一律算成功或失败。

只报告本开发面板的分子/分母、逐例配对变化。8 例人工场景不做“总体成功率”的统计推断。

### 4.2 首批连续指标

PUSH：接触建立时间、累计真实接触时长、接触丢失时长、选中片段/法向跳变、期望与实际参考方向、实际接触点轨迹、物体位移向量与转角、退出原因。无接触点时写缺失，不能补零冒充观测。

REPOSITION：沿合法估计切向累计的进度与原始轨迹、请求距离、间隙 min/median/max、意外接触时长、绕角事件、墙/队友最小距离、退出原因。真实跨面可由离线真值评估，不能输入控制器；绕行完成不自动等于跨面完成。

所有分支：实际物理时间、墙钟、控制周期、终态速度、安全触发、受阻后的可执行选项/短恢复结果（仅已测项）。方向误差只在速度/位移超过预登记小阈值时计算；零位移不能得到漂亮的角度分数。纯旋转目标若未来增加，单独评估角进展与附带平移。

阈值优先沿用现有物理契约；新容差需首次运行前写入并解释依据。本轮不设任意“90% 总门槛”。调优中若需修改指标定义，另起 metric_version，并对缓存原日志重算双方；不得只重算有利版本。

## 5. 可视化交付是主产物

输出建议：`outputs/option_testbench_v1/round_000/`，后续 `round_001/` 等，禁止覆盖历史。

首轮建立可本地打开、不依赖外部服务的 `index.html`：

- 首屏 8 个初态缩略图、问题标签、分支状态与对应回放入口。
- 选择 snapshot 和动作；后续轮 baseline/candidate 并排，同一物理时间轴同步。
- 播放/暂停、逐周期步进、时间拖动、速度切换、复位；结束较早的一侧停在终态并标注，不能拉伸时间伪装同步。
- 图层开关：雷达与拟合片段、当前选中片段、接触目标、法向/切向、期望/实际参考速度、实际力、轨迹、安全间隙。
- 明确显示技能阶段、物理时间、累计进度、接触、退出原因、适用条件与契约判定。
- 物体真值轮廓/中心/接触力矩等离线层使用明显标签，与合法输入层区分。控制器没有目标点时显示“未定义”，不要替它画一个目标点。

优先直接用日志驱动 canvas/SVG 回放，减少 MP4 编码成本。首次允许简洁界面，但必须能看真实运动过程，不能只交截图或均值表。最多编码 2 个关键短视频作为便携材料；视频超时不阻塞已有 HTML。若浏览器自动验收工具不可用，说明未做浏览器交互验证，仍检查资源路径、日志解析与时间索引。

每个问题案例选初始、关键转折、退出三帧；实际只执行一个周期也如实展示，不插值编造运动。生成可分享的短 `REVIEW.md`，直接链接入口和最值得看的 2–3 个案例。

## 6. 首次执行流程与后续人在环协议

### Round 000：测台与诊断基线

1. 冻结当前源码、环境配置、8 个 snapshot、请求菜单、契约与指标。
2. 实现有界执行、原子/增量日志、恢复检查、独立指标和 HTML 回放。
3. 跑 baseline 短测；只修测台问题，不借机优化技能。首次若预算不足，至少交付可运行入口、已完成场景和明确缺项，不宣布测台全部完成。
4. 给出证据支持的最多 3 项候选改动，按收益预期、风险与验证成本排序；推荐下一轮只做其中一项。
5. **停止，等待用户查看回放并反馈。** 不自行跑 round_001。

### 后续每轮：一次可归因的修改

收到反馈后，在运行前写 `ROUND_PLAN.md`：用户观察、要检验的假设、一个主要改动、受影响场景、保持不变项、预期看到什么、何种结果会否定假设。

候选方向包括选面跟踪/滞回、可见线段内接触点、显式换面退出、绕角连续性与受阻反馈。根据实际首轮证据选，不按此列表全部实现。动作历史、网络扩容、世界系新动作菜单另开实验，不混入同一次低层修改。

候选控制器使用显式版本/工厂注入，与 baseline 并存；保留原有训练环境默认行为。接口或动作语义改变就升级版本，不覆盖老 checkpoint 所依赖的实现。不要通过隐式全局 monkeypatch 切换版本。

每轮重跑受影响案例，再保留至少 2 个未针对性修改的固定回归案例；预算不足则明确缺测，不能写“无回归”。交付：

- 一句话说明改动和结果；
- 本轮实际预算、完成/缺失分支数；
- 逐例 `baseline → candidate` 兑现、覆盖、持续时间及副作用；
- 最多 3 个重要观察，附时间戳与回放链接；
- 推荐“保留/回退/证据不足”，最多 2 个下一轮选择，并说明推荐理由；
- 向用户提出一个具体反馈问题，例如“角点处应重新选点还是直接退出”，然后等待。

不得让用户只能在没有可视化证据的抽象参数之间选择。用户接受后才将候选列为下一轮工作基线，但原始 baseline 永久保留。用户另有明确授权时按其授权执行。

## 7. 最小测试和真实性保护

首轮只做必要的定向测试，每组 ≤30 秒、总计算受 §1 限制：

- 同 snapshot 恢复重复短执行一致、不同分支互不污染；
- 同一周期仅推进一次，真实初态速度/接触不被人为清零；
- 信息边界：相同合法输入下，隐藏真值不能改变选面/目标点/适用判断；
- 从原始接触与位移日志独立重算至少一个 PUSH 和一个 REPOSITION 指标；
- 分母含拒绝/超时/缺失、accepted=0 正确处理；
- 超时子进程和后代退出，已有日志保留；
- baseline 配置与旧入口一致，candidate 未被选中时不改变旧行为。

后续只跑受改动影响的必要测试，不重复跑全仓库。正式扩大规模之前再安排较完整回归。

禁止预设相同方向的联合 PUSH 一定兼容，禁止用真值裁掉“效果不好”的联合动作。安全与适用判断必须可由合法信息执行。快测失败、目标无法兑现、场景不可通行都是有效结果，不能删掉。

## 8. 目录、入口与验收

建议新增 `experiments/option_testbench/`，按实际需要划分模块，不为形式创建空模块。提供统一 CLI，至少支持 `prepare / run / render / summarize`，支持 panel、case、controller-version、branch-wall-seconds、total-wall-seconds 和输出目录。README 给出可复制的带 timeout 命令；各阶段可独立重跑，render/summarize 不重新模拟。

每轮至少保存：

```
manifest.json             # 版本、哈希、预算、请求全集与完成状态
panel.json               # snapshot 来源、标签、初态哈希
contracts/               # 运行前冻结的契约与阈值
requests.json            # 运行前固定动作/队友协议/分支清单
logs/                    # 逐周期真实轨迹
metrics.json             # 独立重算结果、分子分母、unresolved
index.html               # 回放入口及相关本地资源
REVIEW.md                # 本轮结论、关键案例、建议和反馈问题
ROUND_PLAN.md            # 后续轮必需，首轮可记录搭建计划
```

首次完成的验收是：**用户能够快速看到每个已执行请求的真实运动、知道技能承诺与实际效果是否一致，并有足够证据决定下一次修改。** 不是“8 个例子必须全部成功”，也不是“option 已泛化”。

规模测试的启动条件暂不预设成功率：用户确认当前代表案例的行为质量后，再单独冻结扩展面板、评估阈值和运行预算。调优场景始终是开发集，后续规模评价必须包含未用于调优的新状态。

保留现有工作树和旧输出；不清理、不自动提交。首次交付明确列出代码改动、运行命令、实际耗时和未完成事项。不得为了结束会话宣称后续优化或规模评估已经完成。
