## 3. 审查发现：先修正这些问题

### 3.1 残差诊断再次引入左补齐索引错误

fit_diagnostic.py 的 MidpointHead.forward 使用 valid.sum()-1 读取 current。真实 token 左补齐：只有一个有效 token 时它在第 32 号槽，代码却读取第 0 号槽；17～32 个有效 token 时也可能读到较早的真实观测。正式 models.py 已有 last_valid_index，应统一复用，禁止复制旧公式。

### 3.2 归一化残差与米制位置混加

单头训练的 target 是标准化后的位移，但 forward 内先把米制 current 加进网络输出；外层又对该输出反归一化，并加上正确的 current。这不是一个干净的残差实现。

严格说，错误不是“两次完整加上当前位置”，而是在反归一化后额外出现了 sigma_delta × current_wrong 的项，网络可能补偿它。因此旧结果是方向性线索，不能直接当作正确残差模型的收益。

### 3.3 诊断 A/B/C 的 mask 口径不符合正式评价

batch 返回 masks，但诊断中的中点误差没有筛选目标可见性；单头损失及其归一化统计也未按可见性筛选。不得把不可见标签中的占位数值计入有效几何回归；更不能拿这一结果直接与正式 masked 指标比较。

### 3.4 小集合实验没有证明整条序列拟合成功

训练时随机采样时刻，评价时每条序列只随机取一个时刻。因此“1 条序列终态误差 0.04 cm”只对应一个被测窗口，不是整条序列的中位误差。选择前 N 个 root 后再取前 N 条序列，也使 roots=count 的日志不可靠。包内样例按相同逻辑，标为 4 的子集仅来自 1 个 root，标为 16 的子集来自 2 个 root。

### 3.5 抽样、初始化与统计结论不完整

- 诊断 A、C 的训练样本写死从 d0 抽取，即使 tier=d1。A 可以解释为“中等规模模型在小规模训练子集上的误差”，不能代表完整训练分布；C 实际是小规模子集训练的单头诊断。
- 单头模型构造之后才 torch.manual_seed(0)，没有保证两种参数化同初始化。应在构造之前固定全部随机源，并配对初始 state_dict、批次顺序。
- per_column 参数存在但未实现相应归一化对照，因此“共享尺度已被证明是瓶颈”没有独立证据。
- 仅凭训练／验证中位数接近，不能排除局部分组或尾部过拟合；单序列终态拟合也不能证明整个管道正确。

### 3.6 结果与复现链路需统一

single_d1.json 的直接预测下一步验证误差为 1.9402339 cm，而 single_next_d1.json 为 1.9680709 cm；all_d1.json 只有 single，不能作为全部诊断的汇总。终态实验指标仍叫 next_step，容易混用。

MANIFEST 记录提交 c715893…，交付消息称 dd6c7e2；记录实际代码树哈希与提交关系，区分打包提交和内容提交。

verify_from_zip.py 只做一次有限输出检查并重新读取指标 JSON，没有重新计算其声明的评价指标。不能用 VERIFY_FROM_ZIP_OK 声称重现了诊断结论。新包必须提供可实际重算的小型证据。

## 4. 阶段一：统一输入、目标变换与评价

### 4.1 单一目标变换接口

实现并复用 encode_target / decode_prediction，明确坐标系、单位、列名、参考值、目标 mask、归一化统计与版本号。模型 forward 只输出标准化数值，不在内部偷偷添加米制位置。

对中点列 y，直接位置预测：

    z = (y - mu_y) / sigma_y
    y_hat = sigma_y * network_output + mu_y

对中点列 y，残差预测：

    delta = y - reference
    z_delta = (delta - mu_delta) / sigma_delta
    y_hat = reference + sigma_delta * network_output + mu_delta

reference 只能来自当前或过去有效观测，不得使用未来可见性／真值来决定参考位置。统一保持 option 起始坐标系。

注意：若 mu_delta 非零，标准化网络输出为零对应均值位移，并非保持当前位置。应验证 network_output=-mu_delta/sigma_delta 时精确还原保持预测；若希望零初始化对应保持基线，可设置相应输出偏置。禁止在报告里混淆“零物理位移”和“零标准化输出”。

### 4.2 可见性策略

采用不扩大模型的默认策略：当前片段有效时 reference=当前中点，否则 reference=固定起始坐标系原点（数值零）。此时不可见→可见样本退化为相对固定原点的位置回归，明确不是复制无效中点。既有有效性字段作为条件输入，不新增真值通路。

- 目标可见：计入几何损失和指标，包括当前不可见→目标可见。
- 目标不可见：不计入几何误差，但保留有效性、退出等监督。
- 持续可见、重新可见、变为不可见、持续不可见分别报告数量；不能删掉困难样本。
- 保持基线用相同的 reference 规则，另留一列历史实现结果（如不同），避免悄悄改善基线定义。

本轮只将两机器人中点的 x/y 改为可选残差，覆盖下一步和终态头。法向、角度、速度、退出分类等保持原参数化。不要把方向向量当作位置直接相减；扩大到其他输出应另行立项。

### 4.3 归一化

保留每组单标量与逐列两种模式。只用实际训练档位及有效训练标签拟合统计；训练种子、样本清单和统计文件全部保存。同一 seed 的模型对照复用统计。

逐列模式设置标准差下限并记录触发列，不能放大小样本近常量列的噪声。缺乏有效训练标签的列显式标记并采用预先规定的有限默认尺度。输入归一化本轮保持不变，避免同时增加变量。

检查随机源：Python random、NumPy、PyTorch；禁止像旧 fit_normalisation 那样只固定 NumPy，却另用未固定的 Python random 抽时间。

### 4.4 必须通过的行为检查

1. 1、6、16、17、32、33 个有效 token 的首末位置与原始序列一致，padding 值改变不影响输出。
2. encode/decode 对有效列往返恢复；位移只加一次，单位一致。
3. 合成恒定位置／恒定已知位移样例，能用指定输出精确解码。
4. 目标无效几何不影响归一化、损失及指标；可见性分类仍受监督。
5. 当前不可见时的 reference 不取无效几何，也不读取未来。
6. 在线预测 API 与离线评价解码同一检查点得到相同原始单位结果。

检查不是对代码结构的镜像测试，要能抓住本轮发现的索引、单位、mask 错误。

## 5. 阶段二：重做最小诊断，分离参数化与尺度

### 5.1 固定评价面板

从中等规模训练集全部训练起点均衡抽样，另外从验证集独立抽样，分别保存 record_id、root_id、窗口结束索引；不能让训练与验证使用相同记录。“同口径”不等于“同一批数据”。

用于单头训练的固定窗口默认 2048，验证默认 2048。同时保留训练固定窗口和未用于优化的训练集诊断窗口，区分记忆能力和训练分布表现。按实际唯一 root／序列／窗口数量记账，保存面板哈希。原小规模子集面板可另作旧结果追踪，但不得与新面板混合比较。

### 5.2 2×2 单头对照

下一步中点、直接终态中点分别执行下表；每格 seed=0,1,2，共 24 个轻量 run。两个目标独立训练，网络仍为相同历史多层感知机单头，3000 更新、相同学习率与调度、相同批次顺序。

| 输出 | 每组单标量尺度 | 每列独立尺度 |
|---|---|---|
| 直接位置 | 对照 | 只改归一化 |
| 当前位置＋位移 | 只改参数化及其目标统计 | 两项结合 |

每个 seed 构造一次初始权重，在四格之间复用；明确归一化改变的是损失度量。上述实验能比较工程配置，不能声称已经把残差结构和目标幅值所有影响完全分离。如果仍要主张纯结构因果，再追加同物理单位损失的直接／残差对照，否则不追加。

按 seed 分别报厘米误差 p50、p90、均方根误差、有效样本量、root 数，和同样本保持基线；不要跨归一化模式比较标准化总损失的绝对大小。

### 5.3 小集合拟合重测

默认使用 1、16、64 条显式指定的执行序列，优先各来自不同 root；若做多命令同 root，必须如实记录。固定有限窗口集训练，评价至少覆盖选中序列的全部合法相邻帧，不再一条序列只测一个时刻。

首先在纯中点单任务上测拟合能力，再用完整多任务设置定位迁移损失。不以某一个窗口拟合成功宣布所有实现正确。若无法拟合，先记录失败分组与损失；只允许一次有依据的延长训练或去掉 dropout 的诊断，单独命名，不混进正式对照。

### 5.4 阶段门槛

工程正确性检查全部通过后，才相信任何训练数字。新残差配置在三个 seed 的验证总体中位误差应优于保持基线，且至少两个 seed 的“持续可见且机器人运动中”子集优于保持基线。该要求是本轮推进门槛，不是结果承诺。

若尾部 p90 明显恶化（默认相对基线超过 10%），或优势只来自 t=0／近静止组，先输出分组诊断，不直接宣称可用。若根本未复现旧收益，最多一次针对性修复／重试，结束该阶段并交付，避免盲目训练全部主对照。

## 6. 阶段三：迁移到完整多任务模型

门槛通过后无需再询问，开发新版本预测器。保留原有全部过程头、终态头、字段和可见性监督；采用验证集选出的中点参数化／归一化策略，不增加网络规模。

正式矩阵只用中等规模训练集：单帧多层感知机、历史多层感知机、历史 Transformer，各 3 seed，共 9 个新配置 run，统一 3200 更新、batch 128。短时和终态可选择不同的目标变换，但三种架构必须采用同一套变换约定。

不强求新模型达到旧单头的 0.123 cm，不用该数值作为硬验收线。正式提升以同口径验证和冻结测试结果为准。终态中点相对修正后的直接预测对照，默认允许最多 5% 的 p50／p90 退化用于“无明显退化”检查；超过则作为短时与终态权衡报告，不自动推荐替换旧模型。

## 7. 评价与模型冻结

测试集只用于配置和预算冻结后的最终评价；不得根据测试集成绩继续选设置。本轮不需要重新回答全部数据规模问题。

必报项目：

1. 执行前 t=0 与执行中 t>0 分开；下一步与终态分开；训练、验证、测试分开。
2. 两机器人分别报中点二维误差、法向角误差、自身位姿／速度误差；不同单位不要合并成一个物理误差。
3. 中点 p50／p90／均方根误差；可见性和退出类别报逐类表现及数量，避免总体准确率掩盖少数类。
4. 机器人平移速度按 <0.01、0.01～<0.05、≥0.05 m/s 分组，明确不是物体速度；按阶段、当前／目标可见性、终态剩余时长分组。
5. 每项列有效窗口数、独立 root 数；三个 seed 各自结果及汇总，不能对每个指标挑不同最优 seed。
6. 同样本保持基线、命令与时间分组统计基线；检查后者的 command signature 是否完整包含两机器人 active 标志，当前代码只拼接了 c[4]，需验证 c[5] 在数据中是否冗余；不冗余就修复并重算。
7. 动作差值／动作排序保留为候选动作敏感性诊断，不宣称等于任务收益排序。
8. root 级配对 bootstrap；定义统计量并说明区间是否包含 seed 波动，禁止把同 root 的帧当独立重复。
9. 参数量、训练墙钟时间、推理 batch=1 和 batch=128 延迟及硬件线程设置。

检查点选择只能基于事先规定的固定验证标准。新版本至少保存最佳验证复合损失和固定预算最终检查点，主要比较用预先选定的一种；不同归一化的标准化损失不能跨设置直接排名。

冻结输出包括输入／目标 schema、归一化统计、坐标定义、有效性策略、解码版本、训练配置、数据与面板哈希。旧检查点只能通过显式旧版本适配器加载，不能悄悄用新解码读取旧输出。

为直接／残差各保留一个小型回放对照，验证修复后的公式与在线接口一致。打包检查缺件、重复项、路径安全、哈希和配置身份。

对原称“9 个既有失败”的测试，列出名称、错误和基线版本复现结果。和本轮数据、时间、mask、预测接口有关的失败必须解决；无关失败记录后不扩大任务去修复。新增相关回归必须全部通过，不能仅汇报通过总数。

## 9. 执行顺序与停止规则

顺序：工程修复与行为检查 → 固定面板和最小诊断 → 单头四格对照 → 验证集选配置 → 完整模型 12 run → 冻结并测测试集 → 独立目录复算与打包。

无需为常规实现选择、可逆修复或已授权训练再次询问。每完成一阶段更新状态，失败则提交具体样本和原始数值。主矩阵已足够回答本轮问题后停止；不要顺带采新数据、扩大模型、连接规划器或运行完整数据规模矩阵。

最终结论允许三种结果：

- 修正后的残差预测稳定改善且成功迁移：交付推荐冻结模型。
- 单头改善但多任务迁移不成功：交付定位结果及可用单头模型，明确完整模型尚未通过。
- 修正评价后收益不稳定：撤回旧强结论，保留全部证据，提出下一项最小诊断。

本轮成功的标准是获得可信、可复现且可用于下一阶段的预测器证据；不预设 Transformer 必须更好，也不以“所有问题已解决”作为交付要求。
