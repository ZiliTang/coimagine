## 2. A：只修已确认的实现与统计问题

### A1. 修正 batch loss 归约

当前 `fit_capacity/trainer.py` 中 `loss_components` 返回四个形状为 `[B]` 的逐样本向量，而 `torch.stack(components).sum()` 对样本也求和了。改为：

```python
per_sample = torch.stack(components, dim=0).sum(dim=0)
loss = per_sample.mean()
```

四项系数、state 内部维度平均、wrapped 角残差保持原样。训练日志的四项及 total 全部使用逐样本均值，注明 batch 实际大小。与 `data_upgrade.training.per_sample_loss(...).mean()` 在相同输入上数值一致。

必要测试：相同参数/同批数据的标量 loss 和参数梯度与旧正确函数一致；同批样本重复两遍，均值 loss/梯度不变。不要继续用“手工均值×样本数”证明错误的求和实现正确。

说明：Adam 对整体梯度缩放有一定抵消，不能把旧 bug 解释为学习率直接扩大 128 倍；最后小批大小不同意味着也不能认定两者完全等价。

### A2. 在对应更新时保存中间模型

现实现训练结束后才写 update1000/3000/6000，三份实际上使用最终参数。改为到达指定 update 时立即保存独立快照，或立即复制参数、稍后写盘；禁止引用后续仍被修改的 tensor。

保留两个 best 的独立参数复制，final6000 单独保存。checkpoint 内记录实际 update、配置、模型参数内容 hash，以及数据内容 hash。文件 hash 与参数内容 hash 分开，不能因元数据不同就认为权重不同。

必要测试：缩小网络和运行步数，以可配置 checkpoint 时刻测试；重新加载早期 checkpoint 的参数/预测必须等于该时刻即时捕获值，最终 checkpoint 必须等于最终值。不要只检查文件名和 updates 字段。对早期 checkpoint 重测物理指标，应与即时日志在数值容差内一致。

### A3. 恢复功能必须真的能恢复

旧代码只在结束时保存 resume 文件，没有实际恢复训练的入口，不能宣称支持中断续训。

在每个固定评估点原子保存恢复状态，增加 resume 入口；保存模型、Adam、数据 RNG、当前 permutation、cursor、updates/seen_samples、best 状态/分数及必要运行 RNG。恢复前核对完整数据内容与配置 hash。使用临时文件后 rename，禁止一半写入后被当作成功快照。

测试用小模型：连续运行 N 步，与运行到非 epoch 边界 M 步后恢复到 N 步，比较最终权重、优化器步数、样本顺序及 best 选择。固定 CPU、无随机层条件下要求一致；若无法一致，应定位原因，不放宽成仅“文件能读回”。

### A4. 候选比较按共同样本配对

旧 `run_candidates.py` 的“paired”文件直接相减两个聚合均值，没有先取共同可行样本。修正为按 `(start_id, candidate_seed)` 配对，在同一对模型都存在可行候选的行上计算收益差和损失差，再先按起点平均、后跨起点平均。

不同 checkpoint 的比较也使用同一方法。输出完整样本的拒绝/无解比例和共同子集上的收益差，不把删去的难例藏起来；uniform 和 candidate_best 也必须在同一子集上重算。

### A5. 最小报告更正

仅用旧原始记录更正：训练 loss 下降是 11/12 而非 12/12；−0.252 和 −0.166 高于 −0.361；较早模型不称“近初始化”。“原 test 无真实成功”对应召回 null，不是召回为零。

“物理最优 checkpoint”只能指实际比较范围和明确指标。旧脚本仅在若干保存点中按两套 val 物体位置误差之和比较，不代表全训练过程中或所有物理指标最优。不要根据两个选点不同就断言有严重实际冲突，应报告指标差值。

A 测试通过后才进入正式新训练。明确实现问题最多两次有依据的修复；仍不通过则交付 BLOCKED 和证据，不调参掩盖。

## 3. B：正确协议下重新运行 12 次训练

全部从相同种子的新初始化开始，不接续旧批求和训练。新目录 `outputs/fit_repair_v1/<run_id>/`；复用已有数据，不重新采样。记录所有原始数据文件完整 SHA256，不只对 scene/episode/index 字段计算“数据 hash”。

同宽同 seed 的两数据组初始参数相同；同数据同 seed 的两宽度使用相同 minibatch 顺序。独立初始化 RNG 和数据 RNG；将整个训练样本索引流滚动计 hash，不只比较前 64 批。

评估时间：update 0、100，以及每 250 次更新至 6000（去重，即含 250、500、750）。每次在完整 train、原 val、分支 val 上评估已有统一指标。训练 batch loss 与 checkpoint 全集 eval loss 分开存档。

保留 checkpoint：

- `fixed_1000`、`fixed_3000`、`fixed_6000`。
- `best_mixed_val`：最小 `0.5×原val总loss + 0.5×分支val总loss`。
- `best_original_val`：最小原 val 总 loss，只是次级选择规则。

best 均排除 update=0，并列保留较早者；禁止增加“至少训练多少步才允许选”的限制。全部训练完成后冻结模型清单，才运行 test 与候选评估。

保留上轮统一指标：四项 loss，各体位置误差及物体角度/速度误差，原始预测非法率和违规类型，终止混淆矩阵与成功 precision/recall，persistence 对照；列窗口微平均、场景等权平均和样本数。空分母用 null。

输出同预算/同种子的训练进度表、256/512 配对表、三种选择规则表。旧有偏差结果仅作历史附件，不与新结果混算种子均值。

## 4. C：两项限定诊断，解释预测失效

### C1. 终止类别为什么恶化：观察证据，不改训练

对全部 12 run 的三个 checkpoint（mixed/original/final6000），在 train、原 val、分支 val 上增加：

1. 真实各类别数量、平均 CE、该类真实标签概率均值，以及各类对总 CE 的贡献。贡献按全数据分母计算，相加恢复总体 CE，避免把小类别均值误当总体占比。
2. 成功 precision/recall、预测成功数、真实成功数；“无真实物理失败”明确标未验证。
3. 对真实成功窗口，预测 `window_complete` 的比例和真实 success 概率；对真实普通窗口，预测 success 的比例。
4. 这些量按 S0/S1 分组；不新增阈值、ECE 分箱或损失权重搜索。

据此判断 CE 上升主要来自成功漏判更自信、普通窗口误判、某一场景族，还是多项共同变化。只能称观测归因，不能宣称终止头造成位置错误，或多头梯度竞争已被证实。

分支 val 的 CE 确实恶化时，不称 mixed 规则“失效”；说明它在状态回归与终止判断间做了何种取舍。原 val 无成功样本，是原 val-only 选择的实际盲点，必须注明。

### C2. 几何非法主要与哪部分误差相关：限定离线替换

不增加训练，仅固定研究两个 run：Old+Random/256/seed0 和 Old+Branch/256/seed0；各取 mixed、original、final6000，在自身 train 与分支 val 上做诊断。选择在看新结果前确定，不挑最好/最差种子。

先重用原预测，统计各违规 pair 的发生比例、最大穿透分布，以及对应物体/机器人位置和角度误差。一个样本可有多种违规，明确各比例不必相加为 1。

随后在预测副本上做三种独立反事实，只调用冻结几何检查：

- 仅把物体 pose（位置与角度）替换为真实下一 pose。
- 仅把两机器人 pose 替换为真实下一 pose。
- 三个刚体的 pose 全部替换为真实下一 pose，作为检查参照。

速度、终止类别等保持原值；分别报告原非法→合法、合法→非法、总非法率。全 pose 真值参照若仍出现明显几何非法，先检查时刻/场景/解码，停止这项归因，不能强行解释为模型问题。

这些混合状态是离线敏感性实验，不一定物理可达；不得把效果称为可部署提升，不将替换后的状态送入 rollout，不根据 test 调阈值。若不同替换相互依赖，直接报告“联合误差”，不要强行指定唯一责任头。

正文只需总结：主要违规在哪些接触对；纠正机器人或物体 pose 各改变多少；训练改善是否改善了这些几何关系。全量细节放附件。

## 5. D：补齐检查点的候选选择对照

### D1. 留出回归评估

12 runs × 三种 checkpoint（mixed/original/final6000），在冻结原 test 和分支 test 上复测统一指标。相同参数内容可缓存，但保留三个逻辑标签。既有 test 已被查看，只称固定留出回归集，不称全新盲测。

### D2. 候选评估范围

同上 36 个逻辑 checkpoint，全部采用上一轮 12 起点、candidate seeds 0/1/2、H=3、K=128 的既有候选和真实参照。核对初态、候选序列与评分 hash，复用精确收益，不新增 H/K/起点。

逐行保存 `(group,width,model_seed,selection,checkpoint_hash,start_id,candidate_seed)`，明确每个候选池实际 K。保留两套协议：

- 未筛选：chosen_true、uniform、candidate_best、selected_bias、selection_excess、regret。
- 执行筛选：拒绝率、无可行候选比例、可行选择真实收益；误拒损失、集合内排序损失及它们的和。

无可行行的选择收益/损失填 null，不赋零、不执行非法候选。无解率同时列 pool 行数/全部 pool 行数，以及三个候选种子全部无解的起点数/12，不能互相替代。

对同 run 的 mixed→original、mixed→final 做 A4 的共同样本配对；256→512 只在同数据组/模型种子/选择规则下配对。列 Δ真实收益、Δ拒绝率、Δ两类损失及分母。对无解情况的变化单独计“有解→无解/无解→有解”。

精确评分对照检查 bias/regret=0；逐行检查误拒损失+排序损失=执行 regret。全部统计从原始行生成，正文不手填不同版本的数字。

本轮不根据 D 的收益重新选择 checkpoint，不把最优事后选点作为正式新算法，不运行闭环。
