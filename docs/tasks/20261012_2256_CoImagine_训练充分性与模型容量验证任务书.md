## 4. 统一指标合同

所有模型评估必须同时记录以下指标，不只报告综合 loss：

| 类别 | 必报指标 |
|---|---|
| 损失 | state、hold、duration、termination 四项逐样本均值及其和 |
| 状态 | 物体/机器人 0/机器人 1 的位置误差均值与 p90；物体 wrapped 角误差；速度误差及单位 |
| 合法性 | 原始解码预测的非法率、非有限数、违规类型和穿透 p50/p90/p99 |
| 终止 | 固定类别顺序的混淆矩阵；真实成功数、成功 precision/recall；预测成功且非法的数量 |
| 基线 | 同样本 persistence 的物体位置/角度误差，模型与它的配对差值 |

说明 raw termination 分类与“通过合法性检查的有效成功预测”不同，二者分开。零正例或零预测正例时填 null 并列分母，不填伪造的 0 或 1。真实 physical_failure 仍无样本时填“未验证”。

训练/验证完整物理指标另按 S0/S1、真实成功/非成功分组。关键运动分组沿用已有定义；若无固定定义，只做总体和上述必需分组，不新增阈值探索。

主汇总为窗口微平均；另列按场景先平均后等权的结果。不得把窗口微平均叫“锚点平均”。分支相关性作为限制说明，不把数千窗口当作数千独立实验。

## 5. B：固定预算训练 × 容量对照

### B1. 唯一实验矩阵：12 次新训练

| 因素 | 取值 |
|---|---|
| 数据组 | Old+Random、Old+Branch，各沿用既有 matched 数据（预期各 3684 个训练窗口） |
| 模型 | 2×256 ReLU MLP、2×512 ReLU MLP，仅宽度变化 |
| 种子 | 0、1、2 |
| 优化器 | Adam，lr=0.001，batch=128，其余沿用原默认 |
| 预算 | 每次固定 6000 次 optimizer.step；不早停，不看 test 决定延长 |

2×512 预期参数量 304,151，实际代码计数核对。Old 不再新增训练，A 已覆盖旧模型；本轮主问题是同数据下的预算与容量，不重做三组数据效果论文。

- 全部从新初始化开始，不从缺少 Adam 状态的旧 checkpoint 声称“无缝续训”。
- 同 width、同 seed 的两数据组，初始参数 hash 应相同。
- 为 minibatch 顺序使用独立 RNG。相同数据组和种子下，两种宽度读取完全相同的样本顺序；参数初始化不得影响数据 RNG。
- 按 epoch 洗牌并保留末尾小批，循环至 6000 updates；记录 seen_samples。不同宽度等更新/等样本，不称等算力，另报训练时间。
- 不改变 loss，不调整学习率，不根据初步效果试第三种网络。

### B2. 检查点与评估时间

固定评估 updates：`0, 100, 500`，以及 `250, 750, 1000, 1250, …, 6000`（即每 250 次，加 100；去重排序）。每个评估点测完整训练集、原 val、分支 val 的四项损失与物理指标。每轮训练日志分开保存训练期间 batch loss 与 checkpoint eval loss。

从上述同一条训练轨迹中，保存：

1. 固定进度 checkpoint：1000、3000、6000 updates。
2. `best_mixed_val`：最小化 `0.5×原val总loss + 0.5×分支val总loss`。
3. `best_original_val`：最小化原 val 总 loss，作为次级敏感性分析。

两种选择均不含 update=0，分数严格更低才更新，并列保留较早者。主规则不换成物理指标、不用 test 或规划收益选模型。

保存模型、optimizer、所有 RNG、updates、样本顺序进度、配置和数据 hash，确保意外中断可恢复。每次评估写日志；禁止任务超时后整批从头重跑。

### B3. 预算与异常停止

默认单训练进程；固定并记录 PyTorch CPU 线程数，默认 4。可使用已有可用 GPU，但同批统一设备，不购买算力或迁移服务器。

前一个 run 的前 500 updates 估计整批耗时。新训练累计墙钟预算 60 分钟；预计超限则将运行状态写明并保留可恢复 checkpoint，不擅自减半某些组的预算后继续做配对结论。NaN/Inf 停止该 run，保存最早异常批次；最多两次针对明确实现错误的修复，不做优化器/超参搜索。

## 6. C：区分预算、容量与选择规则

所有比较先逐 seed 配对，再报三个种子的各值、均值和范围，不只给均值。比较必须使用相同数据组与同一种指标。

必须交付三张紧凑表：

1. **训练进度表**：每个数据组/宽度的 1000、3000、6000 更新，列 train 和两套 val 的位置误差、非法率、总 loss。
2. **容量表**：同数据、同 seed、6000 更新下，512−256 的上述指标差值与时间。
3. **选择表**：每个 run 的 best_mixed_val、best_original_val、final6000 所处更新数、四项 val loss、train/val 物理指标。明确是否出现“总 loss 更好、物理误差更差”。

解释约束：

- 同宽度随更新改善，支持原训练预算/早停限制，但不能声称 6000 更新已经最优或收敛。
- 更宽模型在同预算下稳定降低训练误差，支持宽度增加有帮助；也可能涉及优化便利性，不能证明唯一原因是表达容量。
- train 明显改善而 val 不改善，表明泛化缺口；不据此继续加大模型。
- 总 loss 下降而非法率不降，只说明损失与物理指标可能不一致；若没有梯度或干预证据，不能把某个头断言为因果主因。
- 更宽模型没有改善，不等于 MLP 不适用；网络更大也可能尚未训练充分。

仅为统一措辞，预定义“明显改善”的工程标记：相同配对下，物体位置误差相对降低至少 20%（参考误差非零），且非法率绝对降低至少 10 个百分点，至少 2/3 种子同向改善。分别报告原/分支 val，不能用均值掩盖其中一域退化。这不是统计显著性或进入下一阶段的强制门槛；未达标仍完成 D。

完成本阶段后冻结全部 checkpoint ID 与表格，再打开固定 test 做评估。

## 7. D：一次固定留出集与候选复核

### D1. 固定留出集

对 12 个 run 的 `best_mixed_val`、`best_original_val`、`final6000` 测原 test 与分支 test，重复 checkpoint 可缓存。报告第 4 节指标，不据此重训/选新 checkpoint。原 test 已用于研发，只称固定留出回归集，不宣称全新盲测。

### D2. 固定候选，仅一个设置

仅使用每个 run 的 **best_mixed_val**，共 12 个模型。沿用上一轮全部 12 起点、已有候选种子及同一 `H=3, K=128` 候选缓存。先核对候选、初态、评分、真实参照 hash；缓存完整则复用，不重新调用精确规划器生成候选。缺缓存则先按既有确定性协议恢复，并登记，不能改候选提高覆盖。

继续分别报告：

- 未筛选诊断：原协议 chosen_true、candidate_best、uniform、selected_bias、regret。
- 执行协议：预测可行候选数、拒绝率、无可行候选起点数；仅在有可行候选的起点，选择预测收益最高者。
- 对可行筛选，把总损失拆开：`全部候选真实最佳 − 保留候选真实最佳` 为误拒损失；`保留候选真实最佳 − 实际选中候选真实收益` 为集合内排序损失。两者之和等于相对全部候选的 regret。
- 无可行候选时，后三项填 null 并列计数，不赋值为 0，不偷偷执行非法方案。不同模型条件均值需附分母；额外在双方都有可行候选的公共起点上做 256/512 配对比较。

精确评分对照 `J_hat=J_ref` 的 bias/regret 应为 0。预测非法与真实物理失败分开，禁止将拒绝率直接解释成预测成功率。

本轮到此结束：不跑闭环、不扩大 H/K、不增新种子、不为达到某个收益继续调参。
