## 0. 阅读入口与本轮终点

本轮按 A → B → C → D 顺序执行。阶段通过必要的正确性检查即可继续，不需要逐阶段请求确认。

| 阶段 | 工作 | 交付与终点 |
|---|---|---|
| A | 修正 Grid 诊断口径，补一组无坐标偏置的验证，定位选中方案的首个关键错误 | 冻结 Grid；不重训 |
| B | 连续平台冻结新实验合同，采集数据，训练普通单窗口模型 | 三个种子、一个结构、一次训练配置 |
| C | 连续平台固定候选诊断 | 分清候选覆盖、预测偏差和排序损失 |
| D | 同一候选规则和评分下做闭环对照 | 给出精确模型、学习模型、随机候选结果 |

本轮研究问题：模型是否虚构联合技能序列的物理进展或成功，从而选错方案？误差最早出现在哪里？

“性能变差”“比随机差”“搜索越多越差”均不是验收要求。允许模型准确、排序有效、深层预测没有明显额外问题。不得为制造现象而减少训练、改变场景或恶化候选。

本轮不实现：多尺度预测、跨步约束、新损失、模型集成、分布式预测融合、通信、异步技能、第三台机器人、多物体、机械臂仿真。三个训练种子是独立重复实验，不是 ensemble。

7. Grid 当前递归诊断遇到非法预测时保留上一合法状态继续；主诊断遇到非法预测立即终止。二者协议不同，旧误差曲线不能直接解释主规划流程。

### A2. 无坐标偏置的独立验证集

对上述指标按真实初始状态先汇总，再汇总状态；不要把三个模型种子、候选种子当作独立场景，禁止据此声称高统计显著性。

### A3. 收益误差拆解与错误追踪

把 J_hat-J_ref 按成功奖励、执行步数、终态距离、非法预测罚项分别拆解；分别汇总选中候选和全体候选均值。做代数一致性检查：分项和必须等于总偏差。

在新验证集 H=4、K=256 上：
- 先对每个状态平均各种子的 regret，选择最大的 3 个不同状态；
- 每个状态选择最大 regret 的一次运行，稳定 ID 打破平局；
- 再选 1 个最小平均 regret 状态作对照；
- 输出对应选中候选和精确最佳候选的逐步真状态、预测状态、动作、评分分项。

记录首次完整状态不一致、首次物体位置不一致、首次虚假成功；指出哪一处实际改变了候选排序。仅有状态不同而没有排序证据时写“未建立直接联系”。一例可以有多个错误，不强行归为单一原因。

### A4. 递归对照修复

沿用与主诊断相同的非法预测终止和成功吸收规则。终止之后不再伪造下一状态。

用同一固定真实轨迹比较：
- teacher-forced：每步从真实状态预测；
- recursive：从自身上一预测状态预测。

逐步同时报告：
1. 截至该步的预测终止率、非法率；
2. 仍存活链上的状态误差及样本分母；
3. 全部链上的累计失败/错误比例，防止只比较幸存链。

分清“终止状态判断错误”与“物理状态预测错误”。旧 fallback 曲线只作为历史附件，不替换其原文件。

## 4. 阶段 B：连续平台单尺度模型

### B1. 接口与状态合同

现有技能：move_to、push_contact、hold；双方同步执行一个固定窗口，默认 40 个控制步、2 秒。提前完成的机器人执行 hold；真实成功或物理失败可提前终止窗口。

模型输入：
- 两机器人及物体的位姿、线速度、角速度；
- 当前 success_hold 计时；
- 目标、arena、障碍、物体尺寸等公开几何；
- 双方技能的全精度结构化参数及本窗口最大时长。

模型输出：
- 下一窗口边界的三体物理状态；
- success_hold 计时；
- 窗口实际持续时间；
- 终止类别：window_complete / success / physical_failure。

physical_failure 合并已有 numeric_failure、out_of_bounds、penetration_limit；原始数据保留原类别。success 必须来自真实环境的低速保持判据，不能用“终态物体进入目标”代替。

开始前核实 run_joint_skill 是否在每个窗口重置控制器内部状态。若确实重置，在合同中引用代码位置；若存在跨窗口保留的内部状态，必须纳入输入或记录 BLOCKED，不得静默忽略。同样写清引擎接触缓存没有进入网络输入，这是近似状态模型，不宣称完美 Markov。

预测中间状态不得调用精确动力学、环境 restore/step、真实未来接触或真实未来 success_counter。几何计算可以使用预测状态和已知静态几何。严禁把真实的未来控制力作为模型输入；技能内部控制器未来会产生什么力，是该窗口转移的一部分。

### B2. 单一默认模型与训练约束

采用 PyTorch 普通联合状态 MLP：
- 两层隐藏层，每层 256，ReLU；
- 输入双方技能 kind one-hot 和参数，禁止只输入 candidate_id 或格式化标签；
- 状态采用确定性归一化；位置按 arena 尺寸，角度输入 sin/cos，速度尺度固定写入合同；
- 输出三体状态变化，角度误差用 wrapped difference；
- success_hold 及 duration 有界预测；终止类别用分类头；
- 默认损失：归一化状态 MSE + 计时 MSE + duration MSE + 终止类别 CE，各系数 1；
- Adam，lr=1e-3，batch=128，最多 100 epochs，val loss 连续 12 epochs 无改善停止；
- seeds={0,1,2}，仅按 val loss 选 checkpoint。

不要搜索学习率、网络大小、损失权重；不要按 test 或规划成功率选 checkpoint。不实施数据重加权。记录所有归一化常量；若使用训练集统计量，仅从 train 拟合。

预测为联合点状态递归。非有限输出和超过既有几何失败阈值的预测明确标记 invalid_prediction 并吸收；不得投影到最近合法状态、回退到真实状态、调用 oracle 修复。额外报告 raw 几何违规率。终止 head 的决策阈值/argmax 规则在训练前固定。

### B3. 数据采集与划分

使用现有修复后的十场景，不生成新的几何变体，不扰动初态：

| split | 场景 | 每场景采集回合数 |
|---|---|---:|
| train | S0_dev/S0_v1/S0_v2、S1_dev/S1_v1/S1_v2 | 20 |
| val | S0_v3、S1_v3 | 20 |
| test | S0_v4、S1_v4 | 20 |

总计 200 回合，每回合最多 12 窗口，总上限 2400 窗口。使用场景名和 episode_id 派生稳定随机种子。按整场景划分；禁止同一回合的片段跨 split。报告这是“已有两任务族的场景变体留出”，不宣称新任务泛化。

采集行为：
- 第一窗口均匀采样现有 joint_candidates；
- 后续每窗口：概率 0.5 从当前公开观测生成的候选均匀采样；概率 0.5 原样重复上一联合技能的结构化参数；
- 不按预测或精确收益筛选采集动作；
- 成功/失败立即终止，不能在终止状态继续采集；
- 不把已有精确 MPC 轨迹混入训练集。既有轨迹可用于协议复核，须独立标记。

沿用 schema v2 保存 full-precision 技能、窗口前后状态、时长、终止、控制器版本和场景哈希。补齐初始及末尾 success_counter，避免仅存末值。完整 step 记录至少保留审查用回合；其余可用窗口级记录降低体积，但保留复现 seed 和配置。

训练前一次性输出 split 样本量、物体平移/转动、单推/双推/移动/hold 组合、接触、成功及失败样本覆盖。统计阈值在合同固定为平移 >0.01 m、转动 wrapped magnitude >0.02 rad，仅用于分组评价，不改变技能与任务事件定义。

若成功或关键接触极少，明确写“该分组证据不足”，仍可训练普通基线；不得擅自加采样或改行为策略。

### B4. 模型基本验证

test 分别报告：
- 物体及两机器人的位置误差、速度误差，物体角度误差；
- object_translation / object_rotation / stationary 分组样本数与误差；
- 终止类别混淆矩阵、虚假成功率及其分母；
- 计时误差、duration 误差、raw 非法预测率；
- 与 state persistence 基线比较：预测物理状态不变、未终止窗口继续、duration=2 秒。该基线只作预测参照，不作为精确动力学。

不存在统一精度达标门槛；性能差本身是实验结果。只有接口错位、训练/评估泄漏、NaN 或输出完全不随输入变化等实现异常需要先修复。

## 5. 阶段 C：固定候选排序诊断

### C1. 标量评分合同：新实验独立版本

旧连续 MPC 的字典序 key 不能相减。不更改旧基线；新诊断与新闭环统一使用：

J = 10*S - t/24 - d/L - 20*F

其中：
- S：轨迹真实成功，或模型预测的 success 终止；成功吸收；
- t：从本次规划起点累计执行时间，成功/失败后不再计时；
- L：arena 对角线长度；
- d：已有 passage_cost_to_go，使用当前物体位姿、尺寸、静态几何计算；成功时 d=0；
- F：物理失败或 invalid_prediction，失败吸收；
- 不另加控制力、方向或技能种类奖励。

passage_cost_to_go 包含现有通道几何启发式，必须明确披露；保留普通 corner_distance_to_goal 作为独立指标。该评分不能被描述为模型自行学会了准备动作的价值。

精确与学习评估调用同一 score_components → J 函数；稳定 candidate_id 打破平局。分项、累计时长、终止类别均存原始记录。不要用终点是否在目标内替代 S，不用 logits 概率直接当成功奖励。

加小型手算测试验证：初态已成功、成功吸收、失败吸收、时间只算一次、J_hat=J_ref 时 regret=0。新标量成绩不能直接与旧字典序 9/10 合并成方法对比。

### C2. 评估起点和候选冻结

评估起点共 12 个，每个 test 场景 6 个：
- 一个是该场景合法非终止初态；
- 其余从 test 数据的非终止窗口起点中按 SHA256("continuous-audit-v1|" + episode_id + "|" + window_index) 排序取 5 个；
- 排除完全相同的物理状态和成功计时，不按误差、距离或收益选择；
- 保存能够精确恢复的 episode prefix、完整快照信息、状态和哈希。
不足时写实际数量，不从 train 补齐。

采用 H={1,2,3}，K={16,64,128}，candidate_seeds={0,1,2}。每次生成最大池，较小 K 是同一池的前缀；保存完整池再评估。

候选是固定的、全精度联合技能序列：
- 基于起点公开观测调用已有 joint_candidates，形成 root 技能库；
- H=1：root 候选去重后用 seed 打乱，实际最大数可能是 121；
- H>1：用 seed 从 root 库无放回采样至多 32 个联合技能，分别重复 H 次；再从“双方 move_to staging 一窗口，之后 push_contact”的通用模板中采样至多 32 条；
- staging 点和 push 均来自 root 已有技能库；组合规则只依赖公开几何并写在合同；
- 然后用 root 库均匀采样完整序列补齐至 128 条，去重、稳定打乱。模板不足的份额也用随机序列补齐，避免池被重复技能占满；
- 后续窗口 world 坐标参数原样保存，不按模型或真实未来状态重新生成。

不得加入精确 MPC witness、精确最优序列、模型挑选的序列或依场景 ID 定制的成功动作。这个固定序列策略类有局限，正文如实说明。

### C3. 精确参照与指标

每条固定序列从同一个真实 snapshot 通过独立 planner_env 精确执行；每个候选真值只算一次并由三个模型共用。恢复必须沿用 exact prefix replay；禁止未来泄漏或污染 live_env。

先报告候选覆盖，再报告模型：
- candidate_best_true_return、uniform_candidate_true_return；
- 至少一条成功候选的起点比例；
- 至少一条 d 比起点更低的可行候选的起点比例；
- 候选真失败率及实际去重数；
- selected_bias、candidate_mean_bias、selection_excess；
- candidate_regret、chosen_true_return、chosen_true_success；
- 选中候选的虚假成功率、预测失败/非法率。

按起点汇总；三个模型种子分别列结果，并给均值，不能把重复测量当新增场景。各 H 的裸收益包含不同执行时长，不直接据此证明“越深越差”。

分项拆解必须含成功奖励、时间、距离和失败罚项。分别列选中与候选均值。至少给出 3 个最大平均 regret 起点的逐步案例及 1 个低 regret 对照。预测与真值轨迹并列，不只给最终 GIF。

候选覆盖判据：
- 若 12 起点中不足 3 个拥有可行且 d 降低的候选，标记 C 为 COVERAGE_LIMITED；完成已有诊断，但不执行 D，不训练补救；
- 成功候选少时，可以报告进展排序，不能据低成功率判断模型的完整任务能力；
- COVERAGE_LIMITED 不等于模型高估机制不存在，也不等于连续平台不可用。

### C4. 递归对照

复用 C 的固定序列，比 teacher-forced 与 recursive 的逐窗口状态误差。终止、非法和分母沿用 A4 原则。

计时、终止 head 和状态误差分开报告；不把一条误差曲线自动解释成所有 regret 的原因。

## 6. 阶段 D：同协议闭环基线

C 覆盖判据通过后执行。所有方法每个决策从当前真实观测重新规划，只执行所选序列的第一窗口。

三种方法：
1. exact_fixed_pool：同一固定候选池，精确评估 J；
2. learned_fixed_pool：各独立 checkpoint 递归评估同一池的 J；
3. uniform_root：从同一 root 技能库均匀选择一个窗口。

精确与学习条件：H={1,3}、最大 K=128、最多 12 个 live 窗口。H=1 实际候选数不超过 root 去重数。每次规划只依据当前真实起点生成池；池生成随机种子从场景、窗口、episode seed 确定，不能取决于模型预测。

首次正式闭环只跑 test 的 S0_v4、S1_v4：
- exact：episode seeds={0,1,2}，每个 H 各 6 回合，共 12 回合；
- learned：3 个 checkpoint × episode seeds={0,1,2} × 两场景 × 两 H，共 36 回合；
- random：两场景 × episode seeds={0,1,2}，共 6 回合。
不能把不同 checkpoint 的成绩当作 ensemble。这里两个场景样本很少，只能作为基线复核，不声称统计泛化或新方法优势。

每回合记录真实成功、完成时间、窗口数、几何距离、物理失败、J、实际预测节点、精确模拟步数、前缀重放步数和墙钟时间。

模型拒绝所有候选时终止为 planner_no_feasible_plan，不从 oracle 找替代动作。模型预测已完成时，本轮仍执行选中序列的首窗口，再用真实成功判定决定是否结束；不能因预测成功直接把 live episode 标成成功。

规划中的 exact 环境只用于 exact 方法和诊断参照，learned 方法不能查询未来。所有方法的 live_env 与 planner_env 分离。

新标量协议的 exact 结果须重新运行，不能沿用旧字典序成绩。失败不用改场景或扩大 beam 修到成功。

## 7. 资源边界与 BLOCKED

- A 只有诊断重算；Grid checkpoint 的 SHA256 必须保持不变。
- B 最多 200 回合/2400 窗口，一个训练配置、三个种子。
- C 固定 12 起点、3 个 H、3 个 K、3 个候选种子；嵌套 K 复用真值，不重复模拟。
- D 只跑上列 54 回合；不扩展到十场景或追加大量种子。
- 先用小批次测算每阶段运行成本，写入 STATUS。运行较长时保存 checkpoint 和进度，避免重算；不得为赶时间静默改变协议。
- 如本机资源确实无法完成，交付已完成阶段、剩余预计成本和具体限制；未完成写 NOT_RUN，不以简化结果冒充正式协议。

以下情况停止依赖阶段：
- 接口无法忠实表达窗口状态或终止语义；
- 数据 split 泄漏、无法精确恢复参照、live_env 被规划污染；
- 两次针对性修复后仍有无法解释的 exact 对照不一致；
- C 达到 COVERAGE_LIMITED 时，停止 D，等待下一轮调整候选协议。

模型精度差、regret 没下降、比随机好、深层规划没退化均不是 BLOCKED。
