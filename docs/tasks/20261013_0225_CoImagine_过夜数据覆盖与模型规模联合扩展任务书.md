## 3. A：随机初态与场景规格

### A1. SceneSpec 必须可完整传递

现有 `scene_by_name` 只识别十个固定场景，而编码、解码、几何检查、评估可能多处依赖它。新增最小兼容机制：序列化完整 SceneSpec，使用确定性 scene_id → SceneSpec 注册表；数据加载时显式加载该注册表。旧名称继续解析原固定场景。

所有路径，包括 worker、恢复、预测、评分、几何替换，必须读取同一规格。禁止为了运行把新 scene_id 映射回原场景。scene_id、split、生成 seed 只作元数据，不能加入模型输入。

原 57 维编码支持最多两个轴对齐障碍，本轮保持此限制。固定机器人/物体尺寸、质量、摩擦、控制参数、arena 尺寸。只改变现有输入已经表达的几何量及初始 pose；障碍角度保持 0。新场景端到端 smoke：生成→reset→采集→序列化→加载→编码→预测→几何检查→exact 候选参照。

### A2. 随机场景与初态分布（正式采集前冻结）

S0/S1 各占 50% 的根场景。以现有 development 场景为几何模板，使用以下参数范围；所有米制数值均在当前环境坐标中。

| 项目 | S0 | S1 |
|---|---|---|
| arena | 维持原尺寸 | 维持原尺寸 |
| 静态障碍 | 无 | 仍是两个构成竖直墙与开口的矩形 |
| 墙中心 x | 不适用 | U[1.40,1.80] |
| 开口中心 y | 不适用 | U[0.80,1.20] |
| 开口净宽 | 不适用 | U[0.60,0.85] |
| 墙厚 | 不适用 | 沿用原值 |
| 目标中心 | 原中心各坐标加 U[−0.15,0.15] | 位于墙右侧：x=原目标x+U[−0.10,0.10]，y=开口中心+U[−0.10,0.10] |
| 目标尺寸 | 原值 | 原值 |

物体初态按以下三种提议模式分配：

- 50% 广域：中心从 arena 内包围盒均匀提议，角度 U[−π,π]，再严格检查合法性。
- 25% 墙/通道附近：S0 选一面边界墙，S1 选通道墙的一面；提议物体到该墙面的最近表面间距在 [0.01,0.20] m。不得让物体与其它几何体相交，不能用穿透后投影代替拒绝采样。
- 25% 目标附近：中心在目标中心 x/y 各 ±0.9 m 范围提议，角度 U[−π,π]；要求物体与目标区域有重叠或最近几何距离≤0.30 m，且物体尚未满足完整目标内条件。仅用公开几何判定，不用模型误差选样本。

每台机器人独立按 70% 近物体、30% 广域方式提议。近物体：均匀选物体表面一条边及边上位置，沿外法向放置机器人中心，使圆与物体表面间隙 U[0.005,0.25] m；广域：arena 内均匀提议。机器人初始朝向 U[−π,π]，两机器人均可从任意一侧出现，不固定“左边 A、右边 B”。

初始速度为零、控制器重置、success_counter=0。所有根必须满足既有几何合法性和至少 0.005 m 非接触裕量，未处于吸收成功。根初态只在 reset 时设置，轨迹执行中不得写位姿；速度变化由真实动力学产生。

拒绝采样每根最多 2000 次；失败记录并换下一个确定性根 seed，不放宽容差。不要求根任务全局可解，也不按是否容易成功过滤训练根；合法动力学片段本身就是数据。

### A3. 小型校准与验收

只用独立 `dev` seeds 生成每个“任务族×提议模式”4 个根，共 24 根；不进入任何正式 split。

检查初态合法、输入编码往返、新规格回放一致、不同 seed 确实改变物体/机器人/地图参数、同 seed 重复一致。静态目标不越 arena、障碍尺寸为正。演示图至少展示每格一个根，避免生成器实际都坍缩到同一位置。

若某格接受率<1%，允许**一次**根据几何合法性调整提议实现或该格位置范围，写出前后范围及理由；只能在看训练结果前发生，不能为了模型表现改分布。仍无法有效采样则标记该格 BLOCKED，不静默丢掉它后宣称覆盖完成。

## 4. B：采集单位、数据独立性与固定评价集

### B1. 每个根的固定采集配方

用同一合法根分别执行两条最长 8 窗口轨迹：

1. 随机轨迹：第一窗口从现有 root 技能库均匀选择，随后 50% 重新选、50% 重复上一技能。
2. 一步精确引导：每窗口从同一 root 库确定性抽最多 16 个不同联合技能，以精确物理执行一个窗口后的原 J 选择最优者，再在 live 世界真实执行；并列按稳定 candidate_id。只做离线采集，不改在线规划器。不称它为保证成功的专家。

从引导轨迹中取最后两个非终止窗口起点（只有一个则取一个）。不要求整条引导最终成功，保留所有尝试。

每锚点尝试四个不同首动作：引导实际动作、双方 hold、两个 root 均匀随机动作；重复则从 root 库按稳定随机顺序补齐。每条分支最多 2 窗口，第二窗口 50% 重复、50% 随机。严格恢复真实快照，包括 success_counter 和引擎状态。

每根最多 8+8+2×4×2=32 个真实窗口。成功/真实失败即停止当前轨迹，不从吸收态继续生成重复标签。精确引导候选试算不并入监督训练集，只记录真实执行和分支；试算步数/耗时计入采集成本。

保持所有真实标签，禁止按回报删失败分支。这个配方各规模完全一致；不能后期切换采集策略后把改善归因于纯数据规模。

### B2. split 与数据血缘

先确定 train、val、test 不相交的根 seed 空间。每根的随机轨迹、引导、所有锚点和分支必须留在同一 split。新根不从旧 val/test 的轨迹恢复；拒绝完全相同根几何/初态内容跨 split 重复。

记录 root_id、SceneSpec 内容 hash、family、提议模式、source、trajectory/anchor/branch_id、真实状态与动作。每个实际转移有稳定 ID，可去除完全重复，但不能按浮点近似把不同转移错误合并。

按根而非窗口排序和扩展。不同规模训练集严格嵌套，按六个 family×模式格轮流加入完整根；模式长期占比为 50/25/25，不为了精确条数拆分根。数据规模记录实际窗口数和独立根数，不能只报 episode 总数。

### B3. 验证/测试先冻结

新 val、新 test 各固定 128 个独立根：每个 family 64 根，模式分配 32/16/16。使用与 train 同分布同配方采集，分别得到最多约 4096 窗口。

验证集用于选模和扩量决策；测试根可以预先生成、采集和做数据完整性检查，但模型测试性能在规模/模型清单冻结前不运行。数据生成中的真值合法性检查不算模型调参。

val/test 的 root/轨迹成功数、成功窗口数和 family 分布必须列出。成功根少于每族 5 个时，标记成功类证据有限，不更换“难”根或反复补容易案例。普通状态预测实验继续；成功泛化不作强结论。

旧六初态数据和旧 val/test 不混入新主训练/选模集合；旧 test 仅作为最终历史回归附件。必要时复测旧 checkpoint 在新 val 上表现，但不与新数据训练对照混为同条件。

## 5. C：逐档扩大数据与两种宽度训练

### C1. 规模档位

新广覆盖训练集目标依次为 **8k、16k、32k、64k、128k** 个去重窗口。每档取达到该目标的最短完整根前缀，因此实际条数可略超。最高 128k，不自动再扩。

先完成 8k 并训练，再采下一档；不先花整夜采到 128k 才发现链路有问题。若 8k 未完成且资源不足，交付采集结果，不降低到一小部分后称正式 8k 实验。

### C2. 每档六个 run，控制预算和选模

每档两宽度 × seeds 0/1/2，共六次训练，均从新初始化开始。相同数据、种子的样本顺序跨宽度一致；同宽同 seed 跨规模初始权重相同。

每次最大更新数为 `max(6000, 60 × ceil(N/128))`，不超过 60000；无早停，保持原优化器和损失。这样每档至少约 60 遍数据，避免大数据只因见过的次数太少而失利。记录实际遍数、更新数、时间；不同规模不是等算力实验。

每 `max(250, ceil(Umax/20/250)×250)` 次更新评估一次，并强制含 update100和最终更新。每次测完整新 val；训练过程监控使用按六格/根 hash 预选的最多 4096 窗口固定子集，必须标为 train_monitor，不冒充完整 train。

每个 run 保存两个预定义选点：

- 主选点 `best_new_val_total`：新 val 的四项总 loss 最小值。先各根平均，再各 family×模式格平均，再按冻结的 family/模式权重汇总，避免长轨迹根主导。
- 固定预算末点 `final`，用作选模敏感性分析。

主选点不得排除早期，不按 test、候选收益或非法率偷偷重选。两选点均对完整训练集做一次最终评估，并测新 val 统一指标；不在训练中反复全量解码 128k 数据。

### C3. 是否继续扩量：只读新 val

每档六个 run 完成后，先保存逐 seed 表，再决定下一档。使用两选点分表；主决策读主选点，同宽/同 seed 与上一规模配对。

验证主物理指标 P：三个刚体位置欧氏误差的均值（米）；同时列物体、各机器人、物体角度、非法率、真实成功召回/CE。汇总按 C2 的根/格权重，不把高度相关窗口当独立样本。

某个宽度满足下列任一项，且至少 2/3 种子对应指标改善，记为该档有收益：

1. 平均 P 相对下降≥5%，非法率不恶化超过 2 个百分点；或
2. 非法率绝对下降≥3 个百分点，平均 P 不恶化超过 5%。

还需检查 S0/S1：不能有一族 P 恶化>10% 或非法率恶化>5 个百分点后仍称“全面改善”；此时标混合趋势，不累计为明确收益。

8k 完成后至少尝试 16k、32k（时间允许时），避免一档噪声就停止。之后只要任一宽度有收益即可继续；连续两次规模增加两宽度均无收益，则停止扩量。到 128k 或剩余时间不足完成下一档六 run 时停止，保留已完成档。

若只有 final 显著改善而主选点无改善，允许执行下一档一次验证该趋势，最多一次；报告选模敏感性，不修改主规则。成功指标单独列出，不用它掩盖物理指标恶化，也不以其稀缺为由无限补采。

这些都是工程停止规则，不称统计显著性。不得根据观察到的趋势改 5%/3pp 等阈值。

## 6. D：区分覆盖与数量，并检验预测是否用于决策

### D1. 一次等数量窄覆盖对照

在广覆盖 16k 档完成后执行；若预算不足，则在最终报告明确缺失，不把广覆盖优势单独归因于初态随机化。

仍从旧六个训练固定初态出发，用**同一个 B1 配方**采到与广覆盖 16k 档相同数量的训练窗口，按完整采集根保留，条数误差≤32。这里“根”是重复同一初态的采集回合，报告独立根初态实际仍只有 6 个。

每个固定场景采相同配额（因去重不足只增加采集回合，不篡改初态）。与广覆盖组使用相同去重语义；最多尝试 10 倍目标真实窗口，仍不够则按最大共同规模给两组各训练一个明确标记的等量子实验，不能靠复制样本凑条数。

两宽度×三种子，沿用 C2 训练预算与同一新 val 选模。相同数量下比较窄/广覆盖对新 val 泛化的影响。成功类比例可能不同，必须报告，不能声称这是只改变几何而完全保持标签分布的实验。

### D2. 最终单步留出评估

停止扩量并冻结 run 清单后，对所有完成档位的主选点、final，以及窄覆盖对照，在新 test 上统一评估一次。旧 test 只对第一档、最终档主选点做历史回归。

保持 test 分数不参与补训、重新选规模或新采样。原 test 无成功时 recall=null。展示数据规模 × 宽度学习曲线、train/val gap、非法率、成功识别；别只挑最优 seed。

### D3. 固定候选最小决策验证

首次生成 test 后按根 hash 从每族选择 6 个根，共 12 个；起点固定为这些合法根初态。先于模型评估冻结候选 H={1,3}、K=64、candidate seeds={0,1}，精确真实收益只计算一次缓存。

全部根保留，不按 exact 是否能成功筛选。报告真实最佳可行率、成功候选覆盖和进展 spread；若大量根 H3 内没有好候选，则限制结论，不重新挑容易起点。旧 12 起点/H3K128 可直接复用真值作为历史决策回归，不能替代新起点评价。

仅评估第一档、最终完成档和等量窄覆盖组的**主选点**，两宽度三种子。某两档相同则不重复算。总数通常≤18 个逻辑模型；按预算先新起点、再历史回归。

延用已修正的未筛选/执行筛选两套协议、误拒与集合内排序损失分解、共同 `(start_id,candidate_seed)` 配对。无可行候选填 null 并列覆盖，uniform/candidate_best 在共同子集重算。

精确仿真仅作离线训练引导/评价参照，学习模型规划不能查询真实未来。本轮不新增闭环；先回答数据规模改善是否传递到候选选择。

## 7. 工程验收与自主处理规则

必须测试：新 scene 规格序列化与跨进程解析；初态严格合法；split 血缘不交叉；同 seed 重放一致；规模子集嵌套；数据/参数内容 hash；训练器已有归约/快照/resume 测试；候选共同样本配对与 regret 恒等式。

旧数据、checkpoint、场景定义不覆盖；新增 scene resolver 需向后兼容。数据 shard 写完后原子提交 manifest，未完成 shard 不计入规模。控制线程数并记录资源；每 15 分钟更新 STATUS 的阶段、根数/窗口数、训练完成数、耗时和下一动作。

若出现 NaN、标签时刻错位、真实正常状态被判非法或新 scene 解析错误，停止依赖项，最多两次基于证据的修复，保存错误样本。不能靠调阈值、丢坏样本、换模型来继续。

如果基线在更广分布上表现变差，按 C3 继续必要的下一规模，不能立即认定“广数据无效”；新任务分布更难，必须以同一个新 val/test 比较规模趋势。若两次增加无收益就结束，不把时间花在不停改配方上。

## 8. 最终交付与报告格式

新增 `docs/coverage_scale_v1/`、`outputs/coverage_scale_v1/<run_id>/`、`experiments/coverage_scale/`。包含冻结 CONTRACT、STATUS、自动生成 report、manifest、generator 配置、完整场景注册表、采集/训练/评估入口、恢复命令、错误及偏离记录。

原始数据分片和所有 checkpoint 留在工作目录；审阅包 `coverage_scale_v1_review.zip` 包含修改源码/测试、配置、根场景样例与图、数据覆盖表、学习曲线源表、全部 run 摘要、逐起点评估、第一档与最终档主模型。大数据不必塞入 zip，但 MISSING 列明精确路径/hash/恢复方法。

最终正文≤1800 中文字，详细表附后，只回答：

1. 实际运行多久、做到哪一档、独立初态/窗口数、训练与评估数量；为什么停止。
2. 采样范围真正覆盖了什么，六格接受率、各类成功/接触/运动数量与独立根分母。
3. 扩数据是否改善同一验证/测试集；512 相对 256 的优势是否随数据增加变化。
4. 等量窄/广覆盖结果如何；是否改善非法率、误拒和候选真实收益。
5. 下一步只推荐一个动作。没有到达平台期应写“预算截断，尚未判断饱和”，不能写“scale-up 已不再有效”。

**早上用户应拿到一条可解释的数据—模型学习曲线和可恢复的实验资产，而不是一串未完成的尝试或继续扫参数的建议。**
