## 2. A：必须修复的项目

### A1. 表面速度单位与时间戳

位置：`control.py::update_surface_estimate`，以及 `option.py` 的 SETTLE 调用。

当前函数返回的是匹配点平均法向位移，没有除以时间间隔，却和 0.02 m/s 比较。必须使用两次有效扫描的采样时间戳差求速度，不用固定 dt 代替，也不用消息接收时间代替采样时间。

观测必须携带采样时间。状态缓存保存上一有效扫描、对应机器人采样位姿和时间戳。重复时间戳不生成新速度证据，也不能靠同一帧反复递增稳定持续时间；乱序/非正 dt/不足匹配点返回 unavailable 并记录原因。超过允许新鲜度的帧不得参与判稳。新鲜度上限固定为 0.20 s，本轮不调。

速度聚合使用匹配点法向速度绝对值的 RMS，避免正负运动相互抵消；同时保留原有 signed mean 作为诊断。报告这一调整。单平面的切向运动仍然不可观测，不能声称修复单位后就能完整观测物体运动。

最小测试：

- 0.05 s 内平移 5 mm，估计法向速度应为 0.1 m/s，不能通过 0.02 m/s 门槛。
- 相同真实速度、不同采样间隔，估计量一致。
- 静止表面、运动机器人，经自身位姿补偿后估计近零。
- 重复/乱序帧不能构造持续 0.30 s 稳定证据；正负对称法向运动不能因均值抵消判为静止。
- 切向滑动反例仍保留，真值评估器识别其假稳定；控制器不得偷读真值纠正。

### A2. 固定延迟队列

位置：`option.py` 中 `delay[robot_id] = ready` 附近。

现代码留下已经到达的老帧、删除尚未到达的新帧，会长期重复最早的观测。修复为：每帧带采样/到达时间；按当前时刻投递已到达的最新帧，保留未来到达帧，只清理已被替代的历史帧。队友消息同样处理。

启动阶段没有到达帧时明确 unavailable，不回退为无延迟新观测。若沿用延迟整个观测包的原实验语义，明确自身状态也有延迟；禁止悄悄只保留有利字段为最新值。跨 skill 使用单调时间戳，不能因局部计时重新从零开始造成负年龄。

测试 100 ms 延迟、50 ms 采样：0.10 s 使用 0.00 s 帧，0.15 s 使用 0.05 s 帧，0.20 s 使用 0.10 s 帧。允许数值容差；记录整个选帧序列、消息年龄及最大队列长度。持续运行后时间戳必须前进。

### A3. 制动渐变真正进入执行器

位置：`option.py::_local_force`、`_old_force`、BRAKE；`control.py::brake_force`。

当前阶段机更新参考减速，但施力直接采用零参考，因此渐变没有实际生效。BRAKE 应采用当周期限加速度后的参考速度，计算 `clip_norm(Kv*(v_ref-v_actual),Fmax)`；参考降至零后保持零速反馈。

N 使用其最后实际生效的参考；P 在进入 BRAKE 时以本机器人测得的当前速度初始化参考，明确旧推送公式没有完全等价的速度参考。两者都遵守同一参考减速度上限。第一周期参考也须显式初始化，不能靠 `None -> raw` 绕过限幅。不要把参考加速度限制误写成实际加速度/力变化限制。

测真实送入 backend 的力与记录的参考一致；阶段切换不写物理速度/位姿。BRAKE+SETTLE 的4s上限从进入BRAKE计算，并在两个阶段均生效。

### A4. 接触握手与退出一致性

检查目前全局 APPROACH 是否导致先到者继续以接近速度推物体。按原协议落实：单机器人接触连续0.10s后进入自身 READY，使用0.01m/s法向预接触参考；队友仍可处于 APPROACH。双方 READY 且接触连续满足0.10s后同步 PUSH。

READY 失去接触时清除 ready，回到接近/接触建立流程；从技能启动起的接近/等待总上限仍为5s，不能在READY无限等待。退出先记录原因，再协同制动，不用判稳覆盖中止原因。状态包括 `exit_reason`、`push_completed`、`settled_observed`、`settled_after_abort`，不混为一个成功标签。

有效推动2s按明确的物理控制区间累计，不能进入 PUSH 尚未施力就多加一周期。日志记录区间起止时间和该区间接触判定来源。主动机器人以外的机器人须执行原任务要求的制动，不能只因未列入 active_robots 就始终施零力；O 保持历史路径。

### A5. 验收分母与扰动统计

位置：`experiments/local_contact_option/make_metrics.py`。

- G2/G4 的指定主要分母恢复为 **solo_central + dual_same_side**，基准变体共40个root。另列原四类可推动组80个root，禁止把旧92.5%直接移到新分母。
- G5 同时检查位置P90下降至少20%、角度P90不恶化超过10%。角度使用wrap并报rad和degree；原结果角度约0.0180→0.0216 rad，不能只检查位置就标通过。旧相对角度门槛接近零时只报告绝对差并标数值敏感，不自行加新宽松阈值。
- 保留上一轮全120root的描述表；主要门槛及主要科学解释限定上述指定可推动组，另列偏心/旋转/受阻组，分母写在表头。
- 配对bootstrap按真实root_id重采样，同一root所有臂/变体一起保留。每次重采样重算P90及N−P差/改善率。不能给均值区间贴上P90区间标签。
- 当前代码将 `sorted(per_root)` 的两个变体名与数值zip，产生 `roots=2`。修复并断言真实root数等于目标集合大小，测试用乱序输入检查结果不变。
- 观测判稳/真值判稳/中止后判稳分别统计。覆盖率固定全960次/臂为主分母，子集覆盖率另标。

### A6. 三步接续与终态完整性

位置：`run_continuation.py`。

`len(steps)==3` 是尝试了三步，不是成功完成三步。分别记录 attempted、push_completed、正常完成且判稳；三步完成要求三步都符合正常完成定义。保留原来12个root和动作。

上一轮交付记录重算的正常三步完成是 P=8/12、N=9/12，不是两者10/12；作为旧结果更正表，不冒充修复后的新结果。

下一步入口评估必须检查两机器人和物体的线/角速度；控制器继续与否只能用协议内观测，真值资格只是评估，不得反馈控制。报告假判稳后实际继续的案例。

每步位移用该步初态计算，另报全链累计量。终态来自退出当刻的独立快照，不依赖最后一条抽样日志；最后一周期、失败退出也必须有完整终态。

## 3. B：冻结参数，同批复核

先通过上述定向测试，再执行原24开发root与原120测试root、8变体、4臂。root/动作/扰动文件保留原hash；增益不重新选择。输出完整3840条测试记录，不因旧审查包只带800条而只跑800条。12root接续也重跑。

O 代码路径应保持不变，选定根场景检查旧新O终态一致；所有改动在新模块或向后兼容接口完成。注意共用统计器修复可以改变指标，不能误称O轨迹改变。

以下对照都要有，别只交门槛红绿灯：

1. 修复前/后同组关键量：退出、有效接触时间、观测判稳、真值速度、假稳定、耗时、接续。
2. P对O、N对F：阶段协议作用；P对N：相同协议下的整体控制差异，注明动作参考系/信息不同，不能严格归因为单一控制公式。
3. 同目标速度0.26m/s子集P/N：位移、实际速度、力饱和、位置与角度扰动敏感度。旧控制没有0.08/0.16档，不把混合速度总体当公平速度比较。
4. 原始位移分箱和共同正常完成子集作为辅助结果；全样本结果不能删掉。分箱后root构成不同就声明，不能称严格匹配；禁止靠筛掉失败或更换动作实现“相同距离”。
5. 分阶段位移：接近、READY、PUSH、BRAKE/SETTLE，说明旧控制多移动是否来自更长/更强的预推动或停机滑行。

本轮不以达到位移比0.8为优化目标。比较完成后，只建议下一轮是否需要速度跟踪校准或小规模学习测试。

## 4. C：动画交付是必做项目

用户需要每种控制方式多个案例，不接受只给一个最佳案例或一条混剪。

### C1. 数量与选例

固定8个案例，每个案例同root、同变体、同初态生成O/P/F/N：**32个单臂视频 + 8个四宫格对照视频**。每种控制方式有8个独立动画。

前6个案例：六种interaction class各1个基准变体，按root_id字典序选首个合法root，结果好坏不影响选择。

后2个案例：

- 延迟压力案例：从延迟变体中选N相对无延迟终态偏差最大的root，列出选择规则、数值和排名；同一延迟条件四臂对照。
- 失败/分歧案例：优先选N中止而P正常完成的root；没有则选任一N中止；还没有则选P/N角度响应差最大的root。明确这是结果驱动选例，不代替总体统计。

避免重复root；若规则冲突取下一名。全部记录到 `animation_index.csv/json`，含root、variant、initial-state hash、arm、exit、位移、转角、耗时、是否正常完成及文件名。

### C2. 动画画面

- 统一机器人颜色、物体颜色、坐标范围、长度尺度；四臂同一案例使用同一相机，不各自缩放。
- 从真实t=0初态开始，到退出终态结束；物体初态淡色轮廓、质心轨迹、机器人轨迹。物体/障碍尺寸和角度读取实际场景配置，不硬编码或只用模板。墙厚/边界几何与仿真一致。
- 清楚标注robot0/1，当前阶段、仿真时间、有效接触推动时间、两机器人接触状态、物体线/角速度、结束原因。速度真值注明“评估叠加，控制器不可见”。
- 图例区分局部法向、参考速度和实际施力，箭头分别使用固定比例尺；旧控制没有对应参考时标N/A，不能伪造箭头。机器人圆盘上的箭头不得被描述为实际yaw控制。
- F/O 2s提前结束后，四宫格将终帧冻结并标 `ENDED at t=...`；不得额外模拟后续减速后仍当作其原结果。其他臂继续播放。
- 全部主视频统一1×仿真时间；帧率与抽帧间隔一致。例如50ms控制采样隔一帧导出，应10fps而非20fps。禁止将不同时长轨迹各自压缩成相同播放时长。可另做慢放副本但必须标倍率。
- 文字放在不遮挡运动区域的位置，四宫格每格至少640×480；单臂至少800×600。终帧额外停留1秒仅用于展示，标明视频停留，不增加仿真耗时。

### C3. 格式与查看方式

优先 MP4（H.264、yuv420p，浏览器可播放）。同时给8个四宫格的轻量GIF预览，控制分辨率与体积。若编码依赖无法安装，使用可运行的现有工具导出GIF替代并说明，不能省掉单臂或对照案例。

提供离线 `animations/index.html`：8个案例卡片，首先显示四宫格，下面链接四个单臂视频和指标；不依赖CDN/网络，不自动同时播放所有视频。MP4有播放/暂停/进度条，读者不用运行Python即可浏览。附 `ANIMATION_GUIDE.md`，推荐先看哪3例、每例应观察什么，同时包括失败案例。

### C4. 渲染验收

自动检查所有视频存在、帧数非零、时长与日志相符、初/终态一致。逐个四宫格人工查看至少首帧、推动中段、制动或退出帧，确认文字不遮挡、同案例初态相同、终帧不是空白。

原v1渲染器 `rows[::2]` 配20fps会加快播放，且场景由模板构造；本轮必须按实际时间与完整scene修复，不能仅增加选例列表。渲染只消费日志，不重新跑一个不同轨迹再当作原实验动画。
