## 2. 修正前后，预算与宽度的主要结论是否改变

**方向不变，强度略有变化。** 修正后（正确逐样本均值）同一批 12 次训练：
- **更多更新**：训练总损失 12/12 下降（旧协议是 11/12，唯一反例 Old+Branch/256/seed0 修正后
  0.0272→0.0115）；训练集物体位置误差 Old+Random 0.163→0.144（256）、0.162→0.129（512），
  Old+Branch 0.204→0.172（256）、0.209→0.147（512）；但**原 val 总损失 11/12 变差**
  （如 512：0.0171→0.0232、0.0225→0.0316）。
- **加宽**（512−256，同数据同种子，6000 updates）：训练集物体位置误差 **6/6 更小**
  （−0.008…−0.031，均值 −0.020），训练总损失 6/6 更小；而**原 val 物体位置误差 6/6 更大**
  （+0.005…+0.026，均值 +0.016），墙钟 25 s vs 20 s。
结论与修正前一致：**预算与宽度都只改善训练拟合，没有改善验证**——这是泛化缺口，
不是“训练不够”或“容量不足”的单方面证据。

## 3. 终止 CE 恶化来自哪类样本；几何非法与哪部分误差最相关

**终止 CE 的恶化几乎全部来自成功窗口被漏判。** 分支 val 上（62 个真实成功窗口），
成功类对总 CE 的贡献是 0.405 / 0.995 / 0.987（mixed/original/final），而 `window_complete`
只贡献 0.005–0.015；真实成功窗口被预测为 `window_complete` 的比例 0.72–0.79，
其真实标签概率只有 0.20–0.28，均值 CE 4.8–11.7。反过来，真实普通窗口被误判 success 的
比例只有 0.3%–0.4%。同一批模型在**训练集**上成功窗几乎完全拟合（均值 CE 0.0018、
真实标签概率 0.998），所以这是**场景泛化缺口**而非表达力不足；原 val 完全没有成功样本，
是“只用原 val”选择的实际盲点。这只能称观测归因，不能据此说终止头造成位置错误。

**几何非法与机器人 pose 误差关系最大，物体 pose 次之，两者耦合。** 原始非法率 0.745–0.794，
违规 pair 以 `robot_object`（0.48–0.58）与 `robot_wall`（0.31–0.48）为主，
`object_wall` 0.25–0.38、`robot_robot` 0.05–0.15（一个样本可多对）。离线只替换 pose：
只换物体 pose 后非法率降到 0.61–0.68，只换两机器人 pose 降到 0.46–0.52，
全部替换降到 **0.000**（同时 0 个合法→非法，说明检查器自洽、无时刻/解码错位）。
训练更多并没有降低非法率（0.745→0.762、0.769→0.782）。

## 4. 换选点是否改善候选选择，牺牲了什么

**没有稳定改善。** 36 个 checkpoint 在 H=3/K=128 上（12-run 均值）：`best_mixed_val`
拒绝率 0.881、仅可行 chosen_true −0.376；`best_original_val` 拒绝率 0.918、chosen −0.387；
`fixed_6000` 拒绝率 0.959、chosen −0.326。共同样本配对（分母 7–12 起点/组）：
mixed→original 的 Δ拒绝率 **+0.037**、Δ仅可行收益 **−0.059**；mixed→final 的 Δ拒绝率 **+0.087**、
Δ仅可行收益 **+0.040**（范围 −0.52…+0.37，跨 0）；256→512 的 Δ仅可行收益 −0.076、
Δ拒绝率 −0.001。三组配对里都有 40–53 行从“有解”变成“无解”（另有 27–64 行反向）。
牺牲的是：`fixed_6000` 换来更低的排序损失（0.879 vs 1.024）与更低未筛选 regret（2.831 vs 2.906），
但可行性更差、执行 regret 并未改善；`best_mixed_val` 反过来。误拒损失（2.05 vs 2.22）
与排序损失（1.02 vs 0.88）此消彼长，**总执行 regret 三者都在 3.08–3.28**，差异不构成可用收益。
逐行恒等式 `误拒损失+排序损失=执行 regret` 在 1296 行上最大残差 1.8e-15。

## 5. 下一步与证据限度

**下一步（仅一项）**：用同一条已保存轨迹在**更多中间更新**（例如每 250 步的 best_original_val）
上评估候选，判断“执行 regret 基本不随训练变化”是数据/表示问题还是选点问题——
但这需要先把评估口径固定，本轮不改选模规则、不改损失、不加宽。

现有证据**还不能**支持：①“应该改选模规则”（换选点没有带来可用收益，且三类选择的
执行 regret 几乎相同）；②“应该改损失或多头加权”（终止 CE 的恶化来自成功窗泛化的观测结论，
没有梯度或干预证据）；③“应该换图网络/更强结构”（宽度只改善训练集，验证 6/6 变差，
是泛化缺口而非容量不足）；④闭环或任务层收益的任何结论（本轮未跑闭环）。
另需注意：分支 test 的 50 个成功窗口来自 18 个锚点，不是 50 个独立成功案例；
原 test 无真实成功，其召回为 `null`。
