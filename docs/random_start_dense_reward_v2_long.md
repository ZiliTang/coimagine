# 稠密奖励 v2：24小时长训练执行计划

2026-10-16 用户明确授权长训练与定期监测。

## 冻结预算与任务

- 最长24小时（包含初始化/基线评价），最多5000次更新×每批8条完整训练episode，先到为止。
- 一个种子0；8个独立采样进程，每进程PyTorch单线程；一个同步PPO学习器、CPU单线程。
- 每批8条都由同一个不可变策略快照产生，收齐后才更新；batch按任务提交顺序排列，不按完成时间。
- 原有成功证据清单8个L0 train实例：0005/0010/0013/0017/0020/0038/0056/0063。
  不再因scan=32默默漏掉后三个。不是泛化训练或测试。
- 中心到达、90秒/30技能预算、控制周期与技能均不变。
- 奖励为 `docs/random_start_dense_reward_v2.md` 的v2：真实距离进展、距离积分成本、时间成本、终局奖励，gamma=1。
- 原GRU128、324维输入、条件联合动作头、AdamW 3e-4、weight_decay=0、无熵奖金，
  PPO clip=0.2、value weight=0.5、3 epoch、梯度裁剪5、跨轨迹统一优势归一化。
- 重新初始化，不从旧奖励检查点继承模型或优化器。不引入世界模型、模仿、课程、辅助奖励或新网络。

## 评价与监测

- 初始化：固定8实例确定性/随机策略（每实例3行为种子）及均匀随机技能基线。
- 每50次更新：同8实例确定性/随机评价、逐实例回报/成功/距离/真实周期；不访问测试集。
- 最佳模型只按开发面板确定性成功率、再按最终距离中位数选择，不能称泛化最优。
- 每次更新写 `updates.jsonl`、`monitor.json`、README；记录优势/熵/概率比/梯度、critic更新前后同批解释方差。
- 每30分钟写 `monitor_history.jsonl` 与曲线；评价点也更新曲线。
  这是任务内自动监测，文件可随时查看；不假装已经有人逐次人工审阅。
- 连续最近3个评价点≥75%且较初始化提升≥20pp才记S4门槛；通过也不自动扩采，不提前改变任务。
- 早期低成功率不是提前停训条件。只因模拟异常、非有限数值、worker异常或硬预算停止。

## 恢复与隔离

- 每5更新、评价监测时及正常结束原子保存正常训练路径的恢复检查点。
- 包含迭代号、模型/优化器、torch/numpy RNG、历史、初始评价、最佳选择、精确配置与原始截止时间。
- 采样种子由seed/update确定；worker任务不使用共享环境、共享历史或同轮新策略。
- 恢复时校验奖励/配置/原截止时间和冻结源码；保留检查点之后的旧日志，再从检查点重建规范日志。
- 外层监督进程在原24小时截止时终止整个训练进程组，包含采样worker，不留下孤儿模拟。
- 若硬截止发生在更新中，该更新不计完成；监测保留完整更新，恢复模型可能落后至多4次常规更新。
- 所有实际源码、哈希、实例清单、环境和依赖版本写入新输出目录；历史结果只读。

并行/串行比对使用真实环境短轨迹；正常检查点加载后的连续更新逐张量一致。
首批正式8进程采样还会在学习器侧重算logp/value，不一致立即停止。

## 已知限制

动作/技能阶段历史仍未加入324维策略输入，本轮不偷偷更改架构。
固定8实例评价只能证明开发子集学习，不能证明泛化。
24小时或5000更新也不是收敛保证；结论必须来自真实曲线。
