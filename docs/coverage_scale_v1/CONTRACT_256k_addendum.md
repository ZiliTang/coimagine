# coverage_scale_v1 — 256k 续跑增补契约

本文件是 [CONTRACT.md](CONTRACT.md) 的**增补**，只记录 256k 续跑相对原契约的差异。
原契约的生成器、采集配方、split、场景分布、严格初态判据、去重语义、seed 空间与候选集合
**全部不变**；下面每一条在训练开始前冻结。

## 1. 数据（只增不改）

- 继续在同一个 run 目录 `outputs/coverage_scale_v1/coverage-scale-20261013/` 追加 train shard；
  `RootPlan`、`scenes_train.json`、`roots_train.jsonl` 都是原有的，新根只是原序列的**下一段**。
- 目标：去重后约 256k 窗口，取达到目标的**最短完整根前缀**；实际条数记录在案。
- 采集 worker 由 4 提升到 6（只影响速度，不影响 shard→root 的映射，也不改变任何配方）。
- 原 128k 数据、新 val（128 根）、新 test（128 根）、12 个候选起点与已缓存的精确真值
  **一个字节都不改**；`tier_records(train, 128000)` 的结果必须与上一轮逐条相同（有断言）。

## 2. 训练

| 项 | 128k（原） | 256k（本增补） |
|---|---|---|
| 更新预算 | `min(60000, max(6000, 60·ceil(N/128)))` | `60·ceil(N/128)`，**无 60000 上限** |
| 评估间隔 | `max(250, ceil(Umax/20/250)·250)` | 每 **3000** 次，另加强制 update 100、最终更新、update 0 |
| 保存点 | `best_new_val_total`、`final` | 同上，另加 **`update60000.pt`** |
| 选模规则 | 新 val 四项总 loss 最小（根→格→权重） | **完全相同** |
| 网络/损失/优化器 | 2×256 与 2×512 ReLU MLP、四头、Adam lr=1e-3、batch=128 | **完全相同** |

256k 档 `N≈256000` → `Umax = 60 × ceil(256000/128) = 120000`，仍约 60 遍数据。
`update60000` 的作用是把「更多数据」与「更多更新」分开：它与原 128k 模型更新数相同。

## 3. 分组指标（新增，不改任何阈值）

沿用冻结阈值 0.01 m（物体位移）与 0.02 rad（物体转角），把验证窗口分成：

- **运动划分**（成员可重叠）：`translation`、`rotation`、`stationary`；
- **接触划分**（互斥）：`contact`、`no_contact`。

两个划分**互相独立、彼此重叠**；运动划分内部 `translation` 与 `rotation` 也可同时成立，
只有 `stationary` 是二者并集的补集。重叠计数必须一并报告。

每个分组分别报告**物体、机器人0、机器人1**的位置误差、各自的 persistence 基线
（「预测不动」的位移）与非法率，同时给出窗口均值与冻结的根→格→权重聚合值。禁止只报三刚体均值 P。

## 4. 统一评价

1. 先写 `model_list.json`（路径 + 文件 SHA256 + 参数 hash + 更新数），并对其整体 SHA256；
   之后任何评估都只读这份清单，清单变化即报错退出。
2. 新 test 只评估清单内的 checkpoint，一次性完成；test 分数不参与选模、不决定是否继续扩量。
3. 固定候选只用**主选点**，复用上一轮的精确真值缓存（真值全局只算一次）；H=1 与 H=3 分表；
   配对键为 `(start_id, candidate_seed)`，只有两侧都可行的行进入配对均值；报告选中真实收益、
   好候选误拒损失、排序损失、执行 regret、拒绝率、无可行方案比例与无好候选比例。

## 5. 停止条件

本轮**只做 256k 一档**：不自动扩到 512k，不换结构/损失/几何阈值，不新增闭环，不改技能控制器。
墙钟上限 4 小时；超时保留已完成 run 与断点，交付部分结果。
