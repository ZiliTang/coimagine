## 一、压缩研究背景与本轮目标

作者已有 PushingBots 多机器人协作推动与混合接触规划经验。新研究希望在机器人拥有不同局部接触证据时，学习联合技能的物理后果，并通过有限消息实现准备、辨识和执行的协作规划。目标期刊为 T-RO，但当前尚无已验证的核心创新。

每个机器人保留私有历史 h_i；共同信息 C 包括任务、粗几何、公共运动反馈、过去共同动作和消息。局部模型针对同一个联合 option 预测后果。双方用共同消息记录和相同规划规则提交一致动作。训练可使用特权标签，部署不得读取隐藏真值或他方私有历史。

最终研究覆盖2D、3D平面操作、双臂辅助仿真和移动机器人实机。本轮仅做2D，先回答：

1. 相同公共信息下，私有接触证据是否改变最佳联合动作？
2. 一个有代价的试探，是否因改善后续决策而值得执行？
3. 当前损失主要来自隐藏状态、信息共享限制、消息表示，还是有限搜索？
4. 简单紧凑后验是否已经足够？允许答案为“是”。

通用模型仅用于未来的候选排序加速，不是本轮创新。不接收费API，不依赖Jev或任何特定模型上线。保留可替换排序接口，用规则排序即可完成首轮。

## 二、严格按阶段完成

### 阶段0：确定协议与可复现入口

先检查仓库；若为空，建立轻量 Python 项目。默认 NumPy、pytest、Matplotlib，暂不引入深度学习、分布式框架或Web前端。适配现有项目环境，不擅自更换依赖管理方式。

写一页 `spec.md`：状态、观测表、时序、技能契约、代价、终止条件和oracle适用范围。随后立即实现。模块可以合并，避免为目录结构而过度设计。

### 阶段1：先完成微型有限状态诊断实例

先做2–4个可穷举的小实例，状态显式包含物体/接触配置和隐藏物理类型；它们是grid环境的最小抽象，不宣称连续物理真实性。

建议起点：2–4种隐藏状态、每侧二元局部反馈、每时刻2–3个合法联合option、时域2–3步。时间不足以支持具体序列时合理调整，必须报告实际时域和穷举规模。

至少覆盖：

- M0：公共信息足够。私有通信应无额外收益。
- M1：公共“停滞”相同，但局部响应对原因提供不同证据；恢复方式随原因不同。
- M2：短试探有明确动作成本，反馈能改变后续最佳动作；同时提供试探无信息和试探过贵两个负面对照。
- M3（可选）：准备动作改变接触模式，后续联合技能才更容易完成；区别于只获取信息的试探。

不要设计一个标签为“probe”就免费揭示隐藏真值的按钮。通过公开的有限观测似然表产生局部反馈，写清其“驱动响应/滑移/受约束反馈”的抽象含义。必须允许反馈噪声，并公开完整联合观测表 P(o_A,o_B,y_public | s,a,s')，不能未经验证就假定两侧独立。

试探可以使用一个短推技能；它的位移、代价和观测均由状态转移定义。准备动作若改变接触状态，也应进入同一转移表。禁止额外添加信息增益奖励或“使能奖励”来制造效果。

### 阶段2：完成能看见的grid协作推动

在微型精确验证通过后，实现6×6左右的小地图、两个机器人、一个2×2物体、障碍与目标区域。初版只做平移，物体旋转不是验收必需项；保留姿态扩展接口。先交付4个明确机制的场景，再视结果扩展模板，不一开始堆20张地图。

可采用以下简化规则，具体接触几何须在spec中写清：

- 单机推动能力1，同向合法协推合力2，物体隐藏阻力 r∈{1,2}。
- 机器人必须位于合法接触单元，目标占据区为空，推动才能产生平移。
- 换位沿无碰撞格点路径进行，计路径时长/代价，禁止免费传送。
- 联合option包括合法单推、同向协推、一机保持另一机换位、等待；短推的辨识作用通过实际反馈产生。
- 如加入“约束—释放”，用明确接触模式转移表定义，并注明其符号抽象性质；首版不是必须项。
- 几何、已提交动作、规定频率的物体位姿为公共信息；局部驱动/滑移反馈为私有信息。不得仅为制造私有性而隐藏本来约定公开的位姿或障碍。

几何合法候选由公共几何生成。不因隐藏阻力而预先删除推动候选，否则候选掩码本身泄漏真值。固定一组低层技能契约与代价，所有方法复用。

大grid的联合历史可能无法穷举：明确降级为真模型有限搜索，不能继续使用“精确最优”标签。

## 三、信息边界与严格时序

每个决策边界：

1. 环境分发本侧私有观测和同一公共观测。
2. 各侧仅用自己的历史和公共记录更新信念。
3. 双方由公共信息重建相同候选集合与ID。
4. 各侧同时发送一次不超过B bits的私有证据消息。消息不能依赖同轮尚未收到的队友消息。
5. 双方更新共同记录，由同一确定性公共规则选择联合option；固定候选顺序、随机种子和平局规则。
6. 执行、计代价、生成下一轮观测。

明确t=0是否有局部观测；没有试探就不可提前获得未来反馈。全局日志可记录隐藏真值供评测，但不能传给部署策略。

B=0时，公共协调策略不能暗中使用任何一侧私有信念。不要声称这是所有无通信分散式策略的最优结果；初版oracle只覆盖上述“消息后公共提交”协议类别。

至少用不同输入数据对象隔离 `TrueState`、`PublicContext`、`PrivateHistory` 和 `OracleContext`。普通策略接口不接受环境对象。测试改变隐藏真值而固定可见输入时，普通排序器和策略输入不得悄然变化。

## 四、精确信念与oracle

先用精确表格，不训练神经世界模型。每个机器人用正确的生成模型进行Bayes更新；不可把两个共享先验的后验直接相乘。

公共协调所需精确状态一般为 P(s,h_A,h_B | C)，因为消息依赖私有历史。微型实例枚举私有历史，或证明所用有限局部统计量足够；不能只缓存 P(s|C) 就默认足以预测未来消息。

必须实现并区别命名：

- `O_full`：看到真实状态、真动力学、相同有限时域下的最优策略。
- `O_central`：汇集两侧可获得观测历史，仍不知道隐藏真值；精确POMDP决策，允许未来观测分支。
- `O_codec`：固定消息编码规则，真模型下精确规划公共策略，包括后续观测经过同一编码器产生的消息分支。
- `O_B`：仅限极小实例，枚举满足位数限制的局部消息规则及公共动作规则；离线可用完整生成模型，在线映射只能读合法信息。为控制规模，先实现单个通信决策边界的精确版本，再扩展短时域。
- `TrueModelLimitedSearch`：真模型但受节点/深度限制，明确不是最优oracle。

为每个精确结果输出实际时域、策略类别、编码规则是否固定、遍历节点数和计算耗时。若耗尽预算，返回明确的未完成状态，不输出伪精确值。

同一实例、同一代价、策略集合嵌套且集中方法可模拟通信时，应验证期望成本关系：

J_full* ≤ J_central* ≤ J_B* ≤ J_codec*。

无条件把“用真模型”当性能必然更好的说法不允许，有限搜索可能产生不同偏差。

## 五、最小基线和诊断

首轮必做：

1. 公共信息策略，无私有任务消息。
2. 紧凑后验/隐藏模式消息＋O_codec。
3. 候选后果摘要消息＋相同规划器。
4. 完整共享历史的O_central。
5. 同一消息编码下，不展开未来信息分支的固定序列规划＋实际执行后重规划。
6. 真模型有限搜索与对应精确规划对照。

消息用可检查的离散码本序列化，不把Python float数组标为“1bit”。先比较每侧B=0、1、2；候选ID、缺失掩码等编码内容计入有效载荷。小实例中1bit即可传完二元观测是正常现象，必须报告。没有必要人为阻止简单后验获胜。

后果摘要先对联合候选的成功/停滞概率做显式量化。同预算表示必须有完整码本与解码含义。不得只将某个事件概率叫“世界模型”；环境的完整生成表和技能转移模型要明确可查询。

为单独衡量搜索瓶颈，固定codec；为比较codec，使用相同搜索规则。准备和辨识实验必须有未来观测/消息分支，不能用事后重规划冒充事前信息价值计算。

## 六、通用先验只做接口与规则实现

提供 `OptionPrior.rank(public_context, candidates) -> ordered_ids`，实现identity和简单几何/阶段规则排序。检查排序是合法候选的排列。保留模型适配入口但默认不开启API。

搜索可按固定批次访问候选并保留探索项；当做精确oracle时必须遍历全部合法候选，不允许依据启发式丢弃候选。规则排序只能用于有限预算搜索的工程对照。

如果消息生成需要预测全部候选，全部预测成本计入；不能仅统计最后被搜索的候选。未来追加API时再计网络、缓存、同步开销。当前小候选环境排序不加速是可接受的结果。

## 七、评价、真实运行与必要测试

微型实例优先精确求期望，随机rollout只做一致性核验。grid对所有方法使用相同场景/初始条件集合，保存seed；若随机数消耗会随动作不同而变化，不把同seed宣称为完全配对的观测轨迹。

主代价是达到目标的累计动作/耗时成本，加明确失败或截断成本；配置中固定各项并说明量纲。失败不能通过提前退出获得低代价。另报成功率、执行步数、无效推动、试探次数、bits、搜索节点和墙钟时间。

最少完成以下测试：

- 概率非负且归一，Bayes更新与手算小例子一致；不可能观测有明确处理。
- 同公共记录产生同共同动作；同轮发送不读对方新消息。
- 未来真实反馈不提前用于分支选择；重复转发同一证据不会再次作为独立似然更新。
- 消息实际位数正确；同一实例的oracle成本序关系符合适用条件。
- B增加且策略类嵌套时，精确O_B成本不增加。
- 碰撞/接触/合力/换位代价/终止正确。
- 公共输入相同、私有证据不同的配对例子，展示动作变化或说明为何不变。
- 信息无用或试探太贵时，精确策略不选择无收益试探；存在有用信息时是否选择由求解结果决定。

产生一张oracle差距表、一张通信预算曲线、一张试探成本或反馈噪声扫描图，以及2–3段轻量GIF/PNG序列。可视化标清真实隐藏状态（仅评测展示）、两侧信念、消息、候选评估和最终选择，避免把离线真值画成策略可见输入。

开发案例和留出参数组合分开，保存配置清单。先在开发案例调试并冻结后跑留出组合，不筛除负结果。不得依据测试收益修改奖励或只挑有利通信预算。
