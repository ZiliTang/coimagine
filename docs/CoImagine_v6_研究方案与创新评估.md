## 0. 本版决定与一页摘要

本版在 v5 基础上增加可替换的通用先验排序模块，以减少低价值联合 option 的搜索开销。沿用私有接触信念、有限消息、公共协调计算与未来消息分支的研究主线，保留逐级验证、强基线、精确 oracle 和可证伪要求。上层排序属于工程增强，不单列为方法创新。

**主问题：在局部接触证据不对称、共享信息有限时，如何将每台机器人的私有历史转化为对候选联合技能有用的预测，使团队有效选择准备、辨识和执行动作？**

**首选方法假设：以候选联合技能的后果分布组织消息，而不是只传当前观测或无语义 latent，能否在相同通信与计算预算下更好地保留接触决策所需的信息？** 这是假设，不是已证明优势；低维参数后验和直接动作价值消息是必须面对的强对照。

训练可使用仿真特权状态与反事实技能结果；部署时每台机器人只使用本地历史、公共信息和合法收到的消息。私有预测不必相同，目标是校准与有效合作，不是强行 latent 对齐。

| 实验 | 定位 | 决定 |
|---|---|---|
| 2D 协作推动 | 精确动力学、局部信息和受限通信 oracle | 首先完成 |
| 3D 协作平面操作 | 主要学习、消融、泛化与物理验证 | 核心仿真 |
| 双臂支撑—插入／抽取 | 不对称角色、互补接触技能的跨任务验证 | 辅助仿真，先做插入 |
| 两台移动机器人平面操作 | 实际局部反馈与接触失配下的闭环表现 | 唯一必做实机方向 |
| 四足、双臂实机 | 扩大工程范围但非当前必要证据 | 不列入本轮计划 |

固定两机器人、可靠同步通信、有限技能和已知粗几何。暂不加入开放团队、丢包、异步共识、视频生成或底层技能学习。公共几何不等于公共接触状态；模型必须体现仍然私有的证据。

**当前研究判断：组件重叠程度高，具体问题交叉处值得探索，但算法创新仍需由消息表示、后续规划与公平实验兑现。恢复分布式使问题更完整，不自动获得“空位”。**

本文是待实施方案，不包含已运行实验或测得性能。

**v6 新增决定：**使用统一的 `option_prior` 接口，对公共候选联合技能排序；先接入稳定可用的通用模型 API，Jev 稳定可用后再作替换对照。候选服务可考虑用户提出的 DeepSeek、GLM、GPT 系列；具体版本名、端点、结构化输出支持、价格和可用性在实施时核验，本方案不预设任何型号已经开放或达到特定性能。模型只读公共上下文，排序可缓存、可关闭，调用失败回退到规则排序。最终选择仍由遵守信息边界的物理预测和规划结果决定。

本次修改覆盖方法接口、同步协议、搜索预算、各阶段实验、消融与停止条件；不新增平台或实机任务。

## 1. 研究坐标：我们站在哪几条线的交叉处

### 1.1 相对于作者自己的 PushingBots

PushingBots [1] 是本项目的已有基础，不是外部竞争者。保留其模式生成、几何检查、控制执行和恢复经验；不将其错误描述成“不处理不确定性”或“没有学习”。

新推进聚焦于：**局部交互产生的不同证据，如何进入联合接触后果预测与后续协作决策。** 多机器人多物体调度和新平台数量不是本轮增量。已有完备性结论不能无条件转移到有限预算的学习模型与概率筛选上。

### 1.3 三项关键文献纠偏

1. “分布式世界模型＋通信”已有直接先例 [6][8]；加入私有历史不构成独立新颖性。
2. [9] 的 arXiv 当前 v2 已扩展为 *Action-Consistent Decentralized Belief Space Planning with Inconsistent Beliefs and Limited Data Sharing: Framework and Simplification Algorithms with Formal Guarantees*。不能只按其早期 IROS 标题和范围比较。
3. [7] 的预算主要涉及训练过程共享经验／想象数据。它削弱“首次高效信息共享”的宽泛主张，但不能据其标题断言已经完成了我们拟研究的部署期接触消息机制。

### 1.4 真正值得争取的研究坐标

**分散式信息条件下，面向联合接触决策的技能后果预测与消息表示。**

物理耦合是 A 的动作改变 B 后续可行操作；信息耦合是 A 的局部反馈改变团队对这些后果的判断。论文要解释两者如何通过可执行的消息与规划机制连接，并证明收益超出已有组件的简单拼接。

“多机器人＋隐藏物理＋技能＋特权监督＋双臂”这样的属性合取，不作为空位证明。

## 2. 问题设定：什么是私有，什么是共享

### 2.1 状态和信息边界

真实状态 s_t=(x_t,c_t,θ)：x 是几何／运动状态，c 是可变接触模式，θ 是任务期间相对稳定的物理条件。

公共信息 C_t 包含任务、允许共享的粗几何／低频物体位姿、过去已提交联合动作、协议、时间戳和已交换消息。机器人 i 保留私有传感历史 h_i,t，例如自身驱动响应、局部滑移／接触反馈、短时力矩或局部视觉。

\[
b_{i,t}=P(s_t\mid C_t,h_{i,t}).
\]

允许共享低频位姿是为了控制感知工程范围；它可能揭示部分接触证据，必须测量剩余私有信息是否仍影响决策。若公共信息已经足够，就把这一条件报告为分布式预测无额外收益的边界。

### 2.2 通信约束必须真实计量

每个技能边界固定一个同步双向私有证据通信轮次，每机器人最多 B bits 的任务消息。v6 允许在此之前提交仅由公共信息计算的排序记录；其广播、服务请求及延迟单独计量，不得承载未编码的私有证据。测试扫描 B，不将某个很小预算包装成真实硬件的必然瓶颈。

预算包括消息内容、候选索引、置信度、掩码、私有排序、动作建议以及额外请求。协议头和公共定位流分别记录；传给所有方法的公共信息必须完全相同。候选若由公共数据确定且可本地重建，可免重复发送，但计算时间仍计入。

实时系统的网络包开销与语义有效载荷分别报告。若共享一个低维后验只需几个字节，应该承认带宽问题可能很弱；不得通过隐藏简洁后验基线制造优势。

### 2.3 技能与同步

a_t=((k_A,p_A),(k_B,p_B)) 是联合技能。移动平台包含换位、短推、保持、等待；双臂包含支撑微调、短插入、回退和保持。固定且共享低层控制器。

同一时段按同步边界提交和执行，提前完成者按约定保持；局部碰撞／过载保护可以终止技能，但触发消息与下一轮重规划必须记录。暂不主张异步分布式控制理论。

## 3. 收缩后的方法假设与可实施结构

### 3.1 局部技能世界模型

每台机器人用私有历史与公共信息，对同一候选联合技能 a 预测共享物理后果 Z 和自己的下一步观测：

\[
\widehat P_i(Z_{t+1},o_{i,t+1}\mid C_t,h_{i,t},a).
\]

Z 使用任务相关量：物体增量运动、滑移／停滞事件、技能时长、任务契约结果。先用有限隐藏假设＋条件模型，随后用小型循环编码器。共享参数可以保留，但推理输入必须局部。

同一世界事实不意味着两台机器人的条件分布应该一致。局部不确定性可以是真实信息不足；不做无条件 latent 对齐，不要求局部网络猜中不可辨识的隐藏类型。

### 3.2 首选消息：候选动作条件化的后果摘要

从公共信息产生 K 个联合候选。机器人 i 针对这些候选得到后果概率／统计量，再编码为固定长度消息：

\[
m_i=\operatorname{Quantize}_B\!\left(g_i\left(\{\widehat P_i(Z\mid C,h_i,a^k)\}_{k=1}^{K},C\right)\right).
\]

基础版无需通用模型即可运行；v6 的可选通用先验仅安排候选搜索顺序，见3.7。K 从 4–8 开始，后果事件为可推进、停滞、滑移／失稳等；采用显式量化概率或候选子集摘要。连续位移均值／区间后续加入。候选索引与缺失项处理均纳入编码规范。

这是待检验的归纳偏置：消息围绕“做不同联合动作会发生什么”组织。它可能对当前动作集有效，但无法保留全部未来信息；不宣称是最小充分统计量。后续候选变化时重新生成消息，训练与测试覆盖候选分布变化。

必须与同位数的以下消息比较：原始观测摘要、接触类型／参数后验、通用 learned latent、联合动作 Q／偏好。若完整后验更便宜且更有效，就采用后验通信，不强保留预测消息。

### 3.3 消息聚合与分布式提交

每台机器人收到相同消息记录后，使用同一个可复制的公共状态更新器和评分／搜索程序，选出共同联合动作。共享参数、候选编号、随机种子与平局规则，保证在本版可靠同步通信假设下动作一致。

这是**分布式信息采集和预测＋可复制的公共协调计算**：没有收集全部私有历史的中心节点，但也不是任意异步局部策略各自决策。公共信息协调表示已有理论基础 [10]，不以此作为新颖性。

私有信息必须通过合法消息影响本轮共同决策。若某机器人还用未发送的私有评分单独改变高层动作，就会破坏共同选择；该行为不属于首版协议。低层本地反馈控制仍允许，且其随机结果由模型学习。

聚合器可用消息历史的循环状态 z_C,t，预测联合后果。首版在 2D 使用精确条件表；3D 用训练得到的消息条件模型。不能直接将两个私有后验相乘，或独立采样两个彼此不兼容的物理世界：共享先验、历史消息及相关观测会重复计数。使用显式联合生成模型或学习聚合，校验其概率校准。

### 3.4 规划未来反馈：至少做一次真实的信息分支

从 z_C 或精确公共信念出发，预测候选动作后的公共运动结果和下一轮消息对 (m_A′,m_B′)。在各个可能消息分支下，按同一协议重新选动作。

2D 从真实联合状态生成局部观测，再经过各自编码规则，得到消息对；3D 学习联合的公共结果／下一轮消息分布，或由共享物理隐变量生成两侧观测后编码。模型训练与部署遵守同一通信协议。

首版只展开一层显式观测／消息分支，后续接有限技能序列搜索。消息模型是新增的实际训练成本，不能把“一步预测消息”当作免费能力。仅对固定动作序列 rollout，再执行后重规划，不等同于预先评估信息价值。

固定 θ 在一条想象轨迹内保持一致；接触状态可随动作变化。任何后续动作不能提前读取该分支尚未公开的私有观测或真实 θ。

### 3.5 特权监督的角色

训练可用真实接触模式、物理参数、联合技能结果与快照分支作为标签；部署模型的输入仍为各自信息集。相同可见历史对应多种真状态时，用概率损失学习条件分布，不强迫单值确定答案。

优先采用交互结果监督＋有限分支；特权标签用于改善稀疏事件与未执行候选覆盖。所有仿真分支计入总查询，训练／测试划分隔离整个快照家族。

对照包含同数据同特权标签的通用消息模型。否则只能证明额外监督有用，不能证明我们的消息表示更好。

### 3.6 联合可行性为可删模块

可选 F(b,a) 预测固定控制器在时限内达到联合技能契约的概率。它既可作辅助训练，也可参与候选排序；两种用途分开消融。

每机边缘概率不能直接相乘替代联合成功率。低成功率动作可能有辨识价值，首版采用软排序并保留探测候选；不额外奖励“可行域变大”，不添加使能价值项。

### 3.7 工程增强：可替换的通用先验辅助联合 option 搜索

#### 3.7.1 目的与职责

通用先验用于优先搜索符合任务阶段和协作角色的候选，减少明显无关或低价值分支上的计算。它不负责识别未观测的摩擦、滑移或支撑状态，也不替代私有世界模型。后者依据局部接触历史提供物理证据，公共规划器结合合法消息评估联合后果。

本节是待验证的工程设计，不改变 RQ1–RQ5 和 C1–C3。即使通用模型没有净收益，主体研究仍能用规则排序或不带先验的搜索完成。

#### 3.7.2 输入输出与候选语义

由现有技能库和几何模块生成共同候选集合 A(C)。每个 option 包含固定 ID、双方技能、几何参数、预计持续时间、终止条件及任务契约。公共几何只能过滤确定的几何非法项；隐藏接触条件不能以真值用于过滤。

`option_prior.rank(public_context, candidates, budget) -> ranked_ids`。

公共上下文包括目标、粗几何、当前阶段、已提交动作和允许共享的执行记录；未知物理条件标为未知。禁止读取双方完整私有历史、训练特权状态或另一机器人尚未发送的反馈。输出为候选 ID 的排序，使用结构化约束并校验重复、缺失和未知 ID。缺失项按固定规则补齐；格式错误或超时整体回退。首版不让模型自由生成连续动作，也不依赖自报置信度。

优先排序联合模式，例如“双方协推”“A保持、B换位”“A微调、B等待”“A稳定、B短插入”“一侧探测、另一侧保持”。较大候选空间先排序联合模式，再由几何生成器在模式内部搜索参数；不把两个独立动作分类结果直接拼成联合动作。

#### 3.7.3 与一轮通信协议的兼容

推荐首版执行顺序：

1. 两侧依据同一公共记录确定候选集合、编号和时间戳。
2. 指定一侧仅用公共信息调用排序器，将经校验的排序及候选集合标识提交为公共记录；另一侧不独立调用随机 API 来猜测同一排序。也可使用双方已有的同版本缓存。排序广播计入实际消息量；API 请求／响应字节与时延另列。
3. 双方按已提交的候选约定进行局部预测与编码，各发送一次不超过 B bits 的私有证据消息。
4. 双方用相同公共消息、候选顺序、随机种子与预算运行可复制规划，提交一致联合动作。纯时间截止易造成两侧扩展数不同，首版使用一致的工作量上限；墙钟测试另外记录或明确提交已评估候选编号。
5. 执行固定低层技能，记录反馈，在下一技能边界更新历史并重规划。

排序服务只处理公共信息，因此不合并私有信念。其计算位置不改变信息边界，但调用及同步成本必须报告。收到消息后可以按公共物理评分重新排序；首版不再增加 API 往返。

**单轮协议的重要限制：**如果消息是针对候选子集编码，收到消息后不能免费要求机器人对新候选重新发送私有预测。首版在通信前固定本轮候选覆盖集合；后续扩展仅在已覆盖集合内进行，或由已经训练并验证的公共消息模型对更广候选推断。若要补发私有证据，必须作为额外轮次实验并计量，不能混入单轮主结果。

#### 3.7.4 分批评估与保留探索

先评估排序靠前的一批联合候选，再依据物理预测决定是否扩展。扩展条件包括：已评估候选均未满足风险约束、预期收益不足、预测不确定性高，或不同消息所支持的后果存在显著冲突。停止阈值在开发集确定，不使用测试真值调节。

预留固定份额给几何候选、低排名候选和探测／支撑调整动作，使用共享种子决定补充项。第一版可从每批2–4项、保留约20%评估预算作为工程起点，再在开发集调整；这些不是性能保证。先验只影响访问顺序与预算分配，不用于永久删除候选。

最终在已评估候选中按统一任务代价及风险选择，不直接把语言模型分数乘以物理成功率。探测价值仍通过3.4的未来观测／消息分支计算，不能用语义偏好代替。

#### 3.7.5 计算收益的边界

分别记录候选生成、私有编码所需预测、公共多步 rollout、排序 API、同步与控制等待的耗时。若消息编码仍需要对全部候选做局部预测，这部分计算并未省去；通用先验的收益主要可能来自减少昂贵的后续分支搜索。

对可省略的串行 rollout，粗略盈亏条件为：

\[
T_{\rm API}+T_{\rm extra\ sync} < (M-K)T_{\rm rollout}.
\]

M 和 K 分别为无先验与有先验实际评估的候选数。该式只作工程估算；批量 GPU 推理、共享前缀与并行计算可能使成本非线性，最终以端到端实测为准。K很小、rollout很便宜时可以关闭排序器，不能为证明收益人为放大候选库。

候选量较大或多步想象昂贵时再测试扩大规模。仅在任务阶段变化、公共执行反馈失配或缓存失效时调用；缓存键包含公共状态摘要、候选集合、模型／提示版本，不能沿用不适用的旧排序。API超时立即回退，低层保持／停止规则与现有控制器一致。

#### 3.7.6 模型替换与复现

统一适配通用生成式模型和 Jev 的分类接口，最终都转换为候选 ID 顺序。先选一个稳定服务完成 pilot，暂不开展多供应商大规模比较；Jev 后续作为同接口替换实验。工程选型依据端到端时间、任务成功率、成本、尾部延迟和回退率，不以演示观感选型。

记录模型标识、提示版本、参数、输入输出、缓存命中、调用时间与失败原因。敏感或隐藏状态不写进排序输入；离线回放可以使用冻结排序日志，但实时结果必须计入真实服务时延，不能用回放速度冒充在线速度。

## 4. 研究问题与判别实验

| 问题 | 正向证据 | 会削弱主张的结果 |
|---|---|---|
| RQ1：私有证据是否影响协作？ | 控制公共观测后，局部证据改变最佳联合策略 | 公共位姿已揭示全部所需信息 |
| RQ2：预测组织的消息是否有价值？ | 同 bits、同数据、同规划器下，比摘要／后验／latent／Q 更好地保留决策信息 | 简单后验或 latent 始终持平／更优 |
| RQ3：未来消息分支是否值得建模？ | 在有代价的辨识场景改善任务成本，同时在无信息场景避免探测 | 普通闭环重规划足够、模型误差吞掉信息收益 |
| RQ4：联合建模是否必要于这些任务？ | 比逐机独立模型更准确地预测互补／冲突接触，改善联合动作排序 | 简单独立组合已足够 |
| RQ5：特权与可行性监督增加了什么？ | 在公平查询成本下改善样本效率、校准或搜索 | 收益仅来自更多标签或更多搜索 |

**工程验证 E1（不计作新增核心创新）：**通用先验能否在相同信息与通信协议下，降低达到指定成功率所需的总规划时间或提高固定墙钟预算下的成功率？分别报告搜索质量和服务开销；减少候选数量不能单独证明效率。

RQ1 是问题成立条件，RQ2 是首选方法主张，RQ3 是规划深化。若 RQ2 失败但 RQ3 成立，可改为接触信念规划路线；不能继续用预测消息作为主要创新。

## 5. 实验 A：2D 精确协作推动

### 5.1 可计算世界

先用 6×6 小地图、两个机器人、一个 2×2 带朝向标记物体与障碍。几何公开，物理模式隐藏。基本动作：接触换位、单推、同向协推、保持—释放、等待。换位包含路径与耗时，不免费瞬移。

精确规则：单机器人合法推动能力为 1，两机同向为 2；阻力 r∈{1,2}；独立约束模式 c∈{自由,约束}。能力达标且目标占据区为空时平移一格；约束状态需要指定互补释放组合才可改变。转向／释放用显式离散表及扫掠检查，说明它是物理机制的符号抽象。

局部反馈 o_i 包含自身驱动／滑移事件；公共反馈只含规定频率的物体移动。定义并公开联合观测表 P(o_A,o_B,y_pub|s,a)。观测相关时直接用联合表，不假设独立。

先用二元隐藏变量校验；再用阻力×约束×局部牵引的多个状态测试通信压缩。二元后验可用极短消息传输，是负面对照，不应刻意排除。

### 5.2 四类任务

| 任务 | 要检验的机制 |
|---|---|
| A0 已知条件下直接协推 | 基本联合动作与控制，通信应无明显增益 |
| A1 停滞原因分辨 | 公共停滞相同，局部反馈指向不同恢复方式 |
| A2 准备改变接触条件 | 换位／释放后可使用新联合技能 |
| A3 辨识—准备—执行 | 哪个机器人试探、传什么、何时调整合作方式 |

隐藏先验、私有反馈可靠性、辨识成本、通信预算形成预先定义的测试网格。必须保留公共观测充分、消息无信息、探测过贵、固定稳妥策略足够的条件。

### 5.3 Oracle 体系：改正 v4 的信息公平性

| 参照 | 信息与范围 | 正确用途 |
|---|---|---|
| O-full | 知道真实物理状态，有限时域最优 | 全信息成本下界 |
| O-central | 汇集双方完整历史、真模型、有限时域最优 | 完整观测共享的参照，不是信息公平主基线 |
| O-B | 与部署相同消息预算和协议类别，枚举发送规则及公共动作策略 | 极小实例的公平最优参照 |
| O-codec | 固定具体消息编码器，真模型下精确优化后续公共策略 | 区分消息表示损失与搜索误差 |
| O-model | 真模型替换学习模型，保持有限搜索 | 模型替换诊断，不保证数学上总更优 |

O-B 明确限制在“每步一个同步消息轮次＋公共规则提交联合技能”的策略类别；不能称为无限制 Dec-POMDP 全局最优。

微型 oracle 先限制两种局部反馈、2–3 个联合动作、1–2 bits、时域2–3。枚举各机器人依其私有历史发送符号的映射，以及公共消息到联合动作的映射；离线设计可用完整环境模型，但执行时只能依赖合法信息。更大 grid 用 O-central／O-codec 和近似 O-model，不能把近似结果称为精确最优。

公共精确状态应为 P(s,h_A,h_B|C)，因为预测下一条消息需要考虑隐藏的私有历史；仅用 P(s|C) 未必充分。小例子完整枚举私有历史，正式模型用公共循环状态近似，报告这一近似。

在模型、时域、代价一致，且通信免费或按相同规则可被集中方法模拟的条件下，最优期望成本满足：

\[
J^*_{\rm full}\le J^*_{\rm central}\le J^*_B\le J^*_{\rm codec}.
\]

有限训练／有限搜索的集中基线不必达到该界，也不保证优于所有学习方法。3D 不宣称精确 O-B。

### 5.4 分解与单元检查

- J*central−J*full：物理状态不可见造成的差距。
- J*B−J*central：在所定协议类别下的有限共享损失。
- J*codec−J*B：具体消息表示的损失。
- 真模型有限搜索相对 O-codec 的差距：计算限制。
- 学习模型替换差：经验差，可能受搜索偏差影响，不必非负。

检查同一公共记录必得同一提交动作；重复转发消息不增加额外独立证据；信息更差的机器人允许输出更宽分布；预算增大时最优 O-B 不变差（策略集合嵌套时）。

### 5.5 首轮规模与验收

第一周完成 2–4 个微型 oracle 实例；第二周扩展12–20个 grid 开发模板和通信预算曲线。学习 pilot 5k／20k／50k 技能转移、3 个种子，后续正式测试至少5种子。

先证明受限共享确实影响某些联合决策，再训练神经消息。若简单后验在所有任务都足够，保留它作为主方案，停止为复杂预测消息追加成本。

---

### 5.6 通用先验的2D pilot

复用已有实例、技能和消息协议，比较无先验、规则先验、轻量学习排序器、通用模型排序。先冻结世界模型与编码器，隔离排序收益；对候选数量、描述顺序和公共状态歧义作测试。简单4–8候选场景允许并预期可能无净收益；只在真实任务产生更多接触／模式组合时扩展候选数。

记录近优候选 Recall@K、相对 O-codec 或同信息协议 oracle 的决策 regret、探测动作遗漏、实际展开数及在线总时间。O-full 只作全信息上界参照，不用其真状态指导通用排序。构造公共输入相同、私有接触历史不同的配对案例，检查相同先验能否经合法消息得到不同且合理的最终决策。

## 6. 实验 B：3D 主仿真——协作平面操作

复用 PushingBots 的成熟仿真和移动平台。3D 刚体引擎执行 SE(2) 为主的任务，不同时扩展到任意6D操作。机器人必须经受有限力、速度和接触动力学，禁止通过直接修改物体位置完成推动。

| 任务族 | 私有证据来源 | 联合决策 |
|---|---|---|
| B1 阻力与局部牵引 | 各自驱动指令—运动响应、局部滑移 | 增加参与者、换接触、短推辨识 |
| B2 受约束释放 | 本地接触运动、对公共停滞的不同解释 | 继续推或先侧移／旋转释放 |
| B3 偏置负载与窄通道 | 两侧运动误差／载荷响应 | 互补接触、一机稳定另一机推进 |

首版 B1＋B2，B3 后续。参数使用已标定或物理合理范围，未知质量／摩擦可能不可分辨时，只要求决策相关预测准确。视觉上可见的障碍不能伪称隐藏。

公共定位和私有反馈必须有传感器实现依据。若现有平台没有电流／力信息，则使用本地编码器、IMU、视觉或确实可获得的反馈；若均无决策相关局部证据，则调整传感配置或承认该场景不支持私有信念主张。

训练数据含原规划器轨迹、合法随机探索和失败恢复。快照选择2–4个分支作为 pilot；共享数据与隐藏标签提供给相应公平对照，所有调用计数。随机控制器成功率需重复运行估计，不能把单次结果称为精确物理可行性。

消息预算先扫描0、32、64、128、256 bits／机器人／技能边界及充分共享参照；这是实验刻度，最终按实际编码成本调整。双方总量、轮次、协议开销、定位公共流和在线 p95 时延都报告。

先固定消息格式，再训练其公共消息转移模型；联合微调后应重新生成或重编码数据，防止消息含义改变导致公共模型过期。测试时禁止调用真实隐藏参数进行候选验证。

### 6.1 主仿真的工程验证

在B1／B2中复用同一候选生成器，测量通用排序在不同搜索深度、候选规模和世界模型成本下的适用范围。先用规则排序完成完整闭环，再接一个API，不同时更改世界模型结构。主结果包含真实在线p50／p95规划时间、同成功率下的耗时、调用成本与回退率；缓存冷启动和稳定运行分开报告。

## 7. 实验 C：辅助仿真——双臂支撑与插入

### 7.1 范围与展示目标

只做仿真；先实现插入，抽取仅在可以复用控制器时追加。不做双臂实机，不做柔性物体或复杂装配序列。

A 臂夹持带插槽部件并可做小幅姿态／位置调整；B 臂持插入件。两臂固定局部阻抗／顺应控制器，避免低层技能学习掩盖高层决策。

任务变化包括夹持摩擦／顺应性、轻微对准偏差和接触阻力。在初始粗视觉类似的情况下，阻力反馈可能来自对准问题或支撑微滑。低层技能必须在充分信息条件下可靠完成。

### 7.2 信息与动作

| 项目 | A：支撑臂 | B：操作臂 |
|---|---|---|
| 私有反馈 | 自身关节、夹持稳定性、局部载荷／相对滑移 | 插入深度、末端阻力／力矩、跟踪误差 |
| 高层技能 | 保持、微平移、微旋转、稳定夹持 | 短插入、小幅试探、回退、等待 |
| 对队友影响 | 改变孔位、接触姿态和稳定性 | 改变支撑载荷并产生诊断证据 |

若采用仿真力觉，将其视为规定的本地传感器，有噪声、采样频率和范围；不偷偷向规划器提供完整接触流形。公共相机若能充分分辨滑移，加入“公共信息充分”对照。

展示同样遇阻后：A反馈稳定、B反馈侧向力矩时采用支撑微调；A反馈滑移时回退并稳定支撑。策略分支必须由反馈与成本产生，不能按真实隐藏标签脚本选择。

### 7.3 辅助实验的最小对照

固定顺序／固定支撑策略；无任务消息；同预算观测摘要；参数／模式后验或通用 latent 中主任务最强者；完整方法；充分共享参照。至少保留一个 strong learned-message 对照，不能只与弱手工摘要比较。

报告成功率、完成代价、无效尝试、超力／滑移事件和总消息量；使用未见偏差与摩擦组合。两个域分别训练是方法适用性验证，不声称零样本跨平台迁移。

辅助任务的意义是不对称角色与互补接触，不是因为插入场景本身新。接触世界模型与插入评测已有近邻 [11]。

### 7.4 通用先验的辅助展示

保持既定信息结构，比较“保持支撑并插入”“调整后再插入”“回退并稳定”“探测”等联合模式的排序。重点展示公共状态类似时，局部受力／滑移证据如何推翻初始先验。禁止将真实卡滞类型写入prompt。通用先验改善协作阶段选择是工程结果，私有模型纠正排序是互补性证据；两者分别量化。

## 8. 实验 D：协作平面操作实机

仅使用两台已有移动机器人，选择 B1／B2 中能安全重复复位的任务。通过可更换摩擦垫、负载或可控物理约束构造隐藏差异；确认允许观测中存在可用的私有证据。

所有方法同一低层控制器、同一公共定位流、同一网络预算。日志可离线集中保存，但不能在线向部署策略泄漏另一侧数据。网络受限是受控实验设定，另报告普通充足通信下的结果，不宣称现场网络一定不足。

先 pilot 测量方差，再冻结样本量和排除标准；工程起点每方法每任务族15–20次。优先完整方法、最强紧凑消息基线、原PushingBots／辨识增强版及充分共享参照；执行顺序随机化，失败全部保留。

视频展示同步物体运动、局部证据、消息与选择，不能用事后隐藏真值替代运行时模型输出。通用排序仅在仿真已证明端到端收益后接入实机；若网络等待抵消收益，实机采用规则排序或缓存方案，并如实报告这一工程边界。

## 9. 强基线与预算公平性

### 9.1 必须面对的对照

| 对照 | 目的 |
|---|---|
| PushingBots 原系统／同技能适配 | 区分已有恢复能力与新方法 |
| 本地参数辨识＋后验通信＋同一规划 | 检查简单物理解释是否已足够 |
| 同预算观测摘要 | 检查压缩原始证据是否足够 |
| 同预算 learned latent communication＋同一规划 | 最重要的通用消息强对照 |
| 同预算 Q／动作偏好通信 | 检查是否只需要传“做什么”，不必传后果 |
| 联合 DAF-inspired 预测＋消息接口 | 检验未来可行性近邻；保留历史输入 |
| 不展开未来消息分支的闭环 MPC | 隔离预先考虑信息价值的收益 |
| 逐机器人后果组合 | 隔离联合接触建模 |
| 充分共享完整观测／历史 | 性能参照，非信息公平竞争者 |
| 真模型／oracle | 诊断与小规模最优参照 |

无消息时，公共规则提交联合动作的版本可以评价公共信息本身；另加允许各机器人依私有观测执行的分散式策略基线，以免人为禁止所有私有反馈使用。后者策略类别不同，明确标记。

CoDreamer-style 通信可作为 learned latent 基线的设计依据；若没有完整复现，不标注为原算法结果。VerifyAC 若适配其前提可用作动作偏好／通信触发参照；本方案不声称超越其形式保证。

### 9.2 必要消融

先只做三条主轴：消息表示、是否展开未来消息分支、是否联合建模。然后分开检验特权标签和 F 辅助／候选使用。避免一次做全部笛卡尔积。

同预算包括：输入信息、训练查询与反事实标签、消息 bits 与轮次、在线候选数／模型调用，以及实际墙钟时间。固定调用量和固定墙钟预算分别报告。

对硬编码物理后验明确其额外建模知识；既报告精确后验诊断，也给数据学习的后验基线，避免一边过强或另一边被故意削弱。

### 9.3 通用先验的独立消融

| 对照 | 目的 |
|---|---|
| 无通用先验＋原搜索 | 给出主体方法独立性能 |
| 几何／规则排序＋相同世界模型 | 判断简单启发式是否足够 |
| 轻量学习排序器＋相同世界模型 | 判断通用模型是否有额外工程价值 |
| 通用模型最高排名直接执行 | 隔离物理rollout的必要性；保留同一低层保护 |
| 通用排序＋固定批量rollout | 测排序本身的价值 |
| 通用排序＋条件触发扩展 | 测分批评估的工程收益 |

模型／消息表示主消融使用统一排序器，避免把先验差异混入C1／C2证据；排序消融固定消息编码、训练数据、候选库和世界模型。分别进行固定工作量和固定端到端时间实验。排序广播、API调用、用于消息编码的全候选预测均计入，不只统计最终搜索节点。对直接执行基线也维持相同输入信息；若不给它消息，应明确它是公共信息能力诊断而非信息公平竞争者。

缓存、超时回退和候选保留比例只做必要工程消融，不扩展为新的研究主轴。

## 10. 数据、评价与创新证据

### 10.1 划分

场景家族、物体、隐藏参数配置、episode、快照分支整体分组。私有历史窗口和相邻状态不能散到不同集合。未见联合组合测试要求该组合的执行与特权标签都留出；仅未执行但有标签，应称反事实监督收益。

冻结正式测试条件和通信预算曲线，不根据测试结果挑最有利的带宽或删除不获益场景。

### 10.2 主指标

- 任务：成功率、统一累计代价、时间、无效操作与失败恢复次数。
- 信息：本地／聚合后预测的 Brier、NLL；私有预测不一致不直接作为错误。
- 决策：oracle regret、候选排序、消息前后联合动作选择变化与真实代价变化。
- 通信：每步及每episode总 bits、轮次、实际包字节；任务表现—通信成本曲线。
- 世界模型：连续后果误差、离散事件校准、未来消息分布预测与多步排序。
- 效率：仿真转移／积分步、训练墙钟、在线p50／p95时延；区分私有编码预测与公共搜索rollout。
- 通用先验：近优候选Recall@K、排序被物理证据纠正后的代价变化、模型调用费、缓存命中率、无效输出／超时回退率、全部服务与同步开销。

跨种子及场景组计算区间，正式学习实验建议至少5个种子。不能把同一模型的数千时间步当作独立重复。硬件报告原始成功数、总次数和故障类别。

### 10.3 重点主图

1. 双机器人相同公共停滞、不同局部证据、消息后不同合作策略。
2. 通信预算×信息不对称程度：何时方法有用、何时无收益。
3. O-full／O-central／O-B／O-codec／有限搜索的差距。
4. 主任务中的同预算后验、latent、Q与预测消息比较。
5. 分支规划和联合建模消融。
6. 双臂辅助仿真与移动平台实机；统一展示信息和物理作用。

## 11. 创新评估：能说什么，还缺什么

### 11.1 不单列为创新的内容

私有信念、分布式世界模型、技能抽象、未来 affordance、特权监督、限带宽通信、动作一致性、公共信息分解，以及双臂插入任务本身，均已有相关研究基础。v6新增的通用模型排序、模型替换接口、缓存与回退属于工程实现，不单列为创新；语言模型技能先验结合可执行性已有SayCan等先例[14]。

共享语义目标并不保证预测相同；可行域头不是表示上的必要条件；普通 Q／后验通信打平不能被解释为 baseline “不该成功”。

### 11.2 三项候选贡献

**C1：面向联合接触技能的动作条件化预测消息。** 在同位数和同数据下，把私有证据转为联合操作后果摘要，保留对动作选择有价值的信息。需要优于或明确互补于紧凑后验、通用 latent 和 Q消息；仅优于原始流截断不够。

**C2：遵守私有信息边界的技能级未来消息规划。** 在联合操作改变物理条件的同时，显式考虑未来局部反馈经过通信协议进入公共决策的过程。需要以同模型无分支规划对照证明决策收益；公共协调结构与动作一致性本身不算新。

**C3：从信息受限 oracle 到接触物理与实机的机制证据。** 定量区分私有信息、消息压缩、模型与搜索的限制，在移动推动及双臂支撑—操作中检验。单纯多一个 benchmark 不自动构成独立方法贡献。

上述为研究承诺候选，尚不是已建立结果。若 C1 不成立，可以保留 C2 为主线，但需重新评估与已有 belief-space planning 的差异。

### 11.3 当前新颖性强弱判断

| 维度 | 评估 |
|---|---|
| 问题重要性 | 合理，依托真实接触不确定性和信息归属 |
| 与作者前作区别 | 比集中式 v4 清楚，仍需证明超越原反馈恢复／参数辨识 |
| 组件原创性 | 低；几乎所有基础组件已有先例 |
| 方法原创性 | 尚待建立；主要押注 C1＋C2 的具体实现与机制证据 |
| 实验说服力潜力 | 较好：oracle、3D、辅助域和现成实机基础形成完整链条 |
| 最大风险 | 普通短后验就够；预测消息无优势；人为信息屏蔽；未来消息模型不可靠 |

恢复分布式后，选题更符合多机器人研究目标，但最近邻也更直接。不能把更多设定当成更高新颖性。

### 11.4 投稿定位

RA-L：若一个清晰机制在公平通信／计算预算下有稳定收益，并有可靠实机证据，是合理目标。T-RO：还需将联合预测、消息与后续规划形成有解释力的完整方法，覆盖强对照和适用边界。双臂辅助仿真增强外部适用性，不替代主方法深度，也不保证期刊层级。

研究不以证明“我们首次拥有所有属性”为目标，而以回答“为什么这些局部预测能更有效支持协作接触决策”为目标。

## 12. 实施计划与停止条件

| 阶段 | 建议投入 | 交付与验收 |
|---|---|---|
| 0：信息结构审计 | 3–5天 | 列出公共／私有传感字段、消息格式、真实硬件可获得性 |
| A：微型2D oracle | 1–2周 | O-B与O-central区分、通信无用／有用两类实例、消息成本全部计入 |
| A+：学习与强消息对照 | 2–3周 | 后验／latent／Q／预测消息，固定预算，确认是否值得继续 C1 |
| E：通用先验pilot | 完整2D闭环后3–5天起步 | 单API适配、规则回退、固定模型消融、端到端盈亏；收益不足则关闭 |
| B：主3D仿真 | 4–6周 | B1+B2、接触后果和未来消息校准、同预算主结果 |
| D：移动实机 | 仿真稳定后3–6周 | 真实局部反馈、最强对照、重复复位实验 |
| C：双臂辅助仿真 | 主方法稳定后2–4周 | 一个支撑—插入任务、核心对照、未见物理组合 |

时间以已有资产可复用为前提。优先级为主仿真和实机，双臂不阻塞主线。

停止／转向条件：

1. 公共信息足以决策：该场景不能证明私有信息价值，不人为删除现实可见信息后宣称天然受限。
2. 极短后验在各预算均足够：收缩消息创新，研究其余机制或更真实的隐藏结构。
3. 真模型未来消息分支无收益：不继续训练复杂分支模型来“证明”信息价值。
4. 学习模型无法接近真模型参照：优先改数据、概率建模和传感，不直接加大网络。
5. 双臂低层控制不稳定：暂停辅助实验，避免把控制问题误归为分布式规划失败。
6. 通用排序未优于规则／轻量排序，或服务开销抵消rollout节省：关闭或仅保留离线诊断，不为其增加候选冗余。
7. 排序持续漏掉准备／探测动作：扩大保留集合、调整公共描述，仍无改善则退回原搜索；不修改任务奖励来迁就先验。

### 首轮代码接口

`private_sensor` 严格限制输入；`local_belief` 保存私有历史；`local_skill_model` 输出候选后果；`message_codec` 序列化并计bits；`public_transcript` 记录唯一公共信息；`public_model` 预测未来公共结果和消息；`replicated_planner` 在同一记录上提交同一动作；`oracle_protocol` 枚举受限策略；`eval` 记录分组统计和泄漏检查。

v6增加 `candidate_generator`（合法共同候选）、`option_prior`（可替换排序）、`prior_cache`（版本化缓存）、`prior_commit`（公共排序一致提交）、`budgeted_search`（分批扩展与探索保留）、`api_telemetry`（服务耗时与成本）。这些接口在排序关闭时必须能直接走规则路径。

首先实现通信／策略边界与精确案例，再做神经模型。不要让开发时单进程运行掩盖了跨 agent 直接读内存的非法信息通道。

## Q.  这版方案确实已经可以执行。但如果我们目标是TRO的话，你觉得我们最有可能需要在那个部分做出系统性或者基础性创新？现在的方案至少可以作为一种基线吧，由这个基线有可能衍生出那些结果可能性以及方法演化分支？

## A. **是的，当前方案可以作为一套完整的研究基线。若目标是 T-RO，我认为最值得深入的部分是：如何把分散的接触证据转化为可信的联合操作后果预测，并据此规划那些会改变后续接触条件和信息状态的协作动作。**

这条线同时连接你的 PushingBots 积累、世界模型和多机器人特有的问题。通用先验可以帮助系统跑得更快，但论文的主要深度应来自上述机制。

我也想调整此前方案的一个侧重点：**v5/v6 把“预测消息是否优于其他消息”放得比较靠前，作为初步实验合理；但最终若主要结论只是同样 bits 下消息压缩更好，可能会偏离你希望研究的世界模型与接触规划。**通信应服务于物理决策问题，其重要程度由实验决定。

下面是我的研究判断与待验证假设，不是对新颖性或录用的保证。

**1. 最值得争取的系统性创新：建立“协作如何改变未来”的预测与规划方法。**

目前基线已经能够问：

> 给定当前信念，双方执行这个联合 option，会发生什么？

更深入一步，应该能够回答：

> A 现在采取什么动作，能够让 B 接下来更可靠地执行某个技能？这种改善来自改变物理条件，还是获得了新信息？

例如，A 的动作可能产生三种不同作用：

| A 的作用         | 物理／信息变化               | 对后续 B 的影响              |
| ---------------- | ---------------------------- | ---------------------------- |
| 稳定或调整物体   | 支撑状态、姿态、接触约束改变 | 原本容易卡滞的插入变得可行   |
| 短推或轻微加载   | 暴露滑移、阻力或约束的证据   | 团队能够选择正确恢复动作     |
| 改变接触同时探测 | 物理条件和信念同时变化       | 需要权衡立即推进、准备与辨识 |

**这里最有价值的模型能力，是预测一个协作动作如何改变后续联合技能的结果分布。**它比单步位姿预测更贴近接触规划，也比“这个动作成功率是多少”更能解释合作的必要性。

初版不必增加一个人为的“使能奖励”。继续使用统一任务代价，让准备与辨识动作的价值通过后续预测自然体现。先验证模型是否真的捕获了这种作用，再考虑如何形成更好的结构表示或搜索算法。

如果沿这条路线做深，系统性贡献可以包括：

- 一个表达支撑、约束、接触转换及技能结果的模型；
- 一套利用该模型规划准备—辨识—执行序列的方法；
- 从精确 oracle、连续物理仿真到实机的机制验证。

这比单独增加模型大小或增加场景，更可能形成一篇完整的方法论文。

**2. 最有希望形成基础性创新：明确“联合决策到底需要保留什么信息”。**

私有历史非常长，但规划未必需要重建整个真实世界。它可能只需要区分那些会导致不同最优协作方式的物理假设。

例如，两组摩擦和质量参数虽然不同，但在当前技能库下，所有候选的结果与最佳决策都近似相同，那么规划未必需要区分它们。反过来，两个几乎相同的物体位姿，可能对应“支撑稳定”和“即将滑移”，这一区别必须保留。

因此，可以研究：

> **什么样的局部信念表示，足以支持给定技能集合和规划时域内的联合决策？**

这里的“足够”必须限定任务、技能库与时域；不能仅凭当前动作排序相同，就认为它们对未来也等价。未来观测和消息可能让两种状态产生不同策略。

这条路线可以产生两类成果：

- **方法成果：**学习一种保留联合技能后果及后续信息价值的信念表示，而不是优先优化全部状态的重构。
- **理论成果：**在有限状态／技能条件下，将表示误差、模型误差与规划损失联系起来，明确哪些压缩不会改变决策，哪些误差会使准备或探测被遗漏。

如果理论能直接指导模型结构、训练目标或搜索容错，它会很有价值。若只是附上一条依赖很强假设、无法指导实验的误差界，则不值得为它牺牲主要工作。

**我的排序是：先争取上述系统性创新，再从 oracle 中寻找有实际作用的基础性结论。**不必一开始同时承担两条完整路线。

**3. 当前基线可能产生哪些结果，以及如何据此演化？**

基线最大的价值，是把不同瓶颈拆开。以下几种结果都能决定后续路线：

| 基线结果                                                     | 说明什么                               | 值得发展的方向                               |
| ------------------------------------------------------------ | -------------------------------------- | -------------------------------------------- |
| 很短的物理参数后验就能达到充分共享的表现                     | 隐藏结构较简单，复杂消息没有必要       | 保留简单通信，集中研究接触辨识与信念空间规划 |
| 单步预测很准，但多步协作经常失败                             | 模型未正确描述接触转换或技能间依赖     | **接触模式与技能后果的结构化世界模型**       |
| 真模型显式考虑未来反馈显著更好，学习模型却没有收益           | 信息价值存在，但未来观测／消息预测不足 | **面向主动辨识的世界模型与分支规划**         |
| 各机器人预测分别合理，汇总后却过度自信或选错动作             | 私有证据存在相关性，聚合没有处理好     | **保留相关性与不确定性的分布式信念融合**     |
| 后果预测误差不低，但动作选择很好；另一些低误差模型反而决策差 | 普通预测指标与任务需求错位             | **面向联合决策的表示与训练目标**             |
| 有限搜索差距很大，增加预算即可明显改善                       | 主要瓶颈是计算而非模型                 | 利用预测不确定性和决策影响分配搜索预算       |
| 公共观测已足够，局部证据几乎不改变决策                       | 当前场景不能支持私有信念主张           | 更换有真实信息不对称的任务，或收缩分布式主张 |

这里我最看好的两条主分支是：

**A. 接触结构驱动的技能世界模型。**适合出现“单步还行、多步失效”的情况，也最能发挥你已有的混合模式与接触规划经验。关键是证明结构改善了未见接触组合的预测与规划，而不只是手工规则让训练任务更容易。

**B. 面向联合决策的信念学习与主动辨识。**适合出现“预测指标和决策质量不一致”或“真模型信息分支有价值”的情况。它更接近基础性问题，但训练和验证难度也更高。

这两条可以最终汇合，但前期最好根据基线证据选择主攻方向。

**4. 我会特别关注一个可能很有价值的结果：预测分歧究竟意味着什么。**

两台机器人对同一联合 option 给出不同预测，可能有完全不同的原因：

- 一方拥有另一方没有的有效证据；
- 两侧证据互补，单独看都不足；
- 某个模型遇到了分布外状态；
- 两侧只是因信息不足而保持不同假设。

因此，**不能把分歧一律当成需要消除的误差，也不能把分歧大一律解释成应该探测。**

如果能区分这些原因，系统就能更合理地决定：继续执行、交换证据、增加模型评估，还是做一次实际接触试探。这有可能演化成较强的方法，但建议作为前两条主线中自然产生的研究问题，暂时不要再独立增加一整套模块。

**5. 为了让基线真正引出论文，第一轮应优先做“瓶颈替换实验”。**

我建议先回答四个问题：

1. **把学习世界模型换成真模型，能改善多少？**
   差距大，优先解决模型；差距小，先别继续扩大网络。
2. **把有限搜索换成精确或更充分搜索，能改善多少？**
   差距大，才值得把大量精力投入搜索预算分配与上层先验。
3. **把当前消息换成完整历史或精确紧凑后验，能改善多少？**
   区分信息缺失、消息表示与融合错误。
4. **让规划器真正考虑未来反馈，能改善多少？**
   在真模型下先验证辨识价值，避免训练一个实际上没必要的复杂模型。

这些替换实验应保持其余条件一致，并补上少量交叉组合，因为模型、消息与搜索误差会相互影响。它们比过早完成大量模块消融，更能决定研究方向。

**我对当前方案的最终定位是：它已经足够成为“发现核心困难的实验底座”，但尚未决定最终论文应以哪项机制为中心。**若目标是 T-RO，我最建议押注的表述是：

> **学习能够保留私有接触证据、预测协作如何改变后续技能结果的世界模型，并利用它规划准备、辨识与执行。**

先用基线判断困难主要落在“接触结构”“决策相关信念”还是“未来信息规划”，再把其中一项做深。这样最终方法会由可重复的失败现象推动演化，而不会随着组件不断增加而失去中心。

# 14. 实验后的方案修订（v6.1）

本节写于 2D 阶段跑完之后。所有数字都来自可复现的运行，细节在 `results.md`、
`docs/CoImagine_2D_最终结论_v1.md` 和 `docs/CoImagine_2D_世界模型_v1.md`。
**凡与本节冲突处，以本节为准。**

## 14.1 已经被实验定下来的四件事，以及它们改动了什么

| 结论 | 依据（实测） | 对方案的改动 |
|---|---|---|
| **世界模型必须显式预测隐藏状态的转移** | 对被锁物体成功执行"释放"，**观测向量与执行前逐位相同**；60 个场景里 24 个被锁。而六个候选动作在真值上平均只产生 **1.43** 种不同的下一状态（73% 的状态下六者完全相同） | **§3.1 增加硬性要求**：预测目标必须包含"这一步改变了哪个不可观测量"，不能只拟合可观测量 |
| **"多步可行性损失"不划算** | 把训练数据量对齐后，多步训练的模型从未占优；"更深的状态更难"这个前提也不成立（浅层模型准确率反而随深度上升） | **从 §3.1 移除**该损失；"多个想象步"本身不构成收益 |
| **消息的价值有前提** | 消息价值**恰好等于它所替代的那次实验**；只有在队友**必需**（不是仅仅更便宜）时才有价值。必需测台里 1 比特让学到的模型从随机水平（0.500）到**精确最优**（1.000、零后悔）；而格子世界的动作集让队友不再必需，同一通道**未能移植** | **§3.2 增加前提条款**：先证明"队友不可替代"，再谈消息表示；C1 的对照设计要围绕这个前提 |
| **第一主线应改为多步保真度 + 防止模型利用** | 规划器深度从 2 增到 4 再到 6，闭环成功率 **0.142 → 0.050 → 0.008**，单调变差 | **§12 的停止条件增加一条**：不确定性机制就位之前不再加深搜索。新增 §14.2 |

**一句话概括这四条的共同教训**：在接触任务里，**"看得见的东西"不足以支撑决策**。
必须表示和预测的是不可观测量，而一旦开始预测它们，就必须同时给出"我有多确定"。

## 14.2 新增第一主线：多步保真度与模型利用的防治

### 14.2.1 现象

同一批场景、同一个起点、120 个回合：

| 规划器 | 成功率 | 每次成功代价 |
|---|---|---|
| 两层前瞻 | **0.142** | **11.87** |
| 束搜索 深度 4 | 0.050 | 32.95 |
| 束搜索 深度 6 | **0.008** | **160.70** |
| 精确信念空间参照（同等信息） | 0.392 | 4.72 |
| 全知 oracle | 0.425 | 2.86 |

**搜索越深越差。** 这不是"搜索没做好"——排查过程见下。

### 14.2.2 为什么这不是实现错误（排查记录，值得保留）

按顺序排除了三种解释：

1. **规划器本身选错了吗？** 没有。在单个决策点上，每个深度都正确选出"释放"，
   而且清楚地知道什么时候**不该**释放（126 个"释放必然失败"的场景里一次都没试）。
2. **转移模型错了吗？** 没有。一次"协推"被预测把箱子从距离 5 送到距离 0——
   **而真值也确实是距离 0**（箱子 2×2，目标区在第 4、5 列，移动一格就全进去了）。
3. **估值定义错了吗？** 错了一个，已修：失败代价原来是"只要期望距离 > 0 就收全额"，
   于是"有 79% 概率已经完成"的分支照样付满额罚款，所有分支看起来一样糟，一个免费的"等待"就赢了。
   改成**按失败概率加权**后，两层前瞻从 0.133 提到 0.142。

排除了这些之后，剩下的解释是领域内的经典现象：

> **在一个不完美的学习模型上，搜索得越深，就越能"挖掘"模型的误差。**
> 深度搜索会主动找到那些**模型以为很好、现实里并不好**的动作序列。
> 两层前瞻反而最好，恰恰因为它看不到那么远，挖不出这些错误。

### 14.2.3 两种不确定性必须分开（这是本节的核心）

这是本轮实验最重要的概念区分，直接决定下一步该做什么：

| | **隐藏状态的不确定性** | **模型自身的不确定性** |
|---|---|---|
| 是什么 | "箱子可能在 A 格也可能是 B 格"、"它可能被锁也可能没锁" | "**我这条动力学预测本身可能是错的**" |
| 现在的模型有没有表达 | **有，而且是显式的**：16 种参数上的概率分布、36 个格子上的分布 | **完全没有** |
| 表现如何 | 实测良好：自己抓地力一次动作后准确率 1.00；不该知道的量正确地停在先验附近；**"错且自信"的比例 ≤ 0.008** | 无从谈起 |
| 规划器怎么用它 | 正常地边缘化、分支、更新信念 | 只能把预测当真值，于是**被搜索利用** |

**关键判断：项目的模型在第一种不确定性上已经做得很好，缺的是第二种。**
把这两种混为一谈，就会误以为"模型预测不准"是同一个问题——其实前者是**表示**问题（已解决），
后者是**元认知**问题（完全没做）。

### 14.2.4 为什么普通 MLP 表达不了第二种不确定性（回答"是不是 MLP 做不到"）

**一半对，一半不对。** 需要分清"架构"和"训练目标"：

- **不对的一半：加一个方差头没用，但也**不需要改架构**。**
  让 MLP 额外输出一个方差、用高斯似然训练，学到的是**偶然不确定性**（数据本身的噪声），
  不是"我这个模型没见过这种情况"。而且在分布外，这种方差头的标定会崩，
  **规划器反而会去利用"预测方差小"的区域**——问题原样保留。
- **对的一半：一个确定性的点预测器，在结构上就没有表达"我不知道"的接口。**
  它输出一个数，没有"这个数可能错"的位置可放。而且它还有第二个缺陷：
  单个网络只能给**单峰**预测，表达不了"箱子要么在这、要么在那"这种多模态——
  这一点我们的 factored 模型用显式分布部分解决了，但那只覆盖隐藏状态。

**真正能给出模型不确定性的，按代价从低到高：**

| 方案 | 原理 | 代价 | 风险 |
|---|---|---|---|
| **同架构多 seed 集成**（推荐先做） | 成员分歧 ≈ 认知不确定性 | 训练 k 倍（k=5 即可） | 成员共享数据与架构，误差并不独立，分歧会低估真实不确定性 |
| **自生成 rollout 数据**（推荐并行做） | 规划器实际访问的状态和训练集不一样（分布漂移）——把规划器走过状态的回放数据加进训练 | 需要实现数据回流 | 需要防止"模型自己教自己"的退化 |
| **悲观打分** | 用集成的**下分位数**（而不是均值）作为想象值 | 几乎为零 | 保守度需要调，过保守会退回"等待"（我们已经在冷启动实验里见过这个失败模式） |
| **随机潜变量 / 循环状态空间模型** | 潜状态本身是分布，转移是条件分布 | 大（换架构 + 换训练） | 训练更难，需要重做全部验证 |

**顺序建议：先做前两项，因为它们不改架构、能立刻验证；第三项作为打分层；第四项留到 2D 物理阶段。**

### 14.2.5 这个项目独有的优势：**精确参照可以当"不确定性的量尺"**

这是我认为最值得写进论文的一点，而且是别的设置给不了的：

> 我们的 gridworld 里有一个**精确的信念空间规划器**，它与学习模型**信息相同**。
> 于是可以做到三件在 2D/3D 物理里做不到的事：

1. **把闭环差距分解成"模型误差"与"搜索误差"。** 同一批场景上跑：精确参照、学到的模型 + 同样深度的搜索。
   差距里哪一部分来自模型、哪一部分来自搜索，是可以算出来的。
2. **检验不确定性估计本身是否标定。** 集成成员的分歧，与"实际预测误差"的相关性可以直接测量
   （我们已经有现成的多步准确率探针）。
3. **直接量化"模型利用"。** 在学到的模型上算出"它以为的最优开环计划"的价值，
   再拿真实执行结果去比。**两者的差就是被利用掉的那部分。** 这是一个廉价、直接、可复现的指标。

**换句话说：gridworld 不是我们的研究贡献，它是我们的"仪器"。**
它让我们在还能验证的时候，把不确定性机制验好；等到 2D/3D 物理阶段没有精确参照了，
这套机制才是可信的。这本身就是一条可以写的方法论贡献。

### 14.2.6 这个方向的诚实风险

- **集成分歧只是代理，不是真值。** 成员共享数据和架构，误差相关，分歧会低估真实不确定性。
  缓解办法：不同初始化 + 不同数据子采样 + 不同超参；
  并且**用 14.2.5 的第 2 条去实测它到底有没有标定**，而不是假设它标定。
- **悲观会压死任务表现。** 我们的冷启动实验已经见过这个失败：
  一步代价最优的规则选择放弃，而放弃不产生任何证据，于是永远学不到。
  **保守度必须和探索一起设计**，不能单独调。
- **多步保真度可能撞上表示能力的上限。** 4 步位置准确率 0.833、6 步更差；
  如果加了集成和自生成数据仍然上不去，那就说明需要换表示（随机潜变量），
  而那意味着 2D 物理阶段要重做一遍验证。

## 14.3 下一轮的可执行实验阶梯（建议按序，每步都能单独证伪）

| # | 实验 | 判据（达不到就不往下走） |
|---|---|---|
| 1 | 训练 **5 个不同 seed** 的 factored 模型，测量成员分歧与真实多步误差的**相关性** | 分歧与误差显著正相关（否则集成分歧不是可用的代理） |
| 2 | 用同样 5 个模型做**悲观打分**（均值 − β·标准差），扫 β，跑深度 2/4/6 的闭环 | 深度不再单调变差；且浅层不退化 |
| 3 | **自生成 rollout 数据**回流训练，再测多步准确率 | 4 步位置准确率从 0.833 明显上升 |
| 4 | 量化**模型利用**：想象出的最优计划价值 vs 真实执行价值之差 | 该差额随 β 增大而缩小 |
| 5 | 把 1–4 的结果搬到 2D 物理仿真 | 机制仍然成立（那时没有精确参照，只能靠 1–4 建立的可信度） |

**第 1 步是关键的证伪点。** 如果集成分歧与误差不相关，那么整个"用不确定性防利用"的路线
在本任务上就不成立，应该转向"缩短时域 + 学一个终端价值函数"这条替代路线。

## 14.4 对 §10.2 主指标的修订

原来的指标偏重"预测准不准"。本轮实验表明**有几类量必须单独报，否则会看错**：

| 新增指标 | 为什么必须报 |
|---|---|
| **隐藏状态转移准确率**（例：`P(解开 \| 释放)` 在"抓得住/打滑"两种条件下的值） | 只看可观测量会完全漏掉准备动作；这是本轮最重要的一条 |
| **"错且自信"的比例**（错且 p > 0.8） | 第一版这个数是 18%–25%，修好后 ≤ 0.008。**只看平均准确率看不出这个差别** |
| **分支可分性，以及它的真值对照** | "六个分支画得一样"可能是模型无能，**也可能是世界本来如此**（本任务真值只有 1.43 种）。不报真值对照就会误判 |
| **规划深度扫描**（成功率 vs 深度） | "更深的搜索更好"是被本轮实验证伪的假设，必须每次都扫 |
| **每次成功代价**，而不只是成功率 | 本任务里两者**分离**：成功率与随机持平，但每次成功代价只有随机的 1/3。只报一个会得出相反结论 |
| **集成分歧 vs 实际误差的标定曲线** | 不确定性机制能不能用，全看这条 |

另外把 §10.2 原有的"世界模型：连续后果误差、离散事件校准"具体化：
**离散事件的校准要按隐藏状态分层报**，不能只报总体。

## 14.5 对 §11 创新评估的修订

- **C1（动作条件化预测消息）需要收窄。** 实测说明它的价值有前提（队友必需），
  而且价值上限就是"它替代的那一次实验"。原方案把它当主押注，现在看**前提的建立比表示的创新更关键**：
  如果场景里队友不是必需的，再好的消息表示也测不出收益（我们已经实测到这一点：同一通道在必需测台里
  从随机到最优，在非必需场景里价值为零）。
- **C2（未来消息规划）不受影响**，仍然成立。
- **建议新增一条候选贡献 C4**：

> **C4：用精确参照作为"不确定性的量尺"，测量并修复学习接触世界模型中的模型利用。**
> 在同等信息下存在精确信念空间规划器的设置里，把闭环差距分解为模型误差与搜索误差；
> 直接量化"想象最优 vs 真实执行"的差（模型利用）；并在还能验证的阶段，
> 检验不确定性代理是否标定。给出"什么时候深搜有害、需要什么机制才能让它无害"的机制性结论。

这条的说服力来源与本项目已有结论完全一致，而且它**天然跨越 2D/3D**：
在 2D 建立并验证量尺，在 3D 物理里使用它。

## 14.6 对 §12 停止条件的修订

在原有停止条件之外，增加三条**硬门**：

1. **不确定性机制就位之前，不再加深搜索。** 本轮已实测：深度 2 → 4 → 6 是 0.142 → 0.050 → 0.008。
2. **多步保真度是升级到 2D 物理的前置条件。** 建议门槛：4 步位置准确率从当前的 0.833
   提到 0.95 以上，且深度扫描不再单调变差。达不到就不要进 2D。
3. **任何新的预测损失，都必须先做"等数据量对照"**（把对照组的训练样本数补齐）。
   否则会把数据量效应误读成方法收益——本项目已经犯过一次，报告里记着。

## 14.7 2D/3D 阶段必须继承的设计约束

从本轮的七个"损失看着健康、行为完全错误"的 bug 里提炼出的、**与任务无关**的工程约束：

1. **训练与推断必须喂同一种东西。** 我们在原始数值上训练、用处理后的概率查询，
   训练损失 0.005 而推断完全不对。**特征/数值的语义必须在两边一致。**
2. **凡是条件于某个量的模型，就要在该量的每种取值上求值再混合**，不能把期望当输入。
   否则就是分布外输入（我们因此得到过"自信的 0"，而真值是 1.000）。
3. **隐藏量靠转移往前带，不能每步从观测重新读。** 症状不是报错，而是**规划器莫名其妙地不动**。
   这一条在 2D 物理阶段会更关键：接触状态（是否滑移、接触点在哪）同样部分不可观测。
4. **批量目标的形状要对齐。** `(n,)` 与 `(n,1)` 相减会广播成 `(n,n)`，损失值荒谬但不报错。
5. **校验方式是拿模型输出和模拟器真值逐项对照**（似然表、逐场景的转移预测），
   而不是看训练曲线。**这七个 bug 没有一个能被损失曲线发现。**
