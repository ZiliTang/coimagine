# IMPLEMENTATION_FIX — 实现审查发现的问题与修正

评审发现了训练路径中的确定性错误。**逐条复现、确认、修正，并重训。** 本文记录复现证据、
根因、修正内容与影响范围。

## 0. 结论先行

报告里以下三条**不能作为研究结论**，已撤回并标注"待修正"：

1. "历史窗口优于单帧"
2. "Transformer 不如历史 MLP"
3. "数据增加 32 倍仍无改善（已饱和）"

原因：第 1、2 条比较的对象中，**MLP-current 与 Transformer-history 在训练时根本没有读到有效输入**；
第 3 条依赖的实现里还有时间标签、几何标签定义、基线 mask 与验证集抽样四处问题。
修正后**已重训全部主对照**，结论以 `REPORT.md` 的修正版数字为准。

## 1. 有效 token 读出错误（最严重，影响架构比较）

**现象**：同一个 root 的八个动作，在 t=0 时
MLP-current 的终态 r0 中点 x 全部为 **0.433343 m**、Transformer-history 全部为 **0.430628 m**，
只有 MLP-history 随动作变化。

**根因**：`dataset.build_example` 把真实 token 放在窗口**右侧**（左侧补齐），但 `models.py` 用

```python
index = valid.sum() - 1     # 只对"右侧补齐"成立
```

寻找最后一个有效 token。左补齐下这个索引落在补齐区：

| 情况 | 真实当前 token 位置 | 旧代码读取位置 |
|---|---:|---:|
| t=0（只有一个观测） | 32 | **0（补齐，全零）** |
| 已有六个观测 | 32 | **5（补齐）** |
| 窗口填满 | 32 | 32（恰好正确） |

MLP-current 还额外固定从位置 0 读起始锚点，短窗口下同样读错。因此 **t=0 时这两个模型的输入
是整段零**，输出与命令、观测全部无关；MLP-history 因为展平读取整个窗口而没有这个问题。

**复现命令**（用包内检查点，不需要训练）见 `tests/test_night_sequence_v1.py::test_trained_checkpoints_respond_to_the_command_at_t0`。

**修正**：新增 `last_valid_index()` / `first_valid_index()`，**从 mask 本身取索引**，
不再假设补齐方向；MLP-current 的锚点取第一个真实 slot，current 取最后一个真实 slot。
修正后同一检查（32 root 小数据重训）：

| 模型 | 修正前不同取值数 | 修正后 |
|---|---:|---:|
| MLP-current | **1/8** | **8/8** |
| MLP-history | 8/8 | 8/8 |
| Transformer-history | **1/8** | **8/8** |

**新增回归检查**（评审要求）：`test_changing_a_real_observation_or_the_command_changes_the_output`
——改变**真实有效观测**或**命令**必须能改变输出；只测"改变 padding 不影响输出"是不够的。
该测试对三种架构同时生效。

## 2. 退出时刻 T 多算一个控制周期

**现象**：包内 3 个序列分片共 96 条执行中，最后一条真实观测与单独保存的终态观测**完全相同**，
但 `T_exit` 比它晚 0.05 s（例：最后观测 3.80 s，`T_exit` 写成 3.85 s）。

**根因**：阶段机可以在**施力之前** break，因此退出周期**没有推进物理**。
`T_exit = steps * dt` 把"采样次数"（含 O0 的观测条数）当成了"物理推进次数"，多算一个周期。

**修正**（两层）：
- 执行器新增 `physics_steps`，在每次 `env.step_control` 后自增，`T_exit = physics_steps * dt`；
  对**所有**退出路径都成立，不再从观测条数推断。
- 已有序列**不需要重新仿真**：若退出周期未推进物理，则单独采样的终态观测必然与最后一条观测
  **逐位相同**。该不变量在**全部 4288 个分片、137216 条序列**上验证通过（最大差 **0.000e+00**），
  另有 40 条重新执行确认 `physics_steps == steps - 1`、`T_exit == T_last_sensed`。
  `fix_time_labels.py` 据此重写 `T_exit` / `duration_seconds` / `truth_steps`。

**影响**：总时长与剩余时长标签（`terminal_remaining`）此前的系统性偏移已消除。

## 3. 几何标签定义被悄悄改了

**现象**：第 4 轮"片段中点"是**拟合线段两端点的中点**；第 5 轮实际用的是**扫描点的平均位置**。
两者通常相差几毫米，样本中最大约 1.3 cm。

**根因**：第 5 轮的 `windows.py` 读的是 `patch_midpoint_robot`（扫描点均值），
而合同 §4.2 的措辞是"可见拟合线段两端点中点"。

**修正**：改回**拟合线段两端点中点**（端点一直有保存，因此无需重新仿真，只重建 token），
并在 `windows.py` 写明 `MIDPOINT_DEFINITION`；扫描点均值作为独立诊断字段保留，
两者不会再被混用。

## 4. P1 统计没有使用可见性 mask

**根因**：`GroupedStatistics._summarise` 对连续量直接取整体中位数，不可见片段那批
**零填充**的几何值也进入统计，把它往 0 拉；而合同要求"统计时遵守监督 mask"。

**修正**：新增 `fast_masks`，与模型使用**完全相同**的 mask；连续量改为**逐列在受监督行上取中位数**，
某列完全无监督时回退到全局中位数而不是 0；法向改为**在受监督条目上**取单位向量均值再归一化。

## 5. 验证集每次抽样都在变

**根因**：`evaluate_loss` 每次验证用 `np.random.default_rng(10_000 + update)` 重新抽验证窗口，
最佳 checkpoint 实际在**不同数据**上比较。

**修正**：验证子集在训练开始时**抽一次**并固定复用；`evaluate_loss` 的 `fixed=` 参数使这一点不可能
被无意改回。

## 6. 报告把混合样本指标标成了执行中指标

**现象**：报告"执行中"表中"执行中终态"一列填的是 `all`（含 t=0）的 0.0669 m，
而真正的执行中分组值是 0.0434 m。列名与内容不符。

**修正**：报告生成器改为分别给出 `regime=in_execution` 分组值、固定 Δt 下一步值**与**明确标注的
"全样本（含 t=0）"值，三列分开命名，不再混用。
