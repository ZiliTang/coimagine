# CoImagine 2D 世界模型链路（第一版）

这份文档报告 **编码器 → 潜转移 → 多步想象 → 规划** 这条链路的实现与测量结果。
所有数字都来自实际运行，脚本入口写在最后一节。

## 一、这条链路现在是什么

之前的实现只有一个"从手工特征预测单步结果"的多头 MLP，**没有编码器、没有转移模型、没有想象展开**。
这一版把它们补上了：

| 组件 | 实现 |
|---|---|
| **观测** | 机器人自己的扫描平面（6×6×5 one-hot，180 维）+ 自身坐标（2）+ 自身反馈直方图（4）+ 公共事件直方图（2）= 188 维。没有特权输入 |
| **编码器** | 188 → 96 → 32，输出**潜向量**（线性输出，避免 ReLU 把潜空间压死） |
| **潜转移** | `[潜向量, 动作 one-hot]` → 96 → 32。**这就是能在潜空间里往前推演的东西** |
| **解码头** | 从潜向量读出：下一观测（188）、物体位置（36 类）、接触物理（16 类）、动作代价（1）、物体是否移动（1） |
| **监督** | 物体位置与接触物理用**真值**监督（特权解码头），只在训练时使用，**不是输入** |
| **训练目标** | **多步 rollout 损失**：潜向量连续经过转移多次，每一步的解码头都算损失。另有一项把想象的潜向量拉向"真实下一观测的编码"（停止梯度） |
| **对比模型** | 直接预测下一观测的版本（无瓶颈），同一份数据、同一预算、同一监督 |
| **规划器** | 用**学到的模型**做两步想象给动作打分，**前瞻里完全不碰模拟器**；模拟器只负责执行 |
| **自动微分** | 手写的反向传播引擎，每一个算子和每一步展开都用有限差分校验过（最差相对误差 1e-7） |

## 二、链路真的跑通了（先说结论）

跑通的意思是：给定一个真实决策点，模型对**每个候选动作**都想象出一个下一状态，据此打分，
选出动作，交给模拟器执行，然后继续。上面的分支图就是这个过程的快照。

**但是：这条链路现在还不能用来做决策。** 下面的测量说明原因，而且原因很具体。

## 三、测量结果

### 1. 想象随深度衰减：潜模型明显更好

从真实观测出发想象 4 步，与模拟器实际发生的对比：

| 模型 | 第 1 步 | 第 2 步 | 第 3 步 | 第 4 步 |
|---|---|---|---|---|
| 潜模型 | 0.0098 | 0.0153 | 0.0230 | 0.0306 |
| 直接预测 | 0.0864 | 0.0839 | 0.0860 | 0.0916 |
| **"什么都不变"基线** | **0.0017** | **0.0053** | 0.0139 | 0.0180 |
| 模拟器（自检） | 0.0000 | 0.0000 | 0.0000 | 0.0000 |

**诚实的话：在原始观测误差上，"照抄当前观测"比两个学到的模型都好。** 原因是观测里绝大部分格子是静止的
（墙、空地和看不到的地方），所以这个指标被平凡内容主导，**不能**单独用来判断动力学学得好不好。

### 2. 规划器真正读的量：物体位置

| 模型 | 位置@1 | 位置@2 | 位置@3 | 位置@4 |
|---|---|---|---|---|
| 潜模型 | 0.976 | 0.952 | **0.857** | **0.833** |
| 直接预测 | 0.952 | 0.810 | 0.571 | **0.405** |
| 随机水平 | 0.028 | 0.028 | 0.028 | 0.028 |
| 模拟器 | 1.000 | 1.000 | 1.000 | 1.000 |

**这是这一版最干净的正向结果：潜瓶颈让物体位置在 4 步想象后仍有 83% 准确率，而直接预测塌到 41%。**
这正是潜空间应该带来的好处——它阻断了"把预测喂回输入"造成的误差复合。

### 3. 但它对动作几乎不敏感——这就是不能用的原因

从同一个状态出发，对 6 个候选动作分别想象，看它给出几个**不同**的下一位置：

| 模型 | 6 个分支里给出几个不同位置 | 位置准确率 | 分支熵（均匀=3.58） | 想象误差 | "不变"误差 |
|---|---|---|---|---|---|
| 潜模型 | **1.14 / 6** | 0.884 | 0.17 | 0.0206 | 0.0066 |
| 潜模型（动力学加权） | 1.52 / 6 | 0.792 | 0.34 | 0.0623 | 0.0066 |
| 直接预测 | **1.01 / 6** | 0.884 | 0.38 | 0.0934 | 0.0066 |

**模型在 86%（潜）到 99%（直接）的情况下，对六个动作给出完全相同的下一位置。**
分支图把这件事画得很直白：六个面板里有四个**像素级相同**。

也就是说：**它学成了一个状态估计器，而不是动力学模型。** 它知道物体在哪，但不知道动作会把物体怎么样。
规划器需要靠"动作的后果"来排序，而它对后果几乎不区分——这直接解释了下面的闭环失败。

为什么会这样：训练数据里 **91% 的动作根本不会移动物体**（物体的移动率是 8.5%），
所以损失最小化的答案就是"不管做什么，物体都待在原地"。

### 4. 闭环：一个必须先修的 bug，以及修完之后的真实差距

**先修 bug。** 最初的两步前瞻是这样写的：先想象第一步，**把想象出的观测解码出来，
再拿这个解码结果重新编码**去想象第二步。这对潜模型是自毁——它把瓶颈扔掉了，
用自己模糊的预测当输入。修法是让前瞻**在潜空间里继续**（`continue_from`）。

修之前 / 修之后（40 回合，含 2 步前导）：

| 规划器 | 成功率 | 每次成功代价 |
|---|---|---|
| 学到的模型（潜，**解码再编码**） | 0.050 | 45.70 |
| 学到的模型（潜，**潜空间延续**） | **0.125** | **14.40** |

**成功率提高 2.5 倍，每次成功代价降到三分之一**——这本身说明潜空间必须被延续而不是被解码再编码。

修完之后，120 个回合：

| 规划器 | 成功率 | 平均代价 | 每次成功代价 |
|---|---|---|---|
| 学到的模型（潜） | 0.125 | **1.897** | **15.17** |
| 永远协推 | 0.167 | 6.917 | 41.50 |
| 随机 | **0.200** | 5.412 | 27.06 |

**结果是有两面性的，两面都要说：**

- **它每次成功最便宜（15.17 对 27.06 / 41.50）**——成功的时候它花的代价最少。
- **但它成功得最少（0.125）**，而且平均代价只有 1.90，说明它**很早就放弃**。

也就是说，它是一个**保守**的规划器：不确定就不做。这和此前几轮反复出现的"冷启动下代价最优
规则选择放弃"是同一个现象。它和上一节的诊断也一致：一个对动作不够敏感的模型，
用它的想象排序排不出有效动作，于是倾向于停在廉价的中性动作上。

**所以：闭环能跑通，动作链是连贯的（下面展示的回放里它先 `release` 解开物体、再连推三下进目标区），
但成功率还低于随机。** 瓶颈仍然是动作条件化。

### 4b. 重要更正：这个任务里，六个动作**本来**大多没有可见差别

上一节说"模型对动作不敏感"，这个说法**被自己的对照实验推翻了，我说重了**。
把六个候选动作**真的在模拟器里跑一遍**，数它们产生几种不同的下一状态（只比较世界栅格，
不含会每步都变的反馈/事件计数）：

| | 六个动作真正产生几种不同的下一状态 |
|---|---|
| **模拟器真值** | **1.43**（117 个状态里，85 个状态六种动作**完全相同**，即 73%） |
| 学到的模型想象 | 1.14 |

**所以模型只少区分了 0.3 种，不是少区分了 4.9 种。**"六个面板四个像素级相同"不是模型的失败，
**那就是世界的真相**：在这个任务里，大部分动作确实什么都不改变。

原因是三条叠加：91% 的推失败；`release`/`probe`/`wait` 不产生可见变化；
六个动作里有四个连机器人都不动（机器人平均只在 1.24/6 个动作里移动）。

### 4c. "改成以自己为中心的观测"能解决吗？——实测：不能

把扫描重新以机器人自身为原点（同样的扫描，坐标平移到机器人坐标系），跑同一个对照：

| 表示 | 六个动作真正产生几种不同的下一状态 |
|---|---|
| 世界坐标系栅格 | 1.43 |
| **以机器人为中心的栅格** | **1.43（完全一样）** |

**换坐标系对这个问题的区分度一点帮助都没有**，因为关键的四个动作（`release`、`probe`、`wait`、
`push:1:E`）**根本不让机器人移动**，平移之后还是同一张图。

（换坐标系仍然有别的价值：它把平移不变性做进表示里，不用网络自己学；而且**到了 2D 物理仿真阶段，
雷达本来就是传感器坐标系的**，那时它是自然选择。但它不是这个问题的解药。）

### 4d. 真正的问题：最重要的动作，它的效果**在观测里完全看不见**

我们实测了一件事：

> 对**被锁住**的物体执行 `release`，成功时反馈是 `drove`、公共事件是 `stalled`，
> **观测向量与执行前逐位完全相同**。唯一改变的是隐藏的 `released` 标志。

而 60 个场景里有 24 个是被锁的——**这个任务里最重要的准备动作，在观测空间里是零信息的。**

再看真值：`release` 的成功与否完全体现在 `released` 标志上：

| 场景 | `release` 之后 `released` | 反馈符号 |
|---|---|---|
| 被锁，机器人抓得住 | **True** | `drove` |
| 被锁，机器人打滑 | False | `slipped` |
| 未被锁 | False | `slipped` / `strained` |

**而我原来的世界模型根本没有被要求预测这个标志**（`next_physics` 在整条回合里恒定不变，
我自己还写了个测试断言这件事）。所以它**在表示层面就无法表达"这一步把物体解开了"**，
规划器当然学不会优先 `release`。这和此前从策略侧得到的结果完全对上：
第 31 轮发现，只有"会做准备动作"的策略才能解决被锁回合。

**第一版修法（已实现，部分有效）：** 把隐藏的 `released` 状态加进解码头。结果：

- 模型确实学到了一点关联：`release` 相对 `wait` 抬高 `released` 逻辑值 **+1.71**（被锁场景）。
- **但它没有条件化**：在未锁场景上也抬高 **+1.29**，也就是说它学的是"release 和 released 有关"，
  而不是"release **在能成功时**才改变 released"。
- 而且它开始**凭空捏造可见差别**（`release` 与 `wait` 的想象观测不再相同，但真值是完全相同）。

**所以这一版是"方向对、还没做对"**，下一步要让它条件化：把 `released` 的预测建立在
"这次 release 会不会成功"上（成功与否由机器人自身牵引力决定），并且**明确惩罚观测头上的虚假差别**。

### 5. 试过的修法：加权稀有的"移动"样本——部分有效，但不解决问题

既然动力学只存在于 8.5% 的样本里，就把这些样本在位置头和观测头上的权重提高 30 倍。
结果：

- 动作敏感度 **1.14 → 1.52 / 6**（改善 33%）
- 位置准确率 **0.884 → 0.792**（下降）
- 4 步想象的位置准确率 0.833 → 0.690
- **闭环成功率没有变化（都是 0.050），代价反而更高**

**结论：重加权只是在"敏感度"和"准确率"之间换位置，没有改变"模型不是动力学模型"这个事实。**

## 四、这一版真正确立了什么

1. **链路是完整的、可运行的**：编码器、潜转移、多步想象、只靠模型前瞻的规划器、闭环执行，
   全部实现并有测试。每一步的梯度都用有限差分校验过。
2. **潜瓶颈确实有用**：4 步想象后物体位置准确率 0.833，直接预测只有 0.405。
   这是"为什么要有潜空间"的实测证据，而不是断言。
3. **瓶颈不在信息，在动作条件化**：模型能准确说出物体在哪（0.884），却对"做什么"几乎不区分
   （6 个分支给出 1.14 个不同答案）。**它现在是一个状态估计器。**
4. **规划失败的原因已经定位到这上面**，而不是"网络太小""训练不够"或"观测里没有信息"
   ——单独的分类器从同一份观测里能 100% 读出物体位置。

## 五、下一步（按优先级）

1. **让损失关心"后果的差别"，而不是"状态的准确"。** 现在所有头都是在拟合单个状态；
   应该直接惩罚"不同动作的预测后果太像"这件事。最直接的做法是在损失里加入
   **动作对比项**：同一个状态下的两个动作分支，如果真实后果不同，就要求预测也不同。
   这是决策导向的模型学习，而不是状态拟合。
2. **或者改采样。** 91% 的动作无效果是数据的性质，不是世界的性质。按"效果"分层采样、
   或者在想象里主动选择能区分动作的状态，能从数据侧缓解。
3. **不要再用原始观测 MSE 当主要指标。** 它被静止内容主导（"什么都不变"基线反而最好）。
   应该以"规划器读的量"为准：物体位置、动作结果、以及**分支之间的可分性**。
4. **前置修复：前瞻必须在潜空间里延续**（已完成）。任何"解码成观测再重新编码"的实现都会
   悄悄扔掉瓶颈，并且看起来像是模型不行。
5. 换到 2D 物理仿真时，上面第 1 条会更关键：真实接触动力学的动作条件化更强，
   但如果损失仍然只拟合状态，同样会学成状态估计器。

## 六、可复现入口

```bash
# 收集轨迹并训练两个模型（约 3 分钟）
python - <<'EOF'
from coimagine.learning.world_model_data import collect_trajectories
from coimagine.learning.world_model import LatentWorldModel, DirectWorldModel, train_world_model, save_world_model
train = collect_trajectories(n_episodes=600, horizon=8, seed=0)
for name, m in (("latent", LatentWorldModel(seed=0)), ("direct", DirectWorldModel(seed=0))):
    train_world_model(m, train, rollout_length=3, epochs=200, batch_size=32, lr=1e-2, seed=0)
    save_world_model(m, f"outputs/grid/world_model/{name}.npz")
EOF
```

`learning/autograd.py`（手写自动微分，含梯度校验）、`learning/world_model.py`（模型与训练）、
`learning/world_model_data.py`（轨迹采集）。测试：`tests/test_autograd.py`、`tests/test_world_model.py`。

产物在 `outputs/grid/world_model/`：

# 附录：动作集合，以及每个动作能改变/揭示什么

这一节是实测表，不是从代码读出来的。样本：503 个决策点，覆盖全部 16 种隐藏物理；
「改变」= 执行前后该量真的变了；「揭示」= 该动作的**私有反馈**与该量之间的互信息（比特）。

## 1. 每个动作能**改变**什么

| 动作 | `released`（隐藏） | 物体位置 | 机器人位姿 | 隐藏物理 |
|---|---|---|---|---|
| `push:0:E`（A 单独推） | 0.000 | 0.095 | 0.095 | **0.000** |
| `push:1:E`（B 单独推） | 0.000 | 0.089 | 0.089 | **0.000** |
| `co_push:E`（一起推） | 0.000 | 0.143 | 0.143 | **0.000** |
| `probe:0:E`（试探） | 0.000 | **0.000** | **0.000** | **0.000** |
| `release:0:E`（释放） | **0.254** | 0.000 | 0.000 | **0.000** |
| `wait`（等待） | 0.000 | **0.000** | **0.000** | **0.000** |

**读法（这三条是这次测量最重要的结论）：**

1. **没有任何动作能改变任何隐藏物理参数。** 阻力、约束模式、双方牵引力在一整条回合里是**恒定**的，
   动作只能*揭示*它们，不能改变它们。
2. **整个任务里唯一会被动作改变的隐藏量是 `released`，而且只有 `release` 能改它。**
   条件在被锁且尚未解开时：成功率 **0.50**；其中**这台机器人抓得住时 100%，打滑时 0%**。
   （`released` 在决策点起点的基准率是 **0.0**，前导动作从不释放。）
3. **`probe` 和 `wait` 什么都不改变。** 它们是纯观测/空转：`probe` 唯一的作用是花 0.3 的代价
   换取一次反馈（见下表，它揭示自身牵引力和 push 一样多）。

物体位置和机器人位姿会变，但它们是**可观测量**（扫描里能看到），不是隐藏量。

## 2. 每个动作的反馈能**揭示**什么

互信息（比特），0 表示该动作的私有反馈对这个量一无所知：

| 动作 | 自身牵引力 | 队友牵引力 | 阻力 | 是否被锁 |
|---|---|---|---|---|
| `push:0:E` | **1.000** | 0.004 | 0.116 | 0.121 |
| `push:1:E` | **0.000** | 0.000 | 0.000 | 0.000 |
| `co_push:E` | **1.000** | 0.013 | 0.001 | 0.131 |
| `probe:0:E` | **1.000** | 0.004 | 0.116 | 0.121 |
| `release:0:E` | **1.000** | 0.000 | 0.000 | **0.492** |
| `wait` | 0.000 | 0.000 | 0.000 | 0.000 |

**读法：**

- **自身牵引力是一次实验就完全确定的**（1.000 比特）：任何与物体接触的动作，反馈符号直接
  告诉你自己有没有打滑。`probe` 花 0.3 就能拿到这 1 比特，比 `push`（花 1.0）便宜——
  这正是此前发现"试探有价值、但价值恰好等于它替代的那次实验"的来源。
- **队友牵引力用任何动作的私有反馈都拿不到（最高 0.013 比特）。** 只能靠消息或公共事件。
  这是信息边界的一次独立实测验证。
- **`release` 是判断"是否被锁"最好的动作（0.492 比特）**，远超其他动作（0.12 左右）——
  因为它在被锁时成功、未被锁时失败。
- **`push:1:E` 对 A 什么也不揭示**：A 收到的反馈 623/623 次都是 `idle`。
- 阻力只能被**弱**揭示（0.116 比特），而且和牵引力、约束纠缠在一起。

## 3. 这对研究方向的含义

**gridworld 里"隐藏动力学"只有一位。** 固定的隐藏参数 + 一个二值标志 + 一个能翻转它的动作。
这解释了为什么它是**诊断台**而不是学习挑战，也精确解释了上一版世界模型为什么不会"做准备"：
**唯一的隐藏转移没有被监督。**

**到了 2D 物理仿真，这个表会完全不同，而这正是关键对比。** 那时隐藏量（摩擦系数、
接触点位置、质量分布、是否正在滑移）会**随着每一个接触动作连续变化**，
"这个动作改变了隐藏状态的什么"变成一个内容丰富的问题，而不是一位标志。
所以正确的顺序是：**先在 gridworld 把"预测隐藏转移"这个机制做对**（这里只有一位，
是最小的可验证单元），**再把同一个机制搬到隐藏状态丰富得多的 2D 物理阶段**。

# 附录二：要预测哪些量？——把"参数估计"和"转移预测"分开

上一节把两件不同的事混在一起说了。它们必须分开，否则世界模型的结构会做错。

## 1. 隐藏状态分两类

**A 类：不随时间变化的隐藏参数（4 个）。** 一整个回合里恒定，动作不能改变它们。
它们需要的是**推断 / 信念更新**，其"转移"是恒等映射：

| 参数 | 取值 | 靠什么识别 |
|---|---|---|
| 阻力 | 1 / 2 | 弱（0.116 比特），和牵引力、约束纠缠 |
| 是否被锁 | free / latched | `release` 的反馈最好（0.492 比特） |
| 自身牵引力 | grip / slip | 任何接触动作一次就完全确定（**1.000 比特**） |
| **队友牵引力** | grip / slip | **自身反馈拿不到（≤0.013 比特）**，只能靠消息或公共事件 |

**B 类：随时间变化、且只能被动作改变的隐藏量（1 个）。** 这才是需要**真正的转移预测**的东西：

| 量 | 取值 | 谁能改变它 |
|---|---|---|
| **`released`** | False / True | **只有 `release`** |

## 2. 精确的转移语义（实测，零误差）

**释放：**

```
released' = released OR (latched AND own_traction = grip AND action = release)
```

在 3756 个 (场景, 动作) 对上，**错误 0 个**。

**物体移动：**

```
moved = 接触正确 AND (released OR free) AND  抓得住的推者数 ≥ resistance  AND  推者数 > 0
```

裸规则有 84 个例外（2.24%），而这 84 个**全部**是"推的机器人不在物体东面的接触位置"
（57 个 `co_push` + 16 个 `push:1:E` + 11 个 `push:0:E`）。补上接触条件后规则**零误差**。
接触与否是**可观测**的（自己的位姿 + 物体位置的估计），不是隐藏量。

## 3. 所以世界模型每一步要输出什么

| 输出 | 类型 | 说明 |
|---|---|---|
| **`released'`** | 隐藏**转移** | 唯一真正的隐藏动态；必须**条件化在参数信念上** |
| `object_cell'` | 可观测构型 | 推进程度 |
| `moved'` / 公共事件 | 可观测后果 | 由 `released` 和参数共同决定 |
| `cost'` | 代价 | |
| **参数信念本身** | 不变量的**估计** | **必须保持不变，除非收到新反馈** |

最后一行是结构要求，不是可选项：现在我的模型是一个通用 MLP，参数估计可以在每一步任意漂移。
正确结构是把潜变量分成两半——

- **不变部分**：四个参数的信念，只被反馈更新，**不被动作改变**；
- **动态部分**：`released` + 物体位置 + 机器人位姿，被动作改变。

转移只更新动态部分；不变部分只在收到反馈时做一次贝叶斯更新。

## 4. 为什么这样就能学会"做准备"

因为 `moved` 的规则**同时**依赖 `released`（动态）和四个参数（不变）：

1. `release` 在 (latched ∧ 自己 grip) 时把 `released` 翻成 True；
2. 之后同一条件下的 push 才会 move。

于是深度 2 的规划器**能看到**"先 release 再 push"的期望后果优于"直接 push"，它自己就会去准备。
**关键是条件化**：预测必须建立在参数信念之上。第一版失败正是因为学成了无条件的关联
（被锁场景抬高 +1.71、未锁场景也抬高 +1.29），而不是"**当且仅当** latched ∧ grip 时才翻转"。

## 5. 映射到 2D 物理阶段

| | gridworld | 2D 物理仿真 |
|---|---|---|
| 不变参数 | 4 个离散量 | 摩擦系数、质量、几何（大致不变） |
| 动态隐藏量 | **1 位（`released`）** | 接触点、是否滑移、接触力、物体姿态——**每个接触动作都在连续改变** |
| 转移预测的工作量 | 1 位 | **绝大部分工作在这里** |

**"不变信念 + 动态转移"这个结构可以直接搬过去**，但动态部分从一位变成连续高维，
而且只能从接触反馈间接观测、并与可观测量纠缠。

所以顺序是：**先在 gridworld 把机制做对**（最小可验证单元：一个二值隐藏转移，
条件化在一个二值参数上，有精确的解析真值可以逐位对照），**再搬到 2D**；
到那时新增的难点不是"机制有没有"，而是"隐藏状态连续、高维、且只能间接观测"。
