# ERRATA — fit_capacity_v1

只更正影响本轮判断的报告问题。不重跑 Grid、不重跑旧闭环；所有数值由原始记录重新生成。

## E1 闭环配对键漏掉 model_seed（更正）

`data_upgrade_v1` 的对照案例脚本用 `(scene_id, episode_seed, H)` 作配对键，而每个键下有三个
模型种子，字典被后来的种子覆盖。用正确键 `(scene_id, episode_seed, H, model_seed)` 重算：
36 个学习回合两两配对成 **18 对且键唯一**，改善/相等/退化 = **6 / 2 / 10**，平均 ΔJ **+0.446**。
上一轮报告写的 9/0/9、+0.54 是覆盖错误的产物，**撤回**。最好的一对仍是 S0_v4/seed0/模型 1
（Old −0.45 → Branch +9.04），最差是 S0_v4/seed2/模型 0（−0.58 → −1.36）。
证据：`outputs/fit_capacity_v1/fit-capacity-20261012/a1_audit.json`。

## E2 “三组都低于 uniform”不成立（更正）

原句把两种协议混称。正确表述：
- **未筛选（全候选按 J 排序）**：Branch chosen_true **−0.262 高于** uniform −0.361，
  Old(−0.448) 与 Old+Random(−0.363) 低于 uniform。所以“都低于 uniform”只对 Old/Old+Random 成立。
- **可行性筛选后（仅可行候选内选择）**：三组的仅可行 chosen_true（−0.525/−0.252/−0.166）
  都低于同一 uniform −0.361。
两种协议的数字不得混用；本轮的 D2 表把两者并排列出。

## E3 锚点数与成功窗口数不能混用（更正）

- 分支训练集中**全部锚点 54 个**，其中**至少含一个真实成功窗口的锚点 22 个**；
  分支训练成功窗口 121 个。
- 分支 **test** 成功窗口 **50** 个（不是全部 split 的 233 个）；全部 split 成功窗口 233 个。
- 训练成功锚点 22 也**不等于**独立成功案例数：它们来自 20 条引导轨迹，同一轨迹的多个分支
  不是独立成功实验。此前审阅给出的 22、50 经核对成立，但必须写成“成功锚点/成功窗口”，
  不能写成“独立成功案例”。

## E4 `best_mixed_val` 选择规则在本数据上退化（新发现，重要）

12 个新 run 的 `best_mixed_val` 全部落在极早的更新：Old+Random 六个 run 都是 **update 100**，
Old+Branch 六个 run 是 **250 或 500**。原因是分支 val 的总损失在最初的 100–500 步先下降、
随后随训练上升（例：Old+Random/256/seed0 的 mixed 分数 1.5564(0) → 0.3654(100) → 0.6438(500)
→ 0.7801(6000)），于是“0.5×原val + 0.5×分支val”的最小值总是落在允许的最早点。
这同时解释了上一轮 `data_upgrade_v1` 里 Old 三种子 `best_epoch=0` 的现象：不是“旧模型没训练”，
而是**冻结的选择规则把近初始化的 checkpoint 选了出来**。
`fixed_6000` 的分支 val 损失（1.38–1.47）远高于 `best_mixed_val`（0.53–0.57），
但原 val 损失更低——两者不可比时不得只报一个。
本轮不改变该规则（合同冻结），只如实报告，并同时给出 `best_original_val` 与 `fixed_6000`。

## E5 总损失更好的 checkpoint 与物理误差更好的 checkpoint 不一致（新发现）

12 个 run 的 `loss_vs_physics_disagree` 全为 `True`：同一 run 内，按 `mixed_val` 总损失最优的
checkpoint 与按 val 物体位置误差最优的 checkpoint **从不相同**。因此“val loss 更低”不能当作
“物理预测更好”。证据：`tables/selection_table.json`。

## E6 旧模型的问题不是验证泛化（更正隐含表述）

用原始-vals 规则选出的三个 Old checkpoint，在**其自身完整训练集**上重测的物体位置误差为
0.181 m，原 val 上为 0.196 m——训练集与验证集几乎一样差，而与 persistence 基线的
0.169 m（训练集）/0.158 m（验证集）相比更差。也就是说：旧模型首先是**训练集也没拟合好**，
不是“训练好但泛化差”。`data_upgrade_v1` 里“模型准确度不足是泛化问题”的说法据此更正为
“训练拟合不足，且验证没有额外退化”。
