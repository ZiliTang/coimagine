# C 修正：冻结协议下的单案例重做（负结果，含评分修正）

脚本：`experiments/option_prediction_mechanism_v1/phase_c_frozen/{run_frozen_c.py,recompute_frozen_c.py}`；
结果：`outputs/option_prediction_mechanism_v1/phase_c_frozen/{frozen_c_result.json,frozen_c_recomputed.json}`。
本文件替代 `C_ambiguity.md` 作为 C 的结论；后者已标注**撤回**（特权控制器通路 + 越权协议改动）。

## 1. 第一版错在哪（撤回）

1. **特权控制器通路。** `PushContact` 用**真实物体位姿**解算接触点。两世界命令字符串相同，
   但底层控制器已经知道物体在哪里，机器人随后被拖到不同自身位姿。
   **命令相同不等于控制器没有读特权信息。** 第一版"执行后可区分"至少有相当一部分来自
   隐藏真值经控制器进入运动，不能算自主辨识。
2. **越权改动。** 360° 扫描 → 前向 ±60°、2 s 技能窗 → 6 s、执行接口换成 `PushContact`。
   声明改动不等于符合任务书；"否则没有正例"不构成理由。

第一版的 18 个正例与全部 C4 数值**不再作为证据**。

## 3. 观测同一性：**限定为已实际检查的控制器输入**

已逐元素比较并全部为 0.0 的是**冻结控制器的完整输入集** `LocalContactObservation`：
自身位姿与速度、局部片段（点集、最小二乘线段、距离、世界法向与切向、置信度、时间戳、弧长、
遮挡标签）、接触标志/接触点/接触力/冲量、arena、机器人半径、力上限、技能参数；
以及**八个命令的首控制周期**的 `force`、`reference`、`patch_distance`、`patch_normal`、`contact`
（最大绝对差 **0.0**）。两世界的真值确实不同。

**未验证的部分（不得宣称）**：`scan_surface` 内部的**逐射线缓冲**没有被比较——
原始射线不进入控制器，控制器只消费拟合后的片段，因此逐射线比较对"控制器是否读到不同信息"
不是必要条件；但本文件**只主张已验证的控制器输入相同**，不主张"全部原始扫描逐位相同"。
若要做逐射线核验，需要给 `scan_surface` 加插桩，这不在本轮修正范围内。

## 4. 评分修正：删掉未经授权的负进展截零

第一版（以及 `run_frozen_c.py` 首版）用了

```
progress = min(1, max(0, (d_start - d_end)/max(d_start, 1e-6)))      # 多了 max(0, ...)
```

而 CONTRACT 3.3 是

```
progress = min(1, (d_start - d_end)/max(d_start, 1e-6))              # 只在上侧封顶
```

下侧截零**不在合同里**，是我加的。`recompute_frozen_c.py` **只用已保存的距离、时长与动作代价**
重算（不重新仿真），并同时给出两套分数：

| shift | 评分 | argmax A | argmax B | 互相 regret | 近优集合 | 交集 | 正例 | 任务项信息差 |
|---:|---|---|---|---:|---|---|---|---:|
| 0.5 | **合同** | `couple_pos` | `couple_pos` | **0.0000** | 各为单元素 | 相交 | 否 | **0.0000** |
| 0.5 | 截零（旧） | `tangential_pos_fast` | `couple_pos` | 0.0372 | 2 / 8 个 | 相交 | 否 | 0.0054 |
| 0.75 | **合同** | `couple_pos` | `couple_pos` | **0.0000** | 各为单元素 | 相交 | 否 | **0.0000** |
| 0.75 | 截零（旧） | `tangential_pos_fast` | `couple_pos` | 0.0584 | 2 / 5 个 | 相交 | 否 | 0.0081 |

**关键更正**：那个"argmax 不同"是**截零制造出来的**。按合同评分，两个世界的**最优动作完全相同**
（`couple_pos`），互相 regret 恰好为 0，任务项信息差也是 0。**两世界不需要不同动作。**

## 5. 两个问题必须分开报告

1. **是否存在正进展动作？** **没有。** 合同评分下 `completion` 全 0，
   `progress` 对**全部** 8 个命令、两个世界都**为负**（A：−2.20 ~ −1.36；B：−2.20 ~ −0.89）：
   每个动作都让任务度量变差，最好的也只是"最不坏"。
2. **是否需要不同动作？** **不需要。** 两世界近优集合相交、互相 regret = 0。

## 6. 修正"任务信号恒为零"的解释

我此前的说法**错了**，错在两处：

- 它建立在**我自己加的下侧截零**之上。截零后进度恒为 0，排序退化成"谁快"，
  于是出现了 argmax 差异；按合同评分这个差异不存在。
- 合同下任务信号**不是零，而是非正**：`progress` 可以为负且下不封顶，
  所以角点被推离目标时惩罚会很大（本案例里达到 −2.2）。它**能**区分动作
  （`couple_pos` 明显优于 `tangential_*_fast`），只是在两个世界**给出同样的排序**。

所以正确的结论是：**在这个案例里，隐藏的切向偏移没有改变动作排序**，
而不是"任务信号为零所以测不出来"。

## 7. 仍然保留的适用边界

本案例 `d_start` 很小（物体起始就几乎在目标框内），合同 `progress` 的分母因此很小、
下侧又不封顶，导致任何运动都被记成大幅负进展，任务项**主导**了总收益。
因此这个负结果说明的是：**在这种尺度配置下**，冻结 V 技能 + 合同评分没有把切向歧义
转成决策差异。它**不能**证明"冻结技能下不存在信息歧义正例"。
要判定后者，需要一个**存在正进展动作**的场景（例如目标框与物体尺度可比、或接触构型不产生
0.5–0.8 rad 的转动），并且要事前登记后重跑。本轮按要求**不搜索新场景**。
