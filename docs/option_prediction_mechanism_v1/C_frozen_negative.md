# C 修正：改用冻结协议重做一个案例（负结果）

脚本 `experiments/option_prediction_mechanism_v1/phase_c_frozen/run_frozen_c.py`，
结果 `outputs/option_prediction_mechanism_v1/phase_c_frozen/frozen_c_result.json`。
本节是对第一版 C 的**撤回与替代**，不是补充。

## 1. 第一版 C 错在哪（撤回）

`PushContact` 用**真实物体位姿**解算接触点。两世界收到相同命令字符串，但底层控制器已经知道
物体在哪里，"同一个命令"落到不同材料点上，机器人随后被拖到不同自身位姿。
因此第一版里"执行后机器人位置差 1.5 m 从而可区分"至少有相当一部分是**隐藏真值经控制器进入
运动**的结果，不能算机器人自主辨识。**命令相同不等于控制器没有读特权信息**——这一条我接受。

同时第一版还改了三处不在授权内的实验前提：360° 扫描 → 前向 ±60°、2 s 技能窗 → 6 s、
执行接口换成 `continuous2d PushContact`。"否则没有正例/否则不容易成功"不构成理由；
任务书本来就允许找不到正例后停止。第一版的 18 个正例**不再作为支持研究主线的证据**。

## 2. 重做用的协议（全部冻结）

| 项 | 值 |
|---|---|
| 控制器 | **局部 V**（`OptionExecutor("V")` + `LocalSurfacePush`）；力只由白名单观测生成 |
| 传感 | `scan_range = 0.6 m`、`scan_rays = 72`，机体系**完整 360°**、理想无噪无延迟 |
| 阶段协议 | APPROACH / READY / PUSH（有效接触 2.0 s、墙钟 3.0 s）/ BRAKE / SETTLE（4.0 s） |
| 判稳 | round-3 冻结 `settle_window=0.20`、`min_baseline=0.10`、`max_sample_gap=0.15` |
| 物理 | 3.0 kg、摩擦 0.6、阻尼 8.0/0.6、F_max 15 N、控制周期 0.05 s |
| 唯一改动 | 物体**长度** 1.0 → 5.0 m；厚度保持冻结的 0.25 m，质量/摩擦/阻尼/力上限全不变 |

长矩形机制场景是 CONTRACT 3.2 允许的；把物体加长到 5 m 是为了让两端都落在 0.6 m 扫描之外，
**不需要缩窄视场**（第一版的 ±60° 因此是多余的）。

**案例（事前声明，不看收益再调）**：两机器人固定全局位姿 x = 8.0 / 10.0，位于长边两侧；
物体中心世界 A = 9.0 m、世界 B = 9.0 + shift；目标框中心 x = 9.25（两世界物体中心的**中点**，
谁也不占优），半长宽 (2.5, 0.6)；shift 取 **0.5 与 0.75** 两个事前声明的值。

## 3. 首先要验证的事：底层控制器没有读隐藏真值

这是本轮修正的核心检查，两世界**逐位相同**：

| 检查 | shift 0.5 | shift 0.75 |
|---|---|---|
| 两机器人白名单观测逐元素最大绝对差 | **0.0** | **0.0** |
| 八个命令的**首控制周期**观测+参考速度+输出力最大绝对差 | **0.0** | **0.0** |

观测逐量包含：自身位姿/速度、局部片段点集（机体系）、最小二乘线段、距离、世界法向与切向、
置信度、时间戳、弧长、遮挡标签、接触标志/接触点/接触力/冲量、arena、机器人半径、力上限、
技能参数。首周期比较包含 `force`、`reference`、`patch_distance`、`patch_normal`、`contact`。
两世界的**真值**确实不同（物体中心相差 shift），所以这不是同一个世界。

⇒ 观测与控制器内部状态相同时，**第一周期的参考与输出力逐位相同**；随后才由真实物理自然产生差别。

## 4. 结果：不满足正例判据（负结果）

| shift | argmax A | argmax B | 互相 regret | A 的近优集 | B 的近优集 | 交集 | 正例 |
|---:|---|---|---:|---|---|---|---|
| 0.5 | `tangential_pos_fast` | `couple_pos` | 0.0372 | {tangential_neg_fast, tangential_pos_fast} | 全部 8 个 | 非空 | **否** |
| 0.75 | `tangential_pos_fast` | `couple_pos` | 0.0584 | {tangential_neg_fast, tangential_pos_fast} | 5 个 | 非空 | **否** |

regret 虽然超过 δ=0.02，但 **近优集合相交**，按 CONTRACT 3.3 **不是正例**。
（这正是合同里写的"仅仅 argmax 因微小并列误差不同，不算"。）

物理上两世界**确实分开了**：同一个命令在世界 A 物体几乎不平移（0.000–0.034 m），
在世界 B 平移 0.061–0.236 m——因为 A 里两接触点关于质心对称，B 里偏向一侧，力臂不同。
所以"隐藏切向偏移会影响运动"这件事成立；**不成立的是"它改变了动作排序"**。

## 5. 为什么这个负结果还不够决定性（必须说清）

在本案例里，八个命令、两个世界，**`completion` 全为 0、`progress` 全为 0**：
目标框与物体长度同量级，而冻结的 V 技能会让物体绕厚度方向转动 0.5–0.8 rad，
角点总是被转出目标框，`d_end ≥ d_start` 恒成立。于是

```
Q = completion + 0.5*progress - 0.05*duration - 0.10*action_cost
  = -0.05*duration - 0.10*action_cost
```

排序实际由**技能时长**决定（同一命令两世界的时长差可达 1.1 s，≈0.055 Q）。
因此这个案例的负结果有两层含义，必须分开：

1. **可靠的部分**：一旦移除特权控制器通路与越权协议改动，第一版那种"观测完全相同但近优动作
   不相交"的现象在**本案例中消失**；第一版的 18 个正例不能作为支持研究主线的证据。
2. **不够决定性的部分**：本案例的收益里**任务结果信号恒为零**，所以它也不能证明"冻结技能下
   不存在信息歧义正例"。要判定这一点，需要一个**冻结技能确实能产生目标进展**的场景
   （例如让物体与目标框的尺度可比、或让接触构型不产生那么大的转动），并事前登记后重跑。

本轮按用户要求"只重做一个案例"，**不做参数搜索**：两个 shift 是事前声明的稳健性检查，
不是选优；两个都交付，没有挑一个。结论：**交付负结果**，并给出上面的适用边界。
