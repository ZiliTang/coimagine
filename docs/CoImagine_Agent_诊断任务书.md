# CoImagine：现有实现诊断任务书

请直接执行下面的任务，不要只提出计划。本轮授权你读取项目、运行最小诊断实验、增加必要测试并修复已证实的缺陷；不要开始新研究模块。若缺少源代码、模型或数据，准确列出缺项，不要用文档描述代替实际验证。

## 1. 本轮目标与研究背景

CoImagine 的长期问题是：多机器人如何利用各自的私有接触证据，通过通信比较候选协作方式，并选择准备、辨识和执行动作。候选路线是“私有证据 → 联合技能后果预测与交流 → 短时闭环执行 → 根据反馈重新协商”。长 rollout 不是必须保留的前提，也不要求改用大语言模型。

目前小型格子推动环境中的学习模型规划表现不稳定，有些运行中搜索越深表现越差。我们尚不知道主要原因是模型误差、信念传播、搜索与评分实现，还是任务与指标设计。本轮唯一目标是：通过可复现的替换实验，把这些原因分开，并据此给出下一步决定。

完成不等于成功率提高。证明某个实现错误、排除某个具体解释，或发现任务无法检验原研究问题，都算有效结果。不要以调高分数为导向修改任务。

参考材料：
- `CoImagine_2D_最终结论_v1.md`：历史实验记录，正文含后续修订。
- `CoImagine_v6_研究方案与创新评估.md`：原方案及不断追加的实验解释。
- `DuoMind(1).pdf`：研究背景，不是本轮需要复现的方法。

旧文档存在互相冲突的判断。代码、固定版本的原始输出和本轮复现是证据；“唯一原因”“已排除 bug”等旧文字不是事实前提。

## 2. 开始前固定边界

1. 阅读仓库适用的 AGENTS.md，定位环境、模型、信念更新、规划器、评分和评估入口。
2. 记录当前 commit、未提交改动、模型检查点、数据版本、配置与随机种子。保留原始结果；不要覆盖用户改动或重写历史报告。
3. 固定一小批诊断场景和一批最终评估场景。前者用于找错，后者用于验证；不得根据结果挑选最终评估场景。
4. 先复现一个已有失败检查点，最多用少量轨迹验证症状，不要先启动大规模训练。
5. 用一张简表说明真实执行时每个模块能看到什么。特别区分局部反馈、公共事件、模拟器隐藏状态和训练标签。

先给出简短的代码入口与诊断顺序，然后继续执行。遇到正常实现选择自行处理；不要每修一处就停下来请求确认。

## 3. 按顺序完成诊断

### A. 统一评价口径

先核实以下项目，修正报告生成逻辑中可确认的错误：

- 全场景成功率与可解子集成功率分别报告，并列出分子、分母。不能把全场景 oracle 0.42 与可解子集随机 0.333 直接比较。
- “可解”优先使用该有限环境中的精确可达性检查，在固定动作集与任务时限下定义。如果仅由某个 oracle 实际成功来筛选，名称必须写成“oracle 成功子集”，不能宣称其余场景物理无解。
- 分别报告成功率、所有回合平均代价、成功回合条件平均代价。总成本/成功次数可作为附加指标，但必须单独命名；零成功时写未定义。
- 写清距离误差符号。若采用“预测距离 − 真实距离”，正值表示预测更远，不是更靠近目标。用一个手算例子核对代码与图表。
- 不直接比较输入和测试分布不同的准确率。“99.4% 一步”与“四步实验第一步 41.2%”必须分别追溯检查点、状态来源、动作、隐藏参数/信念输入、预测读出和准确率定义。

如果旧数字无法追溯，标记为未复现；无需重做所有历史实验。

### B. 首要实验：让精确模型接入当前规划器

实现一个最小模型适配接口，让当前规划器能够切换“学习模型”和“精确模型”。搜索、评分、候选动作、执行循环、终止条件与平局规则保持相同。

关键约束：
- 精确模型知道动力学规则，但部署侧仍只能使用相同的观测历史与信念；不得把真实隐藏参数直接送给规划器。
- 只有明确标注的全信息调试实验可以读取真实隐藏状态。它用于隔离搜索错误，不用于宣称公平性能。
- 精确模型在每个信念假设下计算转移和反馈，再按合法概率组合。真实模拟器状态只用于执行与离线核验。
- 候选分支必须独立复制状态；检查枚举候选是否意外改变真实环境、其他分支或随机数状态。

先运行精确模型版本。若它仍出现明显空转、计费异常或本可完成却失败，优先诊断规划器，暂不训练学习模型。

### C. 用独立的小规模穷举核验搜索与信念

在可计算的短时域内，用独立、清楚的参考实现枚举候选并核验动作分数。只选少量有区分度的场景：不需释放、需先释放、释放必然失败、反馈会改变下一步选择、距目标不同距离。

核验两层问题，不能混为一谈：
1. 在与当前规划器相同的分支结构下，检查搜索、剪枝和评分是否正确；允许等价最优动作，不要求编号完全相同。
2. 另用完整反馈分支的短时域策略树作参照，量化“只在第一步分支”等近似的影响。近似差距不是自动等于代码 bug。

重点检查：
- 每一步动作成本是否恰好计一次；终止后是否仍累计成本；失败罚款的概率与时刻是否正确。
- 剩余任务时限与搜索时域是否一致。搜索更深不保证在近似终端估值下闭环单调改善，不能拿非单调本身当 bug 证据。
- 零代价 wait 是否造成反复把推进留给未来。记录计划第一步与后续动作；诊断性改变平局规则或等待成本时单独标注，不能悄悄改变原任务。
- 隐藏参数 θ 在一条想象轨迹中保持不变；不得每步重新独立采样。
- 保留 θ 与动态状态的关联，例如“抓得住且已释放”和“打滑且未释放”，不能只保留独立边缘概率后任意重组。
- 接收到反馈后，分支状态和参数后验必须一起更新；隐藏状态不能每步被观测编码器覆盖。
- 不提前读取未来反馈、队友未发送的私有信息或真实 θ；共享证据不得重复计数。
- 分支概率归一化，零概率分支正确处理，模型输入的形状和数值语义在训练与推断时一致。

诊断至少展示一条“等待胜过推进”的失败轨迹（若可复现）：列出每个候选的动作成本、终端估值、失败罚款、总分、预测后果和实际后果。随后展示精确替换或最小修复是否改变该选择。

B、C 的通过标准是：同一目标与同一分支结构下的短时域分数在数值容差内匹配参考；典型失败均有可复现解释。不要用“精确模型必须100%成功”作为部分可观测、有时限任务的通用要求。

### D. 规划器通过后，才隔离学习误差

在同一规划器与同一评估集上逐个替换模块。按现有接口做最少必要实验，不要为完整矩阵大改架构：

| 条件 | 作用 |
|---|---|
| 精确状态/信念更新＋精确转移与观测 | 公平信息条件下的参照 |
| 仅转移换成学习版本 | 定位动力学预测影响 |
| 仅观测似然换成学习版本 | 定位反馈预测与信念更新影响 |
| 再引入当前学习状态估计/完整系统 | 定位感知、状态估计及模块交互影响 |

混合模块须使用相同的状态语义；若无法保持一致，明确说明该替换无法解释，不要硬拼。误差影响可能相互作用，不要把各行差值当成可直接相加的因果分解。

多步评估必须从同一初始条件、同一动作序列出发，区分：每步输入真值的单步测试、输入自身预测的开环展开、每步收到真实观测的闭环执行。

优先看三个量：
- 决策相关后果：推进、释放、到达目标及关键状态预测。
- 动作排序：学习预测是否把应该推进的动作排在等待之后；模型选中动作在精确评价下损失多少。
- 被选计划的预测收益与精确收益之差，并与未选候选比较。仅看到模型有误差，不足以证明搜索在利用误差。

部分可观测情况下，预测分布应与同信息下的精确分布比较；不要要求未知参数下的预测每次命中单次真值。已知 θ 的测试另列。

不要仅凭真实访问状态上的单步准确率排除分布偏移，还要查看搜索内部生成的状态与连续推进序列。

### E. 最后验证重复性

只复核最终保留下来的少量关键对照。相同模型内比较深度；跨模型时使用至少5个训练种子，固定评估场景并配对比较。分开记录数据、训练和环境随机性。

报告各种子结果、均值与离散程度；若给置信区间，说明计算单位和方法。不能用大量同一模型的评估回合替代训练种子，也不能仅靠区间重叠判断显著性。

若训练资源不够，先交付B—D的诊断证据，明确统计验证尚未完成，不要虚构稳健性结论。

## 4. 修复和范围约束

- 一次只修一个有证据的缺陷，保留最小复现与有实际辨别能力的回归测试，再在固定案例上验证。
- 允许修接口、计费、信念传播、数据读取与评价错误；不要重写整个工程。
- 暂不增加LLM、集成模型、悲观规划、新损失、更大网络、3D或硬件实验。
- 不通过改目标区、加长任务、删除困难场景或调整奖励来掩盖当前问题。诊断变体单独命名。
- 不重复开展与当前失败无关的梯度或通用算子测试；已有验证只有出现具体疑点时才重查。
- 若定位到数据覆盖问题，本轮只做一个最小针对性干预，例如补齐固定关键状态的动作后果；与对照匹配数据量及训练预算。没有必要再次扫描大量超参。
- 本轮不实施新协商环境。即使发现旧环境不适合核心问题，也只提出一个最小后续方案并说明理由。

## 5. 停止条件与下一步决定

| 结果 | 本轮行动与结论 |
|---|---|
| 精确模型下当前规划器仍异常 | 修复并验证规划/信念/执行接口；停止学习方法扩展 |
| 精确模型正常，学习版本退化 | 定位关键模块和动作排序错误；最多一次针对性修复或数据干预 |
| 修复后有效但跨种子不稳定 | 报告不稳定来源与证据缺口；不宣称方法有效 |
| 两者均可用，但私有信息或通信几乎不改变决策 | 保留旧环境作调试台；建议新建能比较不同协作方式的最小任务 |
| 缺少资源或接口无法公平替换 | 准确说明阻碍、已获得的证据与最小补充需求；停止无目的尝试 |

不要因为性能没提高而无限循环修改。若某个阶段发现的缺陷已足以解释主要失败，修复并完成必要复核后即可收尾；不必机械执行所有分支。

## 6. 交付与汇报格式

交付：必要代码修改、可运行的诊断入口、机器可读原始结果，以及一份新的简短诊断报告。路径沿用项目惯例，给出实际命令与版本信息。

用户可读报告正文控制在约1500个中文字以内，不计一张结果表。详细轨迹、配置、日志放附录，不在正文堆叠。不要继续向旧方案追加长篇互相矛盾的修订。

最终报告只回答：
1. 当前主要问题是什么？标注已证实、较支持、尚未确定。
2. 哪个替换实验支持这个判断？给出一张表和一个代表性失败案例。
3. 修复改变了什么，是否跨种子成立？未完成的验证明确写出。
4. 现有环境值得继续做什么，不值得继续做什么？
5. 下一步只推荐一个目标，以及达到什么结果就停止。

避免“唯一原因”“彻底排除bug”“全面验证”等超出证据的表述。通信只在队友必需时有价值、消息价值最多等于一次实验、显式隐藏状态是所有世界模型的必要条件，都不能从当前测台推广为一般规律。

现在从固定版本、核对指标、定位精确模型适配入口开始执行。
