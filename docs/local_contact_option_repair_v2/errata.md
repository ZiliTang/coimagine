# local_contact_option_repair_v2 更正与偏离记录

## E1 v1 的判稳门槛把位移当速度（本轮主修复 A1）

`update_surface_estimate` 返回的是匹配点平均法向**位移**（约 1e-3 m 量级），却与 0.02 m/s 比较，
因此门槛几乎不起作用。修复后：除以两次有效扫描的采样时间戳差、用逐点法向速度的 RMS 聚合、
加 0.20 s 新鲜度与重复/乱序拒绝。后果如实报告：N 的观测判稳率从 92.8% 降到 **65.1%**，
P 从 90.5% 降到 58.9%；零假稳定数字未变（N 0/625，P 13/565）。

## E2 v1 的延迟变体其实没有延迟（本轮修复 A2）

`run_execution` 只把 `variant.observation_delay` 用于日志，从未写进 `OptionConfig`，
所以 v1 的「延迟」臂实际是无延迟的。修复：按变体构造 `observation_delay` 与 `range_noise_sigma`。
后果：v2 的延迟变体才真正延迟，`settle_unobserved`/`settle_timeout` 显著增多。

## E3 延迟队列的投递方向相反（A2）

v1 保留「还没到达的帧」、丢弃「已到达的帧」，长期重复最早观测。修复为投递 `now-delay` 之前到达的
最新帧、保留在途帧、只清理被替代的历史帧；启动阶段返回 unavailable。测试固定 100 ms 延迟、
50 ms 采样时 0.10/0.15/0.20 s 分别使用 0.00/0.05/0.10 s 帧。

## E4 制动渐变没有进入执行器（A3）

阶段机更新了参考减速，但施力直接用零参考。修复为用限幅后的参考计算力；参考在进入 BRAKE 的
**当周期**从实测速度初始化。修复过程中发现并修掉两处次生问题：（a）参考曾被阶段机与施力路径
各更新一次，日志与力不一致；（b）初始化晚了一个周期，导致第一个制动周期仍按巡航参考施力、
下一周期跳变 0.08 m/s。两者都有测试。

## E5 中止原因曾被判稳覆盖（v1 E3 的延续）

v1 已修 `settled_after_abort`，本轮进一步把三个标签拆成 `push_completed`/`settled_observed`/
`settled_after_abort`，并把非活跃机器人从「恒零力」改为制动。

## E6 统计分母与 bootstrap 的两个错误（A5）

- G2/G4 原先用四个可推动类的 80 root；主分母改为指定的 solo_central+dual_same_side 40 root，
  次要组另列。
- `root_p90_bootstrap` 原先把 `sorted(per_root)` 的两个变体名与数值 zip，产生 `roots=2`；
  现在按真实 root_id 重采样、每次重算 P90，并断言 root 数等于目标集合大小。

## E7 接续把「尝试三步」当成「完成三步」（A6）

`len(steps)==3` 只说明尝试了三步。现在分开 attempted / push_completed / normal_completion，
并加入口资格（两机器人与物体线角速度，仅评估）。**旧结果更正**：按同一记录口径重算，v1 的正常
三步完成是 **P=8/12、N=9/12**，不是 v1 报告中的「两臂各 10/12」；v1 报告里的 10/12 是
「尝试跑满三步」的比例。本轮 v2 的正常完成是 **P=7/12、N=7/12**。

## E8 渲染器的时间与场景（C4）

v1 的 `rows[::2]` 配 20 fps 会把播放速度加快一倍，且场景由模板手工拼装。本轮：帧率与日志
采样严格对齐（50 ms 采样 → 20 fps 导出 = 1× 实时），场景从 `RootSpec.scene()` 读取实际几何
（含障碍角度与边界），四臂同一相机，O/F 终帧冻结并标 `ENDED at t=...`。渲染只消费日志。
