## 1. 必要背景：只保留影响实施的事实

长期研究目标：联合技能的长期物理后果如何被可靠预测并用于规划。重点关注：搜索是否倾向选择被模型高估的方案，以及多尺度预测能否降低这种偏差，同时保留先准备、后获益的动作。

分布式是后续架构要求。本轮使用统一物理状态与统一评估接口，不实现通信协议、预测融合或多机器人协商。

旧实现的已报告问题包括：
- 聚合状态递归传播会丢失物理参数与状态的关联。
- 改为逐参数状态后，短链预测改善，但深层闭环未稳定改善。
- 执行后编码器可能把真实位置覆盖成错误位置。
- 曾出现距离方向、动作索引计费错误。
- 推动类关键转移错误被大量静止样本掩盖。

这些是历史报告中的线索，不代表当前代码一定仍有同样问题。当前状态必须现场核实。
“学习规划低于随机”不等于已经证明 model exploitation；“搜索越多必然越差”不是预设结论。

## 4. 阶段 B：旧 Grid 最后一次候选选择诊断

### B1. 限定样本和计算预算

- 默认固定前 20 个有效场景（按稳定场景 ID 排序），不按结果挑选。
- 固定深度 H = 1、2、3；每个深度单独比较。
- 每个场景每个深度最多 128 条不同序列。
- 候选顺序种子默认 0、1、2；集合大小 K = 16、64、128。
- 序列不足时使用实际数量；不同 K 得到同一全集时只计算一次，并注明。
- 先运行 2 个场景 smoke。正式运行若预计超过 30 分钟，统一缩减场景数并在结果前记录，不按成绩缩样本。
- 本轮旧 Grid 的实现、修复与正式运行总预算最多约半个工作日。依赖时钟不可用时，以“两次有针对性的阻塞修复”为停止界限。

### B2. 固定候选，隔离搜索选择

直接生成固定动作序列，不使用 beam；候选生成不得调用模型或真实未来收益。
同一个 H 内，按确定性随机顺序建立嵌套集合 C16 ⊆ C64 ⊆ C128。
序列可按已有动作空间生成；中途动作执行失败应由环境返回结果，不能静默丢弃候选。
同一序列只评估一次并缓存；K 改变时复用记录。

模型侧：
- 使用同一冻结检查点与同一预测管道。
- 模型从初始输入预测整个固定序列，不在中途读取真实执行状态。
- 不增加反馈分支、不重新规划、不更改置信度门槛。
- 将既有累计代价与终端评分拆开记录；如收益 J = -cost，明确写出转换。
- 真实评价与模型评价必须使用同一个明确的评分函数与时间范围。
- 不能把旧 planner 对“最优续接”的评分直接当作一个固定序列的评分。

真实侧：
- 每个序列从同一初始世界/副本开始。
- 执行相同动作序列与相同终止协议。
- 成功后作为吸收终态：后续不再增加执行代价；预测侧采用相同约定。
- 如果旧环境没有兼容的固定序列评分，允许在新诊断脚本中建立薄评分适配；不得修改生产评分器。

### B3. 必须匹配信息条件

旧环境含未知物理参数时，一次真实世界结果不等于预测期望的真值。
优先使用初始信念所对应的精确联合世界分布，逐世界执行候选，再计算期望 J_ref。
不能把 b(θ) 与边缘状态独立相乘冒充精确联合分布。
若只有实际世界可用：
- 保存 J_realized，明确标记为“单世界实现收益”。
- 可报告排序与实现表现，但不能单凭该差值宣称系统性高估。
- 不为补齐这一项重构信念系统。
已知参数/状态模式只能作为单独标记的诊断，不能与原信息条件结果混在一张主表。

若精确联合参照无法以已有接口轻量构造，交付受限结论后结束 B；不阻塞连续环境。

### B4. 统一指标

以下均按收益越大越好：
- chosen = argmax(J_hat)，并列时按稳定 candidate_id 选择。
- selected_bias = J_hat(chosen) - J_ref(chosen)。
- candidate_mean_bias = mean(J_hat - J_ref)。
- selection_excess = selected_bias - candidate_mean_bias。
- candidate_regret = max(J_ref in C_K) - J_ref(chosen)。
- uniform_candidate_return = mean(J_ref in C_K)。

最后一项是“同一候选集内均匀选序列”，不能叫作历史随机策略的同一个基线。
candidate_regret 的最优是候选集内最优，不是全局最优。
同时保存 selected true success（或期望成功率）、累计成本、终态距离等原始量。
跨 H 的任务时长不同，不把不同 H 的裸收益混成“搜索宽度效应”。

### B5. 验收与交付

必须检查：
- 候选嵌套、K 数量、稳定 tie-break 正确。
- 用 J_hat = J_ref 的 mock 替换时，bias=0 且 regret=0（容许明确的数值误差）。
- 候选迭代顺序不改变各候选真实轨迹。
- checkpoint hash、旧生产文件未改变。
- 汇总由原始逐候选表生成。

交付：
- candidates.jsonl：scene_id、seed、H、candidate_id、动作序列、初始状态引用、J_hat、J_ref/J_realized、信息条件、逐步轨迹引用。
- summary.csv：按 H、K 汇总上述指标，并保留每场景明细。
- 最多两张图：K 对选择偏差；K 对真实收益/候选 regret。
- 不超过 500 字结论：支持、未支持或证据不足；列一个代表案例并注明选择规则。
没有观察到偏差放大也算本阶段完成。禁止通过重训、调奖励或挑场景制造趋势。

## 5. 阶段 C：连续环境最小原型

### C1. 物理后端与模型边界

若仓库已有可复现的成熟 2D 刚体后端，直接复用。
否则默认使用 Pymunk/Chipmunk：先查官方 API、确认兼容版本，再锁定版本；不在多个引擎之间反复比较。若不可安装且无已有后端，报告阻塞，不能自行写替代碰撞引擎。

第一版是俯视平面刚体近似，不宣称高保真机器人动力学：
- 两个可全向驱动的动态圆形机器人。
- 一个可平移、旋转的动态长方形物体。
- 静态墙壁/障碍、一个目标区域。
- 重力为零，使用明确记录的桌面阻力/阻尼近似；记录接触摩擦、恢复系数。
- 机器人控制输出为有上限的力；物体只通过物理接触受到机器人作用。
- 禁止执行时直接写位置、瞬移、给物体施加“协作成功”奖励力或人工解锁。
- reset/恢复初态允许设置物理状态。
- 接触力矩来自接触位置与力，不手写“两个机器人一起就移动”的规则。
- 不加入不可见 θ、私有信息、图像编码器或观测噪声。

初始工程默认值（不是论文最优参数）：
- SI 单位；physics_dt=1/120 s；control_dt=1/20 s。
- 一个同步联合技能窗口默认 2 s，即 40 个控制周期。
- 初始候选规划深度 1 与 3；轨迹回放支持至少 6 个窗口。
- 其余质量、尺寸、最大力、阻尼、成功容差由 agent 在合同中一次明确配置，并以基础物理测试校验。
- 若数值稳定性需要改时间步，修改配置、记录原因并重跑物理检查；不能静默改变评估条件。

### C2. 状态和接口合同

实现等价于以下接口，准确名称可沿用仓库：

reset(scene_config, seed) -> observation
export_state() -> replayable_snapshot
restore(snapshot) -> None
step_control(joint_control) -> observation, diagnostics
execute_joint_skill(joint_spec) -> SkillResult
rollout(snapshot, joint_specs, backend) -> TrajectoryResult

observation：
- 固定 ID 顺序的机器人位置/速度。
- 物体位置、角度、线速度、角速度。
- 墙与目标几何、公开物理配置。
- 当前时间、技能执行进度与控制器所需的状态。
不得把 engine handle、碰撞缓存指针或真实未来轨迹作为未来模型的输入。

snapshot 要足以复现未来物理轨迹，包含控制器内部状态与随机数状态（若存在）。
只恢复位姿/速度不一定足以恢复物理引擎的内部接触状态；必须验证。
若后端不支持精确 clone，采用重建初态并重放已执行控制前缀，保存前缀。不能假称精确 clone。

SkillResult：
- 初态、终态、实际持续时间、终止原因。
- 每个控制周期的状态与施加控制。
- 逐机器人的技能规格与控制器版本。
- 目标成功、数值异常、越界、碰撞/接触诊断。
- 时间/力使用量等成本分量；不能只有总 reward。

backend 本轮只有真实模拟器和精确规划适配器；为学习模型保留数据合同，不创建空洞的“已完成世界模型”模块。

### C3. 技能与同步协议

仅实现三个基础反馈技能：
1. move_to(world_xy)：机器人在力限幅下追踪目标位置。
2. push_contact(object_id, contact_local_xy, push_direction_world, force_limit)：移动到接触点附近并按目标方向推动；每个控制周期根据当前物体位姿更新接触目标。
3. hold：阻尼制动或位置保持，具体语义写入配置，不能混用。

controller 可以使用当前完整观测作反馈，但不能查询模拟器未来。
接触点选择来自统一有限模板，例如矩形表面采样位置，不能按场景 ID 返回答案。
接近接触点的失败应真实保留；不得让机器人穿过物体到达推点。
本轮不实现抓取、拉拽、焊接约束，也不把无法用推力完成的墙面释放任务列为必须通过的场景。

一个 joint_spec 指定两个机器人各自技能，同时执行固定窗口。
某机器人提前完成 move_to 后转为明确的 hold，窗口不提前结束；任务真实成功或数值失败可整体终止。
模型预测与真实执行未来必须沿用同一协议。
技能内部有反馈；跨技能的固定候选不依据未来结果改选技能。

### C4. 场景只做两类

S0：自由空间搬运。
- 验证接触推动、偏心推动引起旋转、两侧施力响应。
- 用于调控制器与物理参数，不作为长程规划贡献证据。

S1：长方形物体经过狭窄通道。
- 几何上允许合适朝向通过；初始朝向直接平移不能通过。
- 存在可以通过真实接触实现的“调整朝向—通过”的序列。
- 两机器人初态与空间允许它们到达所需接触位置。
- 禁止把通道做得无解后依靠增大力挤穿。
- 不强求第一版证明“两机器人绝对不可替代”；记录单机器人/联合执行对照即可。

开发时先各一场景，通过后每类固定 5 个轻微布局变体。
变体参数在正式测试前冻结；全部保留，不剔除难例。
不做多物体清障、三机器人、异步、双机械臂、成员加入退出。

### C5. 物理验收

必须完成以下有物理意义的检查，并保存短轨迹：
- 无机器人接触时，静止物体不会因控制命令自行移动。
- 居中与偏心推动具有可区分的平移/旋转响应。
- 机器人施力遵守上限，没有写位姿绕过执行。
- 接触推动不被错误计作任务失败；越界、非有限值另行记录。
- 无持续严重穿透；碰撞容差按物体尺寸记录，不要求引擎绝对零穿透。
- 相同初态与控制前缀重复执行，在规定数值容差内一致。
- 不同候选的模拟副本互不污染。
- 物体处于目标内且低速持续一段配置时间后才成功，不用单帧中心点判定。
- 至少一个 S1 人工指定的技能序列可物理完成。它只是可行性 witness，不是规划器结果。

C 未通过时停止 D 的性能评估，只交付复现与阻塞；不要先训练模型补救控制器或物理问题。

## 6. 阶段 D：精确模拟器规划与数据导出

### D1. 候选生成与评分

使用一个简单的有限模板候选生成器，所有方法共用。允许依据当前几何生成可接近的接触点，禁止查未来真值或注入 witness 序列。
初始预算：每次决策最多 128 条候选；深度 1/3。固定候选种子并记录实际候选数与模拟器步数。
若候选不足，使用实际数量；不通过重复候选充数。

精确基线：
- 从当前真实状态建立独立模拟副本。
- 模拟候选序列，用统一任务评分选择。
- 执行首个联合技能窗口，再观测并重新规划。
- 这是真实模型 MPC 基线，不称“全局最优”或“性能上限”。

第一版使用明确的排序键，避免调奖励制造结论：
1. 成功优先。
2. 成功方案按完成时间、控制使用量依次排序。
3. 未成功方案按物体到目标的几何距离、目标朝向误差、控制使用量依次排序。
4. 完全并列按稳定 candidate_id 排序。

距离与角度计算写独立函数、配手算样例。S1 的长期收益应来自候选序列真的通过通道，不来自手写阶段奖励。
任务若没有指定终点朝向，则删除朝向项，不自加隐含目标。
本轮排序键可作工程基线；后续选择偏差实验需要标定统一标量 J 时，另行冻结评分合同，不能直接把字典序键相减。

### D2. 对照与解释

在全部 10 个冻结场景上运行：
- 同一候选生成器内随机选动作/序列的闭环对照（3 个固定种子）。
- 精确模型 depth 1 MPC。
- 精确模型 depth 3 MPC。

深度不同允许具有不同模拟成本，但必须报告墙钟时间、候选数、物理步数；不能直接宣称计算预算公平。
每个 episode 最多 12 个窗口。超时记失败，不能删掉。
如一次控制器/数值问题修复改变行为，重跑受影响的完整场景组，禁止拼接修复前后数字。

本轮工程门槛：
- S0 与 S1 各至少一个场景，精确 MPC 能完成。
- 至少一个 S1 的成功计划确实包含准备性技能，保存视频与逐步日志。
- 若 depth 1 也全部完成，平台仍可通过基础工程验收，但标记“长程鉴别力尚未建立”；不要宣称长程预测必要性。
- witness 成功而 MPC 失败时，优先检查候选覆盖、搜索预算与评分。最多两轮有针对性修复，仍失败则报告；不靠学习模型掩盖。

### D3. 数据接口

保存实际轨迹，支持后续从同一数据抽取：
- 短时连续片段。
- 单个同步联合技能窗口。
- 连续 2/3 个联合技能窗口。

每条记录至少包括：
episode_id、scene_id、seed、t、state、joint_skill_specs、controller_state、
applied_control、next_state、duration、termination、success、cost_components、
physics_config_hash、controller_version、split。

train/dev/test 按场景或 episode 分组，不能随机拆相邻帧造成泄漏。
本轮轨迹用于工程验收，统一标注 dev；不提前宣称具有未见测试集泛化结果。
仅导出验收执行轨迹，不启动大规模数据采集或训练。

## 7. 交付与最终回复格式

必须交付：
1. 可运行的旧 Grid 诊断（或明确 BLOCKED 原因）。
2. 连续环境、三个反馈技能、精确 MPC 与随机对照。
3. configs、依赖版本、manifest、逐候选/逐时间步原始数据、自动生成汇总。
4. README：安装、smoke、旧诊断、新基线、轨迹回放的实际可执行命令。
5. 至少一段自由空间与一段通道任务的实际模拟视频/GIF；缺少渲染依赖时交付逐帧图与复现命令，不能用生成动画代替真实执行。
6. 状态清楚的 STATUS.md 和不超过 1200 中文字的阶段报告；长日志放附件。
7. 本轮变更清单；不自动推送远程、不覆盖旧报告。遵守仓库既有提交规则。

最终回复仅回答：
- 完成到哪一阶段；哪些 BLOCKED。
- 旧 Grid 是否支持“选择性高估”，证据限度是什么。
- 连续环境是否物理可行、精确 MPC 是否可完成。
- 一张结果表（包含全部场景，不混分母）。
- 关键文件与复现命令。
- 下一步最多一项建议。

禁止写“全测试通过，因此方法成功”。工程正确、环境可行、研究假设成立是三个不同结论。

## 8. 本轮禁止自动开始的后续事项

以下仅说明未来方向，不是当前授权任务：
- 训练连续环境单步世界模型及 teacher-forcing/递归预测对照。
- 跨技能直接预测、跨尺度一致性、选择性复核或保守评分。
- 分布式预测合并、多智能体语言协商。
- 异步选项、三机器人、多物体清障、双臂模拟。
- 自动超参搜索、为获得显著结果扩充样本。

完成 A–D 后交付，让研究负责人根据真实结果确定下一份任务书。
