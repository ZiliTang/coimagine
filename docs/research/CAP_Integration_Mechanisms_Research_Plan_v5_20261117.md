# CoImagine v5：重叠局部程序的检索、接管与语义整合

日期：2026-11-17。状态：研究计划已确认，新增对照与双臂验证尚未实施。

本文承接 [v4：局部程序行为的接管、整合与组合泛化](CAP_Semantic_Handoff_Research_Plan_v4_20261116.md)，保存近期关于重叠 CAP、机械臂应用以及导师建议的混合基线讨论。后续研究定位以本文为入口；v4 的历史证据、信息边界与接管要求继续有效。本文不改变已经冻结或正在执行的实验协议，不启动新的模型调用、训练或三维仿真。

## 1. 研究目标

> 多个在同一任务分布中局部有效、能力交叉重叠的 CAP，能否通过真实接管状态上的修复和监督整合，以较低的增量开发成本，积累可在未见布局与操作组合中复用的能力？其中，场景检索、动态程序路由和扁平语义—动作评分，分别解决了什么问题？

研究对象不是互不相关的技能类别拼接。同一复杂操作任务可能被多个 CAP 解决，但它们的适用条件、失败模式和执行路径不同。新 CAP 可以重点解决当前未覆盖案例，不要求每次修改后独自兼容全部旧案例。

“MoE-CAP”可以作为讨论这一方法族的简称，但我们的主方法并不要求先选择一个专家：它将各 CAP 的描述语义、分支条件余量、历史信号及动作建议扁平组合，直接评分实体绑定的候选动作。严格的程序级路由是重要对照，不与主方法混称。

系统分工保持为：CAP 提供局部行为与决策依据；监督学习整合行为并保留能力；真实接管失败驱动修复取证；RL 是可选工具，不是本轮机制对照的必要组成。

## 2. 两条相互独立的检验轴

1. **表示轴：**几何表示 G、动作建议信号 A、描述与历史语义 D，各自提供什么信息？已有 G/GA/GDA 对照继续保留；不能把 GA 复制单 CAP 建议解释为描述语义泛化。
2. **整合轴：**给定同一冻结 CAP 库和经验，初态选程序、逐步切换程序、学习程序路由、扁平动作评分，哪种机制足够？

先固定表示比较整合机制，再对关键方法增加相同语义输入；不一次展开所有组合。现有低样本收益或某轮留出差异，不能自动回答整合机制问题。数据覆盖、可训练性和闭环行为仍须分开检查。

## 3. 方法与最小数学定义

令 \(h_t\) 为允许读取的实际观测—动作历史，\(x_t=E(h_t)\) 为冻结表示，\(P_i(h_t)\) 为第 \(i\) 份 CAP 在该历史下的建议动作。动作包含操作实体、联合技能、方向/速度及执行尺度。

### 3.1 初态检索，整程执行（R0）

建立开发初态及各 CAP 执行结果表。最简单版本找最近初态，选该初态上的成功 CAP；较稳健版本对 k 个近邻按距离加权，选择局部成功率最高的程序：

\[
\hat p_i(x)=\frac{\sum_{j\in N_k(x):y_{ji}\text{已观测}}w_j(x)y_{ji}}
{\sum_{j\in N_k(x):y_{ji}\text{已观测}}w_j(x)},\quad
i^*=\arg\max_i\hat p_i(x_0),\quad a_t=P_{i^*}(h_t).
\]

\(y_{ji}\) 是 CAP i 从开发初态 j 开始的完整任务成败。未测试不是失败；无支持、无成功近邻和并列时采用预先冻结的回退与破平规则，不能在线试跑所有 CAP 后选择。k、距离、归一化和回退仅在开发/验证集确定。

选定 CAP 之后仍在每个 option 边界闭环决策，不是开环重放成功动作序列。它检验“任务开始时识别适用程序是否已经足够”。

### 3.2 逐边界检索，动态切换（Rt）

成功快照库包含成功轨迹的**中间边界**，而不仅是初态。条目至少保存表示、CAP 身份、真实历史引用和后续结果：

\[
\mathcal D_{\rm prefix}=\{(E(h_{j,t}),i,y^{\rm suffix}_{j,t,i})\}.
\]

最小 Rt 在每个 option 边界检索最近的成功条目，调用其所属 CAP 输出当前动作；执行后重新检索。固定每轨迹采样规则，避免长轨迹因条目更多占据近邻。保留失败轨迹与接管尝试；利用正负证据估计局部成功率属于另一个显式增强版本，不与“只检索成功快照”混报。

**历史上由某 CAP 成功经过的状态，只是相关证据，不是该 CAP 能在新历史下接管成功的标签。**其他 CAP 从同一历史能否成功，在实际尝试前是未知。检索查询不得读取测试场景的未来结果或仿真隐藏量。

初版在所有合法 option 边界允许切换；最小驻留时间、滞回或切换惩罚如有需要，作为后续独立对照，不能只给目标方法增加稳定机制。

### 3.3 学习式程序路由（LR，第二阶段）

\[
i_t=\arg\max_i q_\theta(E(h_t),i),\qquad a_t=P_{i_t}(h_t).
\]

它与 Rt 都选择一个完整程序的当前建议，区别在于适用性由学习函数判断。训练使用同一经验池；真实接管成功、失败与未尝试应区分。多个程序都可成功时不强制构造唯一正确专家；专家建议相同的边界也不能凭专家 ID 变化宣称行为变化。

该对照用于判断：学习收益是否只需要一个更好的程序路由器，而不需要拆解程序知识。

### 3.4 扁平语义—动作评分（F，主方法）

\[
\Phi(h,a)=\operatorname{concat}_i\phi_i(h,a),\quad
\ell(h,a)=f_\theta(\Phi(h,a),\operatorname{enc}(a))
+r_\psi(E(h),\operatorname{enc}(a)),\quad
a_t=\arg\max_{a\in\mathcal C(h_t)}\ell(h_t,a).
\]

语义包括描述、条件余量、历史与动作建议；几何残差贡献受正则约束。先令候选为各 CAP 的完整合法建议并集，与 LR 保持相同动作支持；去重且记录多重建议来源。随后再开放基础动作或机器人间建议重组，单独测量额外动作自由度的作用。不能把支持扩张的收益全部归因于语义组合。

固定快照输入的 R0/Rt 是导师建议的最小基线。历史表示另设匹配版本：若主方法使用历史，须提供相同历史信息的路由/检索对照，不能将信息权限差异当作架构差异。G/A/D 的具体定义沿用对应实验封印，不静默替换已有模型输入。

## 4. 真实接管与公平比较

- **统一记忆协议：**每个 CAP 的记忆必须根据实际执行的动作与观测更新；未选中的 CAP 不能认为自己的建议已执行。可通过前缀重放恢复，也可做同值增量更新；记录成本。不得加载另一条示范的私有阶段变量。不能恢复的 CAP 明确标记接管不兼容，不能把它的失败归因于检索本身。
- **统一运行信息：**快照和语义只读本实验允许的观测、公共信息与合法历史。全局可观测与部分可观测分开登记。实体 ID 仅用于绑定；匹配须处理实体排列与数量变化，不能用场景 ID 近似检索。离线物理快照仅用于诊断复播。
- **统一经验来源：**索引、路由器与评分器使用相同开发经验池；公布各方法实际使用的字段及新增标注成本。失败数据不能删掉，未示范动作不自动算失败。相同数据、相同累计成本两种比较分开报告。
- **统一执行约束：**冻结 CAP/技能/控制器、动作尺度、合法性、任务时限和成功判据；接口错误与物理失败分列，均保留。公共非法建议处理一致，回退不能隐含额外搜索预算。
- **统一数据划分：**按原始场景、扰动家族和完整执行前缀分组；同轨迹相邻快照不能跨训练/测试。已查看并用于修订的留出降为开发诊断，另设未见测试。表示归一化、索引和超参数均在测试前冻结。
- **公平开发预算：**冻结库比较之外，另比较相同累计开发预算的单份持续修订 CAP 与多个局部 CAP。不能用“每份 CAP 相同预算”掩盖库的总预算更大。相同技能和预测资源下的有限搜索规划器作为机械臂任务参照，不能称精确 oracle。

部署延迟包括 CAP 求值、记忆维护、语义、检索或网络推理；GA/GDA 若仍调用原程序，不称为已经完全蒸馏或必然更便宜。

## 5. 指标、诊断与可能结论

主要指标为完整任务成功率、时间/动作成本、教师可解范围保留、教师并集外新增成功、增量开发成本与部署延迟。教师从初态的成功并集是事后参考，不是可部署策略，也不是动态切换策略的理论上界。

机制指标包括切换次数、往返切换、建议冲突率、实际动作变化、接管后成功率，以及检索置信与实际接管结果的关系。自然切换后的成功率有选择偏差，不能直接当作切换的因果收益。

选择少量开发或预注册诊断边界，恢复相同物理状态与合法历史，分别测试保持原 CAP 和切换其他 CAP；保留相同剩余任务预算并计入前缀重放成本。这些分支仅用于离线诊断或已声明的训练取证，不作为测试部署时的免费先知选择。

| 配对观察 | 支持的解释 | 仍需排除 |
|---|---|---|
| R0 已接近整合方法 | 初态适用范围划分可能足够 | 分布是否过窄、是否缺少任务内变化 |
| Rt 优于 R0 | 执行中程序接续具有价值 | 索引规模、表示与数据不匹配 |
| LR 优于 Rt | 学习适用性优于当前距离规则 | 不合理距离、密度偏差和调参预算 |
| F 在相同候选支持下优于 LR | 动作条件化的扁平整合可能有益 | 容量、监督目标和信息差异；并非单独证明语义贡献 |
| 相同 D 加入检索与学习方法都改善 | 描述语义可能改善状态表示 | 是否附带额外历史或隐含动作建议 |
| 离线存在成功接管，但部署选错 | 已有行为可用，选择机制待改进 | 候选缺失、记忆恢复和执行接口错误 |
| 所测 CAP 均无法接管 | 当前库缺少已找到的恢复行为 | 预算有限，不能证明不存在可行解 |

报告每个场景的配对结果、分母、置信区间与失败类型；同轨迹多个边界不当作独立场景。学习方法在预算允许时做多个训练 seed。负结果也应形成可复现的适用边界与机制证据，不能仅以“复杂方法不如简单方法”预先宣称贡献。

## 6. 后续机械臂验证域：有限暂存空间中的目标取出与转运

**任务：**两只机械臂在随机杂乱布局中，通过抓放、推动和接续，将指定物体送到出口；可达空间与临时放置空间有限。

应用原型是药房的盒装药品取用、冰箱内不同深度的刚性食品盒取出、仓储料箱与工作站物料取用。这是应用动机，不宣称第一版涵盖药品核验、食品卫生、柔性包装或实际生产认证。

### 6.1 最小设置与自然变化

- 两臂部分重叠的工作空间；先有限台面，再增加刚性侧壁、隔板或浅货架。
- 起步约 4–8 个盒子或瓶罐等刚体；随机尺寸、位置、朝向、目标身份、出口位置及暂存区占用。数量是待先导确认的设计值，不是已执行配置。
- 共同基础技能：抓取、放置、短推、空手移动、交接；动作绑定物体、机械臂、目标位姿及尺度。需要实际验收运动学、碰撞、抓持和交接，不能用悬浮夹爪结果代替完整双臂验证。
- 同一目标与成功判据下，自然出现直接取出、侧推清障、抓取暂存、先腾空位、换臂接续。无需人工给场景标注技能类别，也不强制某个阶段序列。
- 第一版要求目标送达、其余物体不掉落并满足允许放置约束。恢复所有物体原位是后续独立任务条件，不在首版隐含加入。

初态生成检查非重叠、稳定放置、目标与出口几何合法，并记录拒绝率；这些条件不保证动态可解。允许简单直接抓取解法，不人为禁止合理行为。保留不可解或尚未找到解的案例与总分母；另列有成功见证的诊断子集，不按目标方法成功筛测试。

关键随机变量应包含抓取访问方向、遮挡关系、共享可达区与暂存容量，不能仅增加物体数量或视觉背景。初期可用统一的全局物体观测隔离整合机制，部分可观测与历史依赖作为显式后续条件；具体观测协议须在实施前确定，不能因此放宽现有 2D 封印。

### 6.2 平台与文献依据

- [Vulcan Pick](https://www.amazon.science/publications/vulcan-pick-a-robotic-system-for-picking-targeted-objects-from-fabric-pods)：提供拥挤货架指定物体拣选的真实生产背景；其柔性货架与包装不属于首版复刻目标。
- [主动感知与受限空间重排取物](https://arxiv.org/abs/2411.11733)：研究观察、搬走障碍、寻找临时空位与取出目标的联合规划，支持任务结构的现实性。
- [双臂非单调桌面重排，IROS 2022](https://arxiv.org/abs/2207.08078)：物体可能需多次移动，并涉及交接与搬运顺序；适合作为任务与规划基线参照。
- [双臂密集杂物推—抓，RA-L 2025](https://sites.google.com/view/pg4da/home)：证明推抓协同有明确任务基础，但专门方法已在其设置中表现很强；物体多不自动构成 CAP 缺口，简化夹爪训练也不等于完整机械臂可复现环境。
- [RoboTwin 2.0](https://arxiv.org/html/2506.18088v2)、[代码](https://github.com/RoboTwin-Platform/RoboTwin)、[接口](https://robotwin-platform.github.io/doc/usage/API.html)：优先考察其双臂技能与代码生成基础设施；我们的操作依赖、有限暂存区和任务生成器仍需开发，现成随机干扰不保证具有该结构。

文献支持任务困难与仿真可行性，不证明当前 Sol 在给定预算下必然无法用单份 CAP 覆盖。平台选择仍需工程先导，尚未安装或运行机械臂实验；当前计划只做仿真，不安排实物实验。

## 7. 执行顺序与验收

1. **先在现有 2D 库上验证接管接口。**冻结库、经验与表示；检查同 CAP 重入是否恢复原动作，未被选中 CAP 的记忆是否随真实历史更新，非法输出与索引回退是否一致。
2. **最小机制比较。**固定最佳单 CAP、R0、Rt、已有 F；F 先限定建议并集。先用开发诊断确认索引和执行可用，再冻结独立留出与预算。已公开的旧测试只作诊断。
3. **定向补强对照。**加入 LR、相同历史表示以及几何/语义匹配的检索版本；根据诊断决定是否需要接管标签扩充。开放基础动作的收益另列；不同时启动 RL。
4. **双臂工程先导。**基础技能可靠后，拟用约 50–100 个随机开发场景、少量 CAP 检查难度与互补性；这些是候选规模，正式次数和预算由任务书冻结。若单 CAP 或常规规划已经覆盖充分，则报告边界，不通过临时修改任务制造优势。
5. **有互补性后再做监督与跨布局测试。**检查覆盖重叠、独占覆盖、真实接管与未见组合；区分同分布随机种子留出和关系结构/暂存容量变化的外推。

先导成功意味着管线可复现、基础技能可靠、信息与预算公平，并得到可解释的结果；不以目标方法必须胜出作为工程验收条件。完整实验任务书仍需明确模型档位、CAP 数、场景数、仿真预算、训练 seed、停止条件与留出封印。

## 8. 与 v4 的关系及证据入口

保留 v4 的主张：局部求解、真实接管修复、监督积累与未见组合复用。此次新增三点：

1. 明确关注同一任务族内交叉重叠的程序能力，而非天然互斥的专家类别。
2. 将导师提出的两种检索混合基线纳入核心对照，并用学习式路由连接检索与扁平评分，拆开表示、切换、学习及动作支持的贡献。
3. 将有限暂存空间的双臂目标取出确定为后续仿真验证域，近期机制实验仍优先复用 2D。
