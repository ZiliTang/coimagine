# 研究路线讨论：基于物理交互经验的 LLM Option Policy

日期：2026-11-03。状态：**已讨论、作为优先验证方向；尚未接入 API、采集新数据或启动 benchmark**。本文保存用户提出的方向与 GPT 的分析，不等同于正式实验任务书。

## 1. 用户提出的方向与动机

现有平台已经具备可执行的协作 option、逐 tick 测台、事件决策接口和正在学习的 RL 基线。下一步可以先让冻结的大模型通过 API 选择 option，检验能否可靠完成推动任务，不将训练神经世界模型作为前置条件。

使用训练好的 RL 与基于几何、力学的启发式策略混合采集执行数据，把数据组织成 LLM 可以审查、检索和复用的决策材料；之后比较不同经验表示、检索方式和开放权重模型（用户举例 DeepSeek、Qwen）。未来可加入其他物理交互场景。

希望回答的主问题是：

> **怎样组织物理交互经验，才能让冻结的 LLM 在有限决策预算下，更准确地选择与组合技能，并适应未见过的动力学条件？**

“高成功率、安全、平顺”是期望效果，需要独立测量。现有结果尚未证明此路线成立。工程上可以减少训练预测器的负担，论文价值仍取决于清晰的假设、对照与泛化证据。

## 2. 与现有工作区别在哪里

不能将“LLM 调用技能”“多机器人 LLM 协作”或“经验 RAG”直接作为创新点：

- [SayCan](https://research.google/blog/towards-helpful-robots-grounding-language-in-robotic-affordances/)：用技能可执行性约束语言模型的技能选择。
- [Code as Policies](https://github.com/google-research/google-research/blob/master/code_as_policies/README.md)：生成处理感知与调用控制原语的程序。我们的第一版可以只选固定 option，不需要生成控制代码。
- [RoCo](https://project-roco.github.io/)：多机器人语言模型协作、环境反馈与 RoCoBench。
- [PragmaBot](https://arxiv.org/abs/2507.16713)：执行反思、短期/长期记忆、检索增强机器人任务规划。

这些链接在本次讨论中已查阅；不是完整文献综述，也不据此宣称不存在更接近的工作。

我们可优先研究**持续接触下的物理耦合与经验适用条件**：两个分别合理的动作组合后可能引起转动、失去接触或相互阻挡；同一个 PUSH 的效果取决于接触布局、速度组合和机器人位置。研究重点是经验怎样帮助模型判断这些后果，以及何时需要恢复、换面或真实探视。

## 3. 首先比较经验内容与表示

向量库、关系库、图数据库暂时作为实现选择。先将相同来源的数据表达成不同材料，比较决策效果：

| 表示 | 保存什么 | 对应假设 |
|---|---|---|
| 原始执行片段 | 可用观测、联合动作、持续时间、后续观测、结果 | 直接给执行案例是否已足够 |
| 结构化效果记录 | 接触条件、位移、转角、接触保持、耗时、失效原因 | 明确物理量是否更容易利用 |
| 成对对照经验 | 同一起点下，不同动作的实际执行后果 | 对照是否帮助判断动作选择的代价 |
| 带适用范围的经验总结 | 条件、结果分布、样本量、不确定性、原始证据引用 | 压缩规律是否节约上下文且保持可靠性 |

GPT 建议优先验证“成对对照＋适用范围”，这是**待测假设**。普通日志中的近邻状态不是严格反事实；只有确实从同一冻结状态执行的分支，才可标记为成对对照。

检索案例并不自动构成世界模型。如果系统能按当前状态与候选动作输出可检验的后果和不确定性，可以称为经验型动力学模型；如果只是返回案例，应称经验库。神经网络预测器可作为后续对照。

## 4. 数据来源与合法信息

三类互补来源：RL 成功/失败轨迹；几何力学启发式轨迹；在二者选择分歧或反复失败状态做的少量有界动作分支。只收成功会遗漏阻挡、错误恢复和不适用条件。

候选记录字段：执行前合法观测与时间历史摘要、option/挡位、事件结束原因、真实持续时间、执行后合法观测、可测效果、失败类型、来源策略、控制器/观测/动作版本、运行 ID 与原始日志引用。区分请求动作、控制器实际阶段、真实接触与物体效果。

必须统一下列边界：

- 在线 LLM、检索器和普通策略使用同一合法信息；不能通过检索键或自动摘要传入隐藏摩擦、真实中心、完整隐藏形状等答案。
- 仿真真值可作离线评分或明确标注的监督目标；给 LLM 提供的经验内容是否包含特权标签，需要事前固定，不能与纯可观测方案混报。
- 当前 v20 是集中式共享观测基线，不能称 B-bit 去中心化。第一版可沿用这个边界。
- 当前 RL mask 仍保留矩形尺寸先验；未知形状主张之前必须剥离并重新验证。
- 各方法使用相同动作空间和控制器。增加 PUSH＋REPOSITION 等组合时，须给所有比较方法一致的接口。
- 固定经验数据量、可访问信息、检索条数/上下文与在线调用预算。更丰富的数据和更长推理预算需要分别报告。

经验总结应能回溯到运行证据，并保存反例、支持数和适用范围，避免将一次成功总结成普遍规律。

## 5. 第一轮验证提案：先做实一个阻挡实例

用户观察到：机器人在物体相反一侧时，有时停着挡路或被物体推着走，未主动绕行。当前尚未锁定唯一 run/tick 并完成因果诊断。WAIT 实现为主动制动，不等于主动让路；PUSH 也不应隐式扩展为绕行。

建议顺序：

1. 用户选定一条具体失败回放，展示双方动作、法向匹配、q、实际接触、参考速度、控制力和物体位姿变化，先分清策略选择与执行器失配。
2. 在现有合法动作菜单下确认可行序列；当前排除了 PUSH＋REPOSITION，因而一机继续推、另一机同时让路并不可选。能否先停推再绕行，需要实测。
3. 接入一个冻结模型，在相同事件边界输出严格结构化联合 option。
4. 比较“仅技能说明 / 普通执行案例 / 成对效果记录”。先看是否改变对阻挡与绕行后果的判断，再看闭环效果。
5. 有明确差异后，扩展少量初始位置；最后才增加模型、任务和经验表示矩阵。

本提案没有规定已授权的 API 费用、模型、次数或上线计划；需另设具体实验配置。当前用户授权的是文档持久化与 Git 同步。

## 6. Benchmark 的必要对照与指标

比较 RL、几何启发式、无经验 LLM、经验增强 LLM，以及直接利用同一经验库的简单近邻策略。近邻对照用于判断收益来自经验覆盖还是 LLM 的组合能力；不预设 LLM 必须超过 RL 才有价值。

除成功率/停止判稳，还报告任务时间、无效推动、恢复与切换次数、非预期转动、阻挡/碰撞、接触保持、力/速度突变，以及 API 调用数、token、墙钟延迟。仿真等待 API 时若暂停，应区分仿真时间与实际运行延迟。没有严格安全性质时使用“风险/平顺指标”，不宣称安全保证。

增加独立的动作后果预测或候选排序诊断，避免把任务成功等同于“理解动力学”。开放权重模型应固定权重版本、推理配置与量化方式；API 模型保存准确标识、日期与原始响应。检索库与测试集按内容和任务族隔离，防止同根或近重复泄漏。

可依次测试新初态、不同接触布局/速度、未见动力学与形状。仅扩大相同矩形随机位置集合，难以证明动力学适应；外观/局部观测相同但隐藏动力学不同的实例，需要合法历史或有成本探视才能区分。

## 7. 对导师的简明定位

我们已经建立可执行、可观测的协作技能平台，并获得可采集有效行为的 RL 基线。下一阶段研究如何把物理交互经验组织成可检索、可核查的决策证据，帮助冻结的大模型在未见条件下选择和组合技能。神经世界模型保留为一种可比较的实现，不再是研究成立的前提。

先以当前推动平台检验经验表示的作用，再决定是否扩展成 benchmark 或加入其他物理交互场景。该调整保留此前围绕合法信息、动作后果、执行反馈与有限计算的研究问题，同时降低对单个学习模型训练成功的依赖。
