# 逐动作检查反馈能否改善 CAP 作者的整局表现

在同一批 64 个新房间，检查反馈组和普通开发组的定稿都只解决了 3 间，成功名单完全相同。检查反馈确实改变了作者写出的策略。它在 41 间发出了不同的动作，却既没有救回也没有丢掉一间。两组较强的历史前身独立解决了 38 间。实验共完成 256 次主评测和 64 次选版补测，全部从房间初态执行，宿主异常为零。

## 同一面板上的五份程序或选版

四个障碍分层各 16 间。两位 GPT-6.2 Sol 作者有相同母程序、公开指南、16 个开发房间和最多 3 版、20 分钟的开发预算。两组都须申报判断并通过交卷检查。检查组开发时额外看到当前程序的逐候选审查和动作执行后的公开观测核对。全部程序使用固定 72 束观测、原 PUSH 事件执行器和相同的 G程序.v1，无外加恢复分支。

| 角色与选版 | 开发成功 / 16 | 新房成功 / 64 | 较共同起点救回 / 丢失 |
|---|---:|---:|---:|
| 历史较强前身 P绕行.v1 | 13 | 38 | 37 / 2 |
| 共同起点 P保守推进.v1 | 2 | 3 | — |
| 普通开发组亲选，保留共同底稿 | 2 | 3 | 0 / 0 |
| 检查组亲选，trial03 | 3 | 3 | 0 / 0 |
| 普通开发组按开发成功数选，trial01 | 5 | 13 | 12 / 2 |

较强前身的开发成绩来自同一批房间的归档，表中五行的新房成绩均来自本轮。普通组定稿为通过公共审查接口的母策略，64 间的实发命令、终局历史和成败都与历史母策略相同。主比较的 0/64 个成败分歧不能证明其他房间或其他作者也会打平。程序组合、逐房间结果和配对区间可分别查阅。[冻结身份](compositions.json) · [逐房间成败](rooms.csv) · [主比较](result.json)

**选版标准会改变对结果的解释。** 普通组 trial01 在开发池救回 5 间、丢掉原有的 2 间，作者宁可交回母策略。检查组 trial03 在开发池救回 2 间、丢掉 1 间，作者接受这次取舍。两组定稿后、读取任何留出成败前，补充登记了统一按开发成功数选版的对照。普通组 trial01 在新房解决 13 间；相对检查组，独胜 12 间、独负 2 间，净差 +15.6 个百分点，按房间分层做配对自助抽样的 95% 区间为 [+6.25, +26.56]。这是同一对作者的补充分析，无法估计换作者后谁更好。[补测登记](selection_sensitivity.md) · [补测程序](selection_composition.json) · [逐例补测与配对统计](selection_result.json)

## 改程序后，为什么没有多解决房间？

两位作者从公开轨迹中都很快发现机器人反复换位、有效推动不足。三个预先选定的检查边界均是程序找到一个合格推动后停止搜索，每处菜单还有 31 个符合其内部条件的动作对。在这些边界，较早停止搜索是合理行为。看到其他动作通过审查，并不能据此判定那些动作在故障发生处更有用。实际使用量也有差异。普通组完成 16 个房间次，检查组完成 32 个房间次。两组各自用完 3 次提交机会，分别有 2 份和 1 份在进入仿真前被拒。两位作者都在约六分钟时完成定稿。[逐版预算、失败提交和开发笔记](development.md)

检查组保留原先的绕行，在持续停滞后才尝试替代推法。与普通组定稿的首次动作分歧出现在 **41/64** 间，中位数是第 **951 tick**。其中 **40** 间从原来的非目标推动改成推动任务箱。只有 **5/40** 在这条新命令期间实际使箱体靠近目标至少 2 cm，原命令对应为 **2/40**，两组位移收益中位数都是零。命令时长和建立接触所用时间可不同，因此这里衡量的是这条指令结束时的效果。最终成败相同仍以实际跑完整局为依据。[共同前缀与每条命令的实测](first_changes.csv)

按事先选定的 4 个房间复核程序自己写下的 PUSH 终点范围，母策略有 **74/118** 次的真实箱体位姿落入承诺范围，检查组为 **70/116**。其余命令部分超出沿向、横向或转角界限。这个小子集没有显示预测变准。另用同一套跨任务检查规则核对可见性、单步进展及实际后续进展；这些宿主指定的 2 cm 指标与程序自己的许可范围分开保存。[作者承诺与真值](issued_permits.json) · [统一指标的逐动作判定](effect_audit_rows.csv)

## 对研究路线的判断

这轮支持把“前提、动作结果、后续可行条件”做成可共用的作者接口。深柜里的四个合成例子能够区分抓稳之后可以直线撤回、会被挡住、因遮挡而无法判定。它们验证了接口的表达能力，真实机械臂上的策略改进仍待检验。[深柜接口检验](cabinet.md)

这轮没有提供证据，说明向作者增加这些检查反馈就能写出闭环更强的策略。从现有记录看，更值得优先解决的是“在具体失效的前缀，哪种替代动作确实能建立接触、推进任务，并留出后续操作空间”。下一次宜从较强的 P绕行.v1 出发，把同一故障前缀下的实际分叉证据交给作者；事先约定如何权衡救回与丢失，并把可修复的提交格式问题和可用的仿真次数分别记账。
