# PUSH 执行、专家分工与语义评分的交叉对照

前导对照的两个 CAP 在一张 200 个房间的留出面板有从 38.5% 到 44.75% 的平均改善，主要变化是拆分后末段推速调整。本轮单独复验调速的时机，再用既有常规四成员库和半开放语义专精四成员库进行更完整的对照。两个库此前由同预算的独立作者从同一个通用 CAP 写出，共七个独立冻结程序。保持各库成员和作者产物，交叉执行器，重新从每个控制条件的真实成功轨迹拟合混合评分器。

- 执行器采用原一体化头，以及经 CONTACT 证实接触、PUSH_FROM_CONTACT 续推并在目标附近调整速度与时长的版本。相同物理和命令时长上限。每局限制 1,800 ticks 与 300 个实际边界。非单翻译 PUSH 动作直接交原控制器。
- 评分器共享候选动作 MLP、两个 64 维隐藏层、Adam，8,000 次更新，batch 64。原始输入包括公开几何、两台机器人的显式动作参数、提案程序与剩余预算。四组分别激活零、三个通道语义量、候选接触语义量，或者同时激活两者，输入宽度相同。
- 通道语义沿用作者选择的静态阻挡、可动阻挡和近墙目标。候选接触语义含推手是否接触已绑定目标，是否能看到相容法向，从当前机器人位置到准备位的距离和估计净空，以及此前同一推向的机器人运动。输入在执行之前从公开数据计算。
- 每种执行器、每个库都单独选择每个开发房间最快成功的固定程序并重放为教师。教师动作与现场合法去重候选逐一匹配。只训练存在多个候选的边界，从成功教师原样获得监督。没有用评估集选种子或权重。
- 训练 400 个开发房间，160 个为既有作者开发池，240 个为新生成自然场景。测试是两张 200 自然房间的新面板，覆盖 2–5 个物体。全部新样本按去掉场景身份的内容哈希核对历史场景。两执行器下各库各四组输入，seed17、29、43，共 48 份模型。
- 主结果为逐房间、先平均种子后的成功率增量。还报告各 seed、两张面板及每个执行器内的最佳开发单 CAP、成功并集、按初态语义标签固定选专家、混合的闭环与并集保留。房间区间以面板和物体数分层配对重抽，同一房间重复跑的种子属于同一观测簇。

并行的调速对照有五组。一体化原速、一体化在动作开始按距离限速、一体化仅在提案前已有接触证据时限速、自动拆分仍按原速、自动拆分且接触后限速。两 CAP 在又一批 200 个随机房间配对比较。另外，开发房间比较常数限速、收窄触发距离和沿动作方向估算进入目标内圈的所需行程。在开发集固定选一个调整版本，随后与常数限速进行配对复验。
