# 从 A 的故障轨迹开发接手专家 B

保持上一轮通用 A（usual s003）和 split_precision 执行器。200 个旧开发房间中依照 A 的实际行为，在 180 至 1150 tick、至少 5 条命令后检测公开故障条件。候选包括四条命令内可见距离改善不足 3.5 cm、分接触与未接触、碰静态障碍、近目标停滞、持续不可见。在至少有 16 个失败及 8 个自恢复房间的族中，按触发后整局失败且末八步至少两次仍有同类故障的比例排序。取 16 条失败、8 条相同触发条件下 A 可以成功的开发前缀。每个 revision 从同一历史（含专家记忆、消耗的 ticks 与决策）交接给 B，一直执行至任务终止。作者只看这 24 个开发案例的公开状态、动作、结局和试跑反馈，可修改 A 源码。最多三版，由 gpt-6.2-sol 作者选一版，authoring_v2 验证冻结后运行正式评价。

路由转移训练使用其余 176 个开发房间，分别自然执行 A、B、在首个 X 后保持 B、在 X 后随机按一至十二条命令成块采样 A/B。路由节点仅含公开的目标可见性与估计距离、目标接触、最近推进及静态接触。边为一个完整 CAP 提案，记录真实后继、实际耗时及消耗的决策预算。以成功和失败为吸收节点，训练有限预算下的最大成功可达概率表。每个真实边界使用剩余预算重规划，保留 A 作为低支持或相等时的选择。图与简单触发均沿 A 进入同一个首发条件 X，才允许接手。简单规则此后保持 B；图可继续 A、选择 B 或再交回 A。

用另 200 个按内容排重的新房间做配对确认。比较全 A、全 B、首次 X 交给 B、X 后图路由的整局成功与实际救回/丢失。以同一 A 前缀的自然后缀和锁定 B 后缀测接手优势，以图相对简单规则的配对净差测路由增益。两者分别给出按房间重抽的区间；作者案例只作开发反馈。单轮、一个作者和一个任务族的结果不能独立识别定向提示优于通用提示的因果作用。

另在确认前固定一项免新增仿真的图诊断。在同一转移表上分别固定后续全 A 和全 B，预测首次 X 的两种锁定成功概率。利用已真实执行的两条后缀检查分歧房间的排序，以及只在 X 比较两个数、选一次然后保持的整局效果。
