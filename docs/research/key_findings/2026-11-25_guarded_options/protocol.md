# 让 CAP 的动作选择和后果声明来自同一份程序

我们要验证一个具体能力。作者写“在这种观测下，推一小段以后我还能换到箱子另一侧”，检查器应当能指出这句话在哪种情况下成立，或者给出会接不下去的具体数值。作者可以用 Python 计算几何量或搜索候选。进入本次检查范围的决策只接受约定的规则格式，执行器从被检查的规则取出动作。

## 谁提供什么

| 提供者 | 内容 | 推箱例子 |
|---|---|---|
| 任务宿主 | 公共观测如何转成带单位的区间、动作及其真实绑定、各动作的前提、结果范围和依据、执行后能看见哪些信号 | 墙距读数为一个区间；同伴让行允许移动；命令占用的 ticks 不超过上限 |
| CAP 作者 | 按优先级排列的规则。每条填写何时用、用哪个动作、预期哪些变化、看到哪种结果后具体做什么 | 墙距在给定范围时选短推；下一次看见可用空间时选择换面 |
| 检查器 | 对宿主列出的每类公共读数，检查实际会选中的第一条规则和所有允许后果，返回证据及未覆盖的观测类别 | 某个后果下只剩 8 cm，但指定的换面需要 15 cm |
| 运行器与测台 | 运行器从当前公共读数取被允许的命令，在下一边界依实际公共信号取后继；测台另行记录实际发出的控制与物理结果 | 把两个机器人的动作和上限交给真实 option 接口；用箱体位姿真值离线核对承诺 |

普通作者程序无权自行把“同伴静止”登记成环境保证。新的感知量、公开结果符号、动作参数或控制器版本都需要宿主给出含义。宿主漏掉一种可能的物理结果会使证明失去对应的物理解释，这个风险需要独立的测台揭示。

## 可检查的最小语言

初版只支持有优先级的规则、区间条件的合取、有限个动作与有限个可观测分支。一个传感区间须**整体落入**条件才启用该规则。例如，要求障碍至少有 15 cm 间距时，测得 12–18 cm 不足以启用。多条条件可以并列写成多条规则表达备选情况。区间端点为有单位的整数，允许单边未知；结果可以取常量、执行前的量、动作效果，或同单位的区间加减。初版只检查到下一条具体动作的入口。

用三个集合说明检查内容。记 \(X\) 为当前公共读数允许的真实状态集合，\(a\) 为规则选中的动作，\(D_a\) 为宿主给出的开动条件。记 \(T_a(X,o)\) 为从 \(X\) 执行 \(a\) 后、下一个公共观测为 \(o\) 时允许的后继集合，\(b(o)\) 为规则在看到 \(o\) 后实际调用的动作，\(D_{b(o)}\) 为它的开动条件。检查要求

1. 当前动作可开始，\(X\subseteq D_a\)。
2. 宿主允许的每种动作变化均落在作者承诺的区间内。
3. 对每个可能出现的公开结果 \(o\)，均有 \(T_a(X,o)\subseteq D_{b(o)}\)。同一种读数对应两种隐藏状态时，两种状态都得允许执行同一个 \(b(o)\)。观察能区分左右通路时，才可以选择不同的接续动作。

程序逐个枚举宿主提供的公共观测类别和结果分支，使用区间包住集合。反例是违反包含关系的模型取值；真实物理是否到得了该取值，需要另查。经验区间可以用于提出试验，但只能得到“按现有估计成立”。模型缺项、规则没有覆盖当前观测、或者只会停止，都有单独的输出。在单一测试程序中可以同时存在获准和拒绝的输入。宿主须根据当前输入逐次决定。

## 验证顺序

| 层次 | 对照与记录 | 判定 |
|---|---|---|
| 规则本身 | 相同当前墙距，短推与长推都满足入口；再改变同伴位移、后继可观测性、模型依据。增加一个只涉及抓取后宽度和柜口净空的深柜算例 | 短推与长推因换面条件得到不同判定；同观测的隐藏分支不能偷看真值；全停和未知不能获得已证通过 |
| 真实发令 | 在原 16 个开发初态，允许同一公开菜单中的 PUSH+YIELD；给本次局部动作链 8 ticks，后续制动需要 2 ticks；只改变第一动作上限 6 或 8 | 检查获准的实际请求、物理控制段、实际时长和下一请求；被拒绝的版本不得发到执行器。这只验证命令与时间 |
| 后果的依据 | 针对同一个冻结程序，先用 16 间开发档案计算两个推进档位的箱体位移范围；在另外 64 间已查看的历史房间核对范围及原程序承诺。用相邻公共里程计核对同伴 | 报每档分母、越界房间数、动作数和一个可重放反例；同房多次动作不当作独立房间 |
| 同一起点改变推进量 | 取编号最小的六间开发房，每间寻找首次公开条件合格的接触 PUSH。配对时保持同一条已发生的前缀、同一推手方向和同一同伴命令，只改结束条件 | 给出可复现前缀数、实际到达进度事件数、箱体位移以及下一命令的公开可下发性。未触发与不匹配单列；两档端点都保持菜单合法也照实记录 |

声明有三条界线。箱体端点合格仍可能在途中发生碰撞；下一动作能开动仍可能无法完成；局部动作都能接上仍可能永远循环。各层分别记录实际发令、物理推进与后继效果，可以防止通过缩到几乎不动来“改善”规则分数。

## 怎样进入下一轮 CAP

最值得交给作者的材料是一条真实局部反例及与它起点相近、同一后继动作确实完成的对照。先把任务缩到一个可以观测的承诺，例如，换面后指定机器人能否在固定预算内与目标的指定一侧建立接触。开发房间用于定义公共条件、误差范围和“接触建立”的事件；按房间冻结新的诊断集，原样核对。

先固定一份规则、一套候选动作和同一批前缀做消融。第一种只检查当前动作前提，第二种再检查作者预期和后继条件。在测台对获准和被拒绝的候选都做配对分叉，避免只看到放行后的结果。用于评价的后继取程序在该次公开观测下实际选的动作。建议首轮用 16 个开发房间制定观测条件和局部动作预算，再用 32 个新房间，每间最多两个预先定义的合格边界。房间没有合格边界也计入覆盖分母。

主要报告三个量。放行误判率是“放行但后继没有在预算内达成”的次数除以放行次数；误拒率是“被拒但实测后继达成”的次数除以实测后继达成次数；有效覆盖是“放行且后继达成”的次数除以全部受测候选数。分母为零时报告未定义，按房间配对汇总。若误判下降但有效覆盖也下降，需要展示哪些可用路线被丢掉。另记停止、重复换位和整局成败。

通过这一步，再比较普通编程组和规则组能否开发出更好的 P。两组获得同一个起始 P、公共输入、开发房间、分叉工具及时间预算，都可提出短推、主动观察、换面或停止。规则组获得可执行声明及检查反馈。这样的作者对照测的是整套开发方式的作用。

### 多轮校准以哪一版为基准

以吸收本轮系列新增分叉数据之前冻结的第 0 版为主对照。第 0 版已有初始动作效果模型，也可在判断不确定时调用单步仿真。为检验校准本身的收益，固定 CAP 规则、候选、接续标准和临场仿真的触发规则与预算上限，各轮只更新效果模型。各版冻结后在同一批未参与调参的新房间、相同决策前缀和候选上配对复测。到自然部署时的整局成绩另行记录。

主比较为最终版相对第 0 版，每轮相对第 0 版的累计变化及相对上一版的增减一并报告。有效覆盖率允许下降的幅度、放行后接续失败率允许上升的幅度，都要在查看确认结果前定好。两项均满足约定后，再比较每百个受测决策触发的临场仿真次数；开发采样和离线测量的仿真另行计数。这里登记的是后续实验口径，容差数值尚待确定。
