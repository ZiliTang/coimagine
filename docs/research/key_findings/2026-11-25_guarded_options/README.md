# 可执行规则能否在 PUSH 前发现下一步接不上的情况？

第一版已经能读取独立的作者规则和宿主模型，逐个检查动作，并让真实执行器调用获准的动作。它能抓住两种编程错误：作者把未来效果写得比宿主允许的更确定，或者其指定的后继动作在部分允许后果下无法开始。真实推箱的主要困难在于找到可信的效果范围，以及把后继动作的前提定义得足够贴近机器人实际要做的事。[设计与验收条件](protocol.md)

## 一个能手算的例子

箱子离墙 28–32 cm，短推和长推当前都能启动。假设短推让箱子向墙移动 4–8 cm，结束后余 20–28 cm，下一步换面至少需要 15 cm，因此允许短推。长推移动 15–20 cm，余 8–17 cm，其中 8 cm 接不上换面，检查器拒绝长推，并返回这个端点。这里的四个区间由合成测台指定。换成从样本拟合的范围，同样的短推规则只能得到“有条件成立”。

17 个对照用例都取得各自预期的结果，3 个在指定模型内成立，9 个有模型反例，2 个依据不足，1 个仅按经验模型成立，2 个无动作。用例还检验了从同一条遮挡观测猜左右通路、遗漏让行同伴的位移，以及只有 STOP 可选。将任务换成抓住物体后能否从柜口撤出，复用了同一个检查器和规则格式。深柜采用符号算例。[逐例判定](static_diagnostic.json) · [作者规则](../../../../experiments/planar_tasks/authoring_v2/guarded_push_example.json) · [宿主模型](../../../../experiments/planar_tasks/authoring_v2/guarded_push_profile.json)

## 实际发生了什么

| 测试 | 观测结果 | 能回答的问题 |
|---|---|---|
| 16 个开发房间，真实发两道命令 | 局部窗口共 8 ticks，需要给制动留 2 ticks。16/16 次发出上限 6 ticks 的 PUSH＋YIELD，并执行后继制动；上限 8 ticks 的版本获准 0 次。16 个短窗口里箱体位移都小于 0.1 mm | 在可以严格计算的时间约束下，检查结果确实决定发令。发出了 PUSH 本身不能证明箱体会移动 |
| 冻结程序的 PUSH 端点 | 16 个开发房间中 309/514 个端点落在作者承诺的联合范围内；另 64 个历史房间中为 **1,183/1,953（60.6%）**。联合范围同时约束轴向、侧向和转角 | 可以独立检验作者的物理前提。按两档机器人进度分别取开发集箱体轴向位移的最小和最大值，另 64 间仍有 9 间、13 次越界 |
| 同伴执行 YIELD | 64 间的 107 次 PUSH＋YIELD 中，38 次同伴起止位移超过 2 cm，涉及有此动作的 58 间中的 22 间。确认房 040 的 tick 496–524，同伴移动 31.3 cm，箱子沿声明方向几乎没有前进 | 把同伴当前位置复制到未来，存在实测反例；这类错误值得在作者交卷前报告 |
| 6 间开发房，从同一接触前缀分别推一个或两个进度单位 | 6/6 对复现原前缀。五间短档 9 ticks、箱体轴向前进约 8.16 cm，长档 17 ticks、约 15.45 cm。两端均仍可继续原推。004 的两档都在第 19 tick 卡住，原动作退出菜单 | 两档改变了物理效果，但只有短档保住原后继的为 **0/6**，只有长档保住的也是 **0/6** |

上述 0.10 m 和 0.20 m 指推手在接触中的定向进度，箱体位移另行测量。分叉两端检验同一推手、方向、同伴命令是否仍可下发，以及接触面是否仍可观测；没有执行后续整段推动。六间的合格边界都在 tick 167，其中五间局部响应几乎重合。64 间历史面板之前已经查看；同房多次命令不能计作独立房间。[真实发令](live_commands.json) · [冻结档案端点核对](physical_replay.json) · [逐房间配对](paired.json)

真实轨迹也可以直接给检查器提供依据。例如，从开发房间的 22 次 PUSH＋YIELD 估计同伴端点位移，向外取整得到 0–454 mm。在另一批房间的 107 段中没有越界。检查器把按此区间申报的动作标为“有条件成立”，把“同伴不动”判为有反例。这个例子只检查端点位移。即使这个区间覆盖了所有观测记录，最大 45.4 cm 的宽度也可能不足以决定能否安全从同伴身后通过。

## 下一项决定

先固定作者、候选和前缀，把“只检查眼下能不能推”与“还检查推完以后实际选的动作能否完成”做同前缀比较。优先采集在公开观测上接近换面空间边界的例子，同时保留常规前缀。每个放行和拒绝都可以通过分叉验证。后继指标用“指定机器人在预算内成功换面并建立接触”，它比菜单仍允许原推动作更接近策略需要的能力。要同时统计错放、错拒和有用动作覆盖率。只有这样，才能区分检查器真的帮助选动作，还是仅让程序变得保守。[后续对照和分母](protocol.md)

## 复现

单独检查一份作者程序时，两份输入都可以替换。退出码 0 表示声明域内全部成立，1 表示至少有一类输入未获证明，2 表示输入无效。读取真实房间档案的后三项需要本地实验数据。

```bash
.venv/bin/python -m tools.cap_guarded_option_probe check --program experiments/planar_tasks/authoring_v2/guarded_push_example.json --profile experiments/planar_tasks/authoring_v2/guarded_push_profile.json
.venv/bin/python -m tools.cap_guarded_option_probe --static-only
.venv/bin/python -m tools.cap_guarded_option_live --out /tmp/guarded_live.json
.venv/bin/python -m tools.cap_guarded_option_replay --out /tmp/guarded_physics.json
.venv/bin/python -m tools.cap_guarded_option_forks
.venv/bin/python -m pytest tests/test_guarded_options.py
```

本轮 26 项新内核用例通过，其中包括用具体整数转移独立核对区间加减的结果。相邻协议和运行器的 39 项用例也通过。
