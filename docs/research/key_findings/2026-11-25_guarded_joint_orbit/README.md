# 联合执行层处理绕行冲突

CAP 指定目标物与合法指令，执行层负责两台机器人的短时避让。允许绕行配绕行、让行或等待，两台机器人的次序均可交换。执行器用当前目标的雷达回波和里程计估计相对运动，在本次命令内向前看至多一秒。只有两台机器人正在接近，且预期中心距离小于两倍机器人半径加 4 cm，才触发冲突处理。

双绕行冲突时，机器人 0 保持方向，机器人 1 在本次命令窗口让行；下一条命令重新判断。通常的绕行配让行沿用既有控制；如果让行者已报告受阻且预计仍会逼近，绕行者先制动。原始绕行配等待保留指定执行者，由它绕开同伴。若上层目标是让任一机器人到达箱子的指定面，换面 option 可以在入口交换推手与同伴，然后由同一推手完成绕行、接近和接触检查。目标面和接触标准保持一致。

## 同一起点配对复测

固定原始推进终点。在开发与历史诊断两组各 16 个房间的已保存前缀上，分别运行固定推手和自动分工。每个前缀试两档推进；从各自相同的推进终点计时，120 tick 内在指定面建立接触才计成功。逐项核对公开历史、目标推进量和换面开始时的物理结果。

| 前缀 | 自动换人的候选数 | 固定原推手完成接触 | 自动分工完成接触 |
|---|---:|---:|---:|
| 开发，早期 | 30/32 | 0/32 | 26/32 |
| 开发，晚期 | 0/28 | 22/28 | 22/28 |
| 历史诊断，早期 | 32/32 | 0/32 | 32/32 |
| 历史诊断，晚期 | 0/22 | 10/22 | 10/22 |

此前强制换人会丢掉全部 22 个开发晚期成功；此次逐例全部保留。历史诊断的早期 16 个房间在已记录的九维起点特征上只有两种取值，且同一前缀的两档推进相关。这两组数据支持在已测局面中把目标面与机器人编号解耦。整局成功率、更广几何分布、持续拥堵时双绕行的通行效率尚待评估。
