# 共同自环能否找到旧库覆盖缺口

新 200 房间的早期共同自环标记 23 个，其中 18 个七位全败；其余 177 个中有 33 个全败。 **开发集上的富集在独立面板复现，可以把这条规则用于开发候选池的优先抽样。** 这是根据已执行分叉构建的离线作者采样工具。识别出一个库外房间，距离用新程序解决它仍有一步实际开发的验证。

## 实验

在开发集看到簇 3 富集后，固定以下筛查。A、B 均为冻结专家。每个房间预先指定由 A 或 B 从头执行四条命令。在此时的真实物理簇为 3（三个参考后侧站位均不可用）、且从同一前缀分叉的 A 和 B 各走 120 tick 后仍处在簇 3 时，标记该房间。标记不读取七位专家的终局，遇到窗口内终止不标记。独立确认中，七个不同 CAP 各从每个房间的原始初态自然执行到底，使用同一优化执行器、原有预算，没有窗口截短。共 1,400 个单 CAP 闭环，任务成功并集为 **149/200**。

| 面板与筛查规则 | 被标记房间中七位全败 | 未标记房间中七位全败 | 找回全部七位全败房间的比例 |
|---|---:|---:|---:|
| 开发，固定早期窗口 | 12/16（75.0%） | 31/184（16.8%） | 12/43（27.9%） |
| 独立确认，固定早期窗口 | 18/23（78.3%） | 33/177（18.6%） | 18/51（35.3%） |
| 开发，任一已采边界 | 20/36（55.6%） | 23/164（14.0%） | 20/43（46.5%） |
| 独立确认，任一已采边界 | 31/54（57.4%） | 20/146（13.7%） | 31/51（60.8%） |

早期两组的全败率差为 **+59.6 个百分点**，按独立房间重抽的 95% 区间为 [+40.6, +76.1]。任一边界规则涉及不同房间获得不同次数的检测机会，难题通常能运行更久，作为次要读数。已经用真值和双分支未来筛查，部署时不能照搬。筛查命中也不能证明缺少站位是整局失败的唯一原因。

## 下一项独立验证

从**开发集**选出七位全败、含该现象的房间和保存的具体前缀。两组作者从同一母本、同一困难初态池、同样源码访问和相同开发预算开始。一组按常规的新覆盖目标开发，另一组额外获得图上的故障条件、代表前缀和恢复回放。每组提交完整 CAP，先在另一批冻结新房间测从初态开始的新增成功并集；再从实际 A 路径上的故障点测 A→恢复 CAP→A 与 A 一直继续的配对救回和丢失，同时保留等时长准备对照。应分别记录局部恢复、新成员独立解决的新房间和交接净收益。本次确认房间已用于评价，不能再作为这项未来作者对照的盲测集。
