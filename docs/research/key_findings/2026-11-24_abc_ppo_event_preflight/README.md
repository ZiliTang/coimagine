# A/B/C 路由的 PUSH 中途决策点

现行 `split_precision` 执行器已经支持在认证后的单推过程中询问 actor。稳定接触连续 3 ticks 时询问一次，随后按推手在推进方向的有效接触里程计每 0.20 m 再问一次。继续时保留控制器、目标绑定和剩余时长。改选时用最新公开观测生成各 CAP 提案，经过现有合法性与交接规则执行。当前覆盖认证单推的推进段，双推、移动和接触建立前沿用原有边界。[推进触发和 PPO 入口](../../../../tools/cap_abc_event_ppo.py) · [底层执行器](../../../../experiments/planar_tasks/semantic_rl/duration_execution.py)

## 12 个固定开发房间的验收

使用冻结的 seed 17、2,000 局基础 actor。全部固定继续时，三组逐房间的公开历史哈希、执行 ticks、物理命令数、终止和成功一致，均为 **9/12**，共 **15,811 ticks**。

| 检查方式 | 时间或事件触发数 | 存在合法替代动作 |
|---|---:|---:|
| 原命令边界 | 0 | 0 |
| 固定 0.6 秒 | 209 | 85 |
| 稳定接触及推进 0.20 m | 212（116 接触、96 推进） | 79 |

更早的 0.2 秒接线检查在同样轨迹上触发 707 次。0.6 秒在这批开发房间的检查机会更接近事件组。审计中发现，用含时长的完整命令过滤会把只延长同一控制的提案当作改选。最终版本用目标及两机器人指令判断是否真有替代。独立强制改选的执行中，时间组接受 42 次、事件组接受 62 次。该测试用于走通执行路径，两组均按候选顺序强制改选。

同一批房间分别收集一次随机 PPO 采样并完成更新。原边界、时间、事件组各收集 237、392、422 个训练决策，其中后两组有 60、67 个中途决策。三组的 PPO 采样与训练 log-prob 最大误差均小于 \(3.5\times10^{-6}\)。20 项相关单测通过。逐房间结果、计时和 PPO 检查保存在 `outputs/semantic_rl/cap_abc_ppo_event_preflight_20261124_03/`。[实测摘要](../../../../outputs/semantic_rl/cap_abc_ppo_event_preflight_20261124_03/summary.json)

## 正式对照配置

入口支持从冻结的 20,000 局检查点恢复三个分支，以相同的每批 50 个新房间、奖励、优化器和单局预算续训。固定 64 间在更新前、每千局和预定末轮报告，末轮再评估同一批新 200 间。0.6 秒是开发集校准值，实际路由后的触发次数仍可能分化。沿用每个决策步的 GAE 衰减及每批相同的训练轮数，新增决策会改变物理时间上的优势归因及梯度更新步数。记录包括决策间隔统计、梯度步数、仿真 ticks 和用时。预检覆盖了三组单批更新，20,000 局父检查点上的正式比较尚未运行。[对照方案](../../future_directions/2026-11-24_cap_interruptible_options.md) · [研究日志](http://localhost:8775/research-journal#abc-ppo-event-preflight)
