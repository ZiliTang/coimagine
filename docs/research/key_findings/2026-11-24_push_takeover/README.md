# 在 PUSH 中途给模块一次提前接管的机会

旧的进度复核发生在单推手 PUSH 已建立接触后的驱动阶段。双推手指令直接走普通执行路径。trial09 的新接手条件又要求两台机器人均未接触物体，且已有较长的低进展历史。这些条件适合停滞后恢复，限制了它在正常推动中途预防碰墙的机会。

## 框架与验证范围

新增可选模块回调。对正在推动目标物的机器人，在首次观测到有效接触、以及此后沿本机器人指令方向每累计推进 0.10 m 时询问模块。同一 tick 的双推手事件合并。模块收到当时的公开观测、在执行的动作、该命令还剩多少 tick 和触发原因，可提议另一条合法联合指令；放弃或只改时长就继续原动作。每次真正中断仍消耗决策和实际执行时间。母程序原有复核仍可运行。0.10 m 是本次测台的试验设置。推进量来自机器人里程计，物体可能没有同步移动。

调用入口为 `tools.cap_fault_curriculum_prefix.run_member(..., push_takeover=member.push_checkpoint, progress_m=.10)`，其中 member 为 full 模式的 BranchMember。该适配器通过封存程序的隔离 worker 预览新模块；作者可以在 module_update 中读取事件的 push_checkpoint.reason 和 remaining_ticks。中途试算使用临时记忆，真实执行反馈仍按原协议提交。

## 六个已查看的开发房间

选用原模块开发案例中的四个母程序失败房间和两个自行恢复房间。先全程监听，核对成败、tick、决策数、事件计数及最终公开历史哈希与原记录一致。再在第一次预警时请求一次 4 tick 的合法制动，检验执行器会在该物理 tick 切换，随后由母程序继续。每间各运行两次。

测台用当前公开扫描拟合目标物外形，将其沿指令方向外推，距离取 0.20 m 和剩余时间内命令速度对应路程两者的较小值。双推手分别检查各自方向。用扫过的面积是否含静态回波做一个简单预警。评估端另外记录目标物与固定障碍或场地边界开始接触的物理 tick，只用于事后对照。

290 次中途复核；6/6 仅监听运行复现原终点历史。11 次开始接触中，3 次在同一条命令内有更早的预警。3 个触发制动的房间都在原双推手命令中途实际切换。单次制动救回 0 个原失败、丢失 1 个原成功（126）。126 的第一次预警在 tick 893，同命令内对上碰撞的预警在 tick 986，不能把两者混为一次干预。

这一轮验证了运行中的 PUSH 能交出控制。接下来可在开发前缀上配对测试继续推、改变推向或先换位，把接下来是否仍碰墙、是否还留有绕行空间以及整局成败一起检查。公开外形估计、遮挡和推物方向偏差仍会影响预警效果。
