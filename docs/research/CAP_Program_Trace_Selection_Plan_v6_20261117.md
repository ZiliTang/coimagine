# CoImagine v6：程序执行特征驱动的 CAP 动作选择

日期：2026-11-17。状态：方案确认；自动程序插桩、建议池评分器及新对照尚未实现。后续大计算任务转移到第二台PC。本文件保存方法与实施顺序，不代表已经启动新训练或CAP开发。

## 1. 目标与已有依据

> 在冻结的重叠CAP库中，程序内部计算结果能否帮助一个轻量选择器，以更少的数据判断动作建议的适用范围，并在真实执行中保留这些程序已有的可解能力？

第一阶段主动收紧动作支持：只选择CAP提出的完整联合动作，不要求网络发现新技能。关注教师可解范围内的能力保留；同时记录并集外新增成功，但不以它为必要条件。单CAP从初态成功的并集是事后参照，不是逐步混合策略的保证或理论上界。

现有证据见[D/A实验报告](../agent_exchange/reviews/DA_Joint_Representation_20261117.md)：12模型、1536评估完成；手工“状态数值×建议匹配”乘积没有显示额外收益。10条成功修复后缀全部可被模型在原接管点复现，但从同10场景初态仅5～8成功；20次失败执行均在第8接管边界前偏离历史donor前缀。远端教师优先级对照由用户报告均值仅提高1个百分点，尚未核验远端原始CSV。不能据此认定一般语义表示无效，也不能把局部拟合等同于闭环能力积累。

## 2. 最小数学闭环

令H_t为部署允许读取的真实观测—已执行动作历史，G(H_t)为几何历史编码。各冻结程序P_i都根据同一个真实历史更新，输出完整建议a_i和执行特征Z_i、有效性掩码M_i：

\[
(a_i,Z_i,M_i)=\operatorname{Trace}(P_i,H_t),\quad
a_i=(e_i,u_i^0,u_i^1,\tau_i).
\]

e为操作实体或无实体，两个u为机器人离散option（含方向/速度），τ为当前duration协议的执行tick。第一阶段不拆开重组两个机器人的建议、不另外枚举时长、不开放基础动作补充。

\[
\mathcal C(H_t)=\operatorname{Deduplicate}\{a_i:a_i\text{通过公开合法性校验}\},\quad
B_i(a)=\mathbf1[a_i=a].
\]

10个CAP各给一条建议时，合法候选数至多10。完全相同的动作合并，保留多来源B(a)，不因为多个专家重复建议而复制候选。比较时包括实体、两个机器人动作ID和时长；候选顺序与破平规则固定。

\[
s_\theta(H_t,a)=f_\theta\big(G(H_t),\operatorname{concat}_i[Z_i,M_i],
\operatorname{enc}(a),B(a)\big),\quad
a_t=\arg\max_{a\in\mathcal C(H_t)}s_\theta(H_t,a).
\]

同一小MLP逐候选评分，因此支持变长候选集。程序特征不手工乘以建议匹配；可解释性作为诊断能力，不作为人工筛选输入的先决条件。选择器不是把某个CAP锁定到任务结束：每个option结束重新读取实际反馈并决策。

如果全部CAP建议非法或为空，采用预先冻结、可由公开菜单验证的安全回退并单独记账；若不存在合法回退则显式终止为失败。不能暗中调用仿真搜索或利用隐藏状态补候选。

## 3. 程序执行特征的定义

不是“按这次执行遇到变量的顺序拼向量”，而是先从冻结源代码构造稳定注册表。槽位绑定CAP源码哈希、函数限定名、AST位置、表达式/赋值类型；运行时只向对应槽位写入数值及掩码。代码修改必须产生新schema版本，不沿用旧模型解释新向量。

第一版记录：

- 有界数值/布尔局部赋值、比较表达式的操作数与判断结果、控制流分支是否经过、数值返回值、允许读取的持久记忆。
- 已有CAP的真实输出动作单独保留；实体引用通过候选绑定或实体相对编码表达，不把实体ID字符串变成连续数值。
- 未执行、无值、非有限值和不支持类型分开编码；不能都填成“物理量为零”。训练集拟合数值缩放与截断规则，测试冻结。
- 初版不逐元素展开所有容器和无限次循环轨迹。循环中的关键归约结果不能全部丢弃；按固定规则保留调用次数、最后值及适用的min/max/mean等摘要，必要时增加有界实体/候选表。固定最大维度与溢出计数，超限显式报告。
- 函数被多次调用时记录固定聚合或有界调用槽位，不让调用次数改变其他字段位置。函数返回后仍保存对应槽位。

插桩不得重复求值带副作用的表达式，不得改变短路逻辑、异常、返回值或程序记忆。优先先在源码副本上做AST插桩与同值验收，再处理现有编译路径；不修改原冻结CAP，不假定Python调试器能直接读取已编译语义内核的全部局部变量。

部署特征只能从合法历史及程序自身计算取得，不记录仿真器对象、真值、未来回报、场景标签、文件路径、随机场景seed或离线成功标志。作者/离线诊断可使用的信息与部署特征分开。完整程序执行轨迹是历史的派生表示，不增加隐藏动力学信息；它是否降低学习成本是待测假设。

## 4. 候选与记忆必须先验收

未选中CAP也只能依据真实已执行动作更新，不能把自己的建议当成已执行。插桩前后，同一历史上的建议、程序记忆与状态更新必须一致。在线增量更新与真实前缀重放应同值。

对成功示范逐边界重新运行全部CAP，核对示范动作是否在当前建议池。缺失时先区分记忆恢复、建议接口、动作参数精度及版本问题；不静默删除样本或将示范动作额外塞入训练候选、却在部署时不给同样支持。

“完整记录内部变量”能帮助描述程序为什么这样选择，不能自动给出哪个选择最有效。一个建议的结果依赖后续策略：

\[
Q^\pi(H,a)=\Pr(\text{任务成功}\mid H,\text{先执行}a,\text{然后按}\pi\text{继续}).
\]

CAP持续接管成功与只执行其一步后交回当前选择器成功必须分别登记，不能共用无条件动作好坏标签。

## 5. 数据与第一轮比较

先复用上一迁移包的10CAP、开发覆盖矩阵与fastest成功轨迹。默认仍采用fastest作为冻结教师规则，priority保留对照证据；不要因均值+1个百分点就改默认规则。第一轮实施前固定开发训练/验证按根场景分组、训练预算及独立新测试集；已有200和本轮80结果都已查看，不能再称盲测。

主要两臂共享候选池、动作编码、来源标记、数据、网络规模范围、优化和几何历史：

1. **G+A建议池评分**：几何历史、候选动作与建议来源。
2. **G+T+A建议池评分**：另加自动提取的程序执行特征T和缺失掩码。

已有手工D输入可作为第三臂，等核心接口通过后再加入。固定优先级选择、现有R0/Rt和各CAP完整执行作为参考，注明是否具有相同历史信息与动作支持。旧全合法动作树GDA属于另一支持条件，不把新旧差值全归因于T。

起步用完整成功轨迹做候选级模仿；若多个等价建议合并，只监督唯一动作条目。多条有证据的可接受行为可另设集合监督，未执行动作不是物理失败标签。训练软max产生竞争不等于测到了反事实失败。

先验证少量轨迹能拟合并闭环复现，再扩展到完整570条或预先冻结的子集。第一轮不同时加入PPO、新CAP开发、大规模数据采集和多层搜索，避免无法归因。数据量曲线在基本闭环通过后再做。

## 6. 真正的修复循环

冻结一版选择器 → 在开发场景完整执行 → 记录它实际访问的争议/失败历史 → 比较有限建议及明确的续接协议 → 找到连贯成功后缀 → 监督整合 → 在相同接管点和原初态分别验收 → 检查既有成功损失。

每轮采样来自当前部署策略，而不是长期只使用旧donor状态。最终盲测不用于找反例、选特征、拟合归一化或挑checkpoint。没有可成功续接时，记录为当前库/有限验证预算未覆盖；是否需要新CAP另开明确预算，不能把“未找到”当作不可解证明。

指标：完整成功率、已知教师可解覆盖保留、接管成功、建议池缺失率、非法/空池率、实际动作切换、示范拟合、每轮新增与丢失成功、CAP/插桩/网络时延、特征维数与缺失率。相同场景配对、多训练seed，场景是统计单位。
