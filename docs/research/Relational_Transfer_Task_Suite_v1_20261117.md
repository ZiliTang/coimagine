# 跨几何布局的关系迁移任务 v1

版本：`relational-transfer-v1`，2026-11-17。状态：8个开发场景已固定并接入测台；均有可复现的成功动作序列。尚未进行本任务组的CAP作者实验、语义学习或模型比较。

## 任务与配对

运输目标物体A到公开目标区域，另有可动物体B。4种布局：东向、北向、西向及斜向，同时改变运输距离、障碍尺寸/角度和整体位置。每种布局有“B占据直线运输通道”和“B已在通道外”两个版本。配对之间只修改B的位置，其他物体、机器人、目标及物理参数完全一致。

所有场景使用相同6×4.8m场地、固定静态墙段、0.2m成功半径、90s执行预算、原MOVE/PUSH/ROTATE技能及成功保持判据。物体A为0.25×1.0m矩形，B质量3kg。初始公开扫描均发现A、B，但策略仍只看到实际扫描表面，不获得完整物体几何真值。场景ID、配对关系标签和可解性记录不进入策略观测。

“挡路”只表示A保持初始朝向直线输运时的几何通道与B相交，不代表必须清障、清障最优或绕行不允许。目标仍只要求A成功到达，搬动B没有额外奖励。初态和目标处同姿态的几何均合法；完整执行见证进一步证明可解。

## 可解性验收及信息权限

工程求解脚本使用了**仿真真值几何**作阶段判断和机器人换位的A*导航；调用的仍是原公共合法option接口。它不是受观测限制的CAP策略，不能用于报告本方法或LLM的能力，也没有进入旧150示范训练数据。

共9次工程尝试：第一次覆盖全部8例，7例成功；斜向挡路初版试图向NW推，但当前可见面只允许NE/N的单侧推动，在公开菜单中不可选，脚本持续回退刹车，90s耗尽。保留该失败。修复仅改变工程动作方案：先MOVE到B右侧，再向W推开B，最终完成运输；场景、控制器、物理和成功条件均未改。

随后通过测台API独立重放8条成功序列，全部成功；8例最终完整物理状态与首次成功尝试**逐项完全一致**，执行ticks也相同。所有动作窗口按测台4ticks边界保存/执行，没有把较长命令压缩为不等价的新边界。挡路四例B确实发生位移；通道已空四例B位移均为0。

21项聚焦测试通过：几何及终点有效、配对仅改变B位置、公共观测无设计标签、预设种子幂等不覆盖、保存/读取保持目标与几何、既有多物体测台执行与回放等。8个新种子及8条成功预设已通过实际HTTP接口保存/读取。未作新的浏览器自动化验收。

工程求解10856ticks＋测台复播9056ticks＝19912ticks（995.6s仿真时间）；无LLM调用、监督更新或PPO。

## 后续科学比较的约束

- 本组已公开用于构建和求解，全部标为development，不能称盲测。后续冻结训练布局，再独立生成测试几何；按布局族留出，避免同锚点扰动混入两侧。
- 当前SEM程序含固定时间/绝对方向/形状分类，不默认跨布局成立。新关系语义须在训练侧产生并冻结。上面的工程求解器及方案不自动交给干净CAP作者或作为预装语义。
- 几何基线需得到相同合法观测，并使用合理的目标相对坐标和实体表示；不能通过劣质绝对坐标编码制造语义优势。保持动作支持、示范、预算及网络可训练性可比。
- 同时检查相同关系的跨布局复用，以及同布局关系改变后的行为变化。不能把“看见B就清障”当作关系推理。
- 后续可增加物体数量/形状和子任务组合，但本版只含两个可动物体与四对布局，不声称已经验证这些泛化。
