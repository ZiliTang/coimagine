# 待讨论：让 option 的实际执行效果更接近其公开含义

状态：待办，待本轮语义专精库与常规库的配对实验结束后共同分析。以下都是待检验的解释。当前语义对照沿用既有控制器、机器人尺寸和避障裕度。

- 在真实分叉和卡滞回放中区分接触前找位、接触建立后推动效果不足、两机互相让行和高层反复切换。分别记录进入条件、实耗时间、接触建立率、沿指令的物体位移、反复尝试次数与未判定案例。先判断问题发生在哪一层。
- 审查 PUSH 描述、可观察前置条件和终止原因。考虑保留一体化 PUSH 并让接触状态和失败原因更清晰，或将其拆成可独立调用的 APPROACH 与有明确接触前提的 PUSH。比较能否可靠到达接触位、是否频繁重复进出、实际推动是否与指令一致。
- 如果确有机器人之间的物理通行干涉，分别考察较小的机器人半径和较小的避障裕度。区分物理上无法同时通过与控制器过早让行，记录碰撞、死锁、误避障和任务成功。半径会影响接触几何，裕度会影响控制器；分别版本化，并让策略在新版本上重新适应。
- 将每项改动放到同一批故障与正常对照回放上定位效果，再讨论是否需要开展新一轮 CAP 开发。仿真状态的事后真值用于核验，策略只能使用决定动作时已得到的信息。
