# 面向混合策略的 CAP 区域精化

2026-11-19 讨论稿。首轮三组作者对照已完成，含最佳单成员、轻量开局路由及五成员逐轮分布。[封存评测与逐场景结果](../key_findings/2026-11-19_regional_cap_authoring/README.md)

**假设。** 给 LLM 一片有共同、可观察几何特征的场景，在同一成员的开发轮次中优先修复附近的失败，有机会让该成员在未展示的邻近初态上也稳定成功。区域可以重叠。最终希望改善的是整套系统在原任务分布上的闭环成功率。旧协议已鼓励新增覆盖，本设计改变的是新增成功应当如何分布。[原 CAP 开发协议](../../agent_exchange/tasks/Random_Room_CAP_Library_20261117.md)

**轮内与轮间的选例。** 在开发前指定一套部署可见的初态描述和距离，只用开发数据定标。先选一个有足够样本的邻域。在成员开发的每轮 M 个备选初态中，优先展示该成员已成功初态附近的失败，同时保留已解邻居作回归检查。尚无成功时从该邻域的代表场景开始。选下一成员的起点时，在有足够邻居的候选中优先选择旧库局部未解比例高的区域，以到最近可靠覆盖区的距离破同分。单个质心容易遮蔽两片成功区之间的空洞。选区、近邻数、每轮预算、无进展时换区的条件在执行前冻结。作者选择案例与部署时选择动作分开，场景 ID 和隐藏布局不进入运行时策略。

| 路线 | 作者在预算内交付什么 | 部署 |
|---|---|---|
| A 通用程序 | 连续多轮修订同一 CAP，以全局开发表现选定一个版本。可用公开几何写条件分支、复用旧版本和子程序 | 一个冻结程序 |
| B 增量覆盖库 | 沿用现有作者目标，保留能为未解场景带来成功的多个程序 | 冻结库，无 trace 的 directQ 每步选动作 |
| C 区域精化库 | 轮内提高一片邻域的成功率，轮间转向覆盖薄弱的邻域 | 与 B 相同的 directQ 和动作规则 |

A 与多程序路线核对作者模型、知识、开发轮次、调用、可核算 token、仿真重置和物理 ticks。B/C 同时匹配程序生成与保留名额、成员筛选规则、旧源码访问、开发初态池、路由训练采集和更新预算。区域内抽样不同属于实验干预。现库从十个生成成员中保留七个，预算比较须计入全部作者轮次。历史库可复用作参照；若作者预算或模型无法对齐，应注明历史比较，并用匹配协议的 B/C 判断生成目标的贡献。另列路由训练和部署计算开销。

**判据。** 在同一批新冻结、整族留出的自然分布房间上比较三条路线的实际闭环成功。对 B/C 另列专家单独执行的并集、并集内混合策略保住的比例、并集外混合策略的成功数。在两库都能解的房间上配对比较保留情况，免受两库并集难度不同的影响。平行检查未展示近邻上的指定成员成功率；邻居先按基础房间聚合。使用同样的轻量公开初态选择器，比较只选一次专家与逐步 directQ，在两库上分别度量局部优势可辨认程度及在线重选的增量。初态独胜仅说明从该处承诺执行一个专家的结果，途中候选动作排序要由闭环验证。开发房间和已查看的 600 例留作诊断。

若 C 只提高专家并集，证据支持扩大覆盖。若在两库共同可解区也更容易保住成功，并在自然分布上获得闭环净增益，才同时支持“生成更容易整合的专家”。若 A 持平或胜出，应报告相同作者投入下单个程序的竞争力；若轻量首步选择已追平 C 的 directQ，应把主要增益归于专家生成和初态可选性。现有证据仅涉及非区域化的历史库。[GA-Q 与专家切换](../key_findings/2026-11-19_cap_policy_switch/README.md) · [初态几何和扰动邻居](../key_findings/2026-11-19_cap_geometry/README.md)

### 首版差异与后续修订（后续对照设想）

首版可能已经受作者提示影响。从零重复各路线，保留首版成绩，才能测完整流程的总效果；同一套程序在许多房间上的测量不能代替多个独立作者运行。另一项问题是同一起点下如何花剩余预算。一个配对方案取三种提示各自生成的首个完整版本，每份依次作为三种续开发方式的共同起点，共九条分支。分支都拿到该起点的同一份代码、开发反馈、公开知识和剩余预算，使用新的作者上下文；多个成员的版本保留规则也需预先固定。每个起点内分别比较，最终在另外冻结的房间评价。该设计把首次生成与后续修订分开，仅代表所选的三份起点；从末版成绩直接扣除首版成绩无法达到同样的控制。此交叉续开发仅为提案。

### 从区域最佳成员继续开发一个通用程序（提案）

本轮开发集上，按同样的全池成绩选版本，区域最佳成员成功 92/160，通用程序成功 62/160。先直接部署这份区域最佳成员，与同一库的实际路由逐房间配对，可以在完全共享前期开发成本的条件下测出路由增量。另可把同一成员交给通用作者追加一轮开发，允许在原版和修订版间按开发成绩择优，将前五轮区域开发与追加预算都计入总成本。这条路线回答高起点下单个程序能走多远。若要比较追加预算的用途，可从同一代码、同一开发反馈分支，在等额新增探索和全池反馈预算下分别做全局修订和区域修订，预先写清单程序或多成员的交付规则，再在双方均未查看的新面板评价。
