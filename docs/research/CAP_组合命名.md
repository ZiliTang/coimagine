# CAP 母策略与恢复分支的组合命名

从 2026-11-24 起，P＋R 研究线的评测使用 **母策略＋启用的恢复分支 @ 交接规则** 作为主名称。它补充现有[策略登记规则](Policy_Registry.md)。正式组合的可复现身份由完整程序的 SHA-256 和执行协议确定。

| 名称部分 | 怎么写 | 什么时候换版本 |
|---|---|---|
| 母策略 P | 稳定的行为名和版本，如 `P绕行.v1`。登记其内置能力。 | 母策略计算动作、维护记忆或感知的实现改变 |
| 恢复分支 R | 每个启用分支写一次，如 `R复接.v1`。关闭的分支省略；没有外加分支时只列 P。 | 同一恢复办法改实现就升版本；新增独立办法取新名 |
| 交接规则 G | 在 @ 后写明版本，如 `G程序.v1`。登记谁优先、何时接管和交还。 | 改入口阈值、出口、优先级或更换学习门控就换版本。学习版本另记 checkpoint、seed |
| 评测条件 | 在表题或每行给出面板 ID、样本数、执行协议、起点类型。 | 换面板、事件机制或起点时分列结果；同前缀续跑写清前缀由谁执行 |

同一面板、同一执行设置、同一 G 的表，可把共同项写在表题，行名只写 P＋R。R 按登记顺序排列，执行优先级由 G 定义。开发期未冻结的候选可标为草案，同时给出轮次和提交编号。新身份用新的名字或版本号，保留以前的映射。

**每轮怎么落盘。** 定稿时在结果目录保存 `compositions.json`，逐组登记组合名、完整程序的 SHA-256、来源 campaign／文件、原始评测列名、面板和执行设置。面板、逐房间表、报告和汇报沿用同一映射。目录与封印继续使用原始路径。`trial04` 指一次提交，`parent` 指一组在本轮的角色；作为来源列出现时带上所属实验。对历史结果补登记前，先按原封印核对，不能只凭同名或行为近似合并身份。

## 当前登记的组成部分

| 名称 | 在最新评测中的含义 |
|---|---|
| P绕行.v1 | 图诊断轮 trial11 中的母策略实现，保留源自第一轮 trial09 的内置侧向绕行。当前无外加恢复的对照由评测器关闭顶层恢复得到。 |
| R换位.v1 | 近期直推不畅时寻找替代推位；源自开放恢复轮 trial06，登记的是图诊断轮 trial11 中实际运行的实现。 |
| R侧推.v1 | 后方推位受限但物体前方可行时，尝试侧推；来自图诊断轮 trial11。本次消融与 R换位.v1 一起开关。 |
| R复接.v1 | 靠墙、接近目标且失去接触时，让一台机器人重建推位；来自本轮 trial04。 |
| G程序.v1 | 原程序规则：旧恢复层检查侧推再检查换位；新复接分支让位于既有提案或活动计划。各分支按照程序内的条件交还；关闭的分支跳过。 |
