# 执行后几何修正的有限复核（第 23 轮）

冻结网络与条件状态规划器，只换第 4 条链路（执行后几何修正），同一检查点、同一 100 场景、beam 1。
三种规则：`encoder`（网络估计，即前一轮行为）、`scan`（把自己的扫描转成兼容位置集合的约束：
唯一时直接使用，不唯一时保留全部兼容位置，隐藏的 `released` 一律不覆盖）、
`true_geometry`（**特权诊断上界**：物体格直接取模拟器真值，不是可用方案，也不是性能结果）。
入口 `scripts/fusion_correction_probe.py`，原始数据 `outputs/grid/diagnosis/fusion_correction.json`。
本轮不调阈值、不重训、不加公共反馈分支。

## 逐个复核退化回合

- **深度 1**：`scan` 与 `true_geometry` 结果完全相同（15/100，同一组 6 个回合），**零新增退化**。
  说明这些状态里扫描已经把位置定到唯一，差异全在编码器。这一层的几何修正是真实且安全的。
- **深度 2**：编码器下的 5 个退化回合 44,68,74,81,86，**`true_geometry` 一个都没能挽回**，
  反而再多退化 3 个（11,28,49），总数 8。也就是说：把执行后几何误差**完全消除**，
  深度 2 的退化不但没减少，还更多。
- **深度 3**：编码器退化 0,27,52,81；`true_geometry` **全部仍未挽回**，再添 20,94，只挽回 1 个。
- 结论：**不能把深层退化归因于观测融合。** 场景 44 的机制（编码器误定位→该行状态被覆盖→`cut`
  崩塌→改选 probe）是真实存在的一类错误，但逐回合复核表明它只解释个别案例，不是深度 2/3 的
  共同原因。前一轮报告中"深层退化已定位到融合"的推广**撤回**。
- 另外，`scan` 与 `true_geometry` 在三个深度上完全一致，说明**残差不是"扫描有歧义"**：
  在这些状态下扫描与真值等价。

## 现在能说什么

1. 条件状态表示修正保留：短链关联恢复、深度 1 从 9/43 到 15/43 且无退化。
2. 执行后几何修正**不设为默认**：`scan` 规则在深度 1 更好且不劣化，但在深度 2/3 反而更差，
   因此只作为诊断选项保留，主链路维持既有行为。
3. 深度 2/3 的失败不在几何估计；仍未被隔离的候选是前几轮量到的单步生产性推动误差
   （真参数下 0.798/0.500/0.870）、beam/评分近似、以及公共事件不参与想象分支。
   按约定，这三项**本轮不动**。
4. 深度 1 的 15/43 仍低于同批随机 16/43，所以这条线到目前仍是**可归因的表示与感知修正**，
   不是方法性能结论。

## 阶段收尾

本阶段的基础排查到此结束：实现事实、评价口径、状态关联、单步关键转移、几何修正都各有一轮
可复现的对照，旧线保留为诊断工具。研究方向的讨论（协作事件预测框架 vs 同步 option 预测）
不再等待这个格子环境把所有模块修到满意；当前环境也没有表达技能持续时间、并发执行与中断衔接，
无法裁决该假设。后续系统继承这些实现教训，但不让它们决定研究问题。
