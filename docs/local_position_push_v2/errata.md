# Errata：对上一会话结论的确认、收紧与再修正

对照对象：`docs/handoff/session_context.md`（上一会话压缩上下文）与
`docs/local_position_push_v1/`（上一轮交付）。本轮所有数字来自本机重跑的 1920 条 test 执行。

## 1. 确认：判稳失败不是"判据太严"

`docs/local_position_push_v1/settle_audit.md` 的 A 节复现成立：V 判稳率 0.674、未判稳 313；
X 0.617、未判稳 368——与已提交值**逐位相同**。

## 2. 再修正：未判稳退出时"物体仍在残余滑行 0.010–0.022 m/s"**是过度概括**

`session_context.md` 第 3 条说未判稳退出前最后 6 个周期物体"真的在残余滑行 0.010–0.022 m/s，
正好骑在 0.02 门槛上"。用**含旋转**的真值参考重算（物体表面材料点速度
`|v_obj + ω_obj × r| · n`）：

| 臂 | 未判稳 | 退出瞬间真值低速 | **完整 0.30 s 保持窗**真值低速 | 退出真值表面速度 p50 / p90 / max |
|---|---:|---:|---:|---|
| V | 313 | 313 | **313** | 0.0000 / 0.0091 / 0.0104 m/s |
| X | 368 | 368 | **368** | 0.0000 / 0.0093 / 0.0105 m/s |

即：**每一个未判稳退出，在被拒那一刻以及被拒的整个保持窗里，真值和两台机器人都是静止的**
（低于 0.03/0.08 的部署阈值）。"残余滑行"的量级 p50 是 0，p90 ≤ 0.0093 m/s，不是 0.010–0.022。

真正的主因在第 4 条：**估计量的噪声地板**。这个区别很重要——如果主因是"物体还在动"，结论会指向
控制/制动；实际指向的是**测量的分辨力**。

## 3. 再修正：门槛反事实的 "+7 个百分点"大部分来自**不会被重分类的中止执行**

`session_context.md` 第 3 节与 `settle_audit.md` B 节："门槛 0.02→0.03，+7 个百分点、190 例
新增里只有 1 例真值不达标，是唯一接近免费的改动"。

重算后分两个population 看（`A2_counterfactual.md`）：

| population | 门槛 0.03 下"达到判据"的新增数（V / X） | 是否改变记录结局 |
|---|---:|---|
| 判据决定集（`settled_observed`/`settle_timeout`/`settle_unobserved`） | **6 / 6** | 会 |
| 中止类（`contact_lost`/`patch_lost`/`patch_support_lost`） | 67 / 121 | **不会** |

上一轮的 `hold_window_is_truly_still` 把 850 条判据决定执行**和** 110 条中止执行放在同一个
分母里扫描，于是把 67 条"中止后其实静下来"的执行也算进了"+7pp"。但控制器在中止路径上把
`exit_reason` 覆盖成中止原因，这些执行**在任何门槛下都不会被记成判稳**。所以：

- 对"判稳率"这个记账指标，0.03 只值 **+6 条**（V 0.674→0.680，X 0.617→0.623），不是 +7pp；
- 真要拿到 +7pp，必须同时**修中止记账**（让"中止后达到判据"能被记下来），那是记账修复，
  不是控制改善。

## 4. 再修正：虚警地板**存在**，但只集中在 `noise` 变体

`session_context.md` 第 2 条撤回"真值静止时估计量中位读到 0.040 m/s"，理由是窗口差了一个周期。
本机重算（含旋转的真值参考、要求连续两个真值静止周期）：

| 范围 | 估计量 p50（真值确静止） |
|---|---:|
| 全样本（两臂合计） | 0.024（见已提交 `settle_audit.md` C 节同口径） |
| 本轮口径（真值表面速度 < 0.005 m/s） | 0.029–0.030 |
| 六个无噪变体 | 0.0032–0.0036 |
| **`noise` 变体** | **0.033–0.037** |
| **`delay` 变体** | 0.0000–0.0001 |

所以"0.040 的地板不存在"**只在无噪变体上成立**；在 `noise`（σ=0.002 m）变体上地板确实存在，
而且**高于 0.02 门槛**，该变体判稳率是 0/120。原因是估计量用相邻两帧（0.05 s）差商：
`σ√2/0.05 ≈ 0.057 m/s`，而统计量是逐点速度**绝对值的中位数**，它抗错配但**不降噪**。
`delay` 变体不是因为噪声，而是 `repeated_timestamp` 让估计量置 None、把 0.30 s 保持清零。

## 5. 缺陷：`settled_after_abort` 是死代码

`option.py` 里 `settled = exit_reason == settled_observed`，中止路径又把 `exit_reason` 覆盖成
中止原因，所以 `settled_after_abort = settled and abort_exit` **结构性恒为 False**。本轮记录了
这一点并给出重算值（部署门槛下 0/0；门槛 0.025 下 V 67 / X 121）。**未修改该字段**——按范围
收紧要求，本轮不动执行协议。

## 6. 确认：估计量是世界系，且真值参考必须含旋转项

`update_surface_estimate` 用机器人位姿把两条扫描都映射到世界系再匹配，**机器人自身运动已经抵消**；
数值核对：物体静止 + 机器人移动 → 0.0000 m/s，物体平移 0.004 m/0.05 s → 0.0800 m/s。
真值参考要用 `v_obj + ω_obj × r` 投影到法向；只用 `|v_obj|` 会低估偏心接触点。
（上一轮的真值窗检查用刚体线速度/角速度阈值，本轮补充了含旋转的表面速度口径。）

## 7. 确认：可预测性目标设错，已按可观测目标重做

`session_context.md` 第 4 条撤回成立——上一轮目标含物体**全局朝向**，原理上不可观测。
本轮 B 节换成"机器人终态会看到的局部几何"（有符号距离 / 切向偏移 / 法向角），
并有断言测试保证目标不含物体全局位姿分量。结果见 `B_transfer.md`：位置类目标的白名单
可预测性已经接近特权上界，姿态类目标仍依赖隐藏朝向。

## 8. 已提交文档与已提交代码不一致

`docs/local_position_push_v1/settle_audit.md` 的 B/C/D 节是用**旧版估计量**生成的，与仓库里
已提交的 `control.py` 不自洽（A 节自洽）。本机用当前代码重跑：A 节逐位相同，B/C/D 节数值不同
（例如 0.03 门槛：文档 0.745/0.744，当前代码 0.750/0.749；这与上面第 3 条的 population 问题
叠加）。**引用上一轮的 settle_audit 时，B/C/D 节需要以当前代码重跑为准。**
