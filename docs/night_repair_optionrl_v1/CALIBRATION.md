# CALIBRATION — 技能能力核查与任务标定（任务书 4.2 / 5.1）

全部数字来自 `experiments/night_repair_optionrl_v1/` 的实测脚本，不是估计。

## 1. 现有技能一次能做什么

对 6 个 dev root 的**每个合法动作**，从初始状态执行一次 option，测量：

| root 类 | 合法动作数 | 最好一次的有效位移 | 中位 | 最差 |
|---|---:|---:|---:|---:|
| solo_central | 9 | +0.200 / +0.202 m | +0.147 / +0.113 | +0.076 / +0.055 |
| solo_offset | 9 | +0.282 / +0.218 m | +0.189 / +0.160 | +0.091 / +0.086 |
| dual_same_side | 180 | +0.434 / +0.423 m | +0.280 / +0.269 | +0.065 / +0.065 |

**"有效位移"指朝目标靠近的距离**，不是位移模长。结论：

- 每个合法动作在初始状态下都让物体**朝目标靠近**（最差的也是正的）；
- 最佳单步有效位移中位数 **+0.250 m**；
- 因此 0.80 m 的目标约需 **3.2 次完美技能**，落在任务书要求的 3–8 次区间内。

## 2. 测到的能力缺口（不修控制器，如实记录）

贪心多步检查（每步在当前状态下实测各动作，选即时进展最大者）：

```
dist=0.60 tol=0.15  距离序列 0.426 → 0.258 → 0.269 → 0.332 → 0.425 → 0.533 → 0.649 → 0.768
dist=0.45 tol=0.20  dual_same_side: 0.034 → 0.084 成功；solo_offset/001: 0.288 → 0.199 → 0.167 成功
                    solo_central:   0.317 → 0.248 → 0.273 → 0.347 → 0.447 → 0.559 → 0.676 失败
```

**缺口：现有技能无法改变推动方向、也无法绕到另一侧。** 一旦物体被推过目标容差，
后续所有动作都只能把它推得更远（距离单调增加），没有任何动作能把它推回来。

这与任务书 4.2 的预判一致："若技能无法绕到另一侧或改变推力方向，先使用已有技能可完成的
任务子集，并记录能力缺口。不要修改低层反馈控制器或临时加入带特权的重定位技能来制造成功。"
本轮**没有**修改控制器，也**没有**加入重定位技能。

## 3. 因此冻结的任务定义（一次有记录的难度简化）

| 项 | 值 | 理由 |
|---|---|---|
| 目标距离 | **0.45 m** | 按实测有效位移，2–3 次技能可达；0.80 m 会在 2 次内越过容差 |
| 目标容差 | **0.20 m** | 单次有效位移 0.15–0.43 m，容差必须吸收一次推过头 |
| 到达保持 | **连续 2 次技能边界** | 计数单位是技能，不是控制周期 |
| 最大技能数 | **12** | 3–8 次有效技能留出余量；超出即截断并保留 |
| 技能菜单 | 公开固定 180 条 | 不按隐藏真值过滤 |
| γ | `0.997 ** (步数)` | 半马尔可夫，按每次技能的实际周期数折算 |

**能力缺口的直接后果**：`solo_central` 类场景在这个任务定义下**仍然不可达**，
因为它给出的有效位移（0.17–0.20 m）相对目标距离偏大、推过头之后无法挽回。
因此 RL 的成功率必须**按场景类分别报告**，不能把三类混成一个数字后声称"任务可行"。

## 4. 这一简化是否算"制造成功"

不算，理由是它同时满足：

1. 没有改变物理、控制器、传感或动作集合；
2. 目标距离与容差是在**测量之后**按公开规则定的，并写进契约；
3. 失败场景（solo_central）**保留在任务里**并且单独报告，没有被剔除；
4. 任务仍然需要 2–3 次有效技能，不是一次到位。

## 5. 随机策略基线（同规则）

| 划分 | 成功率 | 净推进 | 中位技能数 | 平均回报 |
|---|---:|---:|---:|---:|
| validation (64 root) | 0.0156 | +0.187 m | 24 | −1.414 |
| test (64 root) | 0.0156 | −0.111 m | 24 | −2.277 |

（上表是**旧的 0.80 m / 24 技能**设置下测的，保留作为对照；0.45 m 设置的基线见
`outputs/night_repair_optionrl_v1/option_rl/random_baseline.json` 的最新版本。）

随机策略的成功率接近 0、净推进在 0 附近摆动，说明**随机选技能基本无法完成任务**，
这正是需要学习的信号。
