# local_position_push_v1 更正与偏离记录

## E1 共用传感缺陷一：射线分组的距离连续性基准错误（协议修复）

`scan_surface` 原先用**本次 run 的第一条命中射线**作为距离连续性基准，于是分组长度依赖观测的
斜视程度：机器人距平面 0.18 m、平面向侧面延伸 0.7 m 时，本应连续的一段被切成 7/3/5 条射线
（跨度仅 0.068 m）。改为与**相邻**射线比较后，同一帧得到 11/10 条射线。
后果：修复前 X 的 `patch_support_lost` 在 6 类中的 4 类于 0.15 s 误触发。

## E2 共用传感缺陷二：360° 扫描按线性分组（协议修复）

扫描是整圈 72 条射线，但分组从 index 0 线性扫描，跨越 0/2π 的片段被拆成两段。设机器人正对
物体 0.25 m 端面时实际有 14 条射线命中，却以「8 条 + 6 条」出现，跨度只有 0.088 m。
改为环形分组（从一处真实断点起扫）后合并为一段。后果同 E1。

## E3 偏离：支撑几何使用片段自身法向，而不是滤波法向

任务书 3.2 写的是「观测质心 c 和滤波法向 n 构造支撑直线」。按字面实现时，低通滤波的滞后会
混进几何：旋转推动时滞后可达 ~10°，把垂足横向推移 `|c−p|·sin(lag) ≈ 0.035 m`，与整段
观测跨度（实测 0.07–0.08 m）同量级，于是支撑检查变成在检查滤波器而不是检查接触是否滑出可见段。
本轮改为：**支撑线用片段自身的拟合法向**（几何是观测线段的属性），**控制方向仍用滤波法向**
（任务书对 `direction` 的要求不变）。这是有意的偏离，已在此记录；若不接受该偏离，
则需把滤波滞后从判据中剔除的其它方案，而字面实现会让 X 在多数 root 上于 0.15 s 中止。

## E4 偏离：dev 执行验收实际跑了 384 次而不是 48 次

任务书 4.1 要求先用 24 个 dev root 跑 2 臂基准变体（48 次）做执行验收。运行器按 8 个变体一起跑，
实际产出 384 次。基准 48 次子集单独报告（V 23/24、X 21/24 判稳），其余变体作为额外覆盖保留，
不影响 test 分片的一次性验证。

## E5 说明：V 与上一轮 N 不完全可比

E1/E2 修的是两臂共用的传感。因此本轮的 V 与上一轮 `local-contact-option-push-v3` 的 N 数值
不完全可比；本轮所有结论都只用**同批 V/X**，没有把旧报告的数字拼进新表。

## E6 说明：X 的 `force_raw` 有记录，V 没有

V 的速度式不产生位置控制器意义上的"请求力"，其 `force_raw` 字段为空。因此表 3 中 V 的
requested P95 显示为 "-"，不能据此认为 V 没有请求力概念；V 的 `|F|` 即 `Kv(v_ref−v)` 的限幅结果。
