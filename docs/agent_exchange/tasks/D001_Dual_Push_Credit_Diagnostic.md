# D001：双推成功经验为何没有形成稳定贪心行为

2026-10-29，GPT 规划，v1。状态：ready_for_handoff，未执行。

## 选择理由与边界

优先研究双推：有参考可解性证据、有训练期间随机成功、有贪心失败，
比换面零成功更容易追踪“发现 → 优势 → 参数更新方向 → 行为”的断点。
v14 有特权标签的容量探针在 0.8 s 保持下成功，已削弱“必须加网络/历史才能表达”的解释。
现在直接同容量架构对照或双推隔离训练，会同时碰到数据分布与探索差异；先做诊断定位。

问题：冻结末轮策略是否仍能随机完成双推？成功轨迹中的同推是否得到正优势？
双推与其他任务对同推概率的局部更新方向是否冲突？
不把“多任务负迁移”“速度耦合不足”“探索失败”当作既定结论。

本轮不训练、不做 optimizer.step、不更新 normalizer、不续训 checkpoint。
允许对冻结权重求梯度；这只是局部一阶诊断，不是重现历史 Adam/PPO 的实际更新。
保持 944 维输入、46 动作、0.8 s 保持、原 mask、控制器、物理、90 s 预算与奖励。
策略仍是集中式共享合法局部观测基线，不是 B-bit 部署策略。

## A. 同一冻结策略的随机与贪心差距

仅用两个固定训练根 `dual_2`、`dual_0`，不称为泛化验证。
每模型/每根：当前条件贪心 1 条，随机 16 条，动作 seed 固定为 1000–1015。
总计 2 × 2 × 17 = 68 条。相同 seed 仅控制抽样起点，不保证两策略轨迹相同。
初始贪心动作应与原诊断一致；否则先调查复现差异。

逐 actor 决策保存合法输入/掩码、原始与编码观测、动作、old logp、value、reward、dt、terminal，
以及完整联合分布或足以精确重建的冻结引用。保留 5 Hz 执行记录和回放。
物体真值仅用于离线效果标注，不进入策略、mask 或梯度输入。

逐根报告：成功 k/16、回报、完成时间、进入目标但未判稳数、异常数。
同时展示两类分母：动作选择按 actor 决策；同推实际执行/接触/等待按真实秒数。
记录同向平移 PUSH 概率、同向且同速概率、推+换位概率、双方制动概率，
请求到执行的延迟、连续同推段长度和速度配对。概率须对全部合法组合求和，不截断 top-k。
同向不保证朝目标，同速也不是预设成功必要条件；结合实际推进效果解释。

每个贪心决策也离线记录联合 MAP 与条件贪心是否一致；本轮不增加 MAP 闭环分支。
至少保留两个贪心失败和每根首个随机成功/失败的回放；缺失成功就明确写无。
16 次动作重复只描述这两个根上的采样波动，不构成16个场景或16个训练 seed。

## B. 成功经验、批次权重和局部梯度

仅对 joint_types 模型追加其他6个固定训练根各4条随机轨迹（seed 1000–1003），24条。
与 A 中双推相同4个 seed 组成4批：每批8根各1条，保持原训练 episode 配比。
分析每类任务的 episode 数、actor transition 数、模拟秒数与占批次比例。
长失败轨迹可能占更多更新样本；不能把 episode 的1/4直接当作梯度的1/4。

按现有代码逐 episode 计算真实 dt 的 GAE，再严格复现每8条 episode 合并后的优势标准化。
同推/推+换位/制动分别报告：样本量、原始与归一化优势的均值/分位数/正值比例，
区分最终成功与失败；成功 episode 内的全部动作不自动视为好动作。
补充 reward-to-go 与 value 偏差作描述，不能当作独立无偏的动作价值估计。

在相同冻结权重上分解批次初始 PPO actor loss 的梯度：双推、其他任务、熵项。
任务分量沿用完整批次的优势均值/方差及总 transition 分母，不分别标准化，
确保各项求和等于完整 actor 梯度；critic 不混入 actor 梯度。
分别报告 actor body、基础动作头、joint_types 的梯度范数和任务间余弦；零范数记 N/A。
核对 old logp 重算误差 ≤2e-5、梯度重组误差、全部数值有限。

预先固定同一组评测输入：两个双推初始观测，以及 A 的贪心轨迹各前10个决策。
在这些相同输入上测 `log P(同向平移双推)` 对各 actor 参数组的梯度。
用其与各 loss 梯度的负点积，报告普通梯度下降的一阶增减方向，单独列熵项贡献。
这是机制线索；不等于经过 Adam、梯度裁剪、多 epoch 和 normalizer 更新后的真实变化，
更不能追溯证明历史40轮的因果机制。没有明显方向/样本不足时必须保留“不确定”。

## 预算、验证与交付

- 总仿真预算92条 episode；每条原90 s上限；最多4个 rollout worker。
- 仿真与梯度分析总墙钟硬上限15分钟，不含实现时间；每条轨迹/分析阶段检查截止时间，
  调度层到时终止 worker，保留已完成产物并标 incomplete，不自动加预算或补 seed。
- 异常仍在评估分母并计失败；不进入优势/梯度批次，不补采，列出不完整批次。
- 源 checkpoint/normalizer 前后哈希或张量一致；本轮无 optimizer.step、无训练产物替换。
- 验证联合概率归一化与合法性、episode间GAE终止隔离、分任务梯度重组；复用已有测试。
- 输出 manifest、episode_metrics.csv、decision_metrics、advantage/gradient 汇总、原始轨迹和回放。

## 结果如何决定下一步

| 观察 | 下一步候选，不在本轮自动执行 |
|---|---|
| 冻结随机策略也几乎无成功 | 查成功在训练何时丢失、对应快照与动作持续性，不能再用41/80解释末轮 |
| 随机成功仍存在，同推正优势，其他任务方向相反且总方向削弱同推 | 优先双推隔离/混合配对短训，验证数据干扰假设 |
| 成功轨迹关键同推优势弱或负，其他任务冲突不明显 | 优先核查value/GAE信用分配与批次标准化影响 |
| 选择同推却不能持续执行、握手/速度/接触失败占主导 | 固定动作对小测台，先分清执行问题与策略选择问题 |
| 局部梯度支持同推却贪心仍不变 | 检查实际受控一步更新、normalizer漂移、动作概率排序与确定性解码 |

## 对 review 设计点的当前意见

1. 贪心和冻结随机评估并报；暂沿用条件贪心作部署主指标，明确解码定义。
2. 8根适合机制调试；改善声明需后续多个训练 seed、更多独立几何与双侧扰动，不能把重复采样算独立场景。
3. 保留两个头为诊断对象，暂不增容量。若要主张联合交互优势，再做有效参数参与计算的同容量对照。
4. 数据隔离优先于直接过采样，但由 D001 证据触发；换面课程另轮处理。
5. 保持0.8 s与奖励不变；已有容量探针不支持现在把保持时间当首要瓶颈。
6. 集中式全共享是当前行为/数据平台基线；分布式/通信结论需要另设信息协议对照。
7. FOLLOW+ROTATE 暂保留既有语义，专门核查合同及执行行为后再决定，修改须升级动作版本。
8. 请求/执行模式分开命名并明确时间戳；不能为“统一”而抹掉切换中的真实差异。
   旧零字段/phase清理需版本化；本轮不加pair特征、GRU或scan encoder。
9. seed元数据、STOP传播、串并行异常归一化差异应在正式续训前修复并验证；
   多worker resume精确性尚未由单worker测试证明。本轮冻结诊断无需先整套重构。
10. 固定小集成功只作为调试门槛，7/8不能代替任务类别覆盖、保留性与独立泛化验证；不恢复12小时长训。
