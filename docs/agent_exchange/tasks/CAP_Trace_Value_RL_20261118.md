# CAP trace价值学习：v7分阶段实验计划

日期：2026-11-18，Asia/Shanghai。状态：`planned`，待实施；本次仅组织计划与归档已有分析，没有启动插桩实现、新训练或物理评估。数值预算是下一轮建议上限，不是已发生的运行或自动执行指令。

本计划承接[v6](../../research/CAP_Program_Trace_Selection_Plan_v6_20261117.md)，将核心学习目标由成功动作模仿改为结果监督的价值预测与候选约束RL。既有物理、观测、CAP源码、成功条件及旧实验封印保留；新奖励、特征和训练器单独版本化。

## 1. 研究问题与主张边界

主问题：在固定、互补的CAP建议库中，自动程序执行特征能否帮助学习动作的后续价值，并在相同训练与在线尝试预算下改善闭环成功率？

分解为三个可否证问题：

1. **结果监督是否可学**：用完整成功与失败轨迹，能否在模型未拟合的开发根场景上预测各CAP继续执行的收益？
2. **trace是否有增量作用**：在相同几何历史、全部建议和来源信息下，加入trace是否改善价值预测与闭环行为？
3. **跨CAP信息是否有用**：评价某候选时，读取其他CAP的trace是否优于仅读取建议来源CAP的trace？

行为覆盖互补已有证据；trace的信息互补及有限数据下的可学习性尚无实验结论。第一轮验证固定预算下的性能；不据单一数据规模宣称样本效率曲线或一般程序语义泛化。自动trace不保证是价值充分统计量，RL也不消除表示混淆和分布偏移。

## 3. 三个匹配表示组

| 名称 | 所有组共享 | 额外trace信息 |
|---|---|---|
| `GA` | 几何历史G、全部7个CAP建议及身份、当前候选编码/来源、剩余ticks和决策预算 | 无 |
| `LOCAL` | 同上 | 专家价值头读该CAP的trace；候选Q头读所有提出该动作的CAP的trace |
| `GLOBAL` | 同上 | 所有7个CAP的trace及掩码 |

**主比较：GLOBAL−GA。机制比较：GLOBAL−LOCAL。** 所有组都能看到全部建议，不能让GLOBAL通过新增别人的动作输出取得额外信息优势。

固定每CAP块`(trace,validity,proposal,identity)`，汇总时保持来源关系。LOCAL只屏蔽不允许的trace值和运行时trace掩码，不能通过“未执行分支”掩码泄漏其他CAP的trace。当前候选有多个来源时保留这些来源的trace；因此不是任意指定一个代表CAP。

用同一非线性逐候选评分器，使状态/trace与候选能够交互；不使用会在同一状态候选排序中抵消的纯加性`u(trace)+v(action)`结构。建议小型投影＋两层64宽MLP，三组相同输入槽、模块和参数总数，禁用通道置零；报告有效输入维数、活跃通道差异与参数数。精确宽度和schema在P1结束后封印，之后不按结果单独调组。

所有组使用相同trace采集路径后做输入屏蔽，以检验表示效果；同时单独计量CAP计算、trace记录和网络推理开销，不把这一匹配测量当成GA最低部署成本。

## 4. 价值定义、奖励与训练衔接

### 4.1 新奖励协议

第一版主目标为固定任务预算内的成功概率：成功终止奖励1，其余奖励0，折扣`gamma=1`。有限时限与剩余预算进入输入；任务上限1800ticks/300决策不变。这是新的训练奖励版本，不重写旧轨迹原reward。旧时间成本与失败代价作为单独的物理/效率报告保留，不混为当前优化目标。

真实任务失败、固定任务时限耗尽为终止0；基础设施错误、缺失尾部和宿主中断不是可靠任务终止标签，保留并使阶段标记incomplete。不得把这种轨迹伪装成完整失败或删掉后仍声称全矩阵完整。

通用累计公式保存真实时长：`G_t=R_t+gamma**delta_ticks*G_(t+1)`。当前gamma=1时，每个完整轨迹的MC目标为末端成败；若以后改gamma或增加耗时项，必须另版本，不能继续称严格优化成功概率。

### 4.2 专家续接价值V

`V_i(H)`表示从当前真实历史开始持续执行CAP i直到任务结束的成功概率。先用CAP i完整轨迹的实际后缀回报监督，保留i身份；未执行专家的结果不能从其他根/其他轨迹中搬过来当标签。相同初态的7个CAP可以有7个实测标签，中间历史通常只有行为CAP的一个标签。

输出用sigmoid限定[0,1]，以均方误差/Brier目标拟合，不使用动作分类准确率替代价值验收。离线监督均匀抽取可用决策边界，不按成功/失败过采样；各组使用相同样本顺序，报告轨迹长度造成的边界权重。验证同时给出每根等权指标，避免长失败轨迹支配结论。

V可产生独立的policy-switching诊断策略：取最大V_i对应CAP的当前动作，每边界重新评价。准确V、充分历史、同一奖励和剩余时限下的策略改进理论只作为设计依据，不宣称近似模型具有保证。

### 4.3 候选动作Q与离线初始化

最终主策略学习`Q_C(H,a)`：先执行完整候选a，随后继续在实时CAP建议池中选择的价值。Q不带“必须继续哪个CAP”的标签。

P2先验收V与policy switching；通过后，正式模型先训练V，再冻结V版本，为记录到的真实转移构造一步改进初始化目标：

`y_init = R_t + (1-d_t) * gamma**delta_ticks * max_i V_i(H_(t+1))`。

这个目标表示在记录动作之后，下一边界选择一个CAP继续执行的近似价值；不是已测得的最优Q，也不是整段混合策略实测回报。只监督记录中实际执行的动作，不给其他候选伪造转移。下一边界所有CAP必须由同一真实前缀恢复，不能读取下一动作或未来成败作为输入。

Q可继承相应表示组V编码器的初始化，使用独立候选头；后续保留冻结V记录，避免同一个输出同时被当作V_i与混合Q解释。V在未见混合历史上的外推误差会影响初始化，必须报告，不能将该步骤称为无误差的策略改进。

三组V阶段共享完全相同的真实MC标签；Q初始化的数值目标因各组V估计不同而可能不同，在线访问数据也会不同。因此正式闭环比较检验的是同一算法流程下的表示整体效应，不宣称Q阶段是在逐值相同伪标签上的纯输入消融。V留出预测对照单独用于判断固定真实标签下的表示增益。

### 4.4 在线候选约束RL

在线采用Double-DQN式目标：在线Q选择下一合法候选，目标Q评价它；任务终止处不bootstrap。目标为混合选择器的候选Q，明确停止使用CAP整段MC回报作为这个头的固定真值。sigmoid限制值域并不能消除max偏差，仍须检查高估及校准。

只在当前合法去重建议池中epsilon-greedy探索。回放按50%离线真实转移、50%本模型在线转移混合，均按边界均匀抽样。在线数据不跨表示组共享，记录由此产生的访问分布差异。全CAP的记忆只接受实际动作，未选CAP不能虚构自己的执行。更新全部表征与Q头，normalizer固定为离线训练统计。

建议优化配置：Adam、lr=3e-4、batch=64、梯度范数上限1；目标网络每250次梯度更新同步。V与Q阶段使用相同基础优化配置；任何P2调参在正式阶段前记录并一次性冻结，不基于最终测试挑配置。

### P1：trace与候选接口

在源码副本上实现稳定AST schema：CAP源码hash、函数/调用位置、赋值/比较/分支/返回槽位固定；维护机器人/实体对应关系，不把原始实体ID、循环索引或内存地址作为连续语义量。部署输入禁止场景ID、随机seed、路径、未来结果和真值。

记录数值/布尔量、比较操作数及结果、分支、可用记忆和有界循环摘要；未执行、缺失、非有限和不支持类型分别编码。建议每CAP最多1024数值槽，缺失状态另计。超过上限先交回schema和覆盖统计，不能按模型效果手挑变量或截掉溢出后假装完整。源代码规则定义的筛选/聚合与所有排除项必须可审查。

先用固定32条已有轨迹的完整实际历史（成功、失败兼有，按来源/ID选择，开发用途）作只读前缀重放：原/插桩CAP建议、记忆、短路行为、异常与返回同值；在线式增量和从头前缀恢复同值。候选精确去重、身份来源、空池回退、实体重命名、未执行trace掩码和禁止结果泄漏均测试。

参数/schema冻结后对全部拟用离线数据做建议覆盖审计：记录的实际CAP动作应在池中，缺失逐条解释，不能额外塞入标签动作。所有组归一化只用训练根拟合。

验收门槛：选取历史上的原/插桩动作和记忆100%同值、在线/离线输入同值、候选无不明缺失、无未记账溢出。先测提取速度/维数/峰值内存和磁盘预估，再决定全量缓存；按轨迹分片与流式批读取，禁止一次将全部候选矩阵装入内存。此阶段不新增物理执行，不训练正式模型。

- 旧GDA与旧200/80结果仅作背景，不跨动作支持或面板计算增益。该200根在本阶段统一解封后进入“已查看”状态，不能再次用于调参后称盲测。
- 1200/1536等历史执行不计入新预算。本计划新增物理执行上限为P2的48＋P3的1800＋864＋P4的5000＝7712次，最大13881600ticks；没有包含缺失原轨迹的补采。如需补采另列协议和预算。

## 7. 指标、统计与决定

主指标：新200根上的GLOBAL−GA最终成功率差；同场景先平均3个训练seed，再按物体数分层做场景配对bootstrap（10000次，固定统计seed2026111803），同时列每seed分子分母及差值。区间条件于这3份已训练模型，不能声称覆盖所有训练随机性；200才是独立初态数。

主要机制诊断：GLOBAL−LOCAL；各组在线−离线；7CAP教师并集内成功保留、并集外成功；固定CAP009对照；每次监控新增/丢失成功。主比较只有GLOBAL−GA，其余区间标探索性，不根据多项比较中偶然正值宣称机制成立。

价值诊断分开：V用真实CAP续接成败作Brier/MAE；Q只用其冻结选择器实际执行回报评价选中动作的预测，不能拿CAP续接标签声称校准了混合Q。单次真实结果是回报样本，不是该状态概率真值。

报告：候选数/分歧率、非法/空池率、教师动作缺失、实际动作切换而非仅CAP ID切换、首分歧及高分失败回放；每CAP trace维数、缺失/溢出、CAP/trace/网络时延、CPU/RAM/磁盘、每阶段真实预算。全部任务失败保留，基础设施异常独立列出，不能删掉后维持“完整”结论。

建议解释规则：

- GLOBAL稳定优于GA、且GLOBAL相对LOCAL也有收益：支持trace有增量价值，并支持跨CAP信息互补；仍只限冻结库和分布。
- LOCAL与GLOBAL接近且都优于GA：支持本CAP的程序计算有用，跨CAP汇总暂未显示额外必要性。
- 三组在线都改善但彼此接近：收益更符合结果监督/在线状态覆盖的作用，不能归于trace。
- 离线V预测改善但闭环未改善：检查续接目标、混合状态外推和校准，不把预测指标提升当作策略成功。
- 拟合正常但无闭环增益：记录负结果，定位少量首分歧，不自动加CAP、加seed、加预算或改奖励。

## 8. 工程产物、边界与下一步

建议新实现放在`experiments/planar_tasks/semantic_rl/program_trace_value_v1/`，按schema/instrumentation、candidate_pool、dataset、value_models、learner、audit分离；provider-neutral driver位于`experiments/planar_tasks/authoring_v2/`，遵循其冻结/验证约定。旧迁移和旧实验入口保持历史用途，新driver仅通过两包相对index读取数据。
