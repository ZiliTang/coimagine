# REPOSITION单挡与PUSH真实速度挡位

2026-11-03，GPT直接实施。用户要求优化仿真中的运动速度：REPOSITION每方向一个挡，参考至少0.30m/s；PUSH保留多挡并上调。本轮不改物理、奖励、观测或进度决策接口，不训练。

## 两个实际问题

1. REPOSITION底层切向目标/速度上限已经是0.30m/s，但v13 factory外层又乘`action.speed/0.30`。用户截图这条“绕行后南推1.9m”preset用旧ID42，即CW的0.12m/s挡，实际参考再次缩为40%。旧挡位确实有控制作用，不能说旧三挡从未生效。
2. PUSH当前主要走持久candidate/q′分支。它使用固定向内0.05m的参考偏移、位置增益6/s及固定0.30m/s限幅，绕过了`speed_command`。旧菜单虽写0.04/0.08/0.16/0.32，主要接触路径并没有兑现这些速度。

## 当前实现

- 只在v19建立新动作表`testbed-speeds-v1`，不修改冻结v13/v14/v15/v16动作表/训练实现。
- REPOSITION每方向只有0.30m/s一个可选挡；CW/CCW分别保留旧最高挡ID43/40作为canonical ID。其余旧绕行ID38/39/41/42仅作读取别名，进入session/env时映射到40/43，不进入菜单/当前mask。撤掉旧的无效REPOSITION speed参数框。
- PUSH平移四挡改为0.10/0.20/0.30/0.40m/s；ROTATE/FOLLOW不改挡位。
- 接触位置反馈增益仍为6/s；把固定0.05m的向内参考偏移改为`v/6`，原固定0.30限幅改为当前挡位v。q/q′/选面/接近过程保留。居中时对应法向参考v；有切向纠偏、避障、位置误差时，实际法向分量可能低于挡位，实际运动速度也受现有力/阻力约束。
- 0.30m/s时`v/6=0.05m`，恢复原有接触反馈。试过恒定法向速度＋独立切向项，N+E角偏从约0.0007增到0.131rad，因此未保留该候选。
- 保留46个历史存储ID，当前可选动作42个；mask排除4个兼容别名。后续RL采样必须使用v19动作表/mask，不能继续读冻结v13菜单。当前未重建RL策略头或启动训练。
- 新run记录动作版本、codebook hash及实际动作labels；旧run原件不改。旧preset读取时只在内存归一化绕行ID；前端编辑序列按当前挡位显示，历史回放标识历史动作速度。旧preset/override JSON逐文件hash核对未改。

## 固定实例：绕行后南推1.9m

初态、预算、sequence方向及goal不变，唯一动作变化是CW统一0.30m/s及PUSH挡位接线。

| 观察 | 原版 | 当前 |
|---|---:|---:|
| MOVE阶段仿真时间 | 19.35s | 8.15s |
| MOVE参考速度中位数 | 0.12m/s | 0.30m/s |
| MOVE实际速度中位数 | 0.10m/s | 0.2498m/s |
| 完整仿真时间 | 26.90s | 16.15s |
| 控制tick | 538 | 323 |

随后仍能接触并进入PUSH；没有同candidate/同action连续帧超过5cm的q跳变，所有状态有限、施力未超过原限值。task success仍为true，但它只是附加标签。

## PUSH速度兑现检查

同一接近东推初态，每挡固定30×0.2s，均120控制tick，保留原goal且不要求task complete。106tick处于PUSH。

| 挡位m/s | 法向参考中位数m/s | 机器人实际速度中位数m/s |
|---|---:|---:|
| 0.10 | 0.0972 | 0.0694 |
| 0.20 | 0.1964 | 0.1403 |
| 0.30 | 0.3000 | 0.2143 |
| 0.40 | 0.4000 | 0.2857 |

因此“上调菜单”与“控制输出确实响应挡位”分别得到核对。较低挡位相对旧的实际固定0.30行为会变慢；不能声称四挡物理速度都比旧实现更快。
