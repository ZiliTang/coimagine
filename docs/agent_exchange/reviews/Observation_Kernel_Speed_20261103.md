# 观测计算提速：实现、等价性与实测

2026-11-03，GPT直接实施。用户已查看无轮廓memory版并确认，要求继续优化观测速度。本轮仅改雷达/边段拟合的计算实现；不以task complete作为验收。

## 保留的改动

`src/coimagine/random_start/lidar.py`：

1. 将每个遮挡物分别布尔选列、分别归约最短交点，改为对连续primitive组一次`minimum.reduceat`。仍按原遮挡物顺序处理最近命中/等距优先级。
2. 对完全相同heading/射线数复用精确射线方向，保持原角度表达式及`math.cos/sin`结果；缓存上限128，数组只读。primitive所属组的纯拓扑索引缓存上限64。均不存物体轮廓、历史命中或估计状态。
3. 批量转换range/valid，减少逐元素Python转换。
4. 每对相邻射线的连续性条件只计算一次，供分组起点和遍历共同使用。连续性阈值、拟合/分裂算法不变。

试过只对厚墙计算圆角修正，但单例耗时略增，没有保留；候选源码及测量仍保存。没有恢复轮廓memory，没有改q/EKF/控制器、物理、20Hz、72根body-fixed射线、5m量程、类别/遮挡/时间戳、奖励或脚本预算。无新增依赖。

## 耗时

固定“进度预算 · 接近阶段东推”，91控制tick、4.55s仿真。每种模式各5次计时，取中位数；计时不含cProfile。优化前是已去memory的当前基线，不混用更旧版本数字。

| 测量 | 修改前 | 修改后 | 耗时减少 |
|---|---:|---:|---:|
| 无记录环境执行 | 108.26ms | 95.14ms | 12.1% |
| RL式环境执行＋真实观测向量/mask消费 | 113.84ms | 103.66ms | 8.9% |
| 离线雷达扫描＋边段拟合，288次/重复 | 109.69ms | 91.65ms | 16.4% |

最后一行：矩形/T/三角形/八边形、遮挡/不同朝向的96个72射线输入，每轮重复3遍；6次新旧交替计时，减少执行顺序偏差。只是这组几何负载的中位耗时，场景、朝向复用及拟合复杂度变化会影响收益。

RL式基准按0.8s actor边界、0.2s dense消费观测，实际构造向量和mask，固定命令、无神经网络/PPO/IPC。约878控制tick/s、43.9倍实时仅适用于本实例此环境采样基准，不能当作完整训练或多worker吞吐。每轮实际扫描/拟合仍各182次，没有靠少采样提速。
