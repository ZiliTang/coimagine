## 2. 确定根因，不是迟滞数值太小

### 2.1 锁定后仍无条件重跑 selector

baseline `unknown_shape.py:1904–1907` 已从 `_commit_q` 读取锁定 q，但 `1932–1937` 的独立 `if SIMPLE_SELECTOR` 又调用 `select_simple_point` 并覆盖 q，`1939` 写入 `sk.allocated_q`。

之后 `_nearest_visible_q` 的 .10 m 迟滞只检查“重选后的 q → 最近候选”，没有比较“上一拍已提交 q → 重选结果”。若前者很小或原样返回，该检查完全挡不住跨面切换。

`baseline_q_writes.json` 是运行时 Python 行追踪，不是根据 reason 字符串猜测：

- t=5.00，上一拍 q 约 `(2.0677,2.1635)`，行1939覆盖后仍在上方，行1972再小幅修正。
- t=5.05，行1939直接写成 `(2.0633,1.8471)`，跨到下方；最终 reason 却仍显示 `nearest_face_candidate`。
- t=5.15，行1939写成 `(2.0711,2.1716)`，又回到上方。

每拍先置 allocated_q=None 的清理也会出现在追踪里；这不是物理候选消失。旧 reason 在坐标赋值时尚未更新，同样不能代表真实 writer。

另外旧单机分支在 simple 模式里仍试图使用只有非 simple 分支才定义的 `df`，靠宽泛 except 隐藏异常；本次整理成互斥的 selector 分支，一并移除这个错误控制流。

### 2.2 q 所在段与控制法向独立选择

`UnknownShapePush._step_impl` 原先每拍按照 gap 独立选择最近的方向兼容 patch，未要求它是 q 所在的段。日志因此能出现“q 在下方斜边，控制 n 却属于上方斜边”。

离线计算 `abs(n_control·(q−face_points[0]))`，旧轨迹最大 **.1418 m**。这不是 q′ 小偏移能解释的，因为此计算使用 q 而非 q′。单独限制 q 步长也不会修正法向/参考点不一致。

### 2.3 无限直线不是有限边段身份

`visible_faces` / `_merge_memory_faces` 仅按法向和 rho 合并，可能把同一直线上的不相连片段连成一段；原代码还会直接混用略不同 t 坐标系里的 lo/hi。需要用有限段的连续性与同一坐标基比较。

## 3. 已实施的修复

主文件：[unknown_shape.py](../../../experiments/option_rl_v19/unknown_shape.py)。

1. **实际 skill 生命周期内只提交一次候选。** 删除无条件单机重选、后置 nearest 覆盖和多套 EMA/单机缓存的重复写入链。相同 action 重建 skill 也会产生新提交，避免继承旧实例状态。
2. **锁定边段/材料接触参考，不锁死世界坐标。** `track_contact_q` 使用现有 direct contact velocity 作短时预测；只有法向匹配、预测点距线≤.05 m、预测点落在观测有限支持±.05 m 内才关联。用当前同段拟合线修正法向误差，保留预测点的切向坐标，不再把每次可见区间中点变化当作材料点运动。
3. **q 和控制法向绑定同一观测段。** allocator 传递实际匹配的 `SurfacePatch`；step 使用该 patch，而非再独立挑最近 patch。候选 ID 随提交生命周期保持，不因坐标第四位变化就新建；每拍刷新 q/n/t/support/可见有效性。
4. **看不到同段时保持参考并等待。** 相邻45°面和远处平行片段不自动取代当前段。失配在 debug 中显式记录，重新看见同段时恢复原 ID，不靠隐藏真值补几何。
5. **有限段合并需连接。** 片段投影到同一 t 后检查重叠/≤.04 m 间隙；memory 仅在连续支持上扩展，不凭法向相同把分离片段连接起来。
6. **写入来源可直接查看。** `selector_debug.q_tracking` 保存 previous/predicted/final q、逻辑 segment_id、selector_evaluated、每个可见段的匹配/拒绝量及最终来源。q′ 偏移与 EKF/direct 算法、物理/目标/成功条件未修改。

这里的 segment_id 是本 option 内的观测关联身份，不是假设知道真实 polygon edge ID。当前关联是局部、保守的；失配后不负责主动探视或全局重定位。

## 4. 同实例结果

跳变统一定义为“连续两条有候选记录的 q 距离 > .05 m”；缺失不填零。与 handoff 的39次一致。

| 指标 | 原版本 | 最终修复 |
|---|---:|---:|
| 前130 tick q 跳变 | 39 | **0** |
| 全800 tick q 跳变 | 125 | **0** |
| 最大可观测 q 步长 | .360287 m | **.019990 m** |
| q 到控制拟合线最大距离 | .141801 m | **约2.1e-15 m** |
| 候选 ID 数 | 470 | **1** |
| stage=push 时长 | 7.90 s | **38.45 s** |
| task success | false | **false** |
| 最终距目标 | .6425 m | **1.1750 m** |

最后一项明显更差，不能隐藏。修复后机器人能持续在初始选定的斜边推进，初始内法向约 `(0.924,0.383)`；物体走向偏东北，不能据“稳定推进”声称实现了正东方目标。末态约 `(4.458,2.853)`。后续应在同实例上讨论 PUSH_E 的方向语义/选面与任务序列，不把任务方向问题继续解释成 q 跳变，也不为过关改目标或本轮顺手改控制。

stage 时长是控制器输出标签，不冒充独立的真实接触契约分数。最大q步长是在实际轨迹测得，不是新增一个2cm限幅器把曲线压平。
