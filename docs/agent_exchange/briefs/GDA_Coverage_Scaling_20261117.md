# 为什么先扩GDA的随机覆盖

最近一个失败案例中，成功CAP的建议确实存在，但GDA偏向了其他CAP的建议；这说明需要研究选择适用性，不足以归因于范式失败。前轮270条示范比124条带来一定测试改善，而25条局部修复没有整体净收益。

这次只改变完整示范覆盖：再让冻结CAP库跑400个随机开发初态，原270条和扩充数据各训练3个随机种子，同样42000更新，再比较200全新场景。既有100例仅用作已见诊断。

若扩充在多数种子上保留旧能力、增加教师可解范围并提高新测试，支持先扩大经验覆盖。若收益波动，则看是否只在个别种子有效；若拟合良好但仍丢能力，需要进一步考虑“每初态只留最快一条”的监督选择或路由机制。不能保证成功率随样本量单调上升，也不靠追加预算追正结果。

本轮无RL、新CAP或检索基线。目标是减少当前关于RL或架构的混杂因素，先判断监督数据能否支持稳定选择。完整预算与实施约束见[任务书](../tasks/GDA_Coverage_Scaling_20261117.md)。
