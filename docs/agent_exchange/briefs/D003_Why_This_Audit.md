# D003 给用户的说明：先查清“接触不上”还是“接触后留不住”

2026-10-29。

D002告诉我们：要求机器人更久地坚持原动作，并没有稳定改善推进。
但它还没有告诉我们，问题到底在策略选错了动作，还是在底层执行过程。
这次要找到最早出现问题的一步，再决定下一轮改什么。

我们固定看8个例子：

- 两个已知成功的双推参考，先看正常接近、接触、启动和推进的过程。
- 四个此前没有形成双侧接触的窗口，覆盖两种目标方向和不同准备状态。
- 一个双方短暂接触后丢失的窗口，查接触后发生了什么。
- 一个原来在窗口最后才接触的例子，避免把“没看到后续”误当成失败。

后六个例子统一观察4.8秒，前3.2秒必须复现D002，多出的1.6秒只看清后续。
不会不断加长时间直到成功，也不会用新后缀改写D002负结果。

关键变化是记录方法。以前一行日志混合了“控制前是否接触”“控制计算后的状态”和“运动后的位姿”。
现在把一个0.05秒控制周期拆开记录：看到了什么、协调器读了什么、控制器发了什么力、物理实际怎么动。
这样才能区分正常的一拍延迟与真正的逻辑问题。

为了确保记录器没有干扰机器人，每个例子各跑一次原执行、一次带详细记录的执行，轨迹必须一致。
共16次重放；只有4条是完整成功参考，其余12次是前缀重放加短窗口。
正式执行、分析和回放总上限5分钟，针对性测试另限2分钟。

我们希望得到以下一种有证据的判断：

- 动作在该位置或方向下不合适：优先改策略选择，不能用惩罚逼它坚持。
- 准备过程中某个条件一直达不到：定位是感知几何、接近控制还是等待逻辑。
- 已接触却留不住：重点查参考速度、实际相对运动和恢复过程。
- 前提都满足但协调没有按约定工作：才考虑修协调逻辑。

也允许结论是“证据不足”，不能为了交付强行找一个bug。
已知成功参考只证明控制器存在可行执行序列，其制动命令原本含离线真值判断，不算RL学会。

**本轮只审计，不训练、不调参数、不修控制器。**
切换惩罚继续冻结，independent停车问题不并入。
最终交付应告诉我们一个最值得验证的具体改动，而不是再列一长串可能原因。
