# 这一夜要解决什么

我们的目标不是让雷达端点画得更漂亮，而是让机器人知道：**我正在接触的表面，此刻向哪里、以多快的速度运动？**
比如下面的机器人向北推，左边机器人同时向东推，下面的机器人必须向东跟随，否则接触会沿物体漂移。
只知道自己的推速不够；只看一个面的法向运动也不够。之前用端点推算接触世界坐标，依赖链长，误差容易进入控制。

这次保留 EKF，但换它的主要证据：真正接触时，用自己实际测到的法向速度；没接触的机器人也可以用雷达追踪一小段直线的方向、法向位置。
这些观测共同约束同一个刚体的运动，不必先知道物体大小、中心或背面的形状，也不要求全轮廓匹配。
如果只看到同一个平面、某个方向确实无法估计，算法要承认不确定，而不是把未知速度当零。

接触之前，局部点/线片段负责挑选安全接触位置；接触之后，控制器跟随估计的表面速度，再按需要做少量左右微调，不再沿着“端点→中点→目标世界坐标”的链条持续定位。
未来曲面仍可沿用刚体表面速度接口，但当前直线观测的做法不能直接保证曲面有效；这次不扩物理后端。

你授权 DS 这一夜可以自己反复修改方法、调噪声和关联、修控制，不需要一次失败就停下来等确认。我把这个权限明确写进了任务书。
总预算8小时、最多1200次物理尝试；所有失败、探针、测试和重跑都入账，最后20分钟必须整理交接。
物体形状先验必须去掉；奖励、物理、成功判据和最终验收样本不能为了过关而改。

最后看三个结果，而不是只看几段好录像：

1. 信息是否合法：改掉隐藏尺寸/背面，保持可见历史相同，算法输出不能改变。
2. 运动是否估准：在观测确实足够的时段，接触处侧向速度和角速度的误差、置信度、可用时长是否达标。
3. 推动是否好用：固定40条任务回归和40条协作控制场景，各至少80%通过，并且每个场景族都有最低要求。另有关闭接触信息/几何信息/侧向调整的对照，检查究竟什么在起作用。

这会先修复 RL 所依赖的动作执行层：将来策略选择“推”以后，尽量由稳定的控制器处理接触跟随，减少策略为感知漂移和执行振荡兜底的负担。
它不能证明 RL 已学会协同，也不能保证以前的checkpoint仍有效；这一夜不训练。

如果全部通过，交回一个可用的无形状先验控制版本；如果未通过，也必须交回已完成的先验剥离、最好的合法实现和明确失败分布，不能换回已知矩形方案报喜。
