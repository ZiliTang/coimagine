# 先把一个换面失败实例看清、做通

此前我们修了不少局部 bug，但没有沿同一条失败轨迹把整个行为做通。一个环节刚改好就跑全体测试，结果容易变成“成功率没动”，仍不知道下一环有没有真正执行。

这次固定 `T_reposition_2_p0`：机器人先换到另一侧，再向南推，最后制动。初态、动作、时间和目标全部不变，只有一个实例。

它暴露的问题很具体：机器人离自己选的接触候选还有约34 cm时已经接触物体并开始推；后来确实侧移了约6 cm，但距候选仍约21 cm。我们需要先看到它究竟怎样走到这个状态，才能一起决定该改候选、接近路线、速度，还是接触后的分支。

**DS 首先交一张能逐帧查看的诊断页，暂不自主改算法。** 你能暂停到首次接触前，看到雷达点、拟合线、候选、实际接触点、位置误差、阶段条件、指令/实际速度、施力和物体响应；它们共用时间轴，可以在冻结的旧版与新版之间同步对照，并在某一帧留下备注。

你查看后参与逐步调整。每版继续只盯这一实例，看它有没有真正到达想去的位置、有没有安全接触、能否持续推进，直到原脚本下完成原目标。多个相互依赖的子问题可以按行为链连续解决，不要求每改一个参数就去跑全体场景。

**一个实例做通并经你确认以后，才检查镜像、双推和其他场景。** 这样能先弄清楚方法是否可实现，再判断是否泛化、是否牺牲其他能力。

对 RL 的帮助是先得到一个行为可解释、确实能执行的 option。否则策略选对动作也可能被控制器的接触过程拖垮，训练效果就难以解释。单实例调通仍不证明普遍可靠，也不直接授权训练。

本次仅交付可视化和诊断：优先复用现有日志，缺数据时最多补4次同一实例的冻结版本运行；没有新算法搜索或全场景评测。任务书：[D011](../tasks/D011_Single_Case_Visual_Diagnosis.md)。
