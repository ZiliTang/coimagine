# D008 给用户的说明：机器人侧移后，为什么“应该顶的位置”也跟着变

上轮已经确认：4 cm 偏移确实写进了目标，安全投影也没有把它裁掉。但机器人一移动，估计出的接触参考点也会变化；两者有时互相抵消，让最终目标没有按预期移动。

这次要查的是：**参考点变化是在反映真实几何，还是雷达区间和跟踪历史让它产生了偏差？** 先把这件事讲清楚，才知道是否值得改控制器。

可以把它理解为：我们让机器人“沿边挪四厘米”，但它对“边的中间在哪里”的判断也可能变了。如果这个基准同时偏了六厘米，最后看起来就像原来的指令反了。这只是现象，不能因此马上断言端点算法坏了。

本轮会把已有轨迹逐帧放回物体坐标系，并对照真实边和端点检查四层：

1. **看到了多准？** 雷达通常只知道端点在两根射线之间的一段区间内。真端点在区间里时，中点偏一点并不代表测量错误；还要看这个区间是否已经宽到不足以支持四厘米纠偏。
2. **历史有没有帮忙？** 跟踪器会用过去的位置和估计速度预测，再用当前区间修正。它可能减少抖动，也可能保留或累积偏差。
3. **参考点怎么算出来？** 单独算清端点位置、选哪一端、法向方向和边长对误差各贡献多少，确认各项加起来能还原记录。
4. **为什么抵消指令？** 把正负偏移、镜像和原版 A 一起看，避免只从失败的一侧挑解释。

在成功复现原跟踪器输出之后，再比较两个固定离线基线：去掉速度预测，以及直接使用当前区间中点。它们只读取已经记录的扫描，不生成新的物体运动。若去掉预测明显更准，下一轮才考虑只改这一项；若主要是测量区间太宽，就应处理可观测性，而不是增加 gain。

对 RL 的帮助是：让 PUSH 的接触位置与执行反馈更可靠，减少策略需要适应的估计漂移。它不能证明新控制器更稳定或 RL 成功率提高；这些需要后续独立对照。

范围覆盖34条完整记录、3,934个控制 tick，另两条稀疏非干扰记录单列。新增物理运行为0，不改控制器，不训练。离线分析与检查总运行上限30分钟，交回后由 GPT 复核，再定唯一改动。
