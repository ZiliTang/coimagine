# D002 给用户的说明：让策略有耐心，但仍能及时停止

2026-10-29。对应已定参数和分流条件的D002任务书。

我们想改善的是：RL发出需要准备的动作后，能不能给它足够执行机会，
而不是刚接近、刚对齐就换任务。D001提示短暂尝试很多，但还没有证明多坚持一定有效。

第一步不训练：从已有日志固定12个状态，比较原后续动作与原同推动作连续执行3.2秒。
检查双方是否建立接触，以及物体是否更接近目标。若持续执行经常无效或更糟，就在此停止，
不把“缺乏耐心”当作既定原因修改训练。

第一步通过后，比较“无新惩罚”和“有新惩罚”：

- actor仍每0.8秒决策，底层仍20Hz控制，不同时改频率。
- 每台机器人刚开始一种模式就换成另一种，最多额外扣0.08。
- 距上次模式改变0.8秒时最多扣约0.053，1.6秒时约0.027，2.4秒后不扣。
- 改速度不扣，进入制动不扣，明确执行失败后退出不扣。
- 插入一次制动不会立即清除之前的计时，防止绕过成本。
- 不额外奖励等待，原任务的时间成本和90秒失败代价仍然存在。

0.08是每台机器人约2秒原时间成本的量级；2.4秒给连续3个决策间隔的尝试机会。
这是固定的保守候选，不是已经验证的最佳值。执行侧不自行调参。

正确计算成本需要知道最近非制动模式、过去多久、是否失败。
所以两组都追加相同16维合法历史摘要，输入944变960；新增输入权重初始化为零，
保证最初动作概率与原模型一致。原网络其余权重和已有持续偏置都保留。
两组唯一比较因素是新增成本为0还是0.08，不能只给惩罚组增加信息。

两组从同一joint第40轮模型出发，各用两条后续随机流训练20轮，共4次短训。
这是检验当前模型能否改善的小实验，不是证明架构优势。
若进入训练，总预算最多640条训练episode和400条评估episode；另有第一步24条短分支。
仿真、训练、分析、评估合计执行上限20分钟，数值测试另限3分钟。

判断好坏仍看原任务：是否更稳定成功，是否能停住，完成时间有没有变差。
动作切换少了、惩罚少了而成功没改善，不能说方案有效。
除了末轮，还看最后三次评估的成功保留，不挑偶然最好的一次。

这一轮要回答：**减少过早切换，能否转化为稳定任务成功，而不让策略更固执？**
诊断未通过或训练没改善，都保留负结果并停止，不自动扩大惩罚或开始长训。
