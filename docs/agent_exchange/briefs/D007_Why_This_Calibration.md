# D007 给用户的说明：先确认“让它侧移”这件事能不能做到

现在的困惑像这样：我们把机器人应该顶住的位置往旁边挪了，画面上的目标点也动了，但机器人没有明显跟上，物体仍在偏转。

这时继续调“旋转纠偏增益”，可能只是在改变目标点，没改变实际接触位置。RL 看到的也会是一个难以预测的 PUSH：同一个动作有时推进、有时带着物体转。先把这一层测清，才知道应该改控制器，还是让策略学习选择更合适的位置。

本轮做两次减法，保留一组原版作为对照：

1. 暂时关闭依据方向偏差、旋转速度和横向漂移来挪目标点的反馈，保留原来的接触位置分工与安全边界。这样目标不再受好几套纠偏同时影响。
2. 在上一步基础上，去掉一项额外的侧向速度阻尼。底层仍有速度反馈、加速度限制和力上限；要检验删掉它是否让机器人更能跟上目标，以及会不会增加振荡。

然后给一个机器人很小的左右目标偏移：每次 4 cm，持续 1 s。逐层看目标是否被安全投影挡住、速度指令是否发出、机器人是否侧移、实际接触点是否跟随，以及物体怎么转。左右镜像也跑，避免只把一个场景的转偏恰好抵消掉。

**为什么不直接把旋转 gain 改成 −0.18？** DS 测到这个值的终点角度较小，但这不等于证明了负号就是阻尼。按照理想接触力矩公式，当前正号本来可以是正确方向；实际反向表现正说明“目标点→真实接触→物体转动”还没有测清。

结果会这样影响下一步：

- 减法后更能跟随，推进和稳定性也保住：保留简单候选，再考虑只恢复有必要的一条方向纠偏。
- 目标被安全区间裁掉：先处理可行接触位置，不加 gain 强推。
- 指令已发出但机器人仍不侧移：继续检查速度/力限制和接触约束。
- 法向估计跳变：先校准感知，避免用错误的“旋转速度”闭环纠偏。

正式对照最多 36 条短轨迹，测试与分析总运行预算 900 s；无 RL 训练，不改默认，不改物理或奖励。它不能证明 RL 成功率提升，但能帮助我们给 RL 提供更简单、更可解释的动作执行能力。
