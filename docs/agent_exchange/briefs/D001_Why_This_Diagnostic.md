# D001 给用户的说明：为什么先检查双推的学习过程

2026-10-29。补充解释，不改变已经移交给 DeepSeek 的任务范围和预算。

我们优化 RL 的近期目标，是让它在少量已确认可解的任务上，稳定地选择并持续执行有效动作，
再扩大训练场景。现在的关键困难是：训练中有双推成功，但最终策略每次选择自己最偏好的动作时，
往往变成“一台推，另一台换位”，两个双推场景都失败。

这次要回答：成功经验在哪一步没有转化为稳定行为？本轮不会训练出更好的模型，
它的产出是缩小下一轮应该改什么的范围。

## 为什么“偶尔成功”和“稳定会做”可以不同

训练时策略按概率抽动作，不总选概率最高的动作。即使它更偏好一推一换位，
也可能抽到双方同推，并最终成功。贪心评估总选当前最偏好的动作，可能反复走同一条失败路径。
成功还需要连续推进、适时停止，所以初始一次同推概率也不能代表整条任务成功率。

此外，旧报告的41/80、50/80来自训练过程中不断变化的策略，不能说明最后那个模型还保留多少成功能力。
因此先固定模型测试，才能确定我们要解释的差距是否真实存在于当前模型。

## 三步检查分别解决什么

1. 固定模型，在两个双推场景重复随机执行，并与贪心执行对照。
   这回答“当前模型还会偶尔成功，还是训练后期已经连这种能力也丢了”。
   看完整动作与执行记录，分清没选择同推、选了但没执行成、推进了却没停住。
2. 检查学习算法如何评价这些动作。
   PPO不会把成功轨迹里的每个动作都一律奖励，而是估计“这个动作比原先预期好多少”，称为优势。
   如果真正有用的同推没有得到正评价，多采这些数据也未必能有效强化它；
   下一步应查价值估计和延迟成功的信用分配。
3. 检查不同任务是否把同一模型往相反方向调整。
   单机任务可能鼓励“一台工作，另一台让开”；双推任务则需要两台一起工作。
   我们检查双推经验是否推动同推概率上升，而其他经验又将其压低。
   这是待验证猜测；梯度分析只给局部方向，不能单独证明历史训练失败的原因。

## 结果如何帮助改善 RL

| 如果观察到 | 下一轮优先尝试 |
|---|---|
| 有随机成功，同推得到正评价，却受到其他任务更新的抵消 | 双推隔离训练与混合训练的短对照，验证是否需要调整数据混合 |
| 成功中的关键同推没有得到有效正评价 | 检查价值估计、优势计算与延迟回报，而不是先增大模型 |
| 策略选了同推，但大部分时间卡在等待、切换或接触失败 | 固定动作检查执行过程，再决定调整策略还是控制器 |
| 当前随机策略也很少成功 | 查成功能力何时丢失及其保留情况，修正对旧累计成功率的解释 |

优先双推，是因为它已有成功经验可追踪；换面还缺少成功经验，探索、持续执行和信用分配更容易混在一起。
已有监督容量探针也表明当前网络能在这些小场景表达成功行为，因此现在还没有充分理由先加大网络。

本轮最多92条轨迹，仿真与分析15分钟，不改权重、奖励或控制器。
验收目标是定位下一项值得验证的改动，不要求出现更高成功率。
两场景和局部梯度只能给线索，不能证明泛化或最终因果；如果证据不清楚，明确交回“不确定”。
