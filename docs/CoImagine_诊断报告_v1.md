# CoImagine 诊断报告（第 20 轮）

诊断对象：6×6 格子推动环境里的学习世界模型规划链路。基线版本 `e10262b`，本轮改动见附录 B。
评估集固定：`generate_situations(n=300, lead_in=0, seed=55000)`，所有策略先做同一个公共热身动作 `probe:0:E`。
运行入口：`python -m coimagine.cli diagnose --output outputs/grid/diagnosis --seeds 0,1,2,3,4`
（快跑：`--quick`）。原始结果：`outputs/grid/diagnosis/diagnosis.json`；下表为它的汇总。

---

## 1. 当前主要问题（按证据强度）

**已证实（代码事实，各有可复现的最小例）**

1. `plan_with_model`（学习世界模型的两步规划器）**把末端的进度项算了两次**：续步按 `cost + w·dist` 选，
   给首动作打分时又加了一次 `w·dist`。`scoring_identity_checks` 用已知输出的桩模型从分支记录重建分数，
   旧式每个动作多出 9 分。**已修**，重建误差降到 3e-11。
2. 同一规划器的距离启发 `_worst_cell_distance` **方向反了**：它算的是"物体各格到最远目标格的最小值"，
   把离目标一步的物体读成 5–6 而不是 1，而且随物体 y 变化（目标区跨所有行）。
   `belief_probe._cell_distance_distribution` 早就修过同一个错误，这条线漏了。**已修**。
3. 修好之后，`plan_with_model` 的"深度 2"与"深度 1"**完全等价**：`wait` 代价 0、状态不变，永远是续步
   argmin，深度 2 的分数在代数上退化成深度 1。桩模型上逐动作分数相同；精确表模型在 30/30 个决策点
   选出同一个首动作。**所以这条规划器"加深搜索"结构上不可能有收益**——这是近似设计，不是编程缺陷，
   未改，只登记。
4. 历史评价口径有错：`rollout_probe` 的 `solvable` 是"全知 oracle 在同时域实际成功"，不是精确可达；
   `run_closed_loop` 把测量窗口开始前就已解的回合记为 0 代价成功；`run_episode` 截断失败时**不记失败代价**，
   失败退出会变便宜。新入口把三者分开命名并显式列出分子分母。
5. 两个历史数字在代码里**无法追溯**：四步实验第一步 0.412；"想象距离−真实距离 +0.53/+0.74/+0.66"。
   另 `最终结论` 把 0.994 写成"端到端"，代码里 0.994 是"给定真实物理"的一步准确率，端到端是 0.986。
   `direct.npz`、`latent.npz` 已无法用当前结构加载。

**较支持（同一规划器、同一评估集，只换模型）**

- **学习模型是主要瓶颈，不是搜索/信念实现。** 精确表模型接进同一规划器后，可达子集成功率随深度
  单调上升，学习版不升反降（见第 2 节表）。
- **主导模块是转移，不是观测似然。** 模块替换（factored 线、深度 2、43 个可达回合）：精确转移+精确观测
  0.535；学习转移+学习观测 0.279；精确转移+学习观测 **0.651**；学习转移+精确观测 0.279。
- 把精确模型接进 `plan_with_model`（60 场景、25 可达）：学习版 0.040 / 0.000（深度 1/2），精确版 0.400；
  即使把物理后验冻结成均匀先验（信息严格少于学习模型），精确动力学仍是 0.400。

**尚未确定**

- 深度惩罚只在 **5 个训练种子、1 个固定评估集**上量过，未做置换检验或置信区间。
- 混合模块两侧共用同一状态布局，替换合法；但学习观测模型的输入分布与训练时不同，各行差值不是纯因果分解。

## 2. 支持判断的替换实验

同一规划器、同一批固定场景，只替换模型（factored 线，`plan_with_search`，beam 1，深度 1–3）。
下表是**唯一一张结果表**，括号内为成功数/分母。

| 模型 | 深度 1 | 深度 2 | 深度 3 |
|---|---|---|---|
| 精确表模型 + 精确信念（43 个精确可达回合） | 15/43 = 0.349 | 23/43 = 0.535 | 31/43 = 0.721 |
| 学习模型，5 个训练种子（同一批 43 回合，均值[最小,最大]） | 0.307 [0.233, 0.349] | 0.098 [0.023, 0.163] | 0.135 [0.047, 0.233] |
| 学习模型 `belief.npz`（150 场景里的 63 个可达回合） | 10/63 = 0.159 | 15/63 = 0.238 | 7/63 = 0.111 |
| 随机动作（300 场景里的 126 个精确可达回合） | — | — | 37/126 = 0.294 |

**代表性失败案例。** 场景 6，`r=1, free, A=slip, B=grip`，物体在 (1,0)，两台机器人都贴在物体西面。
B 单独推得动，物体离目标 3 格，精确可达。精确表模型 + 深度 2 的候选分：`wait` **29.000** <
`probe:0:E` 29.300 < `push:1:E` 29.625 → 选 `wait`。原因是失败代价 20 对"等"和"推一步"几乎相同，
前瞻只到第 2 步、够不到 3 步外的目标，而 `wait` 免费且状态不变；同一场景深度 3 能解出。
完整分支与分数在 `outputs/grid/diagnosis/diagnosis.json` 的 `failure_traces`。

## 3. 修复改变了什么，是否跨种子成立

两处评分缺陷都改在 `world_model_probe.py`，各带最小回归测试（`tests/test_diagnosis_round20.py`，
含一条"旧式会多算多少"的断言，防止回归测试空过）。修复让评分与文档公式一致，但**对学习模型的闭环
成功率没有可测改善**：学习 `latent_released` 在 60 场景上修复前后都是 0–2 个成功，落在 5 种子离散带内。
跨种子成立的是"深度 1 最好、深度 2/3 更差"这一现象本身；"修好评分就能让学习模型可用"不成立。

**未完成**：5 个种子的置换检验/置信区间；混合模块分布外输入的量化；`direct.npz`/`latent.npz` 的重训复现。

## 4. 这个环境值得/不值得继续什么

**值得**：当机制诊断仪器。精确可达、精确信念空间参照、信息边界、最小失败例都可复现且已测试。
**不值得**：当方法对比基准。300 场景里精确可达只有 126 个（0.420），随机在可达子集上 0.294，
可达回合本身只有 2–3 步；全场景上限 0.420、随机 0.294–0.333，动态范围窄、方差大。
在这个测台上继续报"方法更好"的数字没有解释力。

## 5. 下一步（只推荐一个目标）与停止条件

**目标**：只做一次针对性数据干预——用与对照匹配的训练预算，补齐"连续成功推动"这一 regime
（当前只占 6.4% 的转移），然后在固定评估集上按 ≥5 个训练种子配对比较。

**停止条件**：若学习规划器在精确可达子集上的跨种子区间与随机基线区间重叠，判定该环境无法鉴别，
停止在此环境上的方法迭代，转而提出一个能把"oracle − 随机"动态范围拉开的最小新任务
（只提方案，本轮不实施）；若稳定超过随机，才继续谈接近精确参照。

## 附录 A：统一口径的定义

- **精确可达**：在固定动作集与任务时限下，对 (物体位置 × 已解开 × 两台机器人位置) 的有限状态空间做
  广度优先搜索，返回最少动作数；`None` 表示时限内不可达。**只有它叫"可解"。**
- **oracle 成功子集**：全知 oracle 在时域 16 实际成功的回合。在本评估集上它与精确可达一致（126/300，
  0 个分歧），但名称与定义必须分开，不能把 oracle 的成功当作物理可达性。
- **指标**：`成功率 = 成功数 / 分母`；`所有回合平均动作代价`；`成功回合条件平均总代价`；
  `总代价/成功次数`（零成功写 undefined）。总代价 = 动作代价 + `FAIL_COST=20`（仅失败回合计一次）。
- **距离误差符号**：`预测距离 − 真实距离`，距离 = 物体各格到最近目标格的曼哈顿距离取最大。
  正 = 模型以为更远（悲观）；手算例见 `diagnosis.json` 的 `audit.distance_sign`。
- **测量窗口**：开始前已解、或被公共热身动作解掉的回合不计入分母，数量单独报告。

## 附录 B：改了什么，旧数字追溯

改动：`world_model_probe.plan_with_model`（去掉重复进度项，续步与打分用同一目标）、
`world_model_probe._worst_cell_distance`（方向改回精确规划器的口径）、
`run_closed_loop` 增加可选的每边界模型工厂（不改变规划器调用）；
新增 `diagnostics/exact_adapter.py`（两个精确模型适配器）、`diagnostics/diagnosis.py`（本轮入口）、
`tests/test_diagnosis_round20.py`、CLI 子命令 `diagnose`。未改任务、代价、奖励与场景生成。

旧数字：0.420/126 与随机 0.333 可复现（后者口径是 oracle 成功子集；同一随机策略换一个 rng 消费顺序
得 0.294，说明基线本身在 0.29–0.33 之间）。0.994 可复现但被 0.986 的"端到端"标签混用；
6.4% 可复现，"四次连续推且至少动两次 = 3/1687" 按仓库内函数算是 7/1687。
0.412 与距离误差 +0.53/+0.74/+0.66 无生成代码，标记**未复现**。
