# 备忘：option 时长/尺度（macro-action）改造与长程信用分配

日期：2026-10-19｜来源：option 测台 Round 000–002 讨论与实测｜状态：**设计输入，未改动 RL 契约**

本文供规划端在完成多轮 option 调优后，整理为下一版实现方案。它不改变当前冻结的
324 维 RL 契约、不启动 PPO、不属于 option 测台轮次。

## 1. 假设：多步换面造成长程信用分配困难

用户提出的假设：在对称角点场景（`edge_turn`）里，要让“与目标同侧的机器人”绕到另一侧，
需要多次切向转移（实测约 6 次 CW / 22 s）；在换面完成前，任何推动都可能把物体推离目标，
真正产生正奖励的协同推发生在很久之后，因此 RL 很难学——**动作与奖励之间的 gap 太大**。

- 支持：Round 002 实测，对称角点双推是力偶（旋转 −62.2°、净平移≈0）；CW 转移 6 次
  （22.15 s）后协同推得到 −0.205 m 朝目标、仅 −13.2° 旋转。
- 限制：该测量是**脚本化固定序列**，只在一个 snapshot 上，不能证明多步换面是 RL 困难的
  唯一原因。诊断里的短失败主导梯度（1517/1687）、共享 critic 梯度远大于 actor、8 s 窗口、
  安全退出短循环等因素仍可能独立起作用。应作为**主假设之一**验证，而不是既定结论。

## 2. 方案：给 option 增加独立的时长/尺度维度

- 动作 = `(类型, 时长/尺度)`：类型沿用现有 15 种（9 PUSH + 4 REPOSITION + 2 WAIT_BRAKE），
  时长/尺度用 8 档 one-hot（1x…8x），两台机器人联合决策。
- 语义建议优先用**“重复同一技能 N 次”**（macro/repeat）：不动物理、不动物理窗口（仍 8 s/技能），
  只把 N 个子技能合成一次决策；这样既减少决策点、又让策略一次承诺一个长动作。
  另一种“把单个技能延长到 N×8 s”属于物理/协议变更，需单独升级环境版本，不建议先做。
- 开始时统一尺度（repeat=1），等价于现有 225 动作策略，便于从 warm start 出发；之后再解冻。

## 3. PPO 是否支持这种双动作编码组合：支持

PPO 只要求**采样与 log 概率用同一因子化、比率用联合 log 概率**。现有 `JointPolicy` 已经是
`p(a0|h)·p(a1|h,a0)`（225 有序对，`evaluate()` 返回两个条件 log 概率之和）。扩展后：

- 每台机器人 `p(type)·p(repeat|type)`（或 `p(type,repeat)`），两机器人再 `p(a0)·p(a1|a0)`；
- 联合 logp = 各项之和；`ratio = exp(new_logp − old_logp)`；clip、优势、价值目标**不用改**；
- 熵：只有对 a0 取期望后 `H(a0)+E_{a0~p}[H(a1|a0)]` 才是精确联合熵；只取采样到的 a0 得到的是
  采样条件熵（当前 RL 日志记录的正是后者）；实现时应显式对 a0 分支取期望；
- 半马尔可夫目标已支持变长技能（现有 `return_to_go`/`prefix_before`，`gamma=1`），macro 只是
  更长的半步。

实现建议用**因子化头**而不是拍平 120 路/机器人（更不是 14400 路联合）：每机器人输出
15 个 type logits + 8 个 repeat logits（可条件化），robot1 再条件化于 robot0 的
`(type,repeat)` embedding；one-hot/embedding 是**条件化输入**，不是输出层本身。

## 4. 实现要点与坑

1. **logp 一致性**：建议 macro 为“一次决策选 (type,repeat) 并执行 N 次子技能”，logp 是单个
   categorical；若改成“每个子边界重新决策但强制同动作”，logp 是 N 项之和。两者都行，但必须与
   采样、replay、PPO ratio 完全一致。
2. **优势归一化分母会变**：决策数从约 800/批降到约 100–200/批，短失败不再淹没梯度；需重新
   校准 advantage 归一化与价值目标。
3. **日志/replay**：macro 分支要记录每个子技能边界与逐周期物理，否则指标与回放无法复核。
4. **信息边界**：repeat 不能依赖队友尚未收到的动作；联合决策要么同步选两台，要么按协议
   先消息后提交。
5. **旧 checkpoint**：schema 变更会使现有契约、warm start 与 checkpoint 失效，必须新开契约、
   重训并做配对比较；不要用隐式全局 monkeypatch 切换。

## 5. 与任务边界的关系

这是**新动作菜单 / 宏观动作**改造。任务书明确“动作历史、网络扩容、世界系新动作菜单另开
实验”。注意**动作契约与输入契约分开管理**：增加 repeat 改变的是动作空间/动作头与相关
checkpoint，**不会自动改变 324 维观测布局**。因此不混进 option 测台轮次，作为下一版独立
预注册实验。

### 5.1 执行语义（必须先定义，否则 repeat 可能只是打包失败循环）

- **重复 N 次技能 vs 连续执行一个更长技能**：repeat 会在每次重复时重置 FIND/ALIGN、法向滤波、
  参考速度与内部计时；连续执行保留这些状态。两者闭环能力不同。
- 若短技能反复因安全条件退出，repeat 可能只是把失败循环打包，而不是形成有效长动作。
- 双机器人 macro 必须定义：双方 repeat 数不同怎么办？一方受阻是否中断整个 macro？中间反馈
  是否允许取消承诺？
- 建议先在测台比较“重复执行”与“保持控制器状态的连续执行”，分解 22 s 里花在有效切向移动、
  重新寻找/对齐、受阻安全退出、等待队友的时间；若耗时主要来自重复初始化，应先优化技能连续性。

## 6. 建议的最小验证（先便宜地证伪）

- 保留物理与 8 s 窗口，只加 repeat ∈ {1,2,4,8}；从 repeat=1 的 warm start 出发，与现有
  225 动作基线在固定小面板上配对比较。
- 指标：决策数、换面完成率、目标进展、学习曲线稳定性、原成功保留、短失败占比。
- 否定条件：repeat 维度没有改善换面完成/目标进展或稳定性，就否掉该假设，不继续扩动作空间。
- 可选：先做脚本化 macro 分支测量（Round 002 已做一版），再决定是否重训。

## 附：Round 002 实测证据（用户授权的超预算有界测量）

`edge_turn`，控制器固定为 `segment-contact-v1`，只改动作序列（每分支 ≤8 技能、≤45 s 物理、
≤15 s 分支墙钟，用户明确授权；批量 7.92 s，渲染 2.46 s）：

| 分支 | 技能 | 物理 | r1 终点/所在侧 | 物体位移 | 转角 | 目标进展 |
|---|---:|---:|---|---:|---:|---:|
| 对称双推 (4,4) | 1 | 5.85 | 下（目标侧） | (+0.006,−0.007) | **−62.2°** | +0.007 |
| CW 转移 ×6（只转移） | 6 | 22.15 | **上（r0 侧）** (1.71,1.51) | (0,0) | 0° | 0 |
| CCW 转移 ×6（只转移） | 6 | 19.70 | 下 (2.39,0.96) | (0,0) | 0° | 0 |
| CW 转移 ×6 后协同推 | 7 | 26.50 | 上 (1.70,1.18) | **(−0.037,−0.205)** | **−13.2°** | **+0.205** |
| CCW 转移 ×6 后协同推 | 7 | 25.75 | 下（未换面） | (−0.284,−0.034) | −27.7° | +0.034 |

结论：
- 对称角点双推是**力偶**（−62.2°、净平移≈0），不是控制器 bug；
- 与目标同侧的机器人绕到另一侧**需要约 6 次 CW 转移 / 22 s**（CCW 需 8 次 / 30.6 s）；
- 换面后协同推得到 **−0.205 m 朝目标、仅 −13.2° 旋转**，约为单推 (4,13) 的 3.5 倍、
  力偶的 29 倍；推动主要来自换面后位于面中部的 r1；
- 转移阶段物体完全不动（“先移动、后推”），真正产生奖励的推在约 22 s 承诺之后，量化了
  长程信用分配 gap，支持增加 option 时长/尺度（repeat）维度的方案。
