# Option 方案设计与演进（供规划侧核验）

日期：2026-10-19｜作者：执行侧 agent｜用途：交给规划侧核验设计动机、边界与判定方式

本文覆盖 option 测台 Round 000–005、模型保真度决策、RL 契约 v4、以及最新一轮讨论
（距离编码、接触区域/锚点跟踪、SUPPORT_FOLLOW、同侧遮挡）。**尚未实现的部分在标题里明确
标注**，请重点核验第 5 节的开放问题。

## 0. 总体目标与约束

- **最终目标**：训练一个 option 级策略，能低成本迁移到实验室的**两台宇树机器狗**（顶部雷达、
  全身控制可实现近似全向运动）。
- **当前阶段目标**：先把 **option 本身** 评测清楚（技能承诺了什么、实际做了什么、为什么失败），
  **RL 影响暂不考虑**。
- **约束**：只维护**一个**环境模型，不做备选/回退；旧的 324 维 RL 结果已**正式作废**；
  不靠缩小成功定义、改奖励、改物理参数或放宽安全条件获得正结果。

## 1. 演进历史（时间线：触发 → 决策 → 动机）

### 1.1 Round 000 — 有界测台与基线诊断（已完成）
- **触发**：需要一个能反复使用、每轮只改一个变量的 option 诊断工具。
- **决策**：8 个冻结 snapshot、24 个预登记分支、三层指标（控制器声称 / 独立重算契约 /
  离线任务效果）、本地 HTML 回放、硬墙钟预算。
- **结果**：24/24 accepted、8/8 states；19 fulfilled / 0 violated；发现 `face` 对称双推
  互相抵消（物体位移 0）、`corner_plus` 擦角 `contact_lost`、`edge_turn` r0 受阻。
- **动机**：先把“测量”做对，再改控制器；避免用弱判据自我说服。

### 1.2 Round 001 — `segment-contact-v1`（已完成，保留）
- **触发**：`corner_plus` 在角点处接触 0.05 s 就丢。
- **决策**：PUSH 加有界切向参考，把机器人中心保持在**可见线段端点内侧**
  `ROBOT_RADIUS + 0.02`；触发量用**切向到端点的偏移**（不是垂直间隙，也不是
  `nearest−distance`，后者会漏掉 `corner_plus`）。
- **结果**：`corner_plus` `contact_lost` → `push_complete`（接触 0.05 s → 2.05 s）；
  `edge_turn` r0 受阻 → 完成；`face`/`corridor_wide`/`teammate` 逐周期不变；baseline 6/6 逐值复现。
- **动机**：这是第一个被证据支持的“低层接触方式确实影响结果”的改动；它仍是 `corner` 类问题
  的真实修复手段（Round 005 排除了“转向”是修复原因）。

### 1.3 用户指出 `edge_turn` 标签歧义（已完成）
- **触发**：用户问“为什么叫 edge_turn、目标在物体的另一侧是相对谁”。
- **决策**：修正双语标签；明确“目标在物体下方，r0 在上方（对侧）、r1 在下方（同侧）”。
- **动机**：标签是给人看的证据，不能含糊。

### 1.4 用户的物理洞察：对称角点 = 力偶（已完成）
- **触发**：用户观察 `(4,4)` 的结果。
- **决策**：确认对称角点双推是**力偶**（实测转角 −62.2°、净平移 ≈0），**不是设计错误**；
  正确策略是让与目标同侧的机器人**多次切向转移**到另一侧再协同推。
- **动机**：避免把物理必然当成 bug 去“修”。

### 1.5 用户假设：多步换面造成 RL 长程信用分配困难（已完成测量）
- **触发**：换面需要约 6 次转移 / 22 s，真正产生奖励的推在很久之后。
- **决策**：先做一次**授权的超预算测量**（≤8 技能 / ≤45 s / ≤15 s），不改控制器。
- **结果**：CW×6（22.15 s）把 r1 绕到另一侧；换面后协同推得到 **−0.205 m 朝目标、仅 −13.2°
  旋转**（力偶 +0.007、单推 +0.058）。
- **动机**：用脚本化序列先证明“策略存在”，再决定是否要宏观动作/尺度维度。

### 1.6 规划侧反馈 → Round 003 指标校准（已完成）
- **触发**：规划侧指出若干口径问题。
- **决策**：v2 指标（PUSH 分 `contact_established` 0.5 s / `full_push` 2.0 s；统计截断到
  个体技能结束；REPOSITION 用请求方向正向进展；队友间隙只减自身半径；法向跳变独立重算；
  条件兑现率分子限定 accepted）。旧指标保留、不覆盖。
- **结果**：汇总数不变（19/10/4、0 violated），逐项数字校准。
- **同时更正**：RL 报告里“exact joint entropy”实为**采样条件熵** `H(a0)+H(a1|a0=记录动作)`。
- **动机**：测量不准，后面的调优都会被误导。

### 1.7 模型保真度：机器人推动时完全不转（已完成原型 + 诊断）
- **触发**：用户指出 `backend._apply_forces` 对机器人 `torque=0`、力在质心，机器人全程不转，
  与真实机器人（用稳定的一侧推）出入过大。
- **决策**：先做**朝向原型 A**（默认关闭），保留 v3.1 对照；随后规划侧定为
  **“全向底盘 + 有朝向的前端推面”**，`oriented=True` 只作诊断，不直接升级为正式模型。
- **Round 004 诊断**：制动误门控**未复现**；`corner_plus` 改善来自 `lidar_only`
  （按**反馈力方向**转 + 随体雷达），`scale_only`（只缩力不转）反而 `blocked`。
- **动机**：先把“加朝向会不会改变结论”测清楚，再决定是否升级。

### 1.8 Round 005 — 最小候选 `heading_target`（已完成，重要负结果）
- **触发**：按规划侧要求，期望朝向必须来自**技能目标**而不是反馈力。
- **决策**：技能声明 `desired_heading`（PUSH 法向 / REPOSITION 切向 / WAIT 为 `None`），
  有界转向，**力从不门控**（制动/安全/避障始终全量）。
- **结果**：制动与 v3.1 **逐值相同**；`face`/`teammate`/`corridor_wide` **任务中性**；
  但 `corner_plus` **没有**复现改善（转到 +89.8° 仍 `contact_lost`）。
- **结论**：Round 004 的 `corner_plus` **行为变化是真实观测到的**，但它依赖“从反馈力反推
  期望朝向”这一**不合适的控制假设**（该力含接近/避障分量），**不能归因于预期的稳定推面机制**，
  因此不计入新模型收益。这一个负结果**不足以证明**所有角点问题都只能靠接触目标修复。
- **动机**：这是本轮最重要的诚实性更正——避免把“非法目标带来的巧合”当成收益。

### 1.9 用户决策：只维护一个模型，三项修改直接进 RL 契约（已完成 v4 时间尺度）
- **触发**：用户明确“只维护这一个环境模型、不用备选/回退、旧 RL 结果作废”。
- **决策**：雷达按上限截取、雷达随体转动、option 内置尺度，直接进契约；确认参数：
  尺度 `{2,6,12,24}` 秒、窗口=预算（≤24 s）、雷达 `distance(min(d,R)/R)+hit+one-hot(3)`
  → 756 维；前端推面本轮不做。
- **已实现**：`ENV_VERSION=random-start-oriented-v4`；48/机器人、2304 联合；观测 756；
  只有一种驱动模型；旧结果加 `INVALIDATED.md`。
- **动机**：多模型/回退最容易记混；旧结果作废后可以放心重构。

### 1.10 用户的 sim-to-real 顾虑 → 距离编码（待实现）
- **触发**：真机推动速度不等于仿真、推力无法在仿真充分标定；时间编码会放大 gap。
- **决策**：动作尺度从**时间**改为**距离目标**（PUSH=沿推动方向正向累计位移；
  REPOSITION=沿边界正向累计路径），**timeout 作为上界**由 `距离/速度×slack` 推导。
- **动机**：距离是平台无关的物理量；速度差异只改变耗时；底层闭环追同一个量。
- **局限**：不能弥补力/摩擦/延迟/打滑。

### 1.11 用户的支撑/跟随想法 → `SUPPORT_FOLLOW`（待实现）
- **触发**：协同推动不要求两台等量给力；一台推、另一台在**非推动侧做支撑性跟随**即可；
  因此 PUSH 应允许“0 m 尺度 = 只跟随”。
- **决策**：建议做成**独立类型** `SUPPORT_FOLLOW`（控制目标不同：维持相对位姿 + 可选小支撑力）；
  控制律用**相对位姿伺服**（法向保间隙/小支撑力、切向误差归零），而不是显式估物体速度。
- **动机**：相对位姿伺服只用雷达+里程计，sim-to-real 友好；跟随行为从误差反馈中自然涌现。

### 1.12 用户的遮挡担忧 → 锚点 + 遮挡模型（待实现，先测量）
- **触发**：两台同高机器人同侧推动时，一台会遮挡另一台的雷达；高度不一致时更明显。
- **现状核实**：仿真**已建模**队友遮挡（队友是半径 0.18 的圆，参与最近命中；category 可区分
  object/teammate）。策略目前**看不到**接触点（`contact_point_robot` 来自物理引擎，只在日志里）。
- **决策**：控制量用**接触区域 + 相对位姿**，不用绝对接触点；用**未遮挡的真实角点作锚点**，
  配合**已知物体边长**重建另一端；用**队友阴影预测**区分“真实角点”与“遮挡边界”；
  加时序滤波与显式失败状态（`both_corners_occluded` / `insufficient_visible_segment`）。
- **动机**：一个可见角点 + 面方向足以算距离与切向位置；遮挡是间歇的，时序滤波可扛；
  但“不可能两端都被遮挡”不严格成立（短边 + 近距离队友）。

## 3. 判定方式：哪些能自动判定，哪些需要人

**可自动判定（仿真有真值、判据可预登记）**：D2/D3/D5/D6 的回归与一致性；D7/D8 的“到达
距离目标且未超时”；D9 的维度/一致性；D10 的锚点误差（对真值）、断点分类正确率、显式失败
比例；D11 的相对位姿误差保持比例与接触保持；D13 的标记存在性。

**需要人参与的四件事**：
1. **阈值/容差**：锚点可接受误差、follow 的间隙/力/位姿容差、距离档位、slack 与 timeout 封顶。
2. **多目标权衡的目标函数**：目标方向位移 / 转角 / 耗时，哪个优先（例如“最大化目标方向位移，
   转角为报告项且不劣于基线”）。
3. **硬件可行性**：狗的最大速度/力、全身控制能否稳定输出小支撑力、雷达高度与物体高度关系。
4. **可选目视复核**：每轮挑 1–2 个代表性分支看回放。

**判定协议**：每轮先写 `ROUND_PLAN.md`（一个问题、一个改动、成功判据+阈值+否定条件、预算），
跑完只报告“是否达到预登记阈值 + 逐例基线对比 + 副作用 + 一个待决策问题”。

## 5. 请规划侧重点核验的开放问题

1. **距离编码的“距离”定义**：主命令用**机器人自身里程计位移**（平台无关、可直接测量）还是
   **用合法观测估计的物体位移**（更贴近“推物体 1 m”，但有噪声）？我倾向主命令用前者、
   物体位移作任务指标。
2. **timeout 是否作为学习维度**：我倾向由 `距离/速度×slack` 推导，保持 48/2304 不变；
   若希望策略自己权衡“慢推久”，则要加第二个尺度维度（动作空间膨胀）。
3. **`SUPPORT_FOLLOW` 是独立类型还是 `PUSH(0 m)`**：我倾向独立类型（契约与控制目标不同）。
4. **遮挡处理的层级**：只用雷达的“锚点+已知边长+时序滤波”是否足够，还是把视觉标签/关节力矩
   作为正式输入（会加部署条件）？我倾向前者，视觉只做离线验证。
5. **“不可能两端都被遮挡”的反例**：短边 0.25 m + 队友半径 0.18 m 近距离时可能两端都遮挡；
   需要接受“保守接近/重新观测/退出”作为合法结果。
6. **2D 假设与真机 3D 的差异**：狗顶部雷达若高于物体，射线可能打在**顶面**而非侧面，
   “侧面拟合/遮挡”模型需要重新定义；这一点仿真无法覆盖，需要实物决定。
7. **判定阈值与目标函数**（第 3 节）：请给出或确认默认值。

## 6. 风险与不确定性

- **sim-to-real gap**：距离编码只保证“机器人走了多远”，不保证“物体被推了多远”（摩擦、
  打滑、转动、延迟、力标定都不同）。
- **遮挡严重程度未知**：需要第 1 轮的测量才知道锚点法能恢复多少。
- **2D/3D 不一致**：雷达高度、物体高度、身体遮挡在 3D 里与 2D 差别大。
- **指标阈值的工程性**：容差取值会直接影响“成功”与否，必须预先固定、不能事后调整。
- **历史结论的边界**：Round 002/004 的若干表述已被收紧（换面序列只是一条可行序列；
  corner 改善是诊断假象），引用时请以最新文档为准。

## 7. 建议的轮次顺序

1. **第 1 轮（只测量+可视化，不改控制）**：同侧遮挡有界测量（间距 0.2/0.4/0.6 m、队友在前/在后）
   + 接触目标可视化 + 三种估计对比（可见片段 / 单角点锚点+已知边长 / 锚点+时序滤波）。
   交付：误差随间距的曲线、可交互回放、一个明确结论。
2. **第 2 轮**：距离编码 + 推导 timeout + 观测进度特征 + 契约判据更新。
3. **第 3 轮**：锚点跟踪与显式失败处理（`both_corners_occluded` 等）。
4. **第 4 轮**：`SUPPORT_FOLLOW` + 场景验证（`face` 对向抵消、`edge_turn` 力偶）。
5. **后续独立轮**：前端推面几何/接触反力矩；RL 重训。

## 9. 规划侧核验后的修订与执行计划 v2（2026-10-19）

本节是规划侧核验后的**权威修订**；与前面小节冲突时以本节为准。

### 9.1 契约表述收紧

1. **v4 是过渡版本**：当前尺度主要是**超时预算**，不是完整执行尺度。PUSH 仍在累计有效接触
   **2.0 s** 后自然完成，推动阶段另有 3 s 上限；选 6/12/24 s **不代表持续推那么久**，可能只是
   允许更长的接近过程。REPOSITION 的名义距离 = `速度×预算`，但 FIND/ALIGN/加速共用同一预算，
   名义距离可能不可达；“MOVE 时间占比 + 正进展”的判据也**不等于**完成请求距离。
   **下一版直接明确：请求距离是目标，超时是未达目标时的退出上限，两者独立。**
2. **姿态统一只完成了一半**：`self.heading` 已统一用于观测、雷达与日志，但后端刚体仍有自己的
   `body.angle/angular_velocity`。圆盘形状让差异暂时不明显；**加入前端推面之前必须先完成物理
   姿态整合**。同时已清理仍接受 `oriented_mode` 却固定使用新模型的接口（配置表面不再撒谎）。
3. **历史负结果的措辞**：反馈力反推朝向是**不合适的控制假设**，不是“非法信息输入”；角点行为
   变化是真实观测到的，只是**不能归因于预期的稳定推面机制**；一个负结果**不足以证明**所有角点
   问题都只能靠接触目标修复。旧 RL 结果标记为“**不适用于当前契约**”，历史诊断本身仍有价值。

### 9.2 距离进度契约（下一版实现）

- 承诺措辞：**建立接触后，沿声明方向完成指定的机器人推动行程**；不叫“把物体推动指定距离”。
- **只计入有效接触期间**；接近、对齐、HOLD 阶段不计入 PUSH 进度。
- 推动方向在开始执行时**声明**；目标区域发生实质换面时应**重新确认或退出**。
- 主进度用**有符号投影累计**（反向位移扣回）；另报**正向总行程**与**反向行程**。
- **不得用逐周期 `max(0, 投影位移)` 作为唯一兑现标准**，否则往复运动可能不断刷进度。
- REPOSITION 同样报沿请求方向的有符号进展与反向运动；可用随边界更新的局部切向，
  但**换面时的进度处理必须明确**。
- 物体位移、转角、目标距离变化继续作为独立的**任务效果**。距离编码的边界：它减少对固定执行
  速度的依赖，但**不解决打滑或物体运动估计**。

### 9.3 timeout 推导

- `T_max = T_prepare + s · D / v_ref`，再受技能上限与剩余任务预算约束；`T_prepare` 覆盖
  FIND/ALIGN/接近，**不塞进距离项**。
- 预算在动作开始时**固定**，不因缺少进展而延长。
- 标注哪些距离档位在当前预算下**本来就难以达到**。
- WAIT 继续以**时间**为尺度，不强行使用距离。
- `SUPPORT_FOLLOW` 加入后动作数允许变化：**动作数是契约的结果，不是设计目标**。

### 9.4 锚点方案：从“一个角点就够”改为“满足条件时可恢复”

- “一个角点 + 面方向 + 已知边长”恢复另一端，还需知道：看到的是**哪个角**、**哪一种边**、
  沿切向**哪一侧**延伸，以及该端点**确实是真角**（而非遮挡/量程/采样造成的可见片段边界）。
  矩形对称性使**单帧未必唯一**。
- 已知物体尺寸必须是**部署时可获得的先验**，不能从实例真值静默读取。
- 锚点允许输出**多个候选或 `uncertain`**，不强制唯一坐标。
- 队友阴影预测只用于判断“**可能被遮挡**”，**不能证明**端点是真角。
- 滤波状态带**观测年龄、置信度、失效条件**；短时预测 ≠ 持续观测。
- 完全遮挡、无法定位时，**明确退出或请求重新观测是合格行为**。
- 区分控制器可见判断与离线标签：`both_corners_occluded` 是**评价标签**；控制器无法确认两角时
  应报 `anchor_unobservable`，**不声称知道隐藏几何**。

### 9.5 SUPPORT_FOLLOW v1：先“跟随”，后议“支撑”

- 独立类型比 `PUSH(0 m)` 清楚：零距离通常意味着目标已完成，**不能表达持续跟随**。
- 在非推动侧保持接触**可能产生抵抗主推的力**；“跟随”与“支撑”**不默认等价**。
- v1 限定为：**根据可见物体区域保持指定相对位置与间隙，不主动施加持续推动力**。
- 先验证：**跟得上、不挡路、不明显增加主推阻力**；确实需要支撑时，再按硬件能否提供
  可测可控接触力单独定义。
- 不为尚未量化的问题先引入视觉或关节力矩。

### 9.6 遮挡测量设计（下一轮，只测量不改控制）

- **间距定义**：机器人直径 0.36 m；0.2 m 若指中心距会重叠 → 明确为**边缘间隙**，或使用合法中心距。
- 场景：1 个无遮挡参考 + 1 个部分遮挡 + 1 个严重遮挡 + 1 个动态遮挡过程，**少而透**。
- 对比：当前可见片段 / 合法角点候选 / 带历史估计；带历史版本必须有**真实观测前缀**，
  **不能用真值初始化锚点**。
- 评价：除位置误差外，还要 **错误确信率、不可观测检出率、重新捕获时间**。
- 回放：控制器实际没有固定目标点时显示“**未定义**”，不要把离线估计点画成它正在追踪的目标。
- 暂不合成总分：**合法性与安全条件优先；兑现率与覆盖率并列；时间、转角、任务进展分别报告**；
  阈值**运行前冻结**，保留连续误差，避免某个容差决定全部结论。
- **雷达几何更正**：水平 2D 扫描平面若**高于物体**，通常是**越过物体**，并非自动打到顶面；
  能否看到侧面或顶面取决于扫描方向、垂直视场与安装姿态。未确认具体雷达与物体高度前，
  **不承诺**现有侧面观测可直接迁移。
- **实测结果（Round 006，已完成）**：长边参考跨度 0.965 m；同侧遮挡后降到 0.15–0.89 m
  （最多 −84%），但**至少一个真实角点保持可见**；朴素“线段端点=角点”在遮挡下几乎每个格子
  都出现**假角点声明**，唯一可靠区分是扫描 `category`（`object→teammate` 是阴影边界）。
  短边（0.25 m）+ 队友正前方时**0 条物体回波、两角点全遮挡**，控制器应报
  `anchor_unobservable`（测量显示可正确报出）。单帧锚点恢复为**两候选**（一个误差 ≤0.018 m，
  一个约 0.95 m），需要自身在面的哪一侧/时序来剪枝。详见
  `outputs/option_testbench_v1/round_006/REVIEW.md` 与 `OCCLUSION.md`。

### 9.7 最终执行顺序
