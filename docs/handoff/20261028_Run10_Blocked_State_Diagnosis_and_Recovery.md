# Run10 受阻状态排查与前置安全分离

2026-10-28。针对三条原始训练轨迹做冻结边界、原控制/候选控制对照。已实现一个有界的安全分离候选；没有重启 RL，也没有把它默认为现有训练入口的新行为。

## 排查结论

这些算例不是初态非法，也不是几何上始终无法分开。原轨迹的前几段 PUSH/RP/ROTATE 可以正常执行，随后机器人相互靠近，进入约 0–2 cm 的边缘间隙区域。

有三个相连的问题：

1. 通用安全检查直接结束当前 option；新 RP 还没进入 MOVE，外侧绕行控制就已经失去机会。
2. 反复重建 option 会重置参考速度/阶段。既没有一个持续的脱离阶段，也没有可靠地恢复到可执行下一动作的间距。
3. standalone FOLLOW 的局部表面跟随仍可能把机器人重新带向同伴。外绕只解决 RP 的部分路径，并没有解决所有混合动作的避碰。

三条完整原始轨迹的退出原因与时刻此前已逐段精确复现；本轮又精确复现了受阻前缀，并从相同物理边界分支。**有路却没有持续恢复动作**是已验证的执行缺口；它是否解释整个 RL 平台期仍未做因果隔离。

## 本轮实现

新增 `EnvConfig(peer_clearance_recovery="boundary_v1")`，版本 `peer-clearance-prefix-v1`。原 `off` 配置保留作明确基线，未隐式修改历史 checkpoint 的执行语义。

在 joint option 开始时，若共享机器人位置显示间隙 ≤3 cm，或短时预测会进入该区域，先暂停名义动作，执行最多 2 s 的安全分离。恢复到至少 6 cm、相对接近速度足够低并连续就绪 0.1 s，再执行原请求。

- 触发/释放只用已有共享运动学；每个机器人的退让方向只用自己的雷达与接触反馈。
- 短程扫掠圆盘检查物体/静态回波，选择不减少同伴间距的方向；不读取物体真值或另一侧私有扫描。
- 原 2 cm 安全退出、碰撞阈值、力/参考速度变化上限、物理参数均未放宽。
- 分离用真实动力学完成，计入原 option 窗口、90 s 任务时钟与原奖励成本；不计入 PUSH/RP 主动行程。
- 这属于安全覆盖：WAIT 一侧也可能短暂退让；其等待时间继续计时。FOLLOW 维护时间不从分离中获得完成 credit。
- 如果观测下找不到安全方向，保留制动，2 s 后明确返回 `blocked_peer_clearance`。这不是全局路径不可达的证明。

此阶段在动作边界生效。**FOLLOW 在正常执行中再次逼近同伴的问题仍然保留**，没有将该候选称为完整避碰方案。

## 实测：相同冻结受阻状态

权威结果：[round_003](../../outputs/option_testbench_v1/peer_clearance_recovery_v1/round_003/)。16 场景 × 2 配置 = 32 分支，全部完成记录；8 s/分支、60 s/批次限制，实际约 56.47 s。原动作、距离请求、时间预算和任务条件不变。

### 主动选择 RP + WAIT

在三条训练源边界上分别请求 CW/CCW RP[0.4 m] + WAIT[2 s]：

| 对照 | 结果 |
|---|---|
| 原控制 | 6/6 在 0.05 s 双侧 safety_abort |
| 前置分离 | 6/6 释放后完成 RP 和 WAIT |
| 典型分离耗时 | 约 0.8–0.9 s |
| 分离期间主动行程 credit | 0 |
| 这些单段分支最大穿透 | 0 |

恢复没有减小原 0.4 m 请求，且原超时预算保持一致。新增单测由本体位移沿上一周期实际指令切向独立复算 RP 进度，确认没有将分离位移补记为换面行程。

### 残余失败与静态阻塞

- 三组 original_next 原动作中，全部能够完成前置分离，但两组随后再次 safety_abort。**2026-10-28 复核更正：0026735 是 WAIT+FOLLOW，0026602 是 WAIT+PUSH；此前将两组都归因于 FOLLOW 不准确。** FOLLOW 与 PUSH 的再次接近需要分别排查。后续 FOLLOW 对照见 `20261028_FOLLOW_Peer_Guard_and_2cm_Gap.md`。
- 两机被封闭窄空间约束时，目标间距确实没有足够空间：分离不穿墙，2 s 后两侧返回 blocked_peer_clearance。
- 仅一侧有退路时，可以由自由侧退让实现分离；被困侧仍可能在后续名义动作上报静态安全退出，不将其标为整段 option 成功。
- 健康 RP 场景与另一清晰场景无需介入；真值轨迹和施力与原控制逐周期完全一致。
