# Run11 vs Run10：相同累计720次PPO更新的早期对比

**新版执行成本显著下降、早期成功机会更多，但尚未形成稳定学习优势；progress没有整体领先，后期仍出现成功行为丢失。** 当前run11继续训练，本报告冻结前720次更新，不随活动任务自动变动。

## 对齐方式与公平性

旧长轮为 `outputs/option_rl_v10/overnight_parallel_20261028/run10_001`，共3375个并行阶段更新、7.84小时。它从前一串行阶段已训练8轮的权重恢复，因此不能简单把旧并行iteration720当作从头720轮。

本报告旧组取串行前8轮＋并行前712轮，新组取从头前720轮；两组均 **5760个用于更新的训练episode、73次64根固定验证**。旧组最后验证累计更新718，新组最后720，因为旧续训后验证网格整体偏移8；窗口均值包含的验证次数相同。

- 两组64个validation、64个test逐项完全一致。验证中3个初始目标内场景一致，主要比较目标外61根。
- seed均0，场景生成器均`simple-legal-v2`；uniform随机目标，每轮8个完整episode；hidden256、PPO epochs4、lr3e−4、entropy系数0.02、gamma1和所有任务reward系数一致。
- 除首轮/旧串行预热外，两组均8个持久worker、批内固定归一化。旧组恢复前另消耗4个未用于参数更新的场景ordinal（64–67），可能已影响归一化；两组用于更新的初态内容交集5756/5760，平均初始距离均约1.006 m。
- 新组并非只改速度：还包含62 vs 68动作表、PUSH绑定FOLLOW、联合动作mask/概率归一化、混合接触与避让、停滞检测、批量扫描/采样快路径等。因此只能比较新旧整套配置，不能单独归因于快速PUSH。
- 同样更新轮数/episode数不等于严格相同PPO样本：旧组83,052、新组88,023个决策transition；优化器minibatch更新次数旧2988、新2924。

## 相同720次更新的结果

验证均值为同一固定面板在73个checkpoint上的时间平均，不是73次独立测试，不据此计算泛化显著性。

| 指标 | 旧Run10 | 新Run11 |
|---|---:|---:|
| 历史窗口累计墙钟时间 | 102.7 min | **61.7 min** |
| 固定验证原始成功率时间均值 | 6.14% | **8.52%** |
| 目标外验证成功率时间均值 | 1.53% | **4.02%** |
| 最好单次原始验证 | 9/64（14.06%） | **13/64（20.31%）** |
| 最好单次目标外成功 | 6/61（9.84%） | **10/61（16.39%）** |
| 验证progress时间均值 | **−0.035** | −0.051 |
| 训练progress每轮均值的均值 | **−0.086** | −0.127 |
| 训练return每轮均值的均值 | −6.45 | **−6.20** |
| ≤0.15s极短联合option / 全部决策 | 31.55% | **8.23%** |
| 统一受阻/安全/停滞退出 / 全部双侧退出 | 41.63% | **24.62%** |
| 联合option时长p95 | 24.00 s | **12.55 s** |
| 训练物理异常episode | 0 | 0 |

墙钟约快 **1.66倍**，耗时减少约40%；这是历史端到端耗时，包含已发生的验证/渲染/预热，不能当作单一控制器CPU微基准。两组累计模拟物理时间只差约1.5%，不是因为新版大幅缩短了任务时域。极短动作等比例直接从全部原始episode决策重算，按决策加权；与dashboard对每轮比例再平均的结果不同。

退出口径统一为 `blocked*`、`safety_abort` 或含`stalled`的原因。旧dashboard原blocked指标不含新停滞类型，不能直接拿那条曲线比较。上述仍是按退出名称分组，控制器改变了退出语义，不是对相同物理失败状态的完全等价识别。

## 学习过程的差异

| 累计更新区间 | 旧目标外验证成功率均值 | 新目标外验证成功率均值 | 旧val progress均值 | 新val progress均值 |
|---|---:|---:|---:|---:|
| 1–100 | 0.89% | **5.07%** | −0.109 | −0.184 |
| 101–200 | 1.15% | **3.93%** | −0.045 | −0.157 |
| 201–400 | 0.90% | **2.79%** | −0.049 | **−0.013** |
| 401–600 | 2.70% | **4.92%** | −0.017 | −0.014 |
| 601–720 | 1.50% | **3.69%** | +0.034 | +0.037 |

新版更早出现真实目标外成功，而且各窗口目标外成功率时间均值均较高；但前200轮平均progress反而更差，到后期窗口才基本追平。这说明“部分场景更容易成功”与“大部分场景都稳步推进”没有同时实现。

单个固定验证根在窗口内至少成功过一次的覆盖：旧19/61，新30/61；这些成功不属于同一个checkpoint，不能宣称策略已掌握30根。

按距离分层的所有checkpoint平均原始成功率：近距（18根，含3根初始目标内）旧21.0%、新26.1%；中距（35根）旧0.43%、新1.96%；远距（11根）旧0、新0.62%。远距仍基本没有稳定成功，不能把新组少数成功解读为长距离规划已解决。

## 尚未解决：遗忘和动作偏好

旧组最好checkpoint累计498次更新，目标外成功6根；最后累计718次更新只成功1根，保留最好时的1/6。新组最好470次更新，目标外成功10根；到720次更新目标外成功为0，保留0/10。新组720点原始3/64全部来自初始目标内，因此必须同时展示最好值、窗口均值和最后值。

![目标外各根成功随更新变化](../../outputs/option_rl_v11/early_comparison_720/root_success.png)

原始动作请求比例（按全部机器人动作请求计数，不是接触时间）：

| 类型 | 旧组 | 新组 |
|---|---:|---:|
| 平移PUSH | 7.72% | 8.45% |
| ROTATE | 9.30% | **31.32%** |
| REPOSITION | 45.81% | 34.10% |
| FOLLOW | 17.88% | 7.28% |
| WAIT | 19.30% | 18.85% |

新版减少了FOLLOW/RP和大量极短失败，主要转向更多ROTATE，平移PUSH比例只略增。720点单轮WAIT请求约58.9%、熵约1.30，值得监测是否继续退化；前20轮平均WAIT约23.1%，不能用单轮推断长期坍塌。旧新动作表和联合分布不同，绝对熵也不能直接当作等尺度探索指标。

## 判断

新版本已经验证了**降低训练迭代成本、减少病态短动作、提高早期成功覆盖**的价值，但没有证据表明其已解决长期学习平台。后续应重点看目标外成功的连续保留、窗口progress、WAIT/ROTATE偏好，而不是仅追逐13/64峰值。

本次仅做只读诊断，未停止当前训练或修改reward/源码。单随机种子、控制器/动作表/联合策略同时变化，没有隔离因果或多种子置信区间。
