## 0. 这个项目在做什么

CoImagine 的 2D 验证。长期目标是用一个**局部可控、终态稳定、转移可预测**的 option（推一下）作为基元，
在其上做 skill 级预测与规划。当前这条线是"接触推动 option"的控制与协议。

**判据不是推动性能**（不是位移、不是速度跟踪、不是和旧 oracle 比 80%），而是任务书自己写的那四条：
接触是否容易维持、有效运动是否足够、状态转移对小扰动是否稳定、是否适合后续技能预测。

## 2. 必须知道的修正与撤回

这些是我在会话后段推翻了自己前面结论的地方，新会话不要沿用旧说法：

1. **撤回**："真值静止时表面速度估计量中位读到 0.040 m/s，是门槛两倍，所以判据无信息量。"
   那是我自己的静止窗口差了一个控制周期（估计量比较**两次扫描**，所以窗口前一个周期也必须静止）。
   修正后这个 0.040 的噪声地板不存在。
2. **估计量是准的**：与正确的真值参考 `(v_object − v_robot)·n` 对齐，估计 0.0180 对真值 0.0157、
   0.0137 对 0.0123、0.0011 对 0.0009。受控反例上中位数聚合严格优于 RMS（1/5 错配：中位数 0.000，
   RMS 0.125），但**真实数据上中位数与 RMS 数值相同（差 ≤1e-5）**，重跑 1920 条的退出分布逐位相同。
   所以那次改动是买保险（已提交 + 已加测试），不是修了病。
3. **判稳失败的真相**：313/313（V）和 368/368（X）的未判稳退出，在退出瞬间真值物体和两台机器人都确实静止。
   但退出前最后 6 个周期里，物体**真的在残余滑行** 0.010–0.022 m/s，正好骑在 0.02 门槛上，缓慢衰减
   （物体阻尼时间常数 3.0/8.0 ≈ 0.38 s）。判据拒绝把一个确实还在动 0.02 m/s 的状态叫静止，这是对的。
   所以既不是"判据太严"，也不是"控制器停不下来"，而是**停机尾迹和门槛同量级**。
4. **撤回**：我早先的"可预测性 R²=0.025"分析**目标设错了** —— 我预测的是"物体终态在机器人起始坐标系里的
   位姿"，其中包含原理上不可观测的**全局朝向**，然后把低 R² 当成"option 难学"。特权数据是做**标签**的，
   不是做**输入**的；而且链上每一步只需要可观测的局部构型。这个分析要用正确的目标重做（见任务书 B）。
5. **早先那个 0.997**（同 root 八变体离散度 0.011 m vs 跨 root 0.192 m）回答的是"能不能区分不同初始条件"，
   **不是**"能不能跨 root 预测"。两个数不矛盾，但引用时要写清楚问的是哪个。

## 3. 定格的数据（可直接引用）

- V/X 对照（1920 条测试执行，120 root × 8 变体 × 2 臂，同一份 APPROACH/READY/PUSH 计时/BRAKE/SETTLE）：
  有效推动完成率 V 0.885 / X 0.803（主分母 40 root：0.900 / 0.800）；判稳 V 0.674 / X 0.617；
  假稳定两者都是 **0**；位移中位 V 0.265 / X 0.209；接续三步正常完成 V 9/12、X 7/12。
- 零间隙等价性：`Kp·δ = Kv·s` 且 `Kd = Kv` 时两律恒等，测试在 3 个速度 × 3 个角度上最大差 1e-9。
  实测 PUSH 期 `gap_signed` 中位 −0.0001 m，所以 V≈X 是**代数等价**，不是巧合。
- 推力从未饱和（峰值 ~6.6 N / 15 N），最大穿透 ~1 mm。
- 判稳门槛反事实（精确，因为 BRAKE/SETTLE 的力与判据无关）：0.02→0.674/0.617；**0.03→0.745/0.744
  且真值窗检查 190 例里只有 1 例误报**；0.06→0.869/0.870 但误报率已高；≥0.08 饱和在 0.87。
- V 与 X 的初始态、root、扰动逐字节相同（`roots_{dev,test}.json` 的 sha256 已记录在 manifest）。

## 4. 未决 / 下一步

任务书 `docs/tasks/20261013_1900_CoImagine_判稳可靠性与可观测转移任务书.md` 写了三件事：

1. 把"每个 option 结束都镇定"从 62–67% 提到 ≥0.90，并且用**真值窗**验证不引入假稳定。
2. 用**正确的目标**（终态可观测局部构型）重做可预测性分析。
3. 在**同一运动类型内**检验"楔形推动"假设（两台机器人推同一条边 vs 相邻两条边）。

已有一个粗糙检验但它是废的（12 个楔形 root 全是 `dual_rotate`，和"平行+平移"比是在比任务类别），
所以那条路还没测过。

用户明确的方向性意见（新会话要尊重）：训练数据与预测模型可以用仿真器特权数据做标签；
option 级只要好用且终态好预测就够了；物体状态可不可观测是**控制策略**的事，可以通过选接触点组合
（"夹出来"）减小不确定性，甚至让世界模型隐式学会偏好可预测的构型。我认可这个方向，但补了一句：
**特权标签补不了缺失的输入**，而且要让"模型发现楔形更可预测 ⇒ 策略偏好楔形"生效，不确定性必须在某处
**显式**进入决策（集成/悲观规划/代价里的方差项），否则均值预测的 MPC 会照穿混叠区。
