# 第一部分：实验设置

## 1.1 任务长什么样

一个 **6×6 的房间**。地上有一个 **2×2 的大箱子**，两台小机器人（A 和 B）去推它，
把它推进房间右侧的**目标区**（第 4、5 两列）。

所有机器人都知道：墙在哪、目标区在哪、彼此站在哪一格。

**机器人不知道的**（这才是任务难的地方）：

| 不知道的东西 | 取值 | 说明 |
|---|---|---|
| 箱子**重不重** | 需要 1 台还是 2 台机器人推得动 | 一整条回合里不变 |
| 箱子**有没有被锁住** | 锁住 / 没锁 | 锁住时必须先做一个"释放"动作才推得动 |
| **我自己**抓地牢不牢 | 抓得住 / 打滑 | 打滑时我用多大力气都推不动 |
| **队友**抓地牢不牢 | 抓得住 / 打滑 | 我**看不到**，只能靠消息或公共事件猜 |

上面四项组合起来是 **16 种可能的情况**，一条回合里固定不变，机器人不知道自己在哪一种里面。

**另外，箱子在哪也要自己看。** 每台机器人身上只有一把射线雷达，射线会被墙和箱子挡住。
它不知道箱子的准确坐标，只能靠自己几次扫描去估计。

## 1.2 机器人能看到/听到什么（信息边界）

这是整个项目的核心约束，很多结论都来自它：

| 信息 | 谁知道 |
|---|---|
| 自己的雷达扫描 | 只有自己 |
| 自己的坐标 | 公共 |
| **"我刚才推的时候打滑了"** 这类**局部反馈** | **只有自己（私密）** |
| **"箱子动了 / 没动"** | **公共广播** |
| 队友的局部反馈 | **谁也看不到**（除非队友主动发消息） |

局部反馈有四种取值：`drove`（推动了）、`strained`（顶住了，力气不够）、
`slipped`（打滑了）、`idle`（我这次没碰箱子）。公共事件只有两种：`moved` / `stalled`。

**最关键的一条**：不通信的时候，**"队友抓不抓得住"我是无法从自己的反馈里知道的**。
这一点后来被单独测过（见 3.6）。

## 1.3 六个动作，以及每个动作到底能改变什么

动作固定六个：`push:0:E`（A 单独推）、`push:1:E`（B 单独推）、`co_push:E`（一起推）、
`probe:0:E`（试探）、`release:0:E`（释放）、`wait`（等待）。

下面是**实测表**（503 个决策点，覆盖全部 16 种隐藏情况）。"改变"= 执行前后这个量真的变了：

| 动作 | 改变"已解开"（隐藏） | 改变箱子位置 | 改变机器人位置 | 改变隐藏物理 |
|---|---|---|---|---|
| `push:0:E` | 0.000 | 0.095 | 0.095 | **0.000** |
| `push:1:E` | 0.000 | 0.089 | 0.089 | **0.000** |
| `co_push:E` | 0.000 | 0.143 | 0.143 | **0.000** |
| `probe:0:E` | 0.000 | **0.000** | **0.000** | **0.000** |
| `release:0:E` | **0.254** | 0.000 | 0.000 | **0.000** |
| `wait` | 0.000 | **0.000** | **0.000** | **0.000** |

**三个要点：**

1. **没有任何动作能改变隐藏物理本身。** 重量、锁、抓地力在一整条回合里是**恒定**的，
   动作只能**揭示**它们，不能改变它们。
2. **整个任务里唯一会被动作改变的隐藏量是"箱子有没有被解开"，而且只有 `release` 能改它。**
   条件在被锁且还没解开时成功率 **0.50**，其中**这台机器人抓得住时 100%、打滑时 0%**。
3. **`probe` 和 `wait` 什么都不改变。** 一个花 0.3 代价换一次反馈，一个什么都不做。

**两条精确规则**（在 3756 个"场景×动作"上逐条验证）：

```
解开' = 已解开 或 (被锁 且 这台机器人抓得住 且 动作是释放)          ← 错误 0 个
推动  = 位置对 且 (已解开 或 没被锁) 且 抓得住的推者数 ≥ 需要的台数  ← 补上"位置对"后错误 0 个
```

第二条裸规则有 84 个例外（2.24%），而这 84 个**全部**是"推的机器人不在箱子西面的接触位置"——
那是**可观测**的几何条件，不是隐藏量。

## 1.4 每个动作的反馈能**揭示**什么（互信息，比特）

| 动作 | 自身抓地力 | 队友抓地力 | 箱子多重 | 箱子是否被锁 |
|---|---|---|---|---|
| `push:0:E` | **1.000** | 0.004 | 0.116 | 0.121 |
| `push:1:E` | **0.000** | 0.000 | 0.000 | 0.000 |
| `co_push:E` | **1.000** | 0.013 | 0.001 | 0.131 |
| `probe:0:E` | **1.000** | 0.004 | 0.116 | 0.121 |
| `release:0:E` | **1.000** | 0.000 | 0.000 | **0.492** |
| `wait` | 0.000 | 0.000 | 0.000 | 0.000 |

- **自己抓不抓得住，做一次接触动作就完全确定**（1.000 比特）。`probe` 只要 0.3 代价就能拿到，
  比 `push` 便宜——这就是"试探有价值，但价值恰好等于它替代的那次实验"的来源。
- **队友抓不抓得住，用任何动作的反馈都拿不到**（最高 0.013 比特）。信息边界的实测验证。
- **`release` 是判断"是否被锁"最好的动作**（0.492 比特），远超其他动作。
- **`push:1:E` 对 A 什么也不揭示**：A 收到的反馈 623/623 次都是 `idle`。

## 1.5 代价

`wait` 0、`probe` 0.3、其余动作 1.0。规划器前瞻的末端还有一笔"失败代价"（20），
用来惩罚"走到时域末尾箱子还没进目标区"。走得步数越多、推得越多，总代价越大。

# 第二部分：方法架构

这条线一共有三代东西，每一代都是对上一代缺陷的回应。

## 2.1 第一代：精确的信念空间规划器（作为参照，不是学习方法）

它**不知道隐藏情况**，但知道**动力学规则的形式**。做法是：

1. 维护一个"我可能在 16 种情况中的哪一种"的概率分布（**信念**）；
2. 往前推演时**在可能的反馈上分支**——"如果我这一步收到 `drove`，我的信念会怎么变"；
3. 沿着推演**同步更新信念**，而不是把信念冻住。

**关键在第 3 条。** 一个"冻结信念"的价值函数没法给"探索性动作"定价，于是会过度对冲。
这一点在第 3.1 节被实测证明。

## 2.2 第二代：第一版学到的世界模型（潜变量版 / 直接预测版）

把"预测"学出来：编码器把观测压成一个 32 维潜向量，一个转移模型把它往前推，
解码头读出下一观测、箱子位置、隐藏物理、代价、箱子是否移动。
同时做了一版**没有瓶颈**的对照：直接从"当前观测 + 动作"预测下一观测向量。

## 2.3 第三代：分解式世界模型（factored model，目前的主力）

第二代有一个根本缺陷：所有事情挤在一团潜向量里，而且**没有观测模型**——
没有 `P(反馈 | 动作, 状态, 参数)`，就没有合法的信念更新，参数估计也就学不出来。

第三代把模型**显式拆成四件事**，每一件都能单独检查：

```
b(θ)     = 从观测算出的 16 种隐藏情况上的概率分布        ← 不变量（整条回合不变）
s_t      = [箱子是否被解开, 箱子在哪个格子(36), 两台机器人在哪(4)]   ← 动态量
s_{t+1}  = Σ_θ b(θ) · 转移(s_t, 动作, 第θ种参数)          ← 动作改变状态，参数决定怎么改
y_{t+1}  = Σ_θ b(θ) · 观测模型(动作, s_{t+1}, 第θ种参数)    ← 动作决定你收到什么反馈
b'(θ)   ∝ P(反馈 | 动作, s_θ', θ) · b(θ)                ← 贝叶斯更新
```

**三个设计要点，每一个都是被 bug 逼出来的：**

1. **转移和观测模型都在 16 种参数上分别算一遍，再按信念加权平均。**
   不是把信念的平均值当成参数向量塞进去。为什么：转移只在**单一确定参数**上训练过，
   喂一个"平均值"属于分布外输入，它会给出一个**自信的 0**——而用真实参数时它给的是 **1.000**。
2. **每个假设预测自己的下一状态**：`s_θ' = T(s, a, 第θ种参数)`，似然在**自己那个状态**上算。
   如果所有假设共用一个"按信念混合出来的状态"，一次本该决定性的证据也清不掉错误假设。
3. **隐藏量靠转移往前带，可观测量从当前观测取。** "已解开"是隐藏的，
   成功的 `release` 让观测**逐位不变**，所以"每步从观测重新读"会**忘记自己解开过**，
   规划器于是永远等下去。

**底层是一个手写的自动微分引擎**（环境里只有 NumPy，没有 PyTorch）。
每一个算子和多步展开图都用有限差分校验过，最差相对误差 1e-7。

## 2.4 规划器

规划器只用**学到的模型**往前想象，**前瞻里完全不碰模拟器**；模拟器只负责执行。

- **两层版本**：对每个候选动作，想象它的结果，在可能的反馈上分支、更新信念，
  再选最好的第二步。
- **束搜索版本**：在动作序列上搜索，只在第一步对反馈分支，每层累加动作代价，
  在时域末端用一个估值收尾（深度 3~6、束宽 2~4 都试过）。

# 第三部分：结果

## 3.1 标定：不知道物理的代价到底有多大

同等信息下，精确的信念空间规划器在**它能解的回合**上，成功率与**全信息 oracle 完全相同**
（都是 **1.000**），代价只高 **18%**（3.47 对 2.94）。

> **不知道接触物理的代价是步数，不是成败**——前提是规划确实在信念空间里做。

而一个**冻结信念**的版本做不到：它无法给信息性动作定价，于是过度对冲，成绩差得多。

## 3.2 什么必须被表示

| 发现 | 数字 |
|---|---|
| 模型**类别**装不下"谁抓得住"或"是否被锁" → 规划器彻底失败 | 差距 18.00，成功率 0 |
| 装不下"箱子多重" → 完全无损（稳妥做法本来就会叫上队友） | 差距 0.00 |
| 潜向量确实带上了接触信息 | 物理解码 0.306（随机是 0.0625） |

**把某个情况从训练数据里删掉，再考它：**

| 删掉的 | 效果 | 用什么策略才测得出来 |
|---|---|---|
| "被锁" | **两个种子都是 300 个回合 0 成功**（见过约 10%） | "推进+使能"（唯一会选 `release` 的学习规则） |
| "重物" | 成功率下降 **3–9 倍** | "能推就推" |

**消融只在一个策略高于它的地板时才有意义。** 用"能推就推"（它从不释放）去测"被锁"，
两条臂都是 0，什么也说明不了——那不是结论，是测不出来。

## 3.3 预测什么才能服务规划

- **逐动作结果分不行**：不管让网络学"会不会动""有没有推进"还是"有没有创造新机会"，
  都被精确参照远远甩开。
- **价值目标在单步决策上更好，在回合层面没有优势**：修正输入后学价值只剩 7% 成功率，
  而粗糙的"能推就推"有 59%。
- **多步可行性损失不划算**（论文方案里提的一项）：把训练数据量对齐之后，它一次都没赢。
  之前的收益完全来自"这种方法顺带能拿到更多数据"。而"更深的状态更难"这个立论前提也不成立
  （浅层模型的准确率反而随深度上升）。
- **连续参数下**：可行集确实是一个**范围**（角度窗口 × 力度阈值）；
  **回归力度阈值**明显优于"永远最大力度/永远最小力度"，而且对输入修正稳健。

## 3.4 一个反直觉的发现：这个任务里，六个动作**本来**大多没有可见差别

把六个候选动作**真的在模拟器里跑一遍**，数它们产生几种不同的下一状态（只比较世界栅格）：

| | 六个动作真正产生几种不同的下一状态 |
|---|---|
| **模拟器真值** | **1.43**（117 个状态里，**85 个状态下六种动作完全相同**，即 73%） |
| 第一版模型想象 | 1.14 |

**所以模型只少区分了 0.3 种，不是少区分了 4.9 种。**"六个分支四个画得一模一样"
不是模型的失败，**那就是世界的真相**。

**换成"以机器人为中心"的观测能解决吗？实测不能：真值 1.43 对 1.43，完全一样。**
因为关键的那四个动作根本不让机器人移动（机器人平均只在 1.24/6 个动作里移动）。

## 3.5 真正的问题：最重要的动作，效果在观测里**完全看不见**

> 对**被锁住**的箱子执行 `release`，成功时反馈是 `drove`、公共事件是 `stalled`，
> **观测向量与执行前逐位完全相同**。唯一改变的是隐藏的"已解开"标志。

而 60 个场景里 **24 个是被锁的**。也就是说，**这个任务里最重要的准备动作，
在观测空间里是零信息的。**

第一版模型**根本没有被要求预测这个标志**，所以它在表示层面就无法表达
"这一步把箱子解开了"，规划器当然学不会优先 `release`。
**这也直接解释了第三代为什么必须那样拆**：要有显式的观测模型（让反馈能反过来更新信念）
和显式的隐藏状态（让"解开"这件事被携带下去）。

## 3.6 通信：最有价值的一条规则

- **消息的价值，恰好等于它所替代的那一次实验。** 任务越长，消息的相对价值越小，
  但绝对值恒等于"一次实验"。
- **只在队友是"必需"（而不是仅仅更便宜）时才有价值。** 在最干净的必需测台里，
  **1 比特消息让学到的模型从随机水平（0.500）直接到精确最优（1.000，零后悔）**。
- **有界的负面结果**：同一套通道**没能移植进格子世界**。因为格子世界的动作集里有
  "队友单独推"，使队友不再**必需**，规则前提不被满足。这是有界的结论，
  不是"消息一般无用"。

## 3.7 冷启动：不试就永远学不到

从全新场景出发，"一步最省"的规则会选择**放弃**，而放弃不产生任何信息，于是它永远学不到（0%）。
强制试一次 → **12.5%**（上限 25%），**再试只增加代价、不再提高成功率**。

## 3.8 factored 模型的观测模型：和模拟器**逐位一致**

学到的似然 vs 模拟器自己的频率（看 `slipped` 这个反馈符号）：

| 动作 | 参数值 | 学到 | 实测 |
|---|---|---|---|
| `push:0:E` | 自己抓得住 | 0.000 | 0.000 |
| `push:0:E` | 自己打滑 | **1.000** | **1.000** |
| `release:0:E` | 自己抓得住 | 0.000 | 0.000 |
| `release:0:E` | 自己打滑 | **1.000** | **1.000** |
| `co_push:E` | 抓得住 / 打滑 | 0.000 / **1.000** | 0.000 / **1.000** |

**这是信念更新的地基，所以直接拿它和模拟器对照，而不是看训练损失。**

## 3.9 factored 模型的信念更新：**该知道的完全知道，不该知道的就保持不确定**

从**均匀先验**出发，只用学到的似然做序列更新（每个数都是实测）：

| 隐藏量 | 1 次接触动作后准确率 | 真值上的概率质量 | 相对先验移动了多少 | **自信地搞错的比例** |
|---|---|---|---|---|
| **自己抓地力** | **1.00** | **1.00** | 1.000（完全确定） | **0.000** |
| 队友抓地力 | 0.60 | 0.51 | 0.128（几乎没动） | 0.008 |
| 箱子多重 | 0.55 | 0.53 | 0.141（几乎没动） | 0.008 |
| 箱子是否被锁 | 0.62 | 0.58 | 0.260（有一点） | **0.000** |

三条读法：

1. **自己抓不抓得住，做一次接触动作就完全确定**，而且从不自信地搞错。
2. **队友抓不抓得住几乎学不到**——**这是对的**，它本来就不可观测。
3. **箱子多重也几乎学不到**——同样是对的（此前实测它对自身反馈只有 0.116 比特）。

最后一行特别关键：**第一版会以 18%–25% 的概率"自信地说错"**，现在降到 0.8% 以下。

## 3.10 factored 模型的转移：学到了那条隐藏规则，而且是**有条件的**

在"箱子被锁"的场景里执行 `release`，模型预测"解开"的概率：

- 这台机器人**抓得住**：平均 **0.995**
- 这台机器人**打滑**：平均 **0.004**，最高的一个场景也只有 0.006

**它学的不是"释放和解开有关系"这种无条件关联，而是"当且仅当我能抓得住时才解开"这个条件关系。**
第一版失败的地方正是在这里。

**参数确实改变了未来预测（多步验证）**：从同一个观测、同一条动作序列，
分别按**真实参数**和**错误参数**（锁和抓地力都不同）展开想象：

| 想象步 | 箱子位置分布的分歧 | 解开概率之差 | 两组参数选出**相同**下一步的比例 |
|---|---|---|---|
| 1 | 0.167 | 0.487 | 0.327 |
| 2 | 0.630 | 0.487 | 0.277 |
| 3 | **0.673** | 0.473 | **0.267** |

**分歧随深度增长，而且第 3 步两组参数仍有 73% 的情况选择不同的动作。**

## 3.11 规划器会做准备，而且**只在准备有意义的时候**

给它**真实参数**时，第一步选 `release` 的比例：

| 情形 | 场景数 | 选 `release` |
|---|---|---|
| 被锁 **且这台机器人抓得住**（释放能成功） | 132 | **0.636** |
| 被锁 **且这台机器人打滑**（释放必然失败） | 126 | **0.000** |
| 没被锁（没有东西可释放） | 242 | 0.062 |

**在 126 个"释放必然失败"的场景里，它一次都没试过。**

**把信念换成它自己从反馈里挣来的**（先做一次接触动作）：

| 情形 | 参数已知 | 参数靠自己推断 |
|---|---|---|
| 被锁且抓得住（**该**准备） | 0.636 | **0.636** |
| 被锁且打滑（**不该**准备） | 0.000 | **0.000** |
| 没被锁（**不该**准备） | 0.062 | **0.186** |

**"该准备"那一列完全没变**——因为自己抓地力被一次动作就确定了。
**代价出在没被锁的场景上：浪费的释放从 6.2% 涨到 18.6%**，
因为决策之前"箱子是否被锁"只有 0.58 的信念质量。

而这个不确定性是**结构性的**：关于"是否被锁"最有力的证据**恰恰来自 `release` 本身**。
所以"我该不该释放"本质上是一个**探索决策**——这正是 3.6 那条规则在模型侧的同一个现象。

## 3.12 回合级对比（120 回合，同一批场景、同一个起始状态）

所有策略先做**同一个**热身动作，所以起点完全一致。

| 规划器 | 成功率 | 平均代价 | **每次成功代价** |
|---|---|---|---|
| factored 模型 + **两层**前瞻 | **0.142** | 1.682 | **11.87** |
| factored 模型 + 束搜索，深度 4 | 0.050 | 1.648 | 32.95 |
| factored 模型 + 束搜索，深度 6 | **0.008** | 1.339 | **160.70** |
| 全知 oracle | **0.425** | 1.217 | **2.86** |
| 精确信念空间参照（同等信息） | **0.392** | 1.850 | **4.72** |
| 随机 | 0.142 | 5.553 | 39.20 |

**两面都要说：**

- **成功率上它和随机持平**（0.142），远低于精确参照的 0.392。
- **但每次成功代价只有随机的 1/3.3**（11.87 对 39.20）。**它成功得少，成功的时候很省——
  是个保守的规划器：不确定就少花。**

## 3.13 核心的负面结果：**搜索越深，效果越差**

0.142 → 0.050 → 0.008，**单调变差**。

排查过程：先确认规划器在单个决策点上是对的（每个深度都正确选出 `release`）；
再确认转移是对的（一次 `co_push` 被预测把箱子从距离 5 送到距离 0，**而真值也确实是距离 0**，
模型完全正确）；最后定位并修好了一个估值定义上的错误（失败代价原来是"平的"，
改成按失败概率加权后，两层前瞻从 0.133 提到 0.142）。

排除这些之后，剩下的解释只有一个是经典的：

> **在一个不完美的学习模型上，搜索得越深，就越能"挖掘"模型的误差。**

4 步想象的位置准确率是 0.833，第 6 步误差已经显著。深度搜索会主动找到那些
**模型以为很好、现实里并不好**的动作序列。**两层前瞻反而最好，恰恰因为它看不到那么远，
挖不出这些错误。**

# 第四部分：主要结论（大白话）

1. **不知道接触物理，代价是"多走几步"，不是"做不成"——前提是你在"可能性"上老老实实推演。**
   精确的信念空间参照和全知 oracle 成功率一模一样，只是多花 18% 的步数。

2. **必须被表示的是离散的接触状态：谁抓得住、箱子有没有被锁。** 箱子多重可以不知道，
   因为稳妥的做法本来就会叫上队友。

3. **这个任务里，动作的后果大多在观测里看不见。** 六个动作真值上只有 1.43 种不同的下一状态，
   73% 的状态下六者完全相同；而最重要的准备动作 `release` 成功后**观测逐位不变**。
   换坐标系（以机器人为中心）对此**毫无帮助**（1.43 对 1.43）。

4. **要学参数，必须有显式的观测模型，而且信念更新必须以动作为条件。**
   同一个反馈符号在不同动作下含义相反：`drove` 在 `push` 之后说明"箱子动了"
   （所以没被锁），在 `release` 之后说明"解开成功了"（所以被锁）。
   脱离动作，这个符号没有意义。

5. **模型能学会"该知道的完全知道，不该知道的保持不确定"，而且从不自信地搞错。**
   自己抓地力一次动作后准确率 1.00；队友抓地力正确地停在先验附近；
   自信错误率从第一版的 18%–25% 降到 0.8% 以下。

6. **规划器会做准备，而且只在准备有意义的时候。** 126 个"释放必然失败"的场景里一次都没试过；
   能成功的场景里做了 64%。

7. **信息的价值，与使用它的能力，是两个不同的量。** 前者由消息实验测出
   （1 比特从随机到最优），后者由闭环测出（同一份证据下学到的规则停在最优的一小部分）。
   把两者混为一谈，就会把"模型不行"误判成"信息不够"（或反过来）。

8. **瓶颈是模型保真度，不是搜索。** 加深搜索单调变差，因为它挖掘模型误差。
   这一条把问题从"决策规则"精确地推到了"多步想象的保真度"上。

# 第五部分：被自己推翻的结论（方法论）

这个项目里有 **8 条结论是后来的实验推翻的**，原因**每一次**都是**对照组或输入被污染**：

| 曾报告 | 真正原因 |
|---|---|
| 学价值一致率 94.7% | 前瞻截断值是**状态无关常数**，参照与标签一起退化成"选最便宜动作" |
| 标定差距 2.50 | 场景里留着"换位"环节，规划器把自己停在队友需要的格子上 |
| "不知道接触物理整条回合代价很大" | 参照是**冻结信念**版本，无法给信息动作定价 |
| "参照过度保守，53% 决策空转" | 用正确参照后，它 73 次等待中 62 次 oracle 也等待 |
| "模型在队友打滑时最差" | **私有反馈泄漏**；去掉后该组反而最好 |
| "薄弱点恰好是信息论上不可用的" | 同上，是泄漏模型的属性 |
| "学价值达到参照的 47%" | 去掉泄漏后**塌到 7%** |
| 多步损失带来 +11 个点 | 是**数据量**效应（2364 对 870 样本） |

**共同教训**：一个结论被推翻时，原因几乎总是**对照组或输入被污染**，而不是效应本身不存在。
修好对照之后，结论往往以更窄但可靠的形式重新成立。

## 5.1 同一个 bug 类型出现了七次，而且**没有一次能被训练曲线发现**

做 factored 模型的过程中，我修掉了七个"损失看着很健康、行为完全错误"的问题：

| # | 问题 | 症状 |
|---|---|---|
| 1 | 解码头拿整个 batch 的第一个样本的标签打分 | 模型学成边缘分布 |
| 2 | 代价目标 `(n,)` 与 `(n,1)` 相减广播成 `(n,n)` | 损失值荒谬 |
| 3 | 观测模型在**原始数值**上训练，却被用**处理后的概率**查询 | 训练损失 0.005，查询完全不对 |
| 4 | 把信念的平均值当参数向量喂给只在确定参数上训练过的转移 | 给出**自信的 0**（真值是 1.000） |
| 5 | 信念更新把"混合状态"当成每个假设的状态 | 一次决定性证据清不掉错误假设 |
| 6 | 隐藏量每步从观测重新读，而不是靠转移往前带 | 规划器**忘记自己解开过，永远等下去** |
| 7 | 失败代价是"平的"，而不是按失败概率加权 | 有 79% 概率已完成的分支照样付全额罚款 |

**唯一抓住它们的方法，是把模型的输出和模拟器的真值逐项对照**（似然表、逐场景的转移预测），
而不是看损失。这是这个项目最值得带到 2D 物理阶段的一条经验。

# 第六部分：没有确立的（不隐瞒）

- **学到的规划器在回合层面仍追不上精确参照**（0.142 对 0.392）。
- **加深搜索会变差**，原因已定位为模型利用，但**没有修**。
- **多步想象的自回归误差会累积**（4 步位置准确率 0.833，更远更差），没有针对性训练。
- **消息规则没能移植进格子世界**（前提不满足）。
- **场景族单一**：都是"机器人贴在箱子西面、往东推"。换布局之前，上面的结论只算一个场景上的。
- **标定测台与闭环测台不完全一致**：有些探针里箱子的位置仍取自模拟器，
  只有隐藏物理需要推断。所以那些是"物理推断"实验，不是完整的"感知 + 物理"实验。
- 完整通信协议（双向、联合公共提交）未实现；3D 与硬件超出本轮范围。

# 第七部分：下一步

按优先级：

1. **让多步想象不累积误差**——针对"多步一致性"训练，而不是只训练单步。
   这是当前唯一的绑定约束。
2. **让搜索对模型不确定性保守**——用集合/分布做悲观估计，直接抑制"挖掘误差"的行为。
   这在基于模型的强化学习里是标准做法，也与这条主线一直以来的"不确定性"主题衔接。
3. **在把 1、2 做完之前，不要加深搜索。**
4. **场景族泛化**：换布局、换推动方向。
5. **换到 2D 物理仿真时，同样的分解结构可以直接搬过去**，而且那条经验会更关键：
   真实接触状态（是否滑移、接触点在哪）同样部分不可观测，
   **凡是从观测里"重新读"隐藏状态的实现都会丢掉它**，而症状不是报错，是规划器莫名其妙地不动。
