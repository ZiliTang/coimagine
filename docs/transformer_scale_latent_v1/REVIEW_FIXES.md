# REVIEW_FIXES — 本轮自己发现并修复的缺陷

任务书要求"每完成一阶段更新状态，失败则提交具体样本和原始数值"。下面是本轮实现过程中
**自己发现并修掉**的问题，每条都给出触发条件与现在的保证。这些缺陷若不修，本轮的对照结论
会直接失真。

## 1. `geometry_mask` 的切片被解析成步长（已修）

**触发**：`geometry_mask[row, step, 0:4 if robot == "r0" else 4:8]`。
Python 把条件表达式绑定到切片的**中位**，实际解析为 `slice(0, 4, 8)`，只写入第 0 列。

**后果**：8 列几何 mask 里有 7 列恒为 0，几何监督几乎全被丢掉（实测可见率 0.09，
真实值约 0.83）。若不修，所有几何指标都建立在错误 mask 上。

**修复**：显式构造上下界 `for first, last, column in ((0,4,6),(4,8,24))`。
**证据**：修复后几何可见率 0.833，与直接统计 token 第 6/24 列（r0 100%、r1 51%）一致。

## 2. 每步重建窗口主导了训练时间（已修）

**触发**：训练循环里每次更新都调用 `build_example` 重建全部 128 个窗口，其 Python 循环
比前反向还贵。

**后果**：直接多步从 0.76 s/更新降到约 0.12 s/更新（**约 6×**），否则本轮无法在预算内
完成 1.6M 配对的多随机种子。

**修复**：新增 `cache.py`，逐面板预计算窗口、mask、标签与未来张量后索引。
**保证**：缓存张量与现算结果逐项比对为**完全相等**（窗口、mask、标签、未来张量）。

## 3. latent 前向把真实前缀编码了两次（已修）

`LatentAutoregressive.forward` 先调用 `rollout`（内含一次 encoder），再为终态头重新编码一次。
已改为 `rollout` 返回 summary 供终态头复用。

## 4. 容量曲线进程未应用线程上限（已修）

`capacity.py` 接受 `--threads` 却从未调用 `torch.set_num_threads`，三个进程各自试图占用全部核心，
把整个矩阵拖慢。已修，并在调度上限制并行度。

## 5. root bootstrap 对索引取中位数（已修）

**触发**：`np.median(np.concatenate([by_root[unique[p]] for p in picked]))` 对**下标数组**取中位数，
而不是对 `difference[selection]` 取。

**后果**：置信区间荒谬（例如 `[+86200, +89600] cm`）。**若不修，配对比较的 CI 全部不可用。**

**修复**：先 `selection = np.concatenate(...)`，再 `np.median(difference[selection])`。
**证据**：修复后 k=1 的 CI 为 `[+0.0773, +0.1139] cm`，与直接计算一致。

## 6. 基线数字把 `t=0` 与 `t>0` 混在一起（已修）

**触发**：`step_p50_cm` 用的是全样本中位数，而 `t=0` 时"下一步"几乎等于当前位置，误差近零。

**后果**：保持基线一度显示 0.122 cm，而 `t>0` 的真实值是 **0.244 cm**，差一倍。
**这正是任务书禁止的混算。**

**修复**：所有比较一律读 `by_regime`；`step_p50_cm` 只作为整体描述，不用于结论。
**保证**：两条独立代码路径（`residual_prediction_v1.build_batch` 与
`transformer_scale_latent_v1.build_multistep`）算出的 `t>0` 保持基线**逐窗口相同**
（最大差 0.0，mask 完全一致，窗口数一致）。

## 7. 重复采同一批 h5 特征导致早期种子浪费（已修）

首次运行在容量曲线上用了"猜测的宽度"：`(176,5,704)` 实为 2,009,569 参数（偏离 1.6M 目标 +25.6%），
`(256,6,1024)` 实为 4,939,329（偏离 4.0M 目标 +23.5%）。

**修复**：改为对**实际构造的模块计数**后选点：0.9M→895,937、1.6M→**1,635,569**（+2.2%）、
4.0M→**4,149,569**（+3.7%）。先前误标的两个点保留为独立的额外数据点
（`capacity_2p0M_seed0` 等），**不冒充**任务书要求的规模。

## 8. 基线回归口径（已修，见 `AUDIT.md` 第 2 节）

原先把"落进上一轮多种子区间"当作复现通过。审阅意见指出这不成立，已改为：
**同一检查点 + 同一面板哈希 + 同一指标**，与**该检查点自己保存的逐窗口预测**比较。
现在两个检查点的绝对差都是 **0.0**。

## 9. 评审前的遗留限制（未修，如实记录）

- `P0`/`P1` 的**可见性回退**只用当前帧可见性，不区分"持续不可见"与"新变可见"的差异；
  两者在 `by_visibility` 里分别计数，但回退规则相同。
- 多步标签的 `t=0` 与 `t>0` 采样比例固定为 25%/75%，未做敏感性检查。
- 4.0M 配置只跑 seed 0，缺多随机种子。
