## 0. 一页结论

1. **两个学习模型都没有稳定超过一个平凡的查表基线。** 在机器人 0、已有真实前缀 `t>0` 上，
   "命令 ＋ 已执行时间"查表（P1_grouped，含双方 active 标志，723 组，命中率 97.5%）的
   中点中位误差是 **k=1 时 0.127 cm**，而直接多步是 **0.384 cm**、latent 是 **0.228 cm**。
   两个模型只在 **k=8**（训练跨度中部）反超该基线（1.043 / 1.074 对 1.137 cm），
   到 **k=16** 又落后（2.081 / 2.957 对 1.963 cm）。
   → **当前不能声称多步表征学到了基线没有的东西**；能说的是"在训练跨度中部略有增益"。
2. **同规模的 latent 递推不劣于直接多步，且在两端明显更好。** seed 0 上
   k=1：0.228 对 0.384 cm（配对 root bootstrap CI `[+0.077, +0.114]`，不含 0）；
   k=8：1.043 对 1.074；k=16：2.081 对 2.957。
   **k=4 处两个统计量方向相反**（误差中位数之差 −0.028 cm 说直接更好，
   逐样本差值中位数 +0.012 cm 说 latent 更好），因此 k=4 判为不分胜负。
3. **扩容的收益很小而代价翻倍。** 直接预测 Transformer 从 0.90M 增到 2.01M（2.24×），
   `t>0` 下一步中位误差 0.201 → 0.186 cm（**−7.5%**），而 batch=128 延迟
   172.7 → 366.8 ms（**2.12×**）。**没有观察到与参数量相称的收益。**

**尚未评估闭环决策收益**：本轮未接规划器。

## 1. 任务难度：这个目标几乎是确定性的

在公开键（双方命令 + 已执行时间 bin）相同的窗口内，第 1 步中点的**组内离散度中位数只有
0.0517 cm**。也就是说，知道命令和时间之后，未来一步几乎已经确定。
这解释了为什么一个**完全不分组**的全局中位位移（P1_global）就能达到 0.220 cm，
而"保持当前"（P0_hold）是 0.244 cm。

**因此本轮所有模型数字都必须与这三条地板一起读**，任何"模型学会了预测"的说法在这条地板
被跨过之前都不成立。

## 5. 收敛与训练量

- 全部配置 3200 次更新、batch 128、AdamW、lr 3e-4（由 seed 0 的 1e-4/3e-4 短试验选出，
  固定验证面板上 3e-4 更优）、余弦退火到 3e-5、梯度裁剪 1.0。
- 学习率选择：1000 次更新时 1e-4 → 验证 5.400，3e-4 → 4.328。
- 训练日志中的批次损失只是优化日志；比较一律用 eval 模式的固定验证面板。
- **同参数量不等于同计算量**：4 线程下直接多步 0.763 s/更新、latent 1.431 s/更新
  （约 1.9×），峰值 RSS 1.50 / 1.84 GB。3200 次更新分别约 41 / 76 分钟。

## 6. 同规模配对的实际定义

| 模块 | 直接多步 | latent 自回归 |
|---|---:|---:|
| encoder | 1,246,880 | 1,246,880 |
| transition | — | 105,440 |
| decoder | 168,984 | 76,824 |
| heads | 54,088 | 32,456 |
| **合计** | **1,469,952** | **1,461,600** |

总参数差 **0.57%**，两侧 encoder **完全相同**。差别是"把参数花在递推还是花在读出头"。
**这不等价于相同容量**：latent 多一层共享递推、解码器更窄。

## 8. 结论措辞约束（逐条对照）

- 小模型负结果**不**否定整条 Transformer 路线 → 本轮只报"当前规模与预算下未见收益"。
- 同参数量**不**等于同计算量或同预测能力 → 第 5、6 节分开列出。
- latent 优于原下一步模型**不**证明 latent 结构优势 → 主对照是同监督的直接多步，
  本轮它只在 k=8 胜出，两端落后。
- 直接终态头改善**不**称为长期自由递推改善。
- 真实 `T` **只**作评估坐标；自主停止规则尚未实现。
- 确定性 latent **不**自动解决状态歧义。
- 本轮改进属于**预测器能力**变化；后续规划对照须用同一组冻结检查点。

## 9. 建议冻结

**当前没有可推荐冻结的多步检查点**：两个 1.6M 配对模型都没有跨过第 1 节的基线地板，
且种子未补全。可继续使用的是**单步**配置 `capacity_0p9M_seed0`（0.90M，`t>0` 0.201 cm，
batch=1 延迟 3.25 ms），它是本轮唯一在单步任务上稳定优于保持基线、成本又低的检查点。

**下一步最小诊断**：先确认"命令＋时间"查表为何能在 k=1 上胜过模型——
若是 `elapsed` 让模型可以退化为查表，则应把该基线作为特征纳入模型输入或作为残差基准；
若不是，则说明当前的多步损失与读出结构没有把已知的确定性利用起来。
