## 2.1 历史读出错误（阻断性）

**旧代码**：`experiments/transformer_scale_latent_v1/models.py::last_real`

```python
lengths = valid.sum(dim=1).clamp(min=1).long() - 1
return hidden[rows, lengths, :]
```

**复现**（`git show ce561da:...models.py`，逐长度核对）：

| 有效 token 数 | 旧函数读到的槽位 | 真实末位 | 判定 |
|---:|---:|---:|---|
| 1 | 0 | 32 | 错 |
| 6 | 5 | 32 | 错 |
| 16 | 15 | 32 | 错 |
| 17 | 16 | 32 | 错 |
| 32 | 31 | 32 | 错 |
| 33 | 32 | 32 | 对 |

在冻结测试面板前 384 个真实窗口上：**238 个读错位置**，其中 **167 个读进补齐区**。
`t=0` 时真实末位是 32，旧函数读到槽位 0——而补齐行的编码器输出被乘零，
所以**历史表示为常数零**，输出与输入无关。审查报告的 226/158 与本次 238/167 同量级，
差异来自 384 个窗口的具体取样。

**修复**：`last_real` 改为调用共享的 `night_sequence_v1.models.last_valid_index`
（由 mask 自身求索引），全仓库只有这一套公式。

**真实调用路径验证**（不是只测工具函数）：对
`DirectMultiStep.encoder → last_real` 的实际张量逐长度断言：

```
 1/6/16/17/32/33 tokens: 读出与真实末位一致 = True，且非零 = True
```

即 `t=0` 时历史编码不再被无条件清零。

**必须撤回的旧结论**：上一轮全部直接多步与 latent 结果都是在错误读出下训练的。
受影响的检查点 `direct_multistep_h8_*` / `latent_autoregressive_h8_*` 不能用"重新评估"
挽救；本轮**重新初始化并重训**，新检查点前缀 `repair_`。

## 2.2 latent 消融样本错配与时间索引

**旧代码**：`LatentAutoregressive.rollout` 先 `latents.append(latent)` 再 transition，
所以第 k 个读出用的是**未推进**的 `z_k`。

**复现**（eval 模式，关闭 dropout）：

```
k=1: 正常与冻结最大差 = 0.000e+00   ← 首步必然相同
k=2: 3.528e-02
k=3: 6.322e-02
k=4: 9.105e-02
```

因此旧报告"冻结改善第一步"**不成立**；而且旧报告把完整面板的 `t>0` 正常结果与
前 512 个混合窗口的冻结结果相比，样本口径也不一致。

**修复**：按任务书推荐的动力学定义重写为

```
z_(k+1) = z_k + Transition(z_k, command, clock, dt)
observation_hat[t+(k+1)dt] = Decoder(z_(k+1))
```

即**先推进再解码**；冻结消融在**每个**未来时刻都用 `z0` 解码。修复后首步就不同
（k=1 最大差 3.454e-02），这与旧实现定义不同，因此**不再要求新实现首步相等**。

## 2.3 训练窗口覆盖被缓存固定

**旧代码**：`train.py` 启动时抽取 4096 个窗口，之后每个 epoch 只是重排同一批。

**复现**：

| 检查项 | 旧实现 |
|---|---|
| 同 seed 两次采样是否相同 | **是**（完全相同的 index 与 end） |
| 覆盖唯一 root | 4096 / 4096 |
| 每个 root 实际取了几条技能记录 | **恰好 1 条** |
| 每个 root 平均有多少条技能记录 | **8.0 条** |

即 7/8 的命令变体与其余时间点**从未进入训练**。"覆盖全部 root"不等于覆盖命令变体。

**修复**：新增 `data.RootRecordIndex`（只缓存语料**布局**）＋每 epoch
`draw()`：root 均衡 → root 内**随机**技能记录 → 记录内**随机**合法结束时刻。
两个 epoch 的样本不同；一次 4096 窗口的采样给出 4096 个唯一 root、4096 个唯一记录、
4096 个唯一 (序列, 前缀) 对、**90 个唯一命令签名**（旧实现只能看到每 root 第一条记录的命令）。
`sample_statistics` 记录唯一 root / 序列 / (序列,前缀) / 命令签名 / `t=0` 比例 / 有效未来标签数。

## 2.4 分组统计基线与"任务确定性"统计

三处错误，全部复现：

1. **`within_group_spread` 实际算的是全局离散度。** 旧代码把**所有组**的位移堆进
   `global_table` 再取中位离散度，然后命名为"组内"。修复后**在组内**计算，再给出两种
   具名汇总（等权、按样本数加权），并报告每组样本数与可见标签数。
2. **命中率只检查外层 key 是否存在**，而实际每个 step 可能回退到全局统计。
   修复后按"实际使用了有效分组统计"计：**58.9%** 的窗口、**56.4%** 的 (窗口, step)
   真正用到了分组统计（旧口径报 97.5%）。
3. **时间分箱在拟合与查表两侧不一致的风险**（float32 时钟 vs `end*0.05`）。
   改为整数步索引 `end // 10`（0.5 s 一格），两侧共用同一个函数。

**旧 0.0517 cm 论断撤回。** 按正确口径（组内、等权、仅可见标签、step 1）重算：

| 机器人 | step 1 组内离散度（等权，cm） | 分组数 |
|---|---:|---:|
| r0 | **0.0091** | 142 |
| r1 | **0.0061** | 120 |

数值比旧报告更小，但**定义不同、样本不同，不能拿旧数字当证据**。
另外必须写明：**任何基线都不是不可突破的误差下限**，它只是当前分组尺度下的一个参照。

## 2.5 扩容结论与交付

- 0.90M→1.64M 的单种子 0.201→0.176 cm 只能称为**改善迹象**；
  上一轮用"另一模型家族的种子极差 0.068 cm"去否定它，方法上不成立（不同族、不同读出），
  本轮改为如实标注"单种子、无重复、不足以判定"。
- 4.15M 点未完成、自主终止未实现、无收敛证据，均已如实标注。
- 固定训练面板与固定验证面板都在 eval 模式评估；随机训练批次损失只作为优化日志。
- 打包验证器新增**接口不变量检查**（不再只做数值复现）：见 `verify_package.py` 中
  对读出位置、t=0 非零、消融首步不同的断言。
